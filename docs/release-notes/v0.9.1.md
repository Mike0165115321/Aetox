# 🚀 Aetox v0.9.1

v0.9.0 แยกงานออกเป็นโต๊ะและตัวแทน รุ่นนี้ตอบคำถามที่ตามมาทันที คือ **แล้วของแต่ละชิ้นเป็นของใคร**

เครื่องมือเขียนเอกสารเป็นของตัวแทนหรือของโต๊ะ · เซิร์ฟเวอร์ MCP ที่ติดตั้งไว้ควรโผล่ที่ไหนบ้าง ·
ความจำของตัวแทนอยู่กับนิยามของมันหรืออยู่คนละที่ · คีย์ API ควรนอนปนกับค่าตั้งค่าไหม · ประวัติ
แชทของสองประตูควรอยู่กองเดียวกันหรือเปล่า

ทุกข้อข้างบนเคยมีคำตอบที่ไม่มีใครตั้งใจ คือ "อยู่รวมกันหมด เพราะยังไม่มีใครแยก"

---

## 1. หนึ่งตัวแทน = หนึ่งโฟลเดอร์

ทุกอย่างของตัวแทนหนึ่งคนอยู่ที่เดียว คำถามว่า "ตัวแทนนี้คืออะไร" ตอบได้ด้วยการเปิดโฟลเดอร์ ไม่ต้อง
ไล่หาสามที่

```
<โฟลเดอร์ข้อมูล>/agents/doc/AGENT.md    นิยามและคำสั่งงาน
<โฟลเดอร์ข้อมูล>/agents/doc/MEMORY.md   สิ่งที่มันเรียนรู้จากการทำงาน
```

ตัวแทนที่ติดมากับแอปวางแบบเดียวกันเป๊ะ การ "ก๊อปออกมาแก้" จึงเป็นการก๊อปจริง ๆ ไม่ใช่การแปลงร่าง

**ปุ่มลบสองความหมาย เลิกปนกันแล้ว**

- **คืนค่าตัวแทนที่ติดมากับแอป** ลบแค่ไฟล์นิยาม ความจำอยู่ต่อ เพราะความจำเป็นของ *ชื่อ* ไม่ใช่
  ของคำสั่งงาน การแก้คำสั่งงานแล้วกดคืนค่าต้องไม่ล้างสิ่งที่มันสะสมมาหลายเดือน
- **ลบตัวแทนที่คุณสร้างเอง** ลบทั้งโฟลเดอร์ เพราะชื่อนั้นหายไปแล้ว ถ้าเหลือความจำไว้ ตัวแทนตัว
  หน้าที่ใช้ชื่อซ้ำจะได้โน้ตของคนอื่นมา

ไฟล์แบบเดิมย้ายให้อัตโนมัติตอนอ่านครั้งแรก ไม่ต้องทำอะไร

## 2. ตัวแทนทั้งสามเขียนคำสั่งงานใหม่หมด

`doc` · `sheet` · `deck` ได้คำสั่งงานใหม่ที่ยาวขึ้นสามเท่า และแต่ละตัวสร้างขึ้นรอบ **ข้อจำกัดข้อเดียว
ที่ทุกอย่างงอกออกมาจากมัน** แทนที่จะเป็นรายการกฎ

| ตัวแทน | แกน |
|---|---|
| `doc` | คนเปิดเอกสารเพราะอยากได้อะไรบางอย่าง ให้เขาก่อน · ดึงรายละเอียดจากแหล่งมาให้ครบ · ถ่วงน้ำหนักหัวข้อตามเนื้อหา ไม่ใช่ตามความสมมาตร |
| `sheet` | ทุกความล้มเหลวคือความล้มเหลวเดียวกัน คือไฟล์ที่ดูถูกแต่คำนวณผิด · ห้ามเดาตัวเลข ให้เว้นว่างแล้วบอก |
| `deck` | มีคนยืนพูดอยู่หน้าห้อง อะไรที่ต้อง *อ่าน* บนสไลด์คือของที่แข่งกับคนพูด และคนพูดแพ้เสมอ |

## 3. ผู้ช่วยหลักไม่แบกเครื่องมือเขียนอีกแล้ว

เครื่องมือเขียนเอกสาร ตาราง และสไลด์ **ไม่อยู่บนโต๊ะไหนเลย** ผู้ช่วยส่งงานให้ตัวแทนแล้วเก็บไฟล์
ซึ่งเป็นเหตุผลที่ตัวแทนมีอยู่ตั้งแต่แรก

ทำได้เพราะไฟล์ตั้งค่าของโต๊ะแยกคำถามสองข้อออกจากกันแล้ว คือมีรายการของที่ **อยู่ในห้องให้ตัวแทน
ใช้ แต่ไม่อยู่บนโต๊ะ** ก่อนหน้านี้มีรายการเดียว การเอาเครื่องมือออกจากโต๊ะจึงเอามันไปจากตัวแทนด้วย

**และงานเขียนยาว ๆ กลายเป็นไฟล์ `.md` เป็นค่าเริ่มต้น** ทั้งคำอธิบาย แผน โน้ต และสิ่งที่ค้นเจอ
ผู้ช่วยเขียนเองเป็นไฟล์มาร์กดาวน์ ส่วนเอกสาร ตาราง และสไลด์ คือคำขอคนละอย่างที่ส่งให้ตัวแทน

## 4. MCP: ทะเบียนกลางที่มีสวิตช์ต่อปลายทาง

**เจอบั๊กที่ทำให้ MCP ใช้ไม่ได้เลยตั้งแต่วันที่เริ่มมีโต๊ะ** เซิร์ฟเวอร์ที่ตั้งไว้จะเชื่อมต่อสำเร็จ ลงทะเบียน
แล้ว **ถูกกรองออกจากทุกโต๊ะ** เพราะไฟล์ตั้งค่าของโต๊ะที่ติดมากับแอปถูกเขียนก่อนที่เซิร์ฟเวอร์ของ
ผู้ใช้จะมีตัวตน มันจึงเรียกชื่อเซิร์ฟเวอร์ไหนไม่ได้เลย ผู้ช่วยตอบว่า "ไม่มี MCP" ซึ่งจากมุมของมัน
คือเรื่องจริง

ตอนนี้ **ตัวเซิร์ฟเวอร์เป็นคนบอกเองว่าจะไปอยู่ที่ไหน**:

```json
{ "name": "sequential-thinking", "for": ["assistant", "coding"] }
{ "name": "video-tools",         "for": ["agent:วิดีโอ"] }
```

หน้าตั้งค่ากลายเป็นทะเบียน กดที่แถวแล้วกางสวิตช์ เลือกได้ว่าจะเปิดให้โต๊ะไหนและตัวแทนคนไหน
รายชื่อมาจากระบบจริง สร้างตัวแทนใหม่แล้วมันขึ้นเอง

- **ใส่ค่าเป็นชื่อตัวแทนได้จริง** ตัวแทนจึงได้เครื่องมือของเซิร์ฟเวอร์นั้นไปใช้ในงานของมัน โดยที่
  ผู้ช่วยหลักไม่ต้องแบก
- **ใช้ตัวแปรสภาพแวดล้อมในหัวข้อและค่าตั้งค่าได้** คีย์จึงไม่ต้องอยู่ในไฟล์ตั้งค่าเลย
- **เครื่องมือที่มาจาก MCP บอกที่มาของตัวเองแล้ว** เดิมชื่อของมันคือชื่อเซิร์ฟเวอร์ต่อด้วยชื่อ
  เครื่องมือ และคำอธิบายเป็นของเซิร์ฟเวอร์ ไม่มีคำว่า MCP อยู่ตรงไหนเลย โมเดลจึงตอบไม่ได้ว่า
  มี MCP หรือเปล่า
- **โหมดสิทธิ์เต็มใช้ได้กับ MCP แล้ว** เดิมมีกฎ "ถามก่อน" ที่แอปสร้างเองแล้วชนะโหมดที่ผู้ใช้เลือก
  ทั้งที่การ์ดเขียนว่า "รับทุกอย่างโดยไม่ถาม" ตอนนี้กฎที่แอปสร้างหลีกให้โหมด ส่วนกฎที่ผู้ใช้เขียน
  เองยังชนะ
- **ปฏิเสธพร้อมบอกเหตุผลตอนเซิร์ฟเวอร์ยังต่อไม่เสร็จ** ซึ่งดีกว่ารับงานไปทำโดยไม่มีเครื่องมือ
  แล้วคืนของที่ดูเหมือนคำตอบ

## 5. ความลับแยกออกจากค่าตั้งค่า

**คีย์ API เคยนอนอยู่ในไฟล์เดียวกับภาษาที่เลือก โต๊ะล่าสุด และชื่อผู้ใช้** ซึ่งเป็นไฟล์ที่คนเปิดดู แปะ
ลงรายงานบั๊ก และถ่ายรูปหน้าจอ ทุกการกระทำธรรมดาพวกนั้นทำให้คีย์รั่ว

```
model-preference.json  →  ค่าตั้งค่า อ่านได้ ยกไปคุยได้
credentials.json       →  คีย์เท่านั้น เข้ารหัสด้วย DPAPI บน Windows
```

- **ไฟล์การล็อกอินก็เข้ารหัสด้วย** เป็นความลับชนิดเดียวกัน ไม่มีเหตุผลให้มีสองมาตรฐาน
- **มีทะเบียนความลับที่เดียว** แล้วทางออกสามทางใช้ทะเบียนเดียวกัน ทั้งบันทึกดีบัก บันทึกคำสั่งเชลล์
  และตารางในฐานข้อมูล เดิมมีทางที่คีย์ในคำสั่งลงไปนอนถาวรได้
- **บันทึกดีบักสร้างด้วยสิทธิ์ไฟล์ 0600 แล้ว**

**และปิดรูที่เปิดอยู่จริง** รายการโฟลเดอร์ห้ามอ่านมีบรรทัด `.aetox` พร้อมคอมเมนต์ว่า "โฟลเดอร์
ข้อมูลของ Aetox: คีย์อยู่ที่นี่" แต่ **มันชี้ผิดโฟลเดอร์ทุกระบบปฏิบัติการ** ไฟล์ที่มีคีย์จึงอ่านได้ด้วย
เครื่องมือไฟล์ทุกตัว ในโหมดที่เดินได้ทั้งเครื่อง ในวงวนที่มีเครื่องมือดึงข้อมูลจากเว็บอยู่ด้วย

ตอนนี้ปิดเป็นรายไฟล์ ไม่ใช่ทั้งโฟลเดอร์ คือ `credentials.json` · `oauth.json` · `.env` ·
`model-preference.json` · `mcp-servers.json` และ `webview/` ซึ่งเป็นโปรไฟล์เบราว์เซอร์ในแอป
(มีคุกกี้ของทุกเว็บที่ล็อกอินไว้) ส่วนโฟลเดอร์บันทึก ความจำ และตัวแทน ยังอ่านได้ เพราะ
นั่นคือ Aetox อธิบายตัวเอง

และทุกการปฏิเสธ **บอกทางออก** ไม่ใช่แค่บอกว่าไม่ได้ เพราะเดิมผู้ช่วยเอาข้อความปฏิเสธไปรายงาน
ผู้ใช้ว่าเป็นข้อจำกัดของผลิตภัณฑ์

## 6. สองประตูแยกกันจริง

- **ประวัติแยกตามประตู และแยกตั้งแต่ตอนดึงข้อมูล** เดิมดึง 200 อันล่าสุดจากทุกประตูมาก่อนแล้ว
  ค่อยกรองทิ้งในหน้าจอ วันที่มีบทสนทนาฝั่งโค้ด 200 อันติดกัน ประวัติฝั่งผู้ช่วยจะ **ว่างเปล่า** ทั้งที่
  ข้อมูลอยู่ในตาราง เป็นบั๊กที่โตตามการใช้งานและโผล่ตอนที่แย่ที่สุด
- **หน้าผู้ช่วยไม่มีโปรเจกต์แล้ว** เอกสารเขียนไว้ตลอดว่าฝั่งผู้ช่วยไม่เจาะจงโปรเจกต์ แต่หน้าจอยัง
  ให้เลือกอยู่ ตอนนี้เดินเข้าประตูผู้ช่วยแล้วเลิกเจาะจงจริง ๆ และขากลับเข้าประตูโค้ดมันเปิดโปรเจกต์
  ล่าสุดให้
- **หน้าโค้ดไม่มีตัวเลือก "ไม่เจาะจงโปรเจกต์"** เพราะฝั่งโค้ดทำงานในโปรเจกต์เสมอ
- **ช่องค้นหาในหน้าโค้ดใช้ได้แล้ว** เดิมมันถูกวาดไว้และต่อสายไว้ แต่ผลลัพธ์ไม่มีที่แสดง พิมพ์ลงไป
  แล้วไม่มีอะไรเกิดขึ้นเลย

## 7. รีเฟรชแล้วไม่เด้งกลับหน้าแรก

ฝั่งหลังบ้านอยู่ข้ามการโหลดหน้าต่างใหม่ คือยังถือเซสชันไว้ ยังจำได้ และคุยต่อจากเดิมได้ แต่หน้าจอ
ที่เพิ่งโหลดไม่เคยดึงบทสนทนากลับมา มันเลยขึ้นหน้าเริ่มต้น เหมือนถูกโยนกลับไปจุดเริ่ม ทั้งที่ระบบ
ไม่ได้ลืมอะไรเลย

เขียนลงไฟล์ให้เห็น ไม่ใช่ค่าที่ซ่อนอยู่ในโค้ด

# 🚀 Aetox v0.9.1 Release Notes — ของใครอยู่ที่ไหน

v0.9.0 แยกงานออกเป็นโต๊ะและตัวแทน รุ่นนี้ตอบคำถามที่ตามมาทันที: **แล้วของแต่ละชิ้นเป็นของใคร**

เครื่องมือเขียนเอกสารเป็นของตัวแทนหรือของโต๊ะ · MCP server ที่ติดตั้งไว้ควรโผล่ที่ไหนบ้าง · ความจำของตัวแทนอยู่กับนิยามของมันหรืออยู่คนละที่ · API key ควรนอนปนกับค่าตั้งค่าไหม · ประวัติแชทของสองประตูควรอยู่กองเดียวกันหรือเปล่า

ทุกข้อข้างบนเคยมีคำตอบที่ไม่ได้ตั้งใจ — คือ "อยู่รวมกันหมด เพราะยังไม่มีใครแยก"

> 📄 ภาพผลิตภัณฑ์ที่ [COMPANY.md](../../COMPANY.md) · เหตุผลเชิงวิศวกรรมที่ [DECISIONS.md](../DECISIONS.md)

## 1. 📦 หนึ่งตัวแทน = หนึ่งโฟลเดอร์

ทุกอย่างของตัวแทนหนึ่งคนอยู่ที่เดียว — "ตัวแทนนี้คืออะไร" ตอบได้ด้วยการเปิดโฟลเดอร์ ไม่ต้องไล่หาสามที่

```
<DataRoot>/agents/doc/AGENT.md    นิยาม + brief
<DataRoot>/agents/doc/MEMORY.md   สิ่งที่มันเรียนรู้จากการทำงาน
<DataRoot>/agents/doc/mcp.json    (ที่ว่างสำหรับรุ่นหน้า)
```

ตัวแทนที่ฝังมากับแอปวางแบบเดียวกันเป๊ะ — "ก๊อปออกมาแก้" จึงเป็นการก๊อปจริงๆ ไม่ใช่การแปลงร่าง

**ปุ่มลบสองความหมาย ไม่ปนกันแล้ว**

* **คืนค่าตัวแทนที่ฝังมา** — ลบแค่ `AGENT.md` ความจำอยู่ต่อ เพราะมันเป็นของ*ชื่อ* ไม่ใช่ของ brief การแก้ brief แล้วกดคืนค่าต้องไม่ล้างสิ่งที่มันสะสมมาหลายเดือน
* **ลบตัวแทนที่จ้างเอง** — ลบทั้งโฟลเดอร์ ชื่อหายไปแล้ว ถ้าเหลือความจำไว้ ตัวแทนตัวหน้าที่ใช้ชื่อซ้ำจะได้โน้ตของคนอื่นมา

ไฟล์แบบเดิมย้ายให้อัตโนมัติตอนอ่านครั้งแรก ไม่ต้องทำอะไร

## 2. ✍️ ตัวแทนทั้งสามเขียนใหม่หมด

`doc` · `sheet` · `deck` ได้ brief ใหม่ที่ยาวขึ้นสามเท่า และแต่ละตัวสร้างรอบ **ข้อจำกัดเดียวที่ทุกอย่างงอกออกมาจากมัน** แทนที่จะเป็นลิสต์กฎ

| ตัวแทน | แกน |
|---|---|
| `doc` | คนเปิดเอกสารเพราะอยากได้อะไรบางอย่าง — ให้เขาก่อน · ลากความเฉพาะเจาะจงจากแหล่งมาให้ครบ · ถ่วงน้ำหนักหัวข้อตามเนื้อ ไม่ใช่ตามความสมมาตร |
| `sheet` | ทุกความล้มเหลวคือความล้มเหลวเดียวกัน — ไฟล์ที่ดูถูกแต่คำนวณผิด · ห้ามเดาตัวเลข เว้นว่างแล้วบอก |
| `deck` | มีคนยืนพูดอยู่หน้าห้อง อะไรที่ต้อง*อ่าน*บนสไลด์คือของที่แข่งกับคนพูด และคนพูดแพ้เสมอ |

## 3. 🪑 ผู้ช่วยหลักไม่แบกเครื่องมือเขียนอีกแล้ว

`doc_write` · `sheet_write` · `slides_write` **ไม่อยู่บนโต๊ะไหนเลย** ผู้ช่วยส่งงานให้ตัวแทนแล้วเก็บไฟล์ — ซึ่งเป็นเหตุผลที่ตัวแทนมีอยู่ตั้งแต่แรก

ทำได้เพราะ manifest ของโต๊ะแยกคำถามสองข้อออกจากกันแล้ว: `chairs:` คือของที่**อยู่ในห้องให้ตัวแทนใช้ แต่ไม่อยู่บนโต๊ะ** ก่อนหน้านี้เป็นลิสต์เดียว การเอาเครื่องมือออกจากโต๊ะจึงเอามันไปจากตัวแทนด้วย และออฟฟิศจะทำสิ่งที่ตัวเองมีไว้ทำไม่ได้

**และงานเขียนยาวๆ กลายเป็น `.md` เป็นค่าเริ่มต้น** — คำอธิบาย แผน โน้ต สิ่งที่ค้นเจอ ผู้ช่วยเขียนเองเป็นไฟล์ markdown ส่วนเอกสาร/ชีต/สไลด์คือคำขอคนละอย่าง ที่ส่งให้ตัวแทน

## 4. 🔌 MCP — ทะเบียนกลางที่มีสวิตช์ต่อปลายทาง

**เจอบั๊กที่ทำให้ MCP ใช้ไม่ได้เลยตั้งแต่มีโต๊ะ** — server ที่ตั้งไว้จะเชื่อมต่อสำเร็จ ลงทะเบียน แล้ว**ถูกกรองออกจากทุกโต๊ะ** เพราะ manifest ที่ฝังมากับแอปถูกเขียนก่อนที่ server ของผู้ใช้จะมีตัวตน มันจึงเรียกชื่อ server ไหนไม่ได้เลย ผู้ช่วยตอบว่า "ไม่มี MCP" ซึ่งจากมุมของมันคือเรื่องจริง

ตอนนี้ **ตัว server เป็นคนบอกเองว่าไปที่ไหน**:

```json
{ "name": "sequential-thinking", "for": ["assistant", "coding"] }
{ "name": "video-tools",         "for": ["agent:วิดีโอ"] }
```

หน้าตั้งค่ากลายเป็นทะเบียน — กดที่แถวแล้วกางสวิตช์ เลือกได้ว่าจะเปิดให้โต๊ะไหน ตัวแทนคนไหน รายชื่อมาจากเอนจิน จ้างตัวแทนใหม่มันขึ้นเอง

* **`for: ["agent:X"]` ทำงานจริง** — ตัวแทนได้ tool ของ server นั้นในงานของมัน โดยที่ผู้ช่วยหลักไม่ต้องแบก
* **`${env:VAR}` ใน headers/environment** — key ไม่ต้องอยู่ในไฟล์ตั้งค่าเลย อ่านตอนต่อ server เหมือนที่ `git credential.helper` และ `docker credsStore` ทำ
* **tool ที่ bridge มาบอกที่มาแล้ว** — เดิมชื่อมันคือ `<server>_<tool>` และคำอธิบายเป็นของ server ไม่มีคำว่า MCP อยู่ตรงไหน โมเดลจึงตอบไม่ได้ว่ามี MCP หรือเปล่า
* **โหมดสิทธิ์เต็มใช้ได้กับ MCP แล้ว** — เดิมมีกฎ "ถามก่อน" ที่แอปสร้างเองแล้วชนะโหมดที่ผู้ใช้เลือก ทั้งที่การ์ดเขียนว่า "รับทุกอย่างโดยไม่ถาม" ตอนนี้กฎที่แอปสร้างหลีกให้โหมด ส่วนกฎที่ผู้ใช้เขียนเองยังชนะ
* **ปฏิเสธพร้อมเหตุผลตอน server ยังต่อไม่เสร็จ** — ดีกว่ารับงานแล้วทำโดยไม่มีเครื่องมือ แล้วคืนของที่ดูเหมือนคำตอบ

## 5. 🔐 ความลับแยกออกจากค่าตั้งค่า

**API key เคยนอนอยู่ในไฟล์เดียวกับ `ui_locale`, `last_desk`, `user_name`** — ไฟล์ที่คนเปิดดู แปะลงบั๊กรีพอร์ต และถ่ายรูปหน้าจอ ทุกการกระทำธรรมดาพวกนั้นทำให้ key รั่ว

```
model-preference.json  →  ค่าตั้งค่า อ่านได้ ยกไปคุยได้
credentials.json       →  key เท่านั้น เข้ารหัสด้วย DPAPI บน Windows
```

* **`oauth.json` เข้ารหัสด้วย** — ความลับชนิดเดียวกัน ไม่มีเหตุผลให้สองมาตรฐาน
* **ทะเบียนความลับที่เดียว** — `debuglog.Redact` แล้วสามทางออกใช้ทะเบียนเดียวกัน: debug log, shell audit log, `tool_runs` ในฐานข้อมูล เคยมีทางที่ `curl -H "Authorization: Bearer …"` ลงไปนอนถาวรได้
* **debug log เป็น 0600 แล้ว**

**และปิดรูที่เปิดอยู่จริง** — denylist มีบรรทัด `.aetox` พร้อมคอมเมนต์ว่า "data root ของ Aetox: key อยู่ที่นี่" แต่**มันชี้ผิดโฟลเดอร์ทุก OS** (`~/.aetox` คือที่เก็บ skills ส่วน data root มาจาก `os.UserConfigDir`) ไฟล์ที่มี model API key จึงอ่านได้ด้วยเครื่องมือไฟล์ทุกตัว ในโหมดที่เดินทั้งเครื่อง ใน loop ที่มี `web_fetch` อยู่ด้วย

ตอนนี้ปิด `credentials.json` · `oauth.json` · `.env` · `model-preference.json` · `mcp-servers.json` · `webview/` (โปรไฟล์เบราว์เซอร์ในแอป — cookie ของทุกเว็บที่ล็อกอินไว้) **ปิดรายไฟล์ ไม่ใช่ทั้งโฟลเดอร์** — `logs/` `memory/` `agents/` ยังอ่านได้ เพราะนั่นคือ Aetox อธิบายตัวเอง

และทุกการปฏิเสธ**บอกทางออก** ไม่ใช่แค่ "ไม่ได้" — เดิมผู้ช่วยเอาข้อความปฏิเสธไปรายงานผู้ใช้ว่าเป็นข้อจำกัดของผลิตภัณฑ์

## 6. 🚪 สองประตูแยกกันจริง

* **ประวัติแยกตามประตู และแยกที่ SQL** — `WHERE` มาก่อน `LIMIT` เดิมดึง 200 อันล่าสุดจากทุกประตูมาแล้วค่อยกรองทิ้งในหน้าจอ วันที่มีบทสนทนาโค้ด 200 อันติดกัน ประวัติฝั่งผู้ช่วยจะ**ว่างเปล่า**ทั้งที่อยู่ในตาราง — บั๊กที่โตตามการใช้งานและโผล่ตอนที่แย่ที่สุด
* **หน้าผู้ช่วยไม่มีโปรเจกต์แล้ว** — §19/§86 เขียนไว้ตลอดว่าหน้าร้านไม่โฟกัสโปรเจกต์ แต่หน้าจอยังให้เลือกอยู่ ตอนนี้เดินเข้าประตูผู้ช่วยแล้วเลิกโฟกัสจริง (เอนจินมี root เดียว การซ่อนปุ่มเฉยๆ จะทำให้ผู้ช่วยทำงานอยู่ในโฟลเดอร์โดยไม่มีอะไรบอก) และขากลับเข้าประตูโค้ดมันเปิดโปรเจกต์ล่าสุดให้
* **หน้าโค้ดไม่มี "ไม่โฟกัสโปรเจกต์"** — โรงช่างทำงานในโปรเจกต์เสมอ
* **ช่องค้นหาในหน้าโค้ดใช้ได้แล้ว** — เดิมมันถูกวาดไว้และต่อกับ store แต่ผลลัพธ์ไม่มีที่แสดง พิมพ์ลงไปแล้วไม่มีอะไรเกิดขึ้นเลย

## 7. 🔄 รีเฟรชแล้วไม่เด้งกลับหน้าแรก

Backend อยู่ข้ามการ reload ของหน้าต่าง — ยังถือ session ยังจำได้ ข้อความถัดไปต่อจากเดิมได้ แต่หน้าจอที่เพิ่งโหลดไม่เคยดึงบทสนทนากลับมา เลยขึ้นหน้าเริ่มต้น เหมือนถูกโยนกลับไปจุดเริ่ม ทั้งที่เอนจินไม่ได้ลืมอะไรเลย

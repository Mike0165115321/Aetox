# 🚀 Aetox v1.2.0

รุ่นนี้เพิ่มความจำอีกชั้นที่ผูกกับโปรเจกต์ ให้ผู้ใช้ชี้จุดบนหน้าเว็บส่งให้เอเจนดูได้ วาดสมการ
คณิตศาสตร์ได้ และให้เอเจนบอกล่วงหน้าได้ว่างานที่รับไปมีกี่ขั้น พร้อมกับปิดช่องโหว่ความปลอดภัย
หนึ่งจุด และแก้สองอย่างที่ทำให้เอเจนโทษตัวเองในสิ่งที่ไม่ใช่ความผิดมัน

อีกครึ่งของรุ่นเป็นเรื่องน้ำหนักกับความถูกต้อง: รายการเครื่องมือที่ส่งไปกับทุกข้อความเบาลง 23%
โดยที่โมเดลไม่ได้รู้น้อยลง · การมอบงานกลายเป็นสวิตช์ที่ปิดมาตั้งแต่แรก · เพิ่มภาษาที่สามได้แล้ว ·
หน้าตั้งค่าครั้งแรกถูกทำใหม่ทั้งชุด · และมิเตอร์ความจำเลิกแสดงตัวเลขที่แต่งขึ้น

## 1. บทเรียนข้ามโปรเจกต์ ข้อตกลงไม่ข้าม

"เครื่องนี้ไม่มี Excel" เป็นจริงไม่ว่าคุณจะเปิดโฟลเดอร์ไหน ความจำแบบนั้นข้ามโปรเจกต์มาตั้งแต่แรก
สิ่งที่ไม่เคยมีที่อยู่คือของอีกแบบ คือ **"ในโปรเจกต์นี้เราตกลงกันว่า X และเพราะอะไร"**

จะเก็บไว้ที่โต๊ะทำงานก็ไม่ได้ เพราะโต๊ะโค้ดเป็นโต๊ะเดียวกันในทุกโปรเจกต์ ของที่เก็บไว้ตรงนั้นจะ
เดินไปโผล่เป็นคำแนะนำในโปรเจกต์ถัดไป และไฟล์ `AETOX.md` ก็ไม่ใช่ที่ เพราะนั่นคือสิ่งที่ **คุณ**
บอกเอเจน ส่วนนี่คือสิ่งที่ **งาน** สรุปได้แล้วคุณกดอนุมัติ

ตอนนี้ความจำมีปลายทางที่สาม เอเจนเลือกได้ว่าจะจำลงส่วนกลาง ลงโต๊ะ หรือลงโปรเจกต์ที่กำลังเปิด
อยู่ ไฟล์เก็บในโฟลเดอร์ข้อมูลของ Aetox ไม่ใช่ในโปรเจกต์ของคุณ จึงไม่มีไฟล์แปลกปลอมโผล่ใน git
และใช้กับโฟลเดอร์ที่ไม่ใช่ repo ได้ด้วย

ลำดับความสำคัญตอนส่งให้โมเดลคือ ความจำของโต๊ะ → ข้อตกลงของโปรเจกต์นี้ → `AETOX.md` ของทีม
และ **เซสชันที่ไม่ได้เจาะจงโปรเจกต์จะมองไม่เห็นชั้นนี้เลย** หน้าตั้งค่าแยกรายการให้ตามเจ้าของ
คุณจึงเห็นว่าบรรทัดไหนเป็นของใคร

## 2. สิ่งที่เอเจนขอจำ กดตัดสินได้ตรงนั้นเลย

เครื่องมือความจำเป็นเครื่องมือเดียวที่งานของมัน **ยังไม่เกิด** ตอนมันทำงานเสร็จ มันแค่จ่อเรื่องไว้
แล้วรอคนตัดสิน แต่หน้าจอปฏิบัติกับมันเหมือนเครื่องมืออื่น คุณจึงเห็นแค่ว่า "มีอะไรชื่อ memory
รันไป" ส่วนข้อความที่มันอยากจำและปุ่มรับ/ไม่รับ ไปอยู่อีกสองหน้าถัดไป

ตอนนี้มีการ์ดอยู่ใต้คำตอบที่เสนอมันเลย อ่านแล้วกดได้ที่นั่น การ์ดอ้างถึงรายการด้วยรหัส ไม่ได้เก็บ
สำเนาข้อความไว้ ข้อเสนอที่คุณอนุมัติไปแล้วจากหน้าตั้งค่าเมื่อสัปดาห์ก่อน จึงไม่กลับมายื่นปุ่มให้กด
ซ้ำอีกในแชทเก่า

และการ์ดเขียนว่า **ขอ** ไม่ใช่ **บันทึกแล้ว** เพราะ ณ วินาทีนั้นยังไม่มีอะไรถูกบันทึก

## 3. คำตอบที่คุณพิมพ์แทรก ก็ยังเป็นคำตอบ

ถ้าคุณพิมพ์แทรกตอนงานกำลังเดิน ข้อความนั้นจะวิ่งเข้าไปในงานนั้นเลย และถ้าโมเดลเขียนคำตอบ
เสร็จไปแล้ว งานจะเดินต่อแทนที่จะให้คุณรอ ปัญหาคือหลังจากนั้นหน้าจอแยกไม่ออกว่าอันไหนคือ
คำตอบ อันไหนคือคำบรรยาย คำตอบที่เขียนจบแล้วจึง **เสียการจัดรูปแบบ เสียขนาดตัวอักษร และเสีย
ตำแหน่ง** ในวินาทีที่คุณกำลังอ่านมันอยู่ (สัญลักษณ์อย่าง `##` และ `**` โผล่มาเป็นตัวหนังสือจาง ๆ)

ต้นเหตุคือข้อมูลที่แยกสองสิ่งนี้ออกจากกันถูกเก็บไว้ที่เดียวและไม่เคยส่งต่อไปไหน ตอนนี้มันเดินทาง
ไปพร้อมข้อความและถูกบันทึกด้วย แชทที่เปิดพรุ่งนี้จึงยังแยกออก

## 4. สมการคณิตศาสตร์ถูกวาดแล้ว

โมเดลที่ถูกถามเรื่องอินทิกรัลจะเขียนตอบมาเป็น LaTeX เพราะคณิตศาสตร์เขียนด้วยสิ่งนั้น แต่หน้าจอ
ไม่เคยรู้จัก มันจึงอ่านสมการเป็นข้อความธรรมดาแล้วพิมพ์เศษสัญลักษณ์ออกมา

ตอนนี้สมการถูกแยกออกมาก่อน แล้ววาดด้วย KaTeX รองรับสี่รูปแบบที่โมเดลใช้เขียนกันจริง ส่วน `$`
เดี่ยวมีเงื่อนไขกันไว้ เพราะ `$` เป็นสัญลักษณ์เงินด้วย ประโยคอย่าง *"ราคา $5 และ $10"* ไม่ใช่สมการ

สมการที่วาดไม่ได้จะแสดงเป็นข้อความเดิม **ไม่ใช่กรอบแดง** เพราะระหว่างที่โมเดลกำลังพิมพ์ สมการ
จะไม่สมบูรณ์อยู่หลายเฟรม และไม่ควรมีอะไรแดงวาบระหว่างทาง ภาษาไทยใน `\text{}` ใช้ได้ และปุ่ม
คัดลอกจะได้ LaTeX ต้นฉบับ ไม่ใช่สิ่งที่ตาเห็น

## 5. ปุ่มรันโค้ดจะขึ้นเฉพาะภาษาที่เครื่องนี้รันได้

เดิมคำตอบว่า "บล็อกไหนกดรันได้" ถูกเขียนไว้สองที่ และไม่มีที่ไหนถามเครื่องเลย ปุ่มจึงโผล่บนภาษา
ที่ยังไม่ได้ติดตั้ง แล้วพอกดก็เด้งไปหน้า Microsoft Store

ตอนนี้แอปถามครั้งเดียวตอนเปิดว่าเครื่องนี้รันอะไรได้บ้าง ปุ่มที่กดแล้วไม่เกิดอะไรจึงไม่ถูกวาด และ
บล็อก Python / Node / Go กดรันได้แล้ว โดยไฟล์ถูกเขียนลงพื้นที่ปลอดภัยแล้วรันผ่านประตูเดียวกับ
ที่โมเดลใช้ จึงได้บันทึกการใช้งาน เวลาจำกัด และสิทธิ์ชุดเดียวกัน

ผลลัพธ์แสดงในแผงของตัวเอง พับเองเมื่อเกินสิบบรรทัด บอกจำนวนบรรทัดกับเวลาที่ใช้ และ **บอก
เมื่อผลลัพธ์ถูกตัด** ถ้ารันไม่ผ่านจะมีปุ่มขอให้ช่วยแก้ ซึ่งส่งทั้งโค้ดและข้อความผิดพลาดไปให้

## 6. ชี้จุดบนหน้าเว็บให้เอเจนดู

เอเจนอ่านหน้าเว็บและกดปุ่มได้อยู่แล้ว สิ่งที่มันทำไม่ได้คือเข้าใจประโยค *"ปุ่มสีฟ้ามุมขวาบนอะ"*
ตอนนี้คุณชี้ได้ และสิ่งที่ลงไปในช่องพิมพ์คือตัวอิลิเมนต์นั้นจริง ๆ ทั้งตำแหน่ง ขนาด สีที่มันแสดงจริง
และโค้ดรอบตัว ลากคลุมพื้นที่ก็ได้ ซึ่งกรณีนั้นแอปจะส่งภาพของบริเวณนั้นไปแทน เพราะคำว่า
"ตรงบริเวณนี้" ไม่มีทางแปลเป็นตำแหน่งในโค้ดได้

ภาพถูกเรนเดอร์จากตัวเบราว์เซอร์ ไม่ใช่แคปหน้าจอ เพราะการแคปหน้าจอจะติดอะไรก็ตามที่ลอยทับ
อยู่มาด้วย

## 7. เอเจนบอกล่วงหน้าได้ว่างานนี้มีกี่ขั้น

การมอบหมายงานทำพร้อมกันหลายชิ้นได้อยู่แล้ว สิ่งที่เพิ่มคือขั้นที่ **ยังไม่เกิดขึ้น** โมเดลที่ค้นเจอ
แปดอย่างแล้วตัดสินใจเองว่าจะส่งไปตรวจต่อ คือโมเดลที่กำลังทำเกินหน้าที่ให้ รอบตรวจสอบเป็นสิ่งที่
มักถูกข้ามพอดีตอนที่คำตอบดูเหมือนเสร็จแล้ว และไม่มีอะไรบนจอบอกว่ามันถูกข้าม

ตอนนี้ขั้นที่ประกาศไว้จะแสดงเป็น **0/8** ค้างอยู่ต่อหน้าคุณจนกว่าจะมีคนทำจริง หลักการคือ
**ทำให้มองเห็น ไม่ใช่บังคับ** Aetox บังคับให้โมเดลเดินรอบสองไม่ได้ แต่ทำให้การไม่เดินมองเห็นได้
และการ์ดบอกด้วยว่าผู้ช่วยแต่ละตัวรันบนโมเดลอะไรและใช้โทเคนไปเท่าไร

## 8. หน้าต่างเปิดในขนาดที่จอรับได้จริง

โน้ตบุ๊ก 1920×1080 ที่ตั้งสเกล 150% ตามค่าเริ่มต้นของวินโดวส์ มีพื้นที่จริงเท่ากับ 1280×720 ในหน่วย
ที่หน้าต่างใช้ Aetox จึงถูกสร้างสูงเกินจอไป 180px แล้วจัดกึ่งกลาง ผลคือขอบบนหลุดออกนอกจอไปอยู่ที่
y = -114 **พร้อมกับปุ่มย่อ/ขยาย/ปิด** ซึ่งเป็นของวินโดวส์ ไม่ใช่ของแอป

ตอนนี้แอปวัดก่อนเปิด นับพื้นที่ทาสก์บาร์ด้วย และมันมีแต่ **หด** ไม่เคยขยาย จอที่มีที่พอจะเปิดได้
เท่าเดิมทุกประการ

## 9. ความปลอดภัย: เครื่องมือค้นไฟล์อ่านทะลุรายการที่ถูกห้าม

เครื่องมือค้นหาอย่าง `grep`, `glob` และ `fs find` ตรวจสิทธิ์ที่ **โฟลเดอร์ตั้งต้น** ครั้งเดียว แล้ว
ส่งทุกไฟล์ใต้มันเข้าไปอ่านโดยไม่ถามซ้ำรายไฟล์ การค้นที่เริ่มจากโฟลเดอร์ที่เข้าถึงได้โดยชอบ จึงอ่าน
ทะลุสิ่งที่ถูกห้ามไว้ข้างใต้ได้ และในโหมดที่ขอบเขตคือทั้งเครื่อง นั่นแปลว่าไฟล์เก็บรหัสผ่านอยู่ห่าง
แค่คำสั่งค้นหาเดียวจากเซสชันที่ถูกห้ามอ่านมันโดยตรง

ปิดแล้ว โดยใช้รายการเดิมและคำตัดสินชุดเดิม ไม่มีการเรียกระบบเพิ่มต่อไฟล์ ไฟล์ที่ถูกห้ามจะถูกข้าม
เงียบ ๆ เพราะการประกาศออกมาว่าไม่ยอมอ่านไฟล์ไหนบ้าง เท่ากับบอกตำแหน่งของมันลงบันทึกฟรี ๆ
และ `glob` ก็กรองด้วย เพราะชื่อไฟล์เป็นการรั่วที่เล็กกว่าเนื้อไฟล์ แต่ยังเป็นการรั่ว

## 10. สองอย่างที่ทำให้เอเจนโทษตัวเองผิด ๆ

**Python บนวินโดวส์เขียนผลลัพธ์ด้วยรหัสภาษาของเครื่อง** สคริปต์ที่พิมพ์ `∞` จะตายด้วย
`UnicodeEncodeError` แล้วไปถึงเอเจนเป็นแค่ "จบด้วยข้อผิดพลาด" มันจึงอ่านว่าคำนวณผิดแล้วรื้อ
คำตอบที่ถูกอยู่แล้วทิ้ง (เกิดจริงสามครั้งในบันทึกวันที่ 16 ส.ค.) อีกแบบเงียบกว่าคือรหัสภาษาไทย
เขียนไทยได้ สคริปต์จึงจบสำเร็จพร้อมข้อความเพี้ยน ซึ่งเอเจนจับไม่ได้เลย ตอนนี้ทุกคำสั่งถูกบังคับ
ให้ใช้ UTF-8 (ข้ามทั้งก้อนถ้าคุณตั้งค่านี้ไว้เองแล้ว)

**WSL อ่านบรรทัดคำสั่งสองรอบ** ทำให้ตัวแปรในคำสั่งถูกแทนที่ไปก่อนที่ bash จะเห็น ผลที่วัดได้
เมื่อ 17 ส.ค. คือคำสั่ง `awk '{print $1}'` กลายเป็น `awk '{print }'` ซึ่งพิมพ์ทั้งบรรทัดออกมาโดย
ไม่มีข้อผิดพลาดให้จับ และที่แย่ที่สุดคือ `false; echo rc=$?` รายงานว่าสำเร็จ **ความล้มเหลวที่ถูก
อ่านเป็นสำเร็จคือทิศทางเดียวที่ผิดไม่ได้** แก้แล้วโดยเปลี่ยนวิธีเรียก

## 11. รายการเครื่องมือเบาลง 23% โดยที่โมเดลไม่ได้รู้น้อยลง

วัดจากการใช้งานจริง 68 เซสชัน 1,883 ครั้ง ก่อนออกแบบอะไรทั้งสิ้น: เซสชันหนึ่งใช้เครื่องมือต่างกัน
**5 ตัว** เป็นค่ากลาง แต่เราส่งคำอธิบายไป **38 ตัว** ทุกข้อความ และไม่มีเครื่องมือตัวไหนถูกใช้เกิน
ครึ่งของเซสชันเลย ตัวเลขนี้ตัดแผน "ส่งแค่ 20 ตัวยอดนิยม" ทิ้ง เพราะไม่มีชุดหลักให้แบ่ง งานต่างกัน
ที่ *เรื่อง* ไม่ใช่ที่ความเข้มข้น

คำอธิบายเครื่องมือหนึ่งตัวมีสามส่วนที่แยกกันได้ และมีอายุการใช้งานต่างกัน:

| ส่วน | ต้องอยู่ตอนไหน | น้ำหนัก (ตัวอย่างจากเครื่องมือเบราว์เซอร์) |
|---|---|---|
| บอกว่ามีอยู่ | ตลอดเวลา | ~10 โทเคน (1%) |
| บอกว่าเรียกยังไง | ตอนเรียก | ~70 โทเคน (9%) |
| **บอกว่าเมื่อไหร่ควรใช้** | **ครั้งเดียว** | **~686 โทเคน (90%)** |

ส่วนที่สามถูกย้ายออกมาส่งไปพร้อม **ผลลัพธ์ครั้งแรก** ของเซสชัน ซึ่งเป็นการเรียกที่ยังไงก็ต้องเกิด
จึงไม่เสียรอบเดินทางเพิ่มเลย และมันสอนตอนเรียกพลาดด้วย ซึ่งเป็นจังหวะที่ขาดคำสอนพอดี

**ไม่แตะเรื่องสิทธิ์เลย** ทุกความสามารถยังอยู่ครบตลอดเวลา สิ่งที่ย้ายคือไบต์ ไม่ใช่สิทธิ์

```
browser   766 → 314 โทเคน   (คำสอน 830 โทเคน กระจายอยู่ใน 9 คำสั่งย่อย)
task    1,568 → 730 โทเคน   (673 โทเคนอยู่ในพารามิเตอร์ agent ตัวเดียว)
shell     854 → 498 โทเคน
```

รวมทั้งบล็อก **10,224 → 7,848 โทเคน** ที่ค่าเริ่มต้น (8,578 ถ้าเปิดการมอบงาน)

สี่อย่างที่ **ไม่** ย้าย และเหตุผลคนละข้อกัน: รายชื่อทีมในเครื่องมือมอบงาน เพราะการเลือกว่าจะมอบ
ให้ใครเกิด *ก่อน* การมอบครั้งแรก · ชื่อเชลล์ที่คำสั่งจะถูกรันด้วย เพราะนั่นไม่ใช่คำสอน แต่เป็น
ข้อเท็จจริงที่ตัดสินว่าจะเขียนคำสั่งยังไง · กฎห้ามพิมพ์รหัสผ่านลงหน้าเว็บ เพราะเป็นกฎความปลอดภัย
ที่ต้องไม่หายไปกับการย่อบทสนทนา · และคำสอนเรื่องการรอผลลัพธ์ ซึ่งกลับด้านกับคำสอนอื่น เพราะ
ความผิดพลาดที่มันกันคือการ *ไม่* เรียกมันเลย

## 12. การมอบงานเป็นสวิตช์ และปิดมาตั้งแต่แรก

77% ของเซสชันที่วัดได้ไม่เคยมอบงานเลย และการปิดไว้ประหยัด **~730 โทเคนตั้งแต่ข้อความแรก**
ปิดแล้ว **ไม่สร้างเครื่องมือเลย** ไม่ใช่สร้างแล้วปฏิเสธ ซึ่งจะยังเสีย 730 โทเคนไปกับการบอกว่าไม่

สวิตช์มีสองชั้น ตัวใหญ่ปิดการมอบงานทั้งหมด ตัวรายคนเอาเอเจนหนึ่งคนออกจากรายชื่อ (~21 โทเคน
ต่อคน) สวิตช์ใหญ่อยู่ใน **เมนูเลือกผู้ช่วยตรงช่องพิมพ์** ไม่ใช่ในหน้าตั้งค่าอย่างเดียว เพราะ
ความสามารถที่ปิดมาแต่แรกและซ่อนอยู่ในหน้าตั้งค่า คือความสามารถที่ถูกตัดทิ้งไปกลาย ๆ

**การซ่อนชื่อไม่ใช่การห้าม** และนี่คือหนี้ที่เกือบเกิด: ตัวกรองรายชื่อกับตัวสั่งงานเคยเป็นคนละทาง
โมเดลที่จำชื่อได้จากบริบทก่อนหน้าจึงสั่งงานเอเจนที่ถูกปิดไปแล้วได้เลย ตอนนี้รวมเป็นทางเดียวที่
ตอบคำถามเดียว คือเซสชันนี้มอบงานให้คนนี้ได้ไหม และถ้าไม่ได้เพราะอะไร

ทุกที่บนหน้าจอเขียนว่า **"มอบงานให้"** ไม่ใช่ "เปิด/ปิด" เพราะสิ่งที่ปิดคือระยะเอื้อมของผู้ช่วยหลัก
ไม่ใช่ตัวเอเจน คุณยังเปิดแชทคุยเองได้ ยังพิมพ์ `@ชื่อ` ได้ แถวที่ถูกปิดจึง **จางลง ไม่ใช่หายไป**

## 13. เพิ่มภาษาที่สามได้แล้ว และจีนตัวย่อคือตัวพิสูจน์

คำถามว่า "เพิ่มภาษาอื่นยากไหม" มีคำตอบสองครึ่งที่ไม่เหมือนกันเลย ฝั่งหน้าจอพร้อมอยู่แล้ว ฝั่ง
เครื่องยนต์ไม่พร้อม เพราะข้อความที่ผู้ใช้อ่านถูกเขียนเป็นฟังก์ชันที่รับสองภาษาตายตัวอยู่ **37 จุด**
บวกอีก 4 จุดที่แตกสาขาด้วยคำถามว่าเป็นอังกฤษหรือไม่ ไม่มีอะไรผิดสำหรับสองภาษา มันผิดเรื่อง
"มีได้กี่ภาษา" ต้นทุนของภาษาถัดไปจึงต้องจ่ายด้วยการแก้โค้ดที่ไม่เกี่ยวกับการแปลเลย ตอนนี้เปลี่ยน
เป็นโครงสร้างที่ไม่ตัดสินว่ามีได้กี่ภาษา

สองกฎที่ผิดเฉพาะตอนมีเกินสองภาษา และผิดมาตั้งแต่ก่อนแปลคำแรก:

- **ตัดรหัสภาษาที่ขีดแรกเสมอ** ทำให้ `pt-BR` ถูกอ่านเป็น `pt` คือยื่นคำแปลโปรตุเกสยุโรปให้คน
  บราซิลโดยดูเหมือนทำงานปกติทุกประการ ตอนนี้ลองรหัสเต็มก่อนแล้วค่อยตัด
- **ภาษาไทยเป็นตัวสำรอง** ซึ่งถูกโดยบังเอิญตอนที่มีสองภาษา พอมีจีน คนที่เจอข้อความที่ยังไม่ได้
  แปลจะได้ภาษาไทย ทั้งที่อังกฤษครบอยู่ข้าง ๆ ตอนนี้ตกไปที่อังกฤษ

ความครบของคำแปลถูกบังคับด้วยระบบตรวจเฉพาะภาษาที่เจ้าของอ่านออก ถ้าไปบังคับกับภาษาที่อ่าน
ไม่ออก ผลที่ได้ไม่ใช่คำแปล แต่เป็นข้อความสำรองที่ใส่ไว้ให้บิลด์ผ่าน ซึ่งเป็นคำโกหกที่ระบบตรวจ
จับไม่ได้ เทสต์จึงตรวจเฉพาะสิ่งที่ตรวจได้โดยไม่ต้องอ่านภาษานั้น เช่น ไม่มีค่าว่าง และตัวแปรใน
ข้อความต้องอยู่ครบ ข้อหลังสำคัญ เพราะคำแปลที่ทำตัวแปรหล่นจะไม่ขึ้นข้อผิดพลาด มันจะแสดงว่า
*"คุณมี  รายการ"* ให้ผู้ใช้เห็นตลอดไป

จีนตัวย่อแปลแล้ว **423 จาก 1,032 ข้อความ** ที่เหลือตกไปอังกฤษตามที่ออกแบบ ฟอนต์จีนถูกผูกไว้
กับข้อความภาษาจีนเท่านั้น ไม่ได้ใส่ไว้ในฟอนต์กลาง เพราะตัวอักษรฮั่นใช้ร่วมกับญี่ปุ่นแต่วาดคนละ
แบบ ถ้าใส่ไว้กลาง ข้อความญี่ปุ่นจะถูกวาดด้วยรูปอักษรจีนเงียบ ๆ

เก็บหนี้ก้อนเดียวกันไปด้วย: การตัดคำ การตรวจตัวสะกด และเสียงที่โปรแกรมอ่านหน้าจอเลือกใช้ ล้วนมา
จากคำประกาศเดียวที่หน้าเว็บของแอปเคยตั้ง `lang="th"` ไว้ตายตัวใน `index.html` แล้วไม่เคยเปลี่ยน
ตามภาษาที่ผู้ใช้เลือก

## 14. หน้าตั้งค่าครั้งแรกใหม่ห้าจอ

จอที่เปิดตอนใช้โปรแกรมครั้งแรกเป็นหน้าเดียวในแอปที่ไม่มีผู้ใช้เก่า และเป็นหน้าเดียวที่ **คนทำ
มองไม่เห็น** เพราะเครื่องที่พัฒนามีคีย์อยู่แล้ว จอนี้จึงข้ามตัวเองทุกครั้ง ตอนนี้มีปุ่มใน **ตั้งค่า →
ทั่วไป** ให้เรียกดูใหม่ได้ โดยล้างเฉพาะความจำเรื่องหน้าตา ไม่แตะคีย์ ประวัติแชท หรือข้อความที่
พิมพ์ค้างไว้

พอมองเห็นแล้วก็พบว่ามันถามผิดคำถาม เพราะ **"ต้องใช้คีย์" กับ "กรอกคีย์ได้" ถูกรวมเป็นข้อเดียว**
บริการอย่าง Codex ต้องมีแพ็กเกจ ChatGPT และไม่มีคีย์ให้กรอก ส่วนคีย์ที่กรอกได้เป็นของอีก
ระบบหนึ่ง คนละโฮสต์ คนละบิล และได้ 401 กลับมาแน่นอน หลังบ้านแยกไว้ถูกต้องตั้งแต่ต้น แต่อีกสามที่ไม่ได้ถาม
รวมถึงเมนูของ CLI ที่วนถามคีย์ไม่จบกับคีย์ที่ไม่มีวันมีอยู่จริง

จอถูกออกแบบใหม่ทั้งชุด จากกล่อง 560px ที่มีเมนูดรอปดาวน์ของระบบปฏิบัติการสองอัน กลายเป็นห้าจอ
ที่ถามทีละคำถาม: **ภาษา** เป็นจอแรกและมีแต่เรื่องนั้น · *"ตอนนี้คุณมีอะไรอยู่ในมือแล้วบ้าง"* ตอบ
เป็นภาษาคน ไม่ใช่ชื่อยี่ห้อ · **ธีมเลือกจากสีจริง** ที่อ่านมาจากไฟล์ธีมตอนเปิด · ทุกจอมีปุ่มย้อนกลับ
และ**ไม่มีทางข้าม** · และจบด้วยจอ "พร้อมแล้ว" แทนที่จะหายไปเฉย ๆ

ค่าเริ่มต้นขนาดตัวอักษรเปลี่ยนตามที่วัดมาแล้ว: ทั้งระบบ **16px** แชท **14.5px**

## 15. มิเตอร์ความจำเลิกแสดงตัวเลขที่แต่งขึ้น

มิเตอร์เคยอ่านว่า `11.4k / 32.0k (36%)` โดยที่ **ครึ่งบนวัดจริง ครึ่งล่างแต่งขึ้น** เลข 32,000 ไม่เคย
มาจากใคร มันคืองบตัดประวัติ 128,000 หารสี่ ที่ถูกหยิบมาใช้เป็นค่าสำรอง

สองอย่างนี้เป็นคนละเรื่องที่ถูกใส่ป้ายเดียวกัน: **งบคือ Aetox เก็บประวัติได้เท่าไรก่อนย่อ ส่วน
หน้าต่างคือโมเดลรับได้เท่าไร** ประวัติของเครื่องเองหักล้างตัวเลขที่ตัวเองวาด รอบใหญ่สุดที่ codex
รับไปคือ 43,434 โทเคน และมีเก้ารอบที่เกินหน้าต่างที่วาดไว้ ขณะที่หน้าต่างจริงของโมเดลนั้นคือ
1,050,000

ตอนนี้ถ้าไม่รู้หน้าต่างจริง หน้าจอจะ **ทิ้งตัวส่วน ไม่ทิ้งมิเตอร์** แล้วบอกขนาดคำขอแทน

และปัญหาถัดมาโผล่ทันที คือการประมาณโทเคนจากจำนวนไบต์ด้วยตัวคูณคงที่ วัดจากเซสชันจริงพบว่า
อัตราส่วนแกว่งระหว่าง **3.45 ถึง 5.46** ตามสัดส่วนไทย/อังกฤษในบทสนทนา ซึ่งเป็นคุณสมบัติของ
*งาน* ไม่ใช่ของโมเดล ที่อัตรา 3.45 งบ 4,200,000 ไบต์คือ 1.22M โทเคน ซึ่งเลยหน้าต่าง 1,050,000
ไปแล้ว ทั้งที่ตัวงบยังอ่านว่าเหลือเยอะ จูนตัวเลขใหม่ก็แก้ไม่ได้ เพราะค่าที่ต่ำพอจะปลอดภัยจะทิ้ง
พื้นที่ไปหนึ่งในสี่ทุกเซสชันที่ไม่ใช่กรณีแย่สุด

ทางออกคือเลิกให้ค่าคงที่เป็นหลักประกันตัวเดียว **ถ้าผู้ให้บริการปฏิเสธเพราะยาวเกิน** Aetox จะย่อ
ประวัติแล้วยิงซ้ำทันที สูงสุดสองครั้ง ส่วนกรณีอื่นอย่างโควตาหมดหรือเงินหมด ถูกกันออกโดยตั้งใจ
เพราะย่อประวัติไม่ช่วยสักอาการ ของเดิมไม่ได้ดีกว่านี้ ของเดิมคือไม่มีอะไรเลย เทิร์นตายแล้วกดใหม่
ก็ตายซ้ำเหมือนเดิม

## 16. เบราว์เซอร์ของเอเจน: ทำงานกับแท็บที่มันเปิดเอง

สามบั๊กในสองวัน ต้นเหตุเดียวกันหมด คือกฎที่สำคัญที่สุดของระบบนี้เขียนไว้ในคอมเมนต์ ไม่ได้อยู่ใน
ตัวโครงสร้างข้อมูล จึงไม่มีอะไรบังคับได้

- เป้าหมายของคำสั่งอ่าน/คลิก/พิมพ์ เคยเป็น "แท็บที่อยู่หน้าสุด" ซึ่งเปลี่ยนทุกครั้งที่ **ผู้ใช้** คลิก
  แท็บของตัวเอง ตอนนี้แท็บของเอเจนเป็นคนละประเภทกับแท็บทั่วไป
- การเปิดหน้าถัดไปถูกเรียกจากเธรดที่ WebView2 **ปฏิเสธเงียบ ๆ** หน้าที่สองเป็นต้นไปจึงตายที่
  การรอครบ 20 วินาทีมาตั้งแต่ 10 ส.ค. ตอนนี้โค้ดแบบนั้นคอมไพล์ไม่ผ่าน ไม่ใช่รอไปเจอตอนรัน
- ข้อความผิดพลาดของเบราว์เซอร์เคยจบที่ไฟล์ล็อกอย่างเดียว เอเจนจึงได้แค่ *"หน้าโหลดไม่เสร็จ"*
  แล้วสรุปว่าเน็ตเสีย และบอกผู้ใช้แบบนั้นสามครั้ง

อีกอย่างที่เจอจากบันทึกการรันจริง ไม่ได้เจอจากเทสต์: **คำสั่งเปิดหน้ารายงานชื่อของหน้าที่เพิ่งจาก
มา** การเดินทางถูกต้องเสมอ ผิดแค่ประโยคที่รายงาน แต่โมเดลอ่านประโยคนั้น และหน้า "เว็บที่เอเจน
เคยเปิด" ก็บันทึกชื่อผิดตามมาด้วย ตอนนี้การเปิดหน้าใหม่ล้างสิ่งที่รู้เกี่ยวกับหน้าเก่าทิ้งก่อน และ
หน้าที่ไม่ส่งชื่อกลับมาเลย เช่น PDF หรือรูป ใช้ URL ที่ขอไปเป็นชื่อ คือแลกชื่อผิดเป็นไม่มีชื่อ

ความสามารถที่เพิ่มมาทุกตัวเป็นการลบทางตัน ไม่ใช่การเพิ่มลูกเล่น: เอเจนจับภาพหน้าเว็บ (`capture`)
จัดการแท็บ (`tabs`) รอให้หน้าพร้อม (`wait`) ย้อนกลับ (`back`) และตอบกล่องโต้ตอบของหน้าเว็บ
(`dialog`) ได้แล้ว พร้อมช่องที่อยู่ที่ค้นหาได้

## 17. ตัวกรองคำสั่งเชลล์: จะปฏิเสธ ต้องมีหลักฐานก่อน

ตัวสแกนเส้นทางอ่านข้อความที่ขึ้นต้นด้วย `/` ในเครื่องหมายคำพูดเป็นเส้นทางไฟล์ ซึ่งกันคำสั่ง
อันตรายได้จริง แต่มันก็ปฏิเสธคำสั่งธรรมดาที่หน้าตาบังเอิญเหมือนกันไปด้วย เช่น `sed 's/^/n=/'`
และ `tr '/' '-'` มันเลือกปฏิเสธไว้ก่อนซึ่งปลอดภัย แต่กำแพงที่กั้นงานปกติก็ยังเป็นกำแพง

เส้นที่ลากใหม่: **เส้นทางที่คำสั่งเขียนมาตรง ๆ ตรวจตามที่เขียน ส่วนเส้นทางที่ระบบเดาเอาจาก
รูปแบบ ต้องมีหลักฐานก่อนจึงจะปฏิเสธได้** หลักฐานที่ถูกที่สุดคือส่วนแรกของเส้นทางนั้นมีอยู่จริง
บนเครื่องไหม และจะไปดูก็ต่อเมื่อกำลังจะปฏิเสธเท่านั้น คำสั่งที่ผ่านจึงไม่ช้าลงเลย

เทสต์ยืนยันด้วยว่า ถ้าตรวจไม่ได้เลย ระบบจะคงคำปฏิเสธไว้ เพราะ ***"ผมมองไม่เห็น" ต้องไม่ถูกอ่าน
เป็น "มันไม่มีอยู่"***

## 18. กฎการออกแบบหน้าจอมีที่อยู่แล้ว

รอบรื้อหน้าตั้งค่าครั้งแรกได้กฎมาชุดหนึ่งที่ใช้ได้กับทุกจอ แต่ไม่มีที่เก็บ บันทึกการตัดสินใจเรียงตาม
เวลา คนที่กำลังจะทำจอใหม่ไม่มีทางไล่อ่าน 3,700 บรรทัดเพื่อหาว่ากดปุ่มแล้วควรยุบกี่เปอร์เซ็นต์

[DESIGN.md](../../DESIGN.md) จึงเกิดขึ้น และเป็นไฟล์ที่ **ชนะ** เมื่อเอกสารขัดกันเรื่องหน้าตา
กฎทุกข้อในนั้นมีจอจริงที่เคยพังอยู่ข้างหลัง เช่น ความว่างที่ไม่สมมาตรคือบั๊ก ไม่ใช่รสนิยม ·
ตัวเลือกเกินเจ็ดอันต้องมีคำถามคั่นก่อน · **ยืมโครงได้ ห้ามยืมเครื่องประดับ** · และเทสต์ต้องล็อก
สิ่งที่ *ห้าม* มี ไม่ใช่แค่สิ่งที่ต้องมี

## 19. เล็ก ๆ แต่รู้สึกได้

- **สกิลของผู้ช่วยที่โมเดลมองไม่เห็น** เอกสารถูกลงทะเบียนไว้และเรียกใช้ได้ แต่ชื่อของมันไม่เคย
  ปรากฏในที่ที่โมเดลมองเห็นเลยตลอดสองรุ่นที่ผ่านมา แก้แล้ว
- **เมนูเหนือช่องพิมพ์วัดกับแพเนลที่มันอยู่** ไม่ใช่กับขนาดหน้าจอ และชิปเหนือช่องพิมพ์ตัดบรรทัด
  แทนที่จะวิ่งเลยขอบ (ชิปเทอร์มินัลเคยแสดงว่า "Windo")
- **เริ่มงานในโปรเจกต์ได้จากแถวของโปรเจกต์เอง** ด้วยปุ่ม + บนแถว แทนการคลิกชื่อซึ่งทุกคนอ่าน
  ว่า "เปิดดู"
- **ระยะห่างใต้คำตอบ** แถวเวลากับปุ่มเคยชิดคำตอบมากกว่าที่บรรทัดในคำตอบชิดกันเอง จึงอ่าน
  เหมือนเป็นบรรทัดหนึ่งของคำตอบ
- **ลายน้ำหลังหน้าแชทเปล่าถูกตัดหัวท้าย** ข้างละ 8px เพราะมันตั้งขนาดจากความสูงหน้าต่างแล้ว
  ไปยืนอยู่ในกรอบที่เตี้ยกว่า ต่างกันมาตลอดแต่ไม่ถึงหนึ่งพิกเซล จนวันที่ขนาดตัวอักษรทั้งระบบ
  ขยับเป็น 16px
- **แท็บว่างของเบราว์เซอร์** เคยกองอยู่บนซ้ายและพาดหัวว่า "แท็บนี้ยังว่าง" ทั้งที่ในหน้ามีประวัติ
  24 รายการรออยู่ ตอนนี้จัดกึ่งกลางทั้งสองแกน และพาดหัวบอกว่ามันเป็นอะไรแทนที่จะบอกว่าไม่มีอะไร

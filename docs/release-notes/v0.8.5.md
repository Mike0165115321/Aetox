# 🚀 Aetox v0.8.5 Release Notes — Aetox รู้เวอร์ชันของตัวเอง และขอให้คนที่ติดตั้งมันเป็นคนอัปเดต

### 1. 🔢 ปัญหาที่ต้องแก้ก่อน — แอปตอบไม่ได้ว่าตัวเองเวอร์ชันอะไร

* เลขเวอร์ชันเคยอยู่ **5 ที่ และไม่มีที่ไหนที่โค้ดอ่านได้ตอนรัน**: const ใน `cmd/aetox` (ซึ่งเป็น CLI ที่ยังไม่ปล่อยเป็นสินค้า), `wails.json` (ถูกอบเข้า Windows resource ที่ Go อ่านกลับไม่ได้), หัวข้อสถานะใน README, badge บนหน้าเว็บ และ Scoop manifest
* บัมพ์มือ 5 ที่เคยรอดมาได้เพราะไม่มีอะไรอ่านมันกลับ — แต่พอแอปเริ่ม **ตรวจหาอัปเดต** การลืมบัมพ์ที่ใดที่หนึ่งไม่ใช่แค่พิมพ์ผิด แต่กลายเป็น**แอปโกหกผู้ใช้ในที่เดียวที่เขาเข้าไปหาคำตอบ**
* **`internal/version` คือค่าเดียวจากนี้ไป** และมีเทสบังคับให้อีก 4 ที่ตรงกัน วิ่งไปกับ `go test ./...` ที่ CI รันอยู่แล้วทั้งสามแพลตฟอร์ม — สำเนาที่ค้างจะทำให้ build แดง แทนที่จะหลุดออกไป · `release.yml` เช็ค tag เพิ่มอีกชั้น เพราะ tag คือสำเนาเดียวที่อยู่นอก repo
* จงใจใช้ const ธรรมดา ไม่ใช่ `-ldflags` stamp — `wails dev` และ `go run` คือวิธีที่แอปนี้ถูกรันจริงทั้งวัน และ stamp จะทำให้ทั้งสองรายงานค่าว่าง คือตัวตรวจอัปเดตจะมืดพอดีตรงที่มันกำลังถูกพัฒนา

### 2. 🔄 ตรวจหาอัปเดต — และหลักการที่สำคัญกว่าตัวฟีเจอร์

* **Aetox จะไม่เขียนทับตัวเองเด็ดขาด** ทางที่ดูง่ายกว่าคือโหลด exe ใหม่มาทับตัวเอง แต่มันต้องมี signing key และ signed feed ถึงจะปลอดภัย ต้องยก UAC เพราะตัวติดตั้งลงที่ Program Files และบน macOS การแทนที่ bundle ตัวเองโดยไม่ notarize จะพัง Gatekeeper — สามปัญหาโครงสร้างพื้นฐาน แลกกับความสะดวกอย่างเดียว
* **แทนที่ด้วยการถามว่า "ถูกติดตั้งมายังไง" แล้วส่งงานคืนคนที่ติดตั้ง** (แนวเดียวกับ opencode): ดูจาก path ของ executable เอง — `scoop/apps/` → Scoop, ใต้ Program Files หรือ `%LOCALAPPDATA%\Programs` → ตัวติดตั้ง, path Windows อื่น → portable
* **Scoop ได้คำสั่ง `scoop update aetox` และจงใจไม่มีปุ่มดาวน์โหลดวางข้างๆ** — การชวนผู้ใช้ Scoop ให้แตก zip ทับ install ที่ Scoop ดูแลอยู่ คือความเละที่ดีไซน์นี้มีไว้เลี่ยงพอดี
* ช่องอื่นทั้งหมดได้หน้า release ซึ่ง**ไม่มีวันเป็นคำตอบที่ผิด** — รวมถึงทุกการติดตั้งที่ไม่ใช่ Windows จนกว่าพอร์ต Linux/macOS จะมาถึงและมีอะไรดีกว่านั้นให้พูด
* Homebrew, AppImage และ dpkg ถูกระบุไว้ในคอมเมนต์แล้วว่าเป็นเคสที่จะเพิ่ม แต่**จงใจไม่เดาตอนนี้** — การตรวจจับที่ไม่เคยทดสอบแล้วบอกคำสั่งอัปเดตผิด แย่กว่าคำตอบสำรองที่มันไปแทน

### 3. 🛡️ ตัวเช็คล้มแล้วต้องไม่พาอะไรล้มตาม

* ออฟไลน์ โดน rate limit หรือมี proxy ขวาง → คืน error แล้ว**ไม่เปลี่ยนอะไรอีกเลย** หน้าจอบอกว่า "ไม่มีอะไรเสียหาย Aetox ใช้งานได้ตามปกติ" ไม่ใช่โยน error ของ Go ใส่ผู้ใช้
* **ETag** ถูก cache ไว้ ทำให้การเช็ครอบถัดไปเป็น 304 เปล่าๆ — นี่คือสิ่งที่ทำให้การเช็ควันละครั้งอยู่ในโควตา 60 คำขอ/ชม. ของ GitHub สำหรับผู้เรียกที่ไม่ยืนยันตัวตน
* **draft และ prerelease ไม่มีวันแจ้งเตือนใคร** — ซึ่งพอดีกับที่ `release.yml` สร้างทุก release เป็น draft
* `AETOX_DISABLE_UPDATE_CHECK` ปิดได้ถาวร และตัวเช็ค **ปฏิเสธการยิง API จริงตอนอยู่ในเทส** — บทเรียนจากตอนที่ CI runner สะอาดๆ ดาวน์โหลด binary ของบุคคลที่สามกลางชุดเทส
* เทียบเวอร์ชันด้วย**ตัวเลข ไม่ใช่ string** — `0.8.10` ใหม่กว่า `0.8.9` ส่วนการเทียบแบบ string ให้คำตอบกลับหัวพอดี · อะไรที่แปลงไม่ได้คืน false เพราะการไม่ขึ้นแบนเนอร์ถูกกว่าการจู้จี้เรื่องเวอร์ชันที่ไม่มีอยู่จริงมาก

### 4. ℹ️ Settings → เกี่ยวกับ Aetox

* เวอร์ชันที่ติดตั้ง, ช่องทางที่ตรวจเจอ, ปุ่มตรวจหาอัปเดต, ลิงก์รายการเปลี่ยนแปลง
* **สี่ผลลัพธ์ สี่ประโยคคนละแบบ** — ล่าสุดแล้ว / มีเวอร์ชันใหม่ / ตรวจไม่สำเร็จ / ถูกปิดไว้ เพราะ "คุณปิดมันเอง" คือทางเลือกที่ผู้ใช้เลือก และต้องไม่แสดงผลเป็นความล้มเหลว

### 5. 🧪 การทดสอบ

* เทสใหม่ 28 ตัว · `internal/update` ครอบคลุม 94.7% ของ statement
* ตารางตรวจช่องติดตั้งรับ path, symlink resolver, OS และ environment เป็นพารามิเตอร์ทั้งหมด จึงรันได้ทั้งสาม runner — และทำให้เคส Scoop shim (ซึ่งเผยตัวว่าเป็น Scoop ก็ต่อเมื่อ resolve symlink แล้ว) ทดสอบได้จริงเป็นครั้งแรก

### 🚫 สิ่งที่จงใจไม่สร้าง

ไม่มี binary ที่เขียนทับตัวเอง ไม่มี sidecar updater · ไม่มี update server ของตัวเอง เพราะ GitHub Releases เป็น source of truth อยู่แล้ว · **ไม่มีการดาวน์โหลดเงียบเบื้องหลัง** ซึ่งจะขัดกับคำสัญญา "ไม่มีอะไรถูกดึงมาโดยไม่ถาม" ที่ Scoop manifest เขียนไว้เอง

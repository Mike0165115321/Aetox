# 🚀 Aetox v0.8.5

## 1. ปัญหาที่ต้องแก้ก่อน: แอปตอบไม่ได้ว่าตัวเองเป็นเวอร์ชันอะไร

- เลขเวอร์ชันเคยอยู่ **ห้าที่ และไม่มีที่ไหนที่โค้ดอ่านได้ตอนรัน** ทั้งค่าคงที่ในโค้ดฝั่ง CLI ไฟล์ตั้งค่า
  ของตัวบิลด์ หัวข้อสถานะใน README ป้ายบนหน้าเว็บ และไฟล์ของ Scoop
- การไล่แก้ห้าที่ด้วยมือเคยรอดมาได้ เพราะไม่มีอะไรอ่านมันกลับ แต่พอแอปเริ่ม **ตรวจหาอัปเดต**
  การลืมแก้ที่ใดที่หนึ่งไม่ใช่แค่พิมพ์ผิด แต่กลายเป็น **แอปโกหกผู้ใช้ในที่เดียวที่เขาเข้าไปหาคำตอบ**
- ตอนนี้มี **ค่าเดียวเป็นต้นทาง** และมีเทสต์บังคับให้อีกสี่ที่ตรงกัน เทสต์นี้วิ่งไปกับชุดทดสอบที่ CI
  รันอยู่แล้วทั้งสามระบบปฏิบัติการ สำเนาที่ค้างจึงทำให้บิลด์แดง แทนที่จะหลุดออกไป และกระบวนการ
  ปล่อยรุ่นเช็คแท็กเพิ่มอีกชั้น เพราะแท็กคือสำเนาเดียวที่อยู่นอกโปรเจกต์
- จงใจใช้ค่าคงที่ธรรมดา ไม่ใช่การประทับค่าตอนบิลด์ เพราะการรันแบบนักพัฒนาคือวิธีที่แอปนี้ถูกรัน
  จริงทั้งวัน และการประทับค่าจะทำให้มันรายงานค่าว่าง คือตัวตรวจอัปเดตจะมืดพอดีตรงที่มันกำลัง
  ถูกพัฒนา

## 2. ตรวจหาอัปเดต และหลักการที่สำคัญกว่าตัวฟีเจอร์

- **Aetox จะไม่เขียนทับตัวเองเด็ดขาด** ทางที่ดูง่ายกว่าคือโหลดไฟล์ใหม่มาทับตัวเอง แต่มันต้องมี
  กุญแจเซ็นและช่องทางที่เซ็นแล้วถึงจะปลอดภัย ต้องขอสิทธิ์ผู้ดูแลระบบเพราะตัวติดตั้งลงใน
  Program Files และบน macOS การแทนที่ตัวเองโดยไม่ผ่านการรับรองจะพังกับระบบความปลอดภัย
  ของเครื่อง คือปัญหาเชิงโครงสร้างสามข้อ แลกกับความสะดวกอย่างเดียว
- **แทนที่ด้วยการถามว่า "ถูกติดตั้งมายังไง" แล้วส่งงานคืนคนที่ติดตั้ง** โดยดูจากตำแหน่งของ
  ตัวโปรแกรมเอง: อยู่ใต้ `scoop/apps/` คือ Scoop · อยู่ใต้ Program Files หรือ
  `%LOCALAPPDATA%\Programs` คือมาจากตัวติดตั้ง · พาธอื่นบน Windows คือแบบพกพา
- **คนที่ใช้ Scoop ได้คำสั่งสำหรับ Scoop และจงใจไม่มีปุ่มดาวน์โหลดวางข้าง ๆ** เพราะการชวนผู้ใช้
  Scoop ให้แตกไฟล์ zip ทับสิ่งที่ Scoop ดูแลอยู่ คือความยุ่งเหยิงที่การออกแบบนี้มีไว้เลี่ยงพอดี
- ช่องทางอื่นทั้งหมดได้ลิงก์ไปหน้า release ซึ่ง **ไม่มีวันเป็นคำตอบที่ผิด**
- ช่องทางติดตั้งของ Linux และ macOS ถูกระบุไว้ในโค้ดแล้วว่าเป็นกรณีที่จะเพิ่ม แต่ **จงใจไม่เดา
  ตอนนี้** เพราะการตรวจจับที่ไม่เคยทดสอบแล้วบอกคำสั่งอัปเดตผิด แย่กว่าคำตอบสำรองที่มันไปแทน

## 3. ตัวตรวจล้มแล้วต้องไม่พาอะไรล้มตาม

- ออฟไลน์ โดนจำกัดจำนวนครั้ง หรือมีพร็อกซีขวาง จะคืนข้อผิดพลาดแล้ว **ไม่เปลี่ยนอะไรอีกเลย**
  หน้าจอบอกว่า "ไม่มีอะไรเสียหาย Aetox ใช้งานได้ตามปกติ" ไม่ใช่โยนข้อความผิดพลาดดิบ ๆ ใส่ผู้ใช้
- แอปจำรหัสรุ่นล่าสุดไว้ การตรวจรอบถัดไปจึงได้ 304 กลับมาเปล่า ๆ โดยไม่กินโควตา นี่คือสิ่งที่ทำให้การ
  ตรวจวันละครั้งอยู่ในโควตา 60 คำขอต่อชั่วโมงของ GitHub สำหรับผู้เรียกที่ไม่ยืนยันตัวตน
- **รุ่นร่างและรุ่นทดสอบไม่มีวันแจ้งเตือนใคร** ซึ่งพอดีกับที่ระบบสร้างทุก release เป็นร่างไว้ก่อน
- ปิดถาวรได้ด้วยตัวแปรสภาพแวดล้อม `AETOX_DISABLE_UPDATE_CHECK` และตัวตรวจ **ปฏิเสธการยิงไปหา
  API จริงตอนอยู่ในเทสต์** ซึ่งเป็นบทเรียนจากตอนที่เครื่อง CI ที่สะอาดดาวน์โหลดไฟล์ของบุคคลที่สาม
  กลางชุดเทสต์
- เทียบเวอร์ชันด้วย **ตัวเลข ไม่ใช่ข้อความ** เพราะ `0.8.10` ใหม่กว่า `0.8.9` ส่วนการเทียบแบบ
  ข้อความให้คำตอบกลับหัวพอดี และอะไรที่แปลงไม่ได้จะถือว่าไม่มีรุ่นใหม่ เพราะการไม่ขึ้นแบนเนอร์
  ถูกกว่าการจู้จี้เรื่องเวอร์ชันที่ไม่มีอยู่จริงมาก

## 4. หน้าตั้งค่า → เกี่ยวกับ Aetox

แสดงเวอร์ชันที่ติดตั้ง ช่องทางที่ตรวจเจอ ปุ่มตรวจหาอัปเดต และลิงก์รายการเปลี่ยนแปลง

**สี่ผลลัพธ์ สี่ประโยคคนละแบบ** คือล่าสุดแล้ว / มีเวอร์ชันใหม่ / ตรวจไม่สำเร็จ / ถูกปิดไว้ เพราะ
"คุณปิดมันเอง" คือทางเลือกที่ผู้ใช้เลือก และต้องไม่แสดงผลเป็นความล้มเหลว

## 5. การทดสอบ

เทสต์ใหม่ 28 ตัว ครอบคลุมโค้ดส่วนอัปเดต 94.7% ตารางตรวจช่องทางติดตั้งรับทุกอย่างเป็นค่าที่
ส่งเข้ามา จึงรันได้บนทั้งสามระบบปฏิบัติการ และทำให้กรณีของ Scoop ซึ่งเผยตัวก็ต่อเมื่อตามลิงก์
ไฟล์ไปจนสุดแล้ว ทดสอบได้จริงเป็นครั้งแรก

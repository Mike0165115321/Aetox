## 1. กำแพงรอบโปรเจกต์มีประตูแล้ว

เวลาคุณเจาะจงโปรเจกต์ เครื่องมือไฟล์ทุกตัวและเชลล์จะทำงานอยู่แค่ในโฟลเดอร์นั้น ข้อนี้ยังเหมือน
เดิม สิ่งที่เปลี่ยนคือสิ่งที่เกิดขึ้น **หลัง** การปฏิเสธ

เดิมพาธนอกโปรเจกต์คือทางตัน ผู้ช่วยรู้พาธที่ต้องใช้ บอกว่าเอื้อมไม่ถึง แล้วคุณต้องไปเปิดเมนู
โปรเจกต์ กด "เพิ่มโฟลเดอร์" ไล่หาโฟลเดอร์เดิมนั้นในหน้าต่างของวินโดวส์ ทั้งที่พาธเขียนอยู่ใน
บทสนทนาตรงหน้าแล้ว จากนั้นค่อยสั่งใหม่ พูดง่าย ๆ คือ **แอปรู้คำตอบอยู่แล้ว แต่ให้คุณไปหาเอง**

ตอนนี้จะมีการ์ดขึ้นมาถามตรงนั้น พร้อมชื่อโฟลเดอร์เต็ม ๆ กด "เพิ่มเข้าโปรเจกต์" แล้ว **คำสั่งเดิม
วิ่งต่อทันที** ไม่ต้องสั่งใหม่ โฟลเดอร์จะเข้าไปอยู่ในรายการของโปรเจกต์นั้น มองเห็นได้ ถอดออกได้
และอยู่ข้ามเซสชัน

สามอย่างที่ตั้งใจให้ไม่เปลี่ยน:

- **ไม่มีปุ่ม "อนุญาตครั้งเดียว"** สิทธิ์ที่ไม่อยู่ในรายการที่คุณมองเห็น คือสิทธิ์ที่หน้าจอเลิกบอก
  ความจริง
- **ที่เก็บรหัสผ่านปิดตายเหมือนเดิม** ทั้ง `.ssh`, `.aws`, โปรไฟล์เบราว์เซอร์ และกุญแจของ Aetox
  เอง ถูกตรวจ *หลัง* ประตู การกดรับจึงเอื้อมไปถึงไม่ได้
- **โหมด CLI ไม่มีการ์ด** ไม่มีหน้าต่างก็ไม่มีคนกด คำปฏิเสธที่นั่นยังเป็นคำปฏิเสธเหมือนเดิม

## 2. เชลล์ของวินโดวส์เป็น PowerShell แล้ว

`cmd.exe` ไม่เคยถูกเลือกเพราะเหมาะกับโมเดล มันแค่เป็นสิ่งที่คำว่า "เชลล์ของวินโดวส์" เคยแปลว่า
และมันเป็นภาษาที่โมเดลเห็นมาน้อยที่สุด คำสั่งแรกของแทบทุกเซสชันจึงตายเพราะเขียนเป็น
PowerShell หรือเขียนเป็น `ls -la` แล้วต้องเสียอีกหนึ่งรอบไปลองใหม่

ลำดับตอนนี้คือ **PowerShell 7 ก่อน แล้วค่อย Windows PowerShell 5.1** ที่วินโดวส์ทุกเครื่องมี
ติดมา และถ้าเครื่องคุณมีแต่ 5.1 เครื่องมือเชลล์จะบอกโมเดลไปด้วยว่า `&&` ใช้ไม่ได้ที่นี่ เป็น
ข้อเท็จจริงข้อเดียว ไม่ใช่ตารางไวยากรณ์ทั้งชุด

**ปุ่มหยุดถูกซ่อมไปพร้อมกัน** เดิมใช้คำสั่งที่อ่านรายการโปรเซสครั้งเดียวแล้วค่อยไล่ปิด โปรเซสลูก
ที่เกิดระหว่างสองจังหวะนั้นจึงรอด กับ `cmd.exe` ที่เริ่มเร็วมาก ช่องนี้แทบไม่มีจริง แต่ PowerShell
ใช้เวลาเป็นวินาทีในการเริ่ม การกดหยุดในช่วงนั้นจึงทิ้งคำสั่งที่คุณสั่งให้หยุดไว้เบื้องหลังเป็นประจำ
ตอนนี้ไล่ปิดสองรอบ

## 3. คำตอบที่กำลังพิมพ์ ดูเหมือนกำลังพิมพ์

คำตอบที่ยังพิมพ์ไม่จบเคยถูก **สร้างใหม่ทั้งก้อนทุกตัวอักษร** สำหรับข้อความธรรมดาไม่มีใครสังเกต
แต่สำหรับของที่มีชีวิตของตัวเอง มันคือความต่างระหว่างทำงานกับไม่ทำงาน:

- ภาพที่โมเดลวาดแล้วสั่งให้เคลื่อนไหว จะค้างอยู่ที่เฟรมแรกตลอดกาล
- การเลือกข้อความในคำตอบจะหลุดกลางลาก
- ส่วนที่คุณกดเปิดดูจะปิดกลับเอง

ตอนนี้หน้าจอเทียบของใหม่กับของเดิมทีละส่วนแทนการรื้อสร้างใหม่ ของที่ไม่เปลี่ยนก็ไม่ถูกแตะ

พร้อมกันนั้น **บล็อกที่ยังเขียนไม่จบจะบอกว่ายังไม่จบ** ด้วยลำแสงบาง ๆ วิ่งรอบขอบการ์ด วางทับ
เส้นขอบเดิมพอดี ไม่มีกล่องเพิ่ม ไม่มีเงา และการ์ดของผู้ช่วยที่ทำงานเสร็จจะค่อย ๆ พับลงแทนที่จะ
หายวับในเฟรมเดียว

## 4. ผู้ช่วยไม่มีเพดานจำนวนรอบอีกแล้ว

เพดาน 24 รอบเคยถูกอธิบายว่าเป็นสิ่งที่ทำให้การมอบงานถูกลง ของจริงกลับกัน ผู้ช่วยที่ชนเพดาน
**ไม่ได้หยุดใช้เงิน มันหยุดกลางงาน** แล้วส่งความล้มเหลวกลับมาบอกให้แบ่งงานแล้วเริ่มใหม่ ซึ่งคือ
งานเดิมที่จ่ายสองรอบบวกเวลาที่รอไป และตัวเลข 24 นั้นก็เดาเอาทั้งนั้น เพราะงานหนึ่งจะใช้กี่รอบ
ไม่ใช่สิ่งที่รู้ได้จากคำสั่ง

ค่าเริ่มต้นจึงเป็น **ไม่มีเพดาน** เบรกที่หยุดการวิ่งหลุดจริง ๆ ไม่เคยเป็นตัวนับอยู่แล้ว ตัวจับคำสั่ง
ซ้ำยังอยู่ ปุ่มหยุดยังถึงทุกผู้ช่วย และทุกการเรียกเครื่องมือยังผ่านด่านสิทธิ์เดียวกับตัวหลัก

ถ้าอยากได้เพดานสำหรับผู้ช่วยตัวไหน เขียน `steps: 40` ในโปรไฟล์ของมันแล้วจะได้ 40 พอดี และ
นาฬิกาบนการ์ดเดินตามงานจริง ไม่ได้หยุดนิ่งตั้งแต่วินาทีแรกเหมือนเดิม

**ผู้ช่วยที่ยิงคำสั่งไม่ซ้ำกันยังไม่มีอะไรหยุด** ตัวจับคำสั่งซ้ำจับได้เฉพาะคำสั่งที่ซ้ำเป๊ะ ๆ ผู้ช่วยที่
เปลี่ยนคำค้นไปเรื่อย ๆ จึงเหลือแค่ปุ่มหยุดเป็นเบรก เปิดค้างไว้โดยตั้งใจ เพราะทางแก้ที่ถูกคือจับ
"ไม่คืบหน้า" หรือกำหนดเพดานเวลา ไม่ใช่เอาตัวนับรอบกลับมาในชื่อใหม่

**ตัวเลขเปรียบเทียบประสิทธิภาพยังค้าง** รอบวัดเต็มครั้งสุดท้ายคือ 27 ก.ค. บน v0.9.2 ตอนตัว

ในวันที่บิลด์นี้ออก

**Linux / macOS ยังทำอยู่** CI รันทั้งสองระบบและเก็บบันทึกไว้ให้ดู แต่ไม่ให้ตัดสินผลรวม เพราะ

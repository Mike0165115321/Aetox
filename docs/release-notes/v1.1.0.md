## 1. 🚪 กำแพงรอบโปรเจกต์มีประตูแล้ว

โฟกัสโปรเจกต์แล้ว เครื่องมือไฟล์ทุกตัว **และ shell** ถูกกักอยู่ในโฟลเดอร์นั้น นั่นยังเหมือนเดิม
สิ่งที่เปลี่ยนคือสิ่งที่เกิดขึ้น**หลัง**การปฏิเสธ

เดิม path นอกโปรเจกต์คือทางตัน ผู้ช่วยรู้ path ที่ต้องใช้ บอกว่าเอื้อมไม่ถึง แล้วคุณต้องไปเปิด
เมนูโปรเจกต์ กด "เพิ่มโฟลเดอร์" ไล่หาโฟลเดอร์เดิมนั้นใน dialog ของวินโดวส์ ทั้งที่ path
เขียนอยู่ในบทสนทนาตรงหน้าแล้ว จากนั้นค่อยสั่งใหม่ **แอปรู้คำตอบอยู่แล้ว แต่ให้คนไปหาเอง**

ตอนนี้การ์ดจะขึ้นมาถามตรงนั้น พร้อมชื่อโฟลเดอร์เต็ม ๆ กด "เพิ่มเข้าโปรเจกต์" แล้ว**คำสั่งเดิม
วิ่งต่อทันที** ไม่ต้องสั่งใหม่ ไม่เสียบทสนทนา โฟลเดอร์เข้าไปอยู่ในรายการของโปรเจกต์นั้น
มองเห็นได้ ถอดออกได้ และอยู่ข้ามเซสชัน

สามอย่างที่ไม่เปลี่ยน และตั้งใจให้ไม่เปลี่ยน:

- **ไม่มี "อนุญาตครั้งเดียว"** สิทธิ์ที่ไม่อยู่ในรายการที่คุณมองเห็น คือสิทธิ์ที่แผงเลิกอธิบายความจริง
- **ที่เก็บกุญแจปิดตายเหมือนเดิม** — `.ssh` `.aws` โปรไฟล์เบราว์เซอร์ กุญแจของ Aetox เอง
  ถูกเช็ค*หลัง*ประตู การกดรับจึงเอื้อมไปถึงมันไม่ได้
- **CLI ไม่มีการ์ด** ไม่มีหน้าต่างก็ไม่มีคนกด คำปฏิเสธที่นั่นยังเป็นคำปฏิเสธเหมือนเดิมทุกประการ

## 2. 🐚 เชลล์ของวินโดวส์คือ PowerShell แล้ว — cmd.exe ออก

`cmd.exe` ไม่เคยถูกเลือกเพื่อโมเดล มันแค่เป็นสิ่งที่คำว่า "เชลล์ของวินโดวส์" เคยแปลว่า และมัน
คือสำเนียงที่โมเดลเห็นมาน้อยที่สุด — คำสั่งแรกของแทบทุกเซสชันตายคาไวยากรณ์ PowerShell
หรือ `ls -la` ก่อนที่คำสั่งที่สองจะลองใหม่เป็น cmd หนึ่งรอบที่เสียไปทุกครั้ง

ลำดับตอนนี้คือ **pwsh (7+) ก่อน แล้วค่อย Windows PowerShell 5.1** ที่วินโดวส์ทุกเครื่องมีติดมา
และถ้าเครื่องคุณมีแต่ 5.1 เครื่องมือ shell จะบอกโมเดลไปด้วยว่า `&&` ใช้ไม่ได้ที่นี่ — ข้อเท็จจริง
เดียว ไม่ใช่ตารางไวยากรณ์

**การกด Stop ก็ถูกซ่อมไปพร้อมกัน** เดิมใช้ `taskkill /T /F` ซึ่งอ่านต้นไม้โปรเซสครั้งเดียวแล้วค่อยฆ่า
ลูกที่เกิดระหว่างสองจังหวะนั้นรอดเป็นเด็กกำพร้า สำหรับ cmd ที่ spawn แทบจะทันทีช่องนี้เป็นเรื่อง
ทฤษฎี แต่ PowerShell ใช้เวลาเป็นวินาทีในการสตาร์ต การกด Stop ในช่องนั้นจึงทิ้งคำสั่งที่คุณ
กำลังสั่งให้หยุดไว้เบื้องหลังอย่างสม่ำเสมอ ตอนนี้เดินต้นไม้เองสองรอบ

## 3. ✨ คำตอบที่กำลังมา ดูเหมือนกำลังมา

คำตอบที่ยัง stream อยู่เคยถูก**สร้างใหม่ทั้งก้อนทุกโทเคน** สำหรับข้อความเปล่าไม่มีใครสังเกต
สำหรับของที่มีชีวิตของตัวเองมันคือความต่างระหว่างทำงานกับไม่ทำงาน:

- ภาพที่โมเดลวาดแล้วสั่งให้เคลื่อนไหวเอง **ค้างอยู่เฟรมแรกตลอดกาล**
- การเลือกข้อความในคำตอบ **หลุดกลางลาก**
- `<details>` ที่คุณเปิดไว้ **ปิดกลับเอง**

ตอนนี้มาร์กอัปใหม่ถูกเทียบกับของเดิมทีละโหนดแทนการรื้อสร้างใหม่ ของที่ไม่เปลี่ยนก็ไม่ถูกแตะ

พร้อมกันนั้น **บล็อกที่ยังเขียนไม่จบจะบอกว่ายังไม่จบ** — ลำแสงบาง ๆ วิ่งรอบขอบการ์ด วางทับ
เส้นขอบที่มีอยู่แล้วพอดี ไม่มีกล่องเพิ่ม ไม่มีเงา ไม่มีอะไรอ้วนขึ้น และการ์ดของผู้ช่วยที่ทำงานเสร็จ
**ค่อย ๆ พับลง**แทนที่จะหายวับในเฟรมเดียว

## 4. ♾️ ผู้ช่วยไม่มีเพดานรอบทำงานอีกแล้ว

เพดาน 24 รอบเคยถูกเขียนไว้ว่าเป็นสิ่งที่ทำให้การมอบงานถูกลง ของจริงกลับกัน: ผู้ช่วยที่ชนเพดาน
**ไม่ได้หยุดใช้เงิน มันหยุดกลางงาน** แล้วส่งความล้มเหลวกลับมาบอกให้แบ่งงานแล้วเริ่มใหม่ —
งานเดิม จ่ายสองรอบ บวกเวลาที่รอไป และตัวเลขนั้นเดาเอาทั้งนั้น เพราะงานหนึ่งจะใช้กี่รอบไม่ใช่
สิ่งที่รู้ได้จากบรีฟ

ค่าเริ่มต้นจึงเป็น **ไม่มีเพดาน** เบรกที่หยุดลูปวิ่งหลุดจริง ๆ ไม่เคยเป็นตัวนับอยู่แล้ว: ตัวจับลูปซ้ำ
ยังอยู่ ปุ่ม Stop ยังถึงทุกผู้ช่วย และทุก tool call ยังผ่านด่านสิทธิ์เดียวกับของตัวหลัก

ถ้าคุณอยากได้เพดานสำหรับผู้ช่วยตัวไหน เขียน `steps: 40` ในโปรไฟล์มัน แล้วจะได้ 40 พอดี —
และนาฬิกาบนการ์ดเดินต่อจริงตามที่ผู้ช่วยทำงานอยู่ ไม่ใช่หยุดนิ่งตั้งแต่วินาทีที่มันเริ่ม

## ⚠️ สิ่งที่รุ่นนี้ยังไม่ได้ติ๊ก

**ผู้ช่วยที่ยิงคำสั่งไม่ซ้ำยังไม่มีอะไรหยุด** ตัวจับลูปซ้ำจับได้เฉพาะ call ที่ซ้ำเป๊ะ ๆ ผู้ช่วยที่
เปลี่ยนคำค้นไปเรื่อย ๆ จึงเหลือแค่ปุ่ม Stop เป็นเบรก รู้อยู่ เขียนไว้ใน `DECISIONS §110` แล้ว
และเปิดค้างไว้โดยตั้งใจ — ทางแก้ที่ถูกคือจับ "ไม่คืบหน้า" หรือเพดานเวลา ไม่ใช่เอาตัวนับรอบ
กลับมาในชื่อใหม่

**BENCHMARK ยังค้าง** รอบวัดเต็มครั้งสุดท้ายคือ 2026-07-27 บน v0.9.2 ตอนตัวโปรแกรม 33 MB
วันนี้ 42.4 MB ข้อ *"ตัวเลขที่เผยแพร่ทุกตัวตรงกับของจริง"* จึงยังเปิดค้างอยู่ในวันที่บิลด์นี้ออก

**Linux / macOS ยังเป็นพอร์ตที่ทำอยู่** CI รันทั้งสองตัวและเก็บ log ไว้ให้ดู แต่ไม่ให้มันตัดสิน
ผลรวม เพราะ Windows คือของที่ปล่อยจริง — ci เขียวจึงแปลว่า "Windows ดี" ซึ่งเป็นสิ่งเดียวที่
มันเคยพูดได้อย่างซื่อสัตย์

**การเซ็นโค้ด** ยังไม่มี (ตัวติดตั้งยังขึ้น SmartScreen) — แต่ *ตัวรุ่นที่ปล่อย* เซ็นด้วย ed25519
ตั้งแต่ v0.9.4 และตัวอัปเดตปฏิเสธการอัปเดตที่ลายเซ็นไม่ผ่าน ไม่ใช่ยอมผ่านไป

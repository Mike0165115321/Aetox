# 🚀 Aetox v0.8.3 Release Notes — ChatGPT กลับมา และ context ถูกลงสี่ทาง

### 1. 🔑 ChatGPT ล็อกอินได้อีกครั้ง และนิยามของคำว่า "เสี่ยง" ถูกเขียนใหม่

* **`codex` กลับมา** พร้อม Responses runtime, catalog entry, การ import session จาก Codex CLI (`aetox login codex --import`) — ส่วน Claude Pro/Max, Copilot, Qwen และ Code Assist **ยังไม่กลับ**
* **ทำไมตัวนี้ตัวเดียว**: v0.8.1 ถอดออกด้วย *กฎ* ข้อเดียว แต่สองตัวที่ถอดทีหลังถูกถอดด้วย **ข้อเท็จจริง** — Google ประกาศตรวจจับจริง และ tier นั้นตายไปแล้ว ส่วน ChatGPT ไม่มีข้อเท็จจริงอะไรค้านเลย: flow ใช้งานได้ต่อเนื่อง และไม่มีใครเห็นหรือได้ยินการบังคับใช้ใดๆ สิ่งที่ v0.8.1 มีต่อมันคือ *สมมติฐาน* — และสมมติฐานเป็นเรื่องที่ผู้ใช้ควรชั่งน้ำหนักเอง ไม่ใช่ Aetox ตัดสินแทนด้วยการเอาปุ่มออก
* **`Risk` เปลี่ยนความหมาย และนี่คือส่วนที่อยู่ถาวร**: `RiskRestricted` ตอนนี้แปลว่า Aetox รู้เหตุผล **เฉพาะเจาะจง** ว่าการล็อกอินนี้อาจทำให้ผู้ใช้เสียบัญชี — เป็นการบังคับใช้ที่ผู้ให้บริการประกาศหรือลงมือแล้ว ไม่ใช่แค่ "รูปทรง" ของ flow · เหตุผลเชิงปฏิบัติแรงกว่า: คำเตือนที่ขึ้นทุกครั้งคือคำเตือนที่ผู้ใช้เรียนรู้ที่จะกดผ่าน ซึ่งทำให้เสียกรณีที่คำเตือนมีไว้เพื่อพอดี
* **ไม่ได้อ้างว่า**: OpenAI อนุญาตให้แอปอื่นใช้ client id ของ Codex CLI — ไม่มีใครพิสูจน์เรื่องนั้น การเปลี่ยนแปลงนี้ตั้งอยู่บน *การไม่มีการบังคับใช้* ไม่ใช่ *การมีอนุญาต* ถ้าวันหนึ่งเปลี่ยน มันจะกลับไปเป็น `RiskRestricted` และถูกถอดออกตามกฎเดิม
* **Account id ที่ backend ใช้ route** ไม่มีอยู่ใน token response เลย มีแค่ใน claim ข้างใน `id_token` ซึ่ง refresh response มักไม่ส่งมาด้วย — จึงต้องอ่านจาก id_token และหิ้วค่าเดิมต่อเมื่อ refresh ไม่ส่งมา ตอนนี้มีเทสตรึงทั้งสามจุด

### 2. 💸 Context ถูกลงสี่ทาง — เพื่อพิสูจน์ว่าโมเดลถูกๆ ก็พอ

* **Anthropic เริ่มมี cache breakpoint จริง**: ตัวอ่าน usage แปลง `cache_read_input_tokens` มาตั้งแต่แรก แต่ Anthropic **ไม่ cache อะไรเลย** ถ้าไม่มี `cache_control` — ทุกคำขอจึงประเมิน prompt เต็มราคาทุกครั้ง ขณะที่หน้า usage รายงาน 0 อย่างซื่อสัตย์ ตอนนี้ mark สามจุดที่นิ่ง (tool definition ตัวท้าย, system prompt, ท้าย history) ตั้งแต่คำขอที่สองของ session เป็นต้นไปได้ส่วนลด 90%
* **Skill ออกจาก tool block**: SKILL.md ทุกไฟล์เคยลงทะเบียนเป็น tool definition ของตัวเอง ส่งไปทุกคำขอ — ติดตั้ง 50 skill แปลว่าแบก 50 schema ทุกครั้งไม่ว่าจะใช้หรือไม่ ตอนนี้เหลือสอง built-in แบน: `skills_list` (ชื่อ+คำอธิบาย) และ `skill_view` (เปิดอ่านทีละตัว) — **รู้ว่ามีอะไรอยู่ราคาถูก รู้ว่ามันทำงานยังไงจ่ายตอนใช้**
* **Prompt สอนให้ทำงานเป็นชุด**: เดิมไม่มีอะไรห้ามโมเดลเปลี่ยนชื่อไฟล์ 200 ไฟล์เป็น shell 200 ครั้ง — 200 รอบของ schema และผลลัพธ์ ซึ่งโมเดล context เล็กไม่รอด และโมเดลที่จ่ายเงินต้องอ่านบทสนทนาทั้งก้อนซ้ำ ตอนนี้บอกชัด: งานเดียวกันหลายรายการ → เขียนสคริปต์เดียว รอบเดียว แล้วสุ่มตรวจ
* **Compaction มีอยู่แล้ว** — สรุปเทิร์นเก่าที่ 80% ของ budget ตรวจซ้ำทุกรอบของ tool loop สิ่งที่รุ่นนี้แก้คือคอมเมนต์ค้างที่ยังสัญญาว่าเป็นงานอนาคต

### 3. 🔎 Agent ค้นความจำตัวเองได้ — `session_search`

* `tool_runs` (จาก v0.8.2) ได้ผู้อ่านคนแรก และไม่ใช่ชั้น learning อย่างที่คิด แต่เป็น **การระลึกความหลัง**
* schema เวอร์ชัน 3 เพิ่ม `tool_runs_fts` (trigram) พร้อม backfill ย้อนหลัง ไม่งั้นแถวที่เขียนตอน v2 จะกลายเป็นช่วงประวัติศาสตร์ที่ค้นไม่เจอถาวร
* ผู้ใช้พูดว่า "เหมือนคราวที่แล้ว" แล้วโมเดลไปค้นทั้ง**บทสนทนาเก่า**และ**งานที่ tool เคยทำจริง** ได้ด้วยตัวเอง — ภาษาไทยค้นได้ (trigram ต้องการ 3 ตัวอักษร และตัว tool บอกตรงๆ แทนที่จะเงียบแล้วไม่เจอ) ราคาเท่ากับ query ฐานข้อมูลหนึ่งครั้ง **ไม่เรียกโมเดลเพิ่ม**
* ลบ session แล้ว index หายไปใน transaction เดียวกัน

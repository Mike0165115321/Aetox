# 🧩 Aetox v1.5.3

รุ่นนี้แก้บั๊กตัวเดียว แต่เป็นตัวที่ทำให้ปุ่มอัปเดตในแอปไม่เคยทำงานจริงเลยสักครั้ง
มาจากผู้ใช้จริงที่กดอัปเดต รีสตาร์ต แล้วเปิดมาเจอเวอร์ชันเดิม

---

## กดอัปเดตแล้วรีสตาร์ต กลับมาเป็นเวอร์ชันเดิม

**เรื่องเดิม** เครื่องที่ลงด้วยตัวติดตั้ง กด "ดาวน์โหลดอัปเดต" แอปโหลดไฟล์ ตรวจลายเซ็น
ครบทุกขั้น กด "รีสตาร์ตตอนนี้" แอปปิดตัวลง... แล้วเงียบ ไม่มีอะไรติดตั้ง แอปไม่เด้งกลับมา
เปิดเองอีกทีก็เจอเวอร์ชันเดิม เหมือนไม่มีอะไรเกิดขึ้นเลย

รากมาจากของดีสองชิ้นที่ไม่รู้จักกัน ชิ้นแรกคือยามเฝ้าโปรเซส: ตั้งแต่เปิดแอป Aetox เอาตัวเอง
เข้า Job Object ของ Windows แบบ "แอปตายเมื่อไหร่ ลูกหลานตายหมด" เพื่อไม่ให้ MCP,
เทอร์มินัล, git ที่แอปเปิดไว้กลายเป็นผีค้างเครื่อง ชิ้นที่สองคือตัวส่งงานอัปเดต: ตอนกดรีสตาร์ต
แอปปล่อยโปรเซสเล็ก ๆ ไว้ข้างนอก หน้าที่ของมันคือ**รอแอปปิด** แล้วค่อยรันตัวติดตั้งและเปิด
แอปกลับมา

ปัญหาคือโปรเซสเล็ก ๆ ตัวนั้นก็เป็น "ลูก" ของแอปเหมือนกัน มันเลยถูกยามเก็บในวินาทีเดียวกับ
ที่แอปปิด — วินาทีเดียวกับที่มันรอมาทั้งชีวิตพอดี ตัวติดตั้งที่โหลดมาแล้วเลยไม่เคยถูกรัน และ
ไฟล์ที่ค้างอยู่ก็ถูกแอปรุ่นเดิมกวาดทิ้งตอนเปิดรอบถัดไป จนไม่เหลือร่องรอยให้เห็นด้วยซ้ำ

เครื่องที่ใช้ตัว portable โดนครึ่งเดียว: ไฟล์ถูกสลับเป็นรุ่นใหม่ตั้งแต่ตอนดาวน์โหลดเสร็จแล้ว
แค่แอปไม่เด้งกลับมาเอง — ซึ่งเป็นเหตุผลที่บั๊กนี้รอดสายตามาตลอด เพราะทางที่ทดสอบบ่อย
คือทางที่อาการเบาที่สุด

**รุ่นนี้** ยามยังเก็บลูกทุกตัวเหมือนเดิม แต่ประตูมีบานเดียวสำหรับโปรเซสที่**ขอออกเอง**
และทั้งแอปมีผู้ขอรายเดียวคือตัวส่งงานอัปเดต ซึ่งเกิดมาเพื่ออยู่ต่อหลังแอปตายโดยนิยาม
พิสูจน์แล้วสองชั้น: เทสที่ให้โปรเซสพ่อตายจริงแล้วตรวจว่าลูกยังหายใจ (และถอด fix ออก
แล้วเทสแดงทันที) กับการไล่ลำดับจริงทั้งเส้นบนเครื่องจริง — โหลดรุ่นจริงจาก GitHub
ตรวจลายเซ็น สลับไฟล์ ปิดโปรเซส แล้วดูแอปรุ่นใหม่เปิดกลับมาเอง

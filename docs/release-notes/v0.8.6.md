# 🚀 Aetox v0.8.6 Release Notes — เทิร์นหนึ่งคือลำดับ ไม่ใช่ข้อความก้อนเดียว

เริ่มจากเรื่องเล็กที่เจ้าของสังเกตเห็น: DeepSeek **สตรีมความคิดสด แต่คำตอบโผล่มาทีเดียว** เงียบไปนานจนแอปดูเหมือนค้าง ไล่ไปไล่มาไปจบที่รูปร่างของ "เทิร์น" ทั้งอัน

### 1. 🌊 คำตอบสตรีมแล้ว — และเหตุผลที่มันเคยไม่สตรีม

* `completeToolLoop` ส่ง `nil` เป็นตัวรับข้อความ แต่ส่งตัวจริงให้ความคิด — **ความคิดเลยสตรีม คำตอบไม่สตรีม** ตรงตามที่เห็น
* ไม่ใช่เรื่องเฉพาะ DeepSeek: provider จริงทุกตัว hardcode `SupportsToolCalling()` เป็น `true` และเดสก์ท็อปมี builtin skill ~30 ตัวเสมอ **เส้นทางที่สตรีมคำตอบจึงไปไม่ถึงในเชิงโครงสร้าง** ตัวเดียวที่เคยสตรีมได้จริงคือ demo provider ที่ไม่ต้องใช้คีย์ — พอผู้ใช้ใส่ API key การสตรีมก็หยุดพอดี
* เหตุผลเดิมคือกัน DSML tool-call markup หลุดออกจอ ซึ่งจริง แต่แคบ: DeepSeek ตั้งต้นที่ wire format ของ Anthropic ซึ่ง tool call มาเป็น block ของตัวเอง **มันหลุดไม่ได้อยู่แล้ว**
* ตอนนี้มี **ตัวกั้นระดับตัวอักษร** กั้นหางไว้ไม่เกิน 7 ตัวถ้ายังอาจกลายเป็น marker ได้ เจอเต็มตัวเมื่อไหร่ล็อกปิดทั้งรอบ — ต้องเป็นตัวกั้นไม่ใช่ตัวกรอง เพราะ marker มาแบบ**ถูกตัดครึ่งข้าม delta เป็นเรื่องปกติ** ไม่ใช่เคสพิเศษ · `<div>`, `a < b`, `List<String>` ผ่านฉลุย

### 2. 🧩 ตัวที่ขวางจริงๆ ไม่ใช่ DSML แต่เป็น "ข้อความก้อนเดียว"

* tool loop เขียนข้อความ**ทุกรอบ** แต่มีแค่รอบสุดท้ายที่เป็น "คำตอบ" อันอื่นต้องถูกจำแนกและดึงกลับ — คำบรรยายหน้าการทำงาน, รอบที่โดน nudge, รอบที่ตอบว่าง, คำตอบที่จบแล้วแต่โดนลดชั้นเพราะผู้ใช้พิมพ์แทรก
* ไล่ดูทั้ง loop เจอ **15 จุด**ที่ต้องตอบคำถามว่า "ข้อความนี้ใช่คำตอบไหม" — คำถามที่**ไม่มีโปรโตคอลไหนถาม** เพราะ Anthropic กับ OpenAI ส่งเทิร์นมาเป็น **block เรียงลำดับ** และทั้งลำดับนั่นแหละคือเทิร์น
* `TurnPart` เก็บลำดับไว้ทั้งอัน — `text` / `thinking` / `tool` — executor ประกอบจาก callback ที่มันมีอยู่แล้ว มันแค่โยนลำดับทิ้งแล้วเก็บประโยคสุดท้าย
* `Reply` ยังอยู่ข้างๆ ในฐานะ**การต่อ text part เข้าด้วยกัน** — context ของโมเดล, store, ชื่อเซสชัน, FTS, sub-agent อ่านของเดิมทุกอย่างโดยไม่ต้องรู้ว่ามี part
* **จุดชดเชยหายไป 2 จาก 15** และเป็น 2 อันที่ string model สร้างขึ้นมาเอง: คำบรรยายกลายเป็น part ไม่ต้องดึงกลับ, คำตอบที่โดนแทรกก็เป็น part ที่ไม่ final เหลือ 3 อันที่ซื่อสัตย์จริงๆ — รอบที่ leak, รอบที่ว่าง, รอบที่ล้ม เพราะข้อความพวกนั้น**ไม่เคยเข้าเทิร์นตั้งแต่แรก**

### 3. 💾 ไทม์ไลน์เครื่องมือถูกเก็บลงฐานข้อมูลแล้ว (schema 5)

* นี่คือสิ่งที่ลำดับซื้อมาได้จริง — **tool call ไม่เคยถูกเขียนลงที่ไหนที่ข้อความเข้าถึงได้** เปิดเซสชันเก่ากลับมา กดปุ่ม "ใช้ N เครื่องมือ" แล้วเคยว่างเปล่า
* migration เดียวกันเก็บ `reasoning` กับ `think_secs` ด้วย — สองฟิลด์นี้อยู่บน `SessionMessage` ตั้งแต่วันที่ panel ความคิดออก และ**ถูกเขียนลงที่ไหนไม่เลย** ทุกครั้งที่โหลดเซสชันมันหายเงียบๆ

### 4. 🔄 ถามคำถามเดิมอีกครั้ง

* **ลองใหม่** (เทิร์นที่ล้ม) · **ตอบใหม่** (เก็บคำตอบเดิมไว้สลับ `‹ 1/2 ›`) · **สลับคำตอบ** · **แก้ข้อความแล้วส่งใหม่**
* สี่ปุ่ม ปัญหาเดียว: **เอาบทสนทนากลับไปเป็นเหมือนก่อนเทิร์นนั้น แล้วรันใหม่** — และนี่เป็นงานฝั่ง engine ไม่ใช่ UI เพราะเทิร์นอยู่ 3 ที่ที่**ไม่ล้มพร้อมกัน**: รายการบับเบิล, ตาราง `messages`, และความจำของโมเดล
* เทิร์นที่ error **ไปถึงความจำโมเดล แต่ไม่ถึงอีกสองที่** เพราะข้อความผู้ใช้ถูกใส่เข้า context ก่อนยิง provider — ส่งซ้ำเฉยๆ เท่ากับถามโมเดลสองรอบ ทุกทางเข้าจึง**สร้าง context ใหม่จาก transcript** ซึ่งเป็นบันทึกเดียวที่เขียนหลังจบงาน
* **ตอบใหม่ตอนที่เทิร์นนั้นแก้ไฟล์ไปแล้ว คือเคสที่อันตรายจริง** — เครื่องมือจะรันทับผลงานตัวเอง แอปจึงถาม ย้อนไฟล์ให้ก่อน แล้วบับเบิลบอกว่าย้อนไฟล์ไหนบ้าง · **จงใจไม่มีปุ่ม "ตอบใหม่โดยไม่ย้อน"** เพราะนั่นคือกับดัก และการไม่ใส่ถูกกว่าการอธิบาย

### 5. 🐛 บั๊กที่เจอระหว่างทาง

* **เทิร์นที่ล้มยิง provider 3 ครั้ง** — tool loop คืน `handled=false` ตอน error ซึ่งชนความหมายเดียวกับ guard clause ที่แปลว่า "ไม่เข้าเงื่อนไข" executor เลยไหลไปยิงซ้ำแบบไม่มี tool และ**ใส่คำถามเข้าความจำโมเดล 2 รอบ**
* **เน็ตสะดุดแล้วเทิร์นหายทั้งเทิร์น** — ตัว retry เดิมดูแค่ status code ไม่เคยดู transport error เลย `no such host` ตอน Wi-Fi กระตุก 2 วินาทีจึงกินทั้งเทิร์น · ตอนนี้ลองใหม่ 2 ครั้ง แต่**ไม่ลอง**ตอนกด Stop หรือ certificate ไม่ผ่าน เพราะสองอันนั้นลองกี่ครั้งก็เหมือนเดิม
* **panel ความคิดพังถาวร** — ตัวแปรถูกตั้งครั้งเดียวตลอดอายุ component กดปิดครั้งเดียว ทุกเทิร์นหลังจากนั้นเหลือแค่จุดกระพริบ
* **แก้ข้อความแล้วไฟล์แนบหลุด** — chip ยังอยู่บนบับเบิล แต่โมเดลไม่ได้รับไฟล์แล้ว

### 6. 🎨 ลำดับคือบันทึก ไม่ใช่หน้าตา

* เคยลองวาดลำดับลงในบับเบิลตรงๆ แล้ว**เจ้าของตีกลับภายในชั่วโมงเดียว** — ความคิดโผล่สองที่ (เป็น toggle ข้างบน และแทรกระหว่างย่อหน้า) แล้ว tool row คั่นทุกสองสามประโยคทำให้สายตาไม่รู้จะจับตรงไหน
* **หน้าตากลับไปเป็นแบบเดิมทั้งหมด** — บับเบิลเดียว แถว toggle ข้างบน คำตอบสะอาดข้างล่าง ส่วนลำดับที่เก็บไว้ถูกพับกลับเข้า toggle เดิม
* โครงข้างล่างคือประเด็น หน้าตาเป็นเรื่องรสนิยม และรอบนี้มันแพ้

### 7. 🧪 การทดสอบ

* ไฟล์เทสใหม่ 8 ไฟล์ · frontend 194 ตัว · Go ครบทุก package
* ตัวกั้น DSML มี 11 เคส รวมกรณี rune 3 ไบต์ถูกตัดครึ่งข้าม delta และกรณี `<` ธรรมดาใน HTML/โค้ด
* เทสระดับ executor ยืนยัน**ลำดับ** ตรงๆ: `text(...) → tool(read) → text(...) → tool(grep) → text(...)`

### 🚫 สิ่งที่จงใจไม่ทำ

ไม่รื้อ `Reply` ทิ้งในรอบเดียว — มันยังเป็น string หลักที่ทุกที่อ่าน การลบต้องไล่ทุก caller ซึ่งเป็นงาน cleanup แยก ไม่ควรมัดรวมกับ release · ไม่เอาลูกของ sub-agent เข้าลำดับตอนนี้ (มีแต่ตัว `task` call) เพราะข้อมูลอยู่ใน `tool_runs` พร้อม `parent_ref` มาตั้งแต่ §67 แล้ว การ join กลับเป็นฟีเจอร์ ไม่ใช่ migration · บับเบิลตอนกำลังทำงานยังเป็น string เดียวและเปลี่ยนหน้าตาตอนเทิร์นจบ — เป็นรอยต่อที่ยังมองเห็น และรู้ตัวอยู่

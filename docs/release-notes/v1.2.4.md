# 🚀 Aetox v1.2.4 — หยุดแล้วงานยังอยู่ อ่านแชทอื่นได้ และปัญหาเลิกถูกจำเป็นบทเรียน

รุ่นนี้เกิดจากคำบ่นสามข้อในวันเดียว และทั้งสามข้อกลายเป็นเรื่องเดียวกันเมื่อไล่ลงไปถึงก้น:
**หน้าต่างทิ้งงานที่เอนจินยังถืออยู่** กดหยุดแล้วไทม์ไลน์หายทั้งแถบ เปิดแชทอื่นดูระหว่างงานเดิน
ไม่ได้เลยแม้แต่จะอ่าน และรอบที่ขออ่านหกไฟล์ก็ยาวเท่าอ่านหกครั้งเรียงกัน

อีกครึ่งของรุ่นเป็นเรื่องที่เจ้าของเห็นแล้วถามว่า *"ไปดูตรงนี้มันจะจำข้อผิดพลาดทำไม"* — คิว
"รอคุณตัดสิน" เสนอให้จำว่าเครื่องนี้ไม่มี Tesseract ตั้งแต่วันนี้ปัญหาของระบบมีห้องของตัวเอง
มีกริยาของตัวเอง และไม่มีทางเดินเข้าไฟล์ความจำได้อีก

> เลขรุ่นก่อนหน้าคือ **v1.2.0** — 1.2.1 ถึง 1.2.3 ไม่เคยถูกปล่อย ไม่ต้องตามหา

## 1. ⏹️ หยุดคือหยุด ไม่ใช่ลบ

กดหยุดกลางทางแล้วเหลือบรรทัดเดียว *"หยุดการทำงานแล้ว"* บนแชทที่ว่างเปล่า แถวเครื่องมือทุกแถว
คำบรรยายทุกบรรทัดระหว่างมัน นาฬิกาคิด — หายหมดทันทีที่เทิร์นจบ

มันหายสองชั้น และการอ่านบั๊กนี้รอบแรกเจอแค่ชั้นที่สอง **หน้าต่างทิ้งงานนั้นไป และเอนจินทิ้งมัน
ไปก่อนแล้ว** ฝั่งเอนจินคือชั้นที่รอดข้ามการปิดเปิดโปรแกรม: ลูปเครื่องมือจบทุกทางที่ผิดพลาดด้วย
การคืนผลลัพธ์เปล่า ลำดับที่มันประกอบมาทั้งเทิร์นจึงออกไปพร้อมกับ error แล้วแถวที่จดลงฐานข้อมูล
ก็ซื่อสัตย์กับสิ่งที่มันได้รับ คือไม่มีอะไรเลย เปิดแชทเดิมขึ้นมาใหม่เจอคำถามที่ไม่มีอะไรอยู่ข้างใต้

ฝั่งหน้าต่างคือสามอย่างที่ต้องเรียงกันพอดี และมันเรียงกันพอดี: Wails ทิ้งค่าที่เมธอดคืนมาเมื่อ
error ไม่ใช่ nil หน้าต่างจึงไม่เคยได้รับสิ่งที่ Go ประกอบไว้ · บับเบิลจึงย้อนไปใช้ข้อความสตรีม
ซึ่งถูกล้างทิ้งทุกรอบที่จบด้วยการเรียกเครื่องมือ — ซึ่งคือจังหวะที่คนกดหยุดพอดี · และบับเบิลไม่เคย
หยิบสแนปช็อตไทม์ไลน์ที่ทางสำเร็จหยิบมาตลอด

ประโยคเดียวกันแก้ทั้งสองชั้น: **เทิร์นที่ถูกสั่งหยุดไม่ได้ทำงานน้อยกว่าเทิร์นที่ทำจนจบ มันทำเท่ากัน
แล้วมีคนสั่งจบ** วันนี้เปิดแชทเก่าขึ้นมาจะเห็นไทม์ไลน์ของเทิร์นที่ถูกหยุด เหมือนที่เห็นของเทิร์นที่
จบเอง และบับเบิลเลิกเขียนว่า `context canceled` เหนือ *"หยุดการทำงานแล้ว"* ซึ่งคือแอปที่โทษ
ตัวเองที่เชื่อฟัง

## 2. 👀 อ่านแชทอื่นได้ระหว่างที่งานยังเดิน

ด่านเดิมปฏิเสธทุกประตูที่ออกจากแชทที่กำลังทำงาน ด้วยประโยคเดียว เหตุผลถูกสำหรับสิ่งที่มัน
ปกป้อง: เอนจินมีคอนเท็กซ์เดียว และการ **เปิด** เซสชันคือการเขียนทับมันกลางความคิด

แต่คำว่า "เปิด" ทำสองงาน **การอ่านบทสนทนาไม่แตะอะไรในนั้นเลย** ประตูจึงแยก: อ่านได้
เขียนไม่ได้ ระหว่างเปิดอ่านแชทอื่น แถบบอกว่ากำลังอ่านอย่างเดียวพร้อมปุ่มกลับ ช่องพิมพ์ถูกปิด
พร้อมบอกเหตุผล และ **ปุ่มหยุดยังกดได้** เพราะเทิร์นที่มันสั่งจบก็วิ่งอยู่ดีไม่ว่าจะมีคนดูหรือไม่

คำตอบไปโผล่ผิดแชทไม่ได้ เพราะเทิร์นไม่ได้เขียนลง "อะไรก็ตามที่อยู่บนจอ" อีกแล้ว — มันเขียนลง
แชทที่มันถูกถาม ซึ่งถูกถือไว้ต่างหาก ส่วนประตูที่ย้ายรากของเอนจินจริง ๆ (เปิดเซสชันใหม่
เปลี่ยนโต๊ะ เปลี่ยนโปรเจกต์) ยังปฏิเสธเหมือนเดิม

และในสมุดรายชื่อ **แชทที่มีงานเดินอยู่สวมวงแหวนเดียวกับที่ซับเอเจนสวมตอนทำงาน** เป็นข้อเท็จจริง
เดียวกันทั้งสองที่ — อันนี้ยังไม่จบ — จึงเป็นไฟดวงเดียวกัน ไม่ใช่ภาษาชุดที่สองให้ต้องเรียนใหม่

## 3. ⚡ รอบที่ขออ่านหกไฟล์ ยาวเท่าการอ่านหนึ่งครั้ง

โมเดลขอเครื่องมือหลายตัวในรอบเดียวได้มาตลอด แต่ลูปเดินทีละตัวเรียงกัน อ่านหกไฟล์ที่ไฟล์ละ
200 มิลลิวินาที จึงกินเวลาจริง 1.2 วินาที ให้กับงานที่ไม่มีลำดับอยู่ในตัวมันเลย

ตอนนี้คำสั่งอ่านที่อยู่ติดกันวิ่งพร้อมกัน กลุ่มละไม่เกินสี่ และผลลัพธ์เข้าคอนเท็กซ์ **ตามลำดับที่
โมเดลสั่ง** ไม่ใช่ลำดับที่ตัวไหนเสร็จก่อน

ส่วนที่รับน้ำหนักคือทิศของรายชื่อ: มันเป็น**รายชื่ออนุญาต** ไม่ใช่รายชื่อปฏิเสธ เพราะตัวประเมิน
ความเสี่ยงตอบว่า "ไม่มีผลข้างเคียง" ให้กับทุกชื่อที่มันไม่รู้จัก ซึ่งคือ MCP ทุกตัวและสกิลทุกตัวที่
เพิ่มเข้ามาหลังมันถูกเขียน — รายชื่อปฏิเสธจะพา API จ่ายเงินวิ่งพร้อมกันสี่ตัวในวันที่มีใครต่อมัน
เข้ามา เครื่องมือสื่อ (OCR ภาพ วิดีโอ ถอดเสียง) อ่านอย่างเดียวเหมือนกันแต่จงใจไม่อยู่ในรายชื่อ:
มันเรียก ffmpeg กับ whisper และสี่ตัวพร้อมกันคือเครื่องที่หยุดตอบ ไม่ใช่เทิร์นที่เร็วขึ้น

## 4. 🧑‍💼 จ้างซับเอเจนหนึ่งคน วาดการ์ดหนึ่งใบ

งานที่มอบให้ซับเอเจนหนึ่งคน แสดงบนจอเป็นสองคนทำงานพร้อมกัน ต่างกันแค่นาฬิกา

ใบที่สองคือ **การนั่งรอ** ของเอเจนเอง — คำสั่งที่มันเรียกเพื่อรอลูกน้องที่ตัวเองจ้างไว้เมื่อ 27 วินาที
ก่อน การมอบหมายถูกแพ็กไว้ใต้ชื่อเครื่องมือเดียว ป้ายของ "รอ" กับ "จ้าง" จึงอ่านเหมือนกันเป๊ะ
เอนจินรู้ความต่างมาตลอด มันแค่ไม่มีที่ให้วางคำตอบ หน้าต่างเลยเดาเอาจากป้าย

วันนี้คำตอบเดินทางมาเป็นข้อเท็จจริงของตัวเอง และถูก **จดลงเทิร์น** ด้วย ไม่ใช่แค่ยิงสด — ไม่งั้น
เปิดแชทเก่าขึ้นมา การ์ดผิดใบเดิมก็กลับมา

## 5. 🧯 "ปัญหาของระบบ" มีห้องของตัวเอง

เจ้าของเห็นคิว "รอคุณตัดสิน" เสนอให้จำว่าเครื่องนี้ไม่มี Tesseract แล้วถามว่า *"ไปดูตรงนี้มันจะจำ
ข้อผิดพลาดทำไม"*

คิวนั้นมีการ์ด 22 ใบตลอดอายุของมัน **สิบเจ็ดใบเขียนโดยตัวสรุป และทั้งสิบเจ็ดใบพูดเรื่องเดียวกัน
คือ "เครื่องมือ X เคยล้มซ้ำ ๆ" มีใบเดียวใน 17 ที่เป็นบทเรียนที่ใช้ได้จริง** อีกห้าใบมาจากเครื่องมือ
ความจำของเอเจนเอง และเจ้าของอนุมัติสามใบ — 77% ของคิวเรียนรู้ถูกเขียนโดยแหล่งที่ผลิตบทเรียน
ไม่ได้ เพราะมันอ่านแถวที่ล้มเหลวอย่างเดียวและไม่อ่านอะไรอีกเลย

ตอนนี้ **Settings → ปัญหาของระบบ** เป็นห้องของมันเอง อยู่ถัดจากห้องเรียนรู้เพราะความอยู่ติดกัน
คือประเด็น: สิ่งที่ Aetox สรุปได้เกี่ยวกับคุณ กับสิ่งที่พังซ้ำ ๆ เป็นคนละเรื่องที่อยู่ในคิวเดียวกันมา
ทั้งปี แต่ละแถวมีสามปุ่ม และปุ่มแรกคือ **ปรึกษาผู้ช่วย** เพราะเป็นปุ่มเดียวในสามที่ตอบคำถามที่อีก
สองปุ่มต้องรู้คำตอบก่อน — มันเป็นที่เครื่องคุณ เป็นที่ Aetox เอง หรือเป็นวิธีที่เอเจนเรียกเครื่องมือ
อีกสองปุ่มคือ **แจ้งปัญหานี้** (เปิดฟอร์ม GitHub ที่กรอกกลุ่มความล้ม จำนวนครั้ง และหลักฐานไว้ให้
ในเบราว์เซอร์ของคุณ — แอปไม่ส่งอะไรเอง) และ **ไม่เป็นไร**

ไม่มีอะไรถูกลบ ของที่ตัดสินไปแล้วยังอ่านได้ในหน้าเดียวกัน และหมายเลขบนเฟืองกลับมาเป็นความจริง
เพราะมันนับเฉพาะบทเรียนแล้ว ของเก่าย้ายห้องมาด้วย (migration 16) ไม่ใช่เพื่อความเรียบร้อย แต่
เพราะกุญแจกันซ้ำคือตัวข้อความ — ทิ้งไว้ข้างหลัง สิบหกคำตัดสินที่คุณทำไปแล้วจะเปิดใหม่ในวันแรก

## 6. 🌦️ "เครื่องนี้ไม่มีโปรแกรมนั้น" คือดินฟ้าอากาศ

กฎเรื่องนี้ถูกเขียนไว้ตั้งแต่ §104 และประตูก็เปิดอยู่ แต่ไม่มีใครพาตระกูล OCR เดินผ่านมัน เครื่องที่
ข้ามขั้นตอนติดตั้ง Tesseract ตอนลงโปรแกรม ล้มสามครั้งติดแล้วกลายเป็นการ์ดที่เสนอกฎถาวรว่า
*"เลี่ยงรูปแบบที่ชนเงื่อนไขนี้ตั้งแต่ครั้งแรก"* — คำสั่งห้ามใช้ OCR ตลอดไป เขียนขึ้นจากโปรแกรมที่
แค่ยังไม่ได้ติดตั้ง

ทุกข้อความ "เครื่องนี้ไม่มี X" ในชั้นเครื่องมือติดเครื่องหมายที่ต้นทางแล้ว: Tesseract ของ OCR ภาพ,
poppler ของตัวอ่าน PDF, ffmpeg ของ OCR วิดีโอ, ไบนารีกับไฟล์โมเดลของตัวถอดเสียง และ git ที่
ไม่อยู่ใน PATH ของตัวมันเอง

## 7. 📊 ตารางการใช้งานเลิกพัง

กดเมนู "การใช้งาน" แล้วไม่มีอะไรเกิดขึ้น ไม่ใช่ตารางที่ดูผิด — คือหน้าที่ไม่เรนเดอร์เลย

แถวคือคู่ (ผู้ให้บริการ, โมเดล) และมีแต่คู่ที่ระบุตัวมันได้ ชื่อโมเดลเลิกเป็นตัวตนตั้งแต่วันที่คอลัมน์
ผู้ให้บริการมาถึง โมเดลที่ถูกใช้ทั้งสองฝั่งของเส้นนั้นจึงมีสองแถว คีย์ด้วยชื่อ สองแถวนั้นคือแถวเดียว
ที่ถูกอ้างสิทธิ์สองครั้ง และ Svelte ปฏิเสธลิสต์ที่มันแยกไม่ออก หน้านี้ยังได้โครงร่างระหว่างรอเดิน
ประวัติทั้งก้อนด้วย และเลิกบอกว่า "ไม่มีข้อมูล" ก่อนที่เอนจินจะได้พูด

## ⚠️ สิ่งที่รุ่นนี้ยังไม่ได้ติ๊ก

**เอนจินยังมีคอนเท็กซ์เดียว** ข้อ 1–3 ข้างบนเป็นรูปเดียวกันทั้งหมด และคำตอบที่ซื่อสัตย์ต่อ
*"สั่งงานหลายเซสชั่นก็ต้องได้"* คือคอนเท็กซ์คนละชุดต่อเซสชัน ที่ลงในรุ่นนี้คือ **ครึ่งที่อ่านอย่างเดียว**
ซึ่งเอากำแพงออกจากกรณีที่เจ็บทุกวัน อีกครึ่งเป็นงาน ไม่ใช่แพตช์ และไม่แกล้งทำเป็นอย่างอื่น
(`DECISIONS §134.4`)

**การอ่านประวัติยังไม่มีเพดาน** เปิดแชทหนึ่งอ่านทุกแถวของมัน ราคาโตตามความยาวของแชทนั้น
สี่กฎที่จะแก้ถูกเขียนไว้แล้วโดยข้อแรกเป็นเครื่องมือวัด ไม่ใช่ฟีเจอร์ และต่อคิวไว้หลังงานเอนจินต่อ
เซสชันโดยตั้งใจ (`DECISIONS §137`)

**เครื่องมือที่รายงานความล้มเหลวผ่านเอาต์พุตของตัวเอง ยังติดเครื่องหมายไม่ได้** ตัวจำแนกอ่านค่า
error ไม่ใช่ข้อความ ของแบบนี้จึงลงหน้าปัญหาโดยไม่มีชนิดกำกับ ซึ่งผิดน้อยกว่าการลงในความจำ
และยังไม่ถูก

**คิวเรียนรู้จะเงียบลง** ตั้งแต่รุ่นนี้มันถูกป้อนโดยเครื่องมือความจำของเอเจนเท่านั้น นั่นคือผลที่ตั้งใจ

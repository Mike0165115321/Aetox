# 🚀 Aetox v1.2.4

รุ่นนี้เกิดจากคำบ่นสามข้อในวันเดียว และทั้งสามข้อกลายเป็นเรื่องเดียวกันเมื่อไล่ลงไปถึงต้นเหตุ:
กดหยุดแล้วประวัติการทำงานหายทั้งแถบ · เปิดแชทอื่นดูระหว่างที่งานยังเดินไม่ได้เลยแม้แต่จะอ่าน ·
และรอบที่ขออ่านหกไฟล์กินเวลาเท่าอ่านหกครั้งเรียงกัน

อีกครึ่งของรุ่นมาจากคำถามของเจ้าของที่ว่า *"ไปดูตรงนี้มันจะจำข้อผิดพลาดทำไม"* คิว "รอคุณตัดสิน"
เสนอให้จำว่าเครื่องนี้ไม่มี Tesseract ตั้งแต่รุ่นนี้ ปัญหาของระบบมีห้องของตัวเองแยกจากบทเรียน

> เลขรุ่นก่อนหน้าคือ **v1.2.0** ส่วน 1.2.1 ถึง 1.2.3 ไม่เคยถูกปล่อย ไม่ต้องตามหา

---

## 1. หยุดคือหยุด ไม่ใช่ลบ

**อาการ** กดหยุดกลางทาง แล้วเหลือแค่บรรทัดเดียวว่า *"หยุดการทำงานแล้ว"* บนแชทที่ว่างเปล่า
ทุกอย่างที่เกิดขึ้นก่อนหน้านั้น ทั้งเครื่องมือที่รัน คำบรรยาย และเวลาที่ใช้คิด หายไปหมด

สาเหตุมีสองชั้น ชั้นที่ลึกกว่าคือ **ตัวเอนจินทิ้งงานนั้นไปก่อนแล้ว** ลูปเครื่องมือจบทุกเส้นทางที่
ผิดพลาดด้วยการคืนผลลัพธ์เปล่า ประวัติที่สะสมมาทั้งรอบจึงหลุดไปพร้อมข้อความผิดพลาด แล้วแถว
ที่บันทึกลงฐานข้อมูลก็ซื่อสัตย์กับสิ่งที่ได้รับมา คือไม่มีอะไรเลย ชั้นบนคือหน้าจอที่ย้อนไปหยิบ
ข้อความสตรีมซึ่งถูกล้างทุกครั้งที่มีการเรียกเครื่องมือ ซึ่งเป็นจังหวะเดียวกับที่คนมักกดหยุดพอดี

**หลักการที่ใช้แก้ทั้งสองชั้นคือประโยคเดียว** เทิร์นที่ถูกสั่งหยุดไม่ได้ทำงานน้อยกว่าเทิร์นที่ทำจนจบ
มันทำไปเท่าที่ทำ แล้วมีคนสั่งจบ ตอนนี้เปิดแชทเก่าขึ้นมาจะเห็นประวัติของเทิร์นที่ถูกหยุด เหมือนที่
เห็นของเทิร์นที่จบเอง และแอปเลิกขึ้นข้อความ `context canceled` เหนือคำว่า "หยุดการทำงานแล้ว"

## 2. อ่านแชทอื่นได้ระหว่างที่งานยังเดิน

เดิมทุกทางที่ออกจากแชทที่กำลังทำงานถูกปฏิเสธด้วยข้อความเดียวกัน เหตุผลถูกต้องสำหรับสิ่งที่มัน
ป้องกัน คือแอปมีความจำชุดเดียว การ **เปิด** เซสชันอื่นจึงเท่ากับเขียนทับความจำนั้นกลางคัน

แต่คำว่า "เปิด" ทำสองงานปนกัน **การอ่านบทสนทนาไม่ได้แตะอะไรในนั้นเลย** ประตูจึงถูกแยก:
อ่านได้ เขียนไม่ได้ ระหว่างเปิดอ่านแชทอื่นจะมีแถบบอกว่ากำลังอ่านอย่างเดียวพร้อมปุ่มกลับ ช่องพิมพ์
ปิดไว้พร้อมบอกเหตุผล และ **ปุ่มหยุดยังกดได้** เพราะงานที่มันสั่งจบก็เดินอยู่ดีไม่ว่าจะมีคนดูหรือไม่

คำตอบไปโผล่ผิดแชทไม่ได้ เพราะงานเขียนลงแชทที่มันถูกถาม ไม่ใช่ "แชทที่อยู่บนจอตอนนั้น" ส่วน
การกระทำที่ย้ายความจำจริง ๆ เช่นเปิดเซสชันใหม่ เปลี่ยนโต๊ะ หรือเปลี่ยนโปรเจกต์ ยังถูกปฏิเสธ
เหมือนเดิม

ในรายชื่อแชท แชทที่มีงานเดินอยู่จะมีวงแหวนแบบเดียวกับที่ซับเอเจนใช้ตอนทำงาน เพราะเป็น
ข้อเท็จจริงเดียวกัน คือ "อันนี้ยังไม่จบ"

## 3. อ่านหลายไฟล์พร้อมกันได้แล้ว

โมเดลขอใช้เครื่องมือหลายตัวในรอบเดียวได้มาตลอด แต่แอปเดินให้ทีละตัวเรียงกัน อ่านหกไฟล์ที่
ไฟล์ละ 200 มิลลิวินาที จึงกินเวลาจริง 1.2 วินาที ทั้งที่งานพวกนี้ไม่ต้องรอกันเลย

ตอนนี้คำสั่งอ่านที่อยู่ติดกันวิ่งพร้อมกันได้ กลุ่มละไม่เกินสี่ และผลลัพธ์เข้าความจำ **ตามลำดับที่
โมเดลสั่ง** ไม่ใช่ลำดับที่ตัวไหนเสร็จก่อน

จุดที่ระวังคือรายชื่อเครื่องมือที่วิ่งพร้อมกันได้ เป็น **รายชื่ออนุญาต** ไม่ใช่รายชื่อห้าม เพราะตัวประเมิน
ความเสี่ยงตอบว่า "ไม่มีผลข้างเคียง" ให้กับทุกชื่อที่มันไม่รู้จัก ซึ่งรวมถึงเครื่องมือจากภายนอกทุกตัว
ที่ต่อเข้ามาทีหลัง ถ้าใช้รายชื่อห้าม วันหนึ่งจะมี API ที่คิดเงินสี่ตัววิ่งพร้อมกันโดยไม่มีใครตั้งใจ

เครื่องมือด้านสื่อ (OCR ภาพ วิดีโอ ถอดเสียง) อ่านอย่างเดียวเหมือนกันแต่จงใจไม่อยู่ในรายชื่อ
เพราะมันเรียก ffmpeg กับ whisper และสี่ตัวพร้อมกันคือเครื่องที่หยุดตอบ ไม่ใช่งานที่เร็วขึ้น

## 4. จ้างซับเอเจนหนึ่งคน ต้องขึ้นการ์ดหนึ่งใบ

งานที่มอบให้ซับเอเจนคนเดียว เคยแสดงบนจอเป็นสองคนทำงานพร้อมกัน ต่างกันแค่เวลา

ใบที่สองคือ **การนั่งรอ** ของเอเจนเอง คือคำสั่งที่มันเรียกเพื่อรอลูกน้องที่ตัวเองจ้างไว้เมื่อ 27 วินาทีก่อน เนื่องจาก
ทั้งสองอย่างถูกเรียกผ่านชื่อเครื่องมือเดียวกัน หน้าจอจึงแยกไม่ออกและเดาผิด ตอนนี้เอนจินบอกมา
ตรง ๆ ว่าอันไหนคือจ้าง อันไหนคือรอ และข้อมูลนี้ถูกบันทึกลงประวัติด้วย ไม่ใช่แค่แสดงสด ๆ ไม่งั้น
เปิดแชทเก่าขึ้นมาการ์ดผิดใบเดิมก็กลับมา

## 5. "ปัญหาของระบบ" มีห้องของตัวเอง

เจ้าของเห็นคิว "รอคุณตัดสิน" เสนอให้จำว่าเครื่องนี้ไม่มี Tesseract แล้วถามว่าจะจำข้อผิดพลาดไป
ทำไม

ตัวเลขตอบชัด คิวนั้นมีการ์ด 22 ใบตลอดอายุของมัน **สิบเจ็ดใบเขียนโดยตัวสรุปอัตโนมัติ และ
ทั้งหมดพูดเรื่องเดียวกันคือ "เครื่องมือ X เคยล้มซ้ำ ๆ" มีใบเดียวใน 17 ที่เป็นบทเรียนที่ใช้ได้จริง**
อีกห้าใบมาจากเครื่องมือความจำของเอเจนเอง และเจ้าของอนุมัติไปสามใบ พูดง่าย ๆ คือ 77% ของ
คิวบทเรียนถูกเขียนโดยแหล่งที่ผลิตบทเรียนไม่ได้ เพราะมันอ่านแต่แถวที่ล้มเหลวและไม่อ่านอะไรอีก

ตอนนี้ **หน้าตั้งค่า → ปัญหาของระบบ** เป็นห้องของตัวเอง อยู่ถัดจากห้องเรียนรู้ เพราะสองอย่างนี้
เป็นคนละเรื่องที่อยู่ในคิวเดียวกันมาตลอด แต่ละแถวมีสามปุ่ม ปุ่มแรกคือ **ปรึกษาผู้ช่วย** เพราะเป็น
ปุ่มเดียวที่ตอบคำถามที่อีกสองปุ่มต้องรู้คำตอบก่อน คือปัญหานี้เกิดที่เครื่องคุณ ที่ตัว Aetox เอง หรือ
ที่วิธีที่เอเจนเรียกเครื่องมือ อีกสองปุ่มคือ **แจ้งปัญหานี้** (เปิดฟอร์มบน GitHub ที่กรอกข้อมูลไว้ให้
ในเบราว์เซอร์ของคุณ แอปไม่ส่งอะไรเอง) และ **ไม่เป็นไร**

ไม่มีอะไรถูกลบ ของที่ตัดสินไปแล้วยังอ่านได้ในหน้าเดียวกัน และตัวเลขบนไอคอนเฟืองกลับมาตรง
เพราะมันนับเฉพาะบทเรียนแล้ว ของเก่าถูกย้ายห้องมาด้วย (migration 16) ไม่ใช่เพื่อความเรียบร้อย
แต่เพราะระบบกันซ้ำใช้ตัวข้อความเป็นกุญแจ ถ้าทิ้งไว้ที่เดิม คำตัดสินสิบหกครั้งที่คุณทำไปแล้ว
จะเด้งกลับมาใหม่หมด

## 6. "เครื่องนี้ไม่มีโปรแกรมนั้น" ไม่ใช่บทเรียน

กฎข้อนี้เขียนไว้นานแล้ว แต่ไม่มีใครพาเครื่องมือกลุ่ม OCR เดินผ่านมัน เครื่องที่ข้ามขั้นตอนติดตั้ง
Tesseract ตอนลงโปรแกรม จะล้มสามครั้งติดแล้วกลายเป็นการ์ดที่เสนอกฎถาวรว่า *"เลี่ยงรูปแบบที่
ชนเงื่อนไขนี้ตั้งแต่ครั้งแรก"* ซึ่งแปลว่าห้ามใช้ OCR ตลอดไป เพราะโปรแกรมที่แค่ยังไม่ได้ติดตั้ง

ตอนนี้ทุกข้อความ "เครื่องนี้ไม่มี X" ถูกติดป้ายไว้ที่ต้นทางแล้ว ทั้ง Tesseract ของ OCR ภาพ,
poppler ของตัวอ่าน PDF, ffmpeg ของ OCR วิดีโอ, ไฟล์โมเดลของตัวถอดเสียง และ git ที่ไม่อยู่
ในพาธ

## 7. หน้าการใช้งานเลิกพัง

กดเมนู "การใช้งาน" แล้วไม่มีอะไรขึ้นเลย ไม่ใช่ตารางที่แสดงผิด แต่คือหน้าที่ไม่แสดงเลย

สาเหตุคือแต่ละแถวเป็นคู่ของผู้ให้บริการกับโมเดล แต่ระบบยังใช้ชื่อโมเดลอย่างเดียวเป็นตัวระบุแถว
โมเดลที่ถูกใช้ผ่านสองผู้ให้บริการจึงกลายเป็นสองแถวที่ชื่อชนกัน แล้วหน้าเว็บก็ปฏิเสธที่จะวาดรายการ
ที่มันแยกไม่ออก ตอนนี้หน้านี้มีโครงร่างแสดงระหว่างรอโหลดด้วย และเลิกขึ้นคำว่า "ไม่มีข้อมูล" ก่อน
ที่ข้อมูลจะมาถึง

## ⚠️ สิ่งที่รุ่นนี้ยังไม่ได้ทำ

**แอปยังมีความจำชุดเดียว** ข้อ 1 ถึง 3 ข้างบนมาจากข้อจำกัดเดียวกันทั้งหมด คำตอบที่ตรงไปตรงมา
ต่อคำขอ *"สั่งงานหลายเซสชั่นก็ต้องได้"* คือให้แต่ละแชทมีความจำของตัวเอง สิ่งที่ลงในรุ่นนี้คือครึ่งที่
อ่านอย่างเดียว ซึ่งเอากำแพงออกจากกรณีที่เจ็บทุกวัน อีกครึ่งเป็นงานใหญ่ ไม่ใช่แพตช์

**การอ่านประวัติยังไม่มีเพดาน** เปิดแชทหนึ่งขึ้นมาคือการอ่านทุกแถวของมัน ราคาจึงโตตามความยาว
ของแชทนั้น มีแผนแก้ไว้แล้ว โดยขั้นแรกเป็นเครื่องมือวัด ไม่ใช่ฟีเจอร์

**เครื่องมือที่รายงานความล้มเหลวผ่านข้อความของตัวเอง ยังติดป้ายไม่ได้** ตัวจำแนกอ่านจากรหัส
ผิดพลาด ไม่ได้อ่านจากข้อความ ของแบบนี้จึงลงหน้าปัญหาโดยไม่มีประเภทกำกับ ซึ่งผิดน้อยกว่าการ
ลงในความจำ แต่ก็ยังไม่ถูก

**คิวเรียนรู้จะเงียบลง** ตั้งแต่รุ่นนี้มันถูกป้อนโดยเครื่องมือความจำของเอเจนเท่านั้น นั่นคือผลที่ตั้งใจ
ไม่ใช่การสูญเสีย เพราะเป็นครึ่งที่เจ้าของอนุมัติสามในห้าใบ

**Linux / macOS ยังทำอยู่** และตัวติดตั้งยังไม่ได้เซ็นโค้ด (Windows จะขึ้นเตือน SmartScreen)
แต่ไฟล์รุ่นที่ปล่อยออกมาถูกเซ็นด้วยลายเซ็น ed25519 ตั้งแต่ v0.9.4 และตัวอัปเดตในแอปจะปฏิเสธ
ไฟล์ที่ลายเซ็นไม่ผ่าน

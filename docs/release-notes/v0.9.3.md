## 1. 🔗 การเชื่อมต่อ — บัญชีที่เอเจนทำงานแทนคุณได้

หน้าใหม่ใน **การตั้งค่า → การเชื่อมต่อ** เริ่มที่ GitHub

เชื่อมบัญชีแล้ว token ถูกเก็บใน**คลังเดียวกับการล็อกอินโมเดล** เข้ารหัสด้วย DPAPI ไม่ใช่ไฟล์
config ธรรมดา — เหตุผลเขียนไว้ในโค้ดอยู่แล้วตั้งแต่ก่อนหน้านี้: ไฟล์ config ถูกก๊อปไปแปะใน
bug report และซิงก์ข้ามเครื่อง ความลับจึงห้ามอยู่ในนั้น

สิ่งที่ได้ทันทีโดยไม่ต้องมีเครื่องมือใหม่สักตัว:

| | ก่อน | หลัง |
|---|---|---|
| repository ส่วนตัว | ❌ | ✅ |
| โควตา | 60 ครั้ง/ชม. | **5,000 ครั้ง/ชม.** |

**Aetox ตรวจ token กับ GitHub ก่อนบันทึกเสมอ** — token ที่ผิดจะไม่ถูกเก็บ ไม่งั้นมันจะไป
โผล่เป็น "repo not found" กลางเทิร์นในอีกสามวัน

### แถว "ใครได้ใช้" — คำศัพท์เดียวกับ MCP

ทุกบัญชีมีแถวเลือกว่าโต๊ะไหนและเอเจนตัวไหนได้ใช้ ใช้ `for:` **แบบเดียวกับ MCP server เป๊ะ**
(ชื่อโต๊ะ หรือ `agent:<ชื่อ>`) เพราะเป็นคำถามเดียวกัน — ของที่ต่อจากข้างนอก ใครได้ใช้

- **ปิด = เครื่องมือหายจากรายการของโต๊ะนั้นเลย** ไม่ใช่ "ถามก่อน" — ประตูที่เปิดไม่ได้
  ไม่ควรให้โมเดลเห็น
- **ยังไม่เคยวาง = ทุกโต๊ะได้ใช้** การอัปเกรดไม่แย่งของที่ใครเคยมีไป
- **เอเจนไม่ได้อัตโนมัติ** — เอเจนได้ของเพราะมีคนยื่นให้ ความเงียบไม่ใช่การอนุญาต

## 2. 🤖 เอเจน `github` — และมาตรฐานที่มันเป็นตัวแรก

เอเจนตัวใหม่ที่ดูแลทุกอย่างฝั่ง remote: เปิดและรีวิว PR, ไล่ CI ที่แดง, จัดการ issue,
ตั้งรีโปให้ได้มาตรฐาน

ความรู้ของมันอยู่ใน**โฟลเดอร์ของตัวเอง** ไม่ใช่ในพรอมป์ — สกิลสี่ใบที่คนอื่นมองไม่เห็น:

| สกิล | มีอะไร |
|---|---|
| `repo-standards` | ไม่มี LICENSE = ไม่มีใครใช้ได้ตามกฎหมาย · README · CODEOWNERS · SECURITY.md · branch protection · Dependabot — **เรียงตามอะไรพังก่อนถ้าไม่มี** ไม่ใช่ตามที่คนพูดถึงบ่อย |
| `pr-workflow` | เขียน description ตามลำดับคำถามที่รีวิวเวอร์ถามจริง · merge เป็นการตัดสินใจของคนอื่น |
| `ci-triage` | อ่าน log จากล่างขึ้นบน · แยกสี่แบบ: พังจริง / flake / environment / config · **รันซ้ำสองครั้งคือเพดาน ครั้งที่สามคือความหวัง** |
| `issue-hygiene` | title ที่ค้นเจอ · triage สามคำถาม · ป้ายสองแกนพอ |

### `needs:` — ประกาศ ไม่ใช่ให้สิทธิ์

เอเจนบอกได้แล้วว่าขาดอะไร (`needs: connection:github, mcp:github`) และเส้นที่ห้ามข้ามคือ
**การประกาศไม่เคยให้สิทธิ์อะไรเลย** สิทธิ์ยังมาจาก `for:` ที่เดียวเหมือนเดิม

เพราะบทเรียนที่เขียนไว้ใน `Mode.MCP` อยู่ก่อนแล้ว: manifest ที่ถูกคอมไพล์มาก่อนที่ของผู้ใช้
จะมีอยู่ อาจอ้างถึงของที่ไม่มีสักตัว แล้วกรองทุกอย่างทิ้งเงียบๆ — `needs:` ที่ชี้ไปหาของ
ที่ไม่มีจึงได้แค่*ประโยคบนจอ* ไม่มีทางทำให้ tool list ว่างโดยไม่มีใครรู้

### ขาดของแล้ว **ขอ แล้วทำส่วนที่เหลือ**

ข้อความรุ่นแรกเขียนว่า *"บอกว่าขาดอะไรแล้วหยุด"* ซึ่งผิด และผิดในแบบที่ควรจดไว้:
มันเปลี่ยนผู้เชี่ยวชาญให้เป็นที่กั้นประตู เอเจน GitHub ที่ไม่มี token ยังมีเครื่องมือไฟล์
ของตัวเอง มีสกิลสี่ใบ และ**คำถามส่วนใหญ่เรื่องรีโปไม่ต้องใช้บัญชีเลยสักนิด**

รูปที่ถูกคือสามข้อเรียงกัน — **ขอ → ทำส่วนที่ไม่ต้องใช้มัน → ห้ามส่งผลลัพธ์ราวกับว่ามีของ
ชิ้นนั้นอยู่** มีเส้นตายเส้นเดียวคือข้อสาม เพราะเป็นความพังที่ปลายทางจับไม่ได้ รูปทั่วไปของ
กฎนี้อยู่ในพรอมป์ของทั้งผู้ช่วยหลักและทุกเอเจนแล้ว:

> ปฏิเสธทั้งงานเพราะขาดชิ้นเดียว กับทำงานจนจบทั้งที่แอบขาดชิ้นหนึ่ง **คือความผิดเดียวกัน
> เล่าคนละแบบ**

## 3. 🚪 หนึ่งประตู — เอเจนตัวเดียวกัน พรอมป์ก้อนเดียวกัน

วัดก่อนแก้:

| | ก่อน | หลัง |
|---|---|---|
| ผู้ใช้เปิดคุยตรง | 15,106 | 15,106 |
| ผู้ช่วยหลักสั่งงาน | **4,429** | **15,106** |

ตอนนี้ `task` ประกอบพรอมป์ลูก**ด้วยตัวประกอบตัวเดียวกับที่ session ใช้ประกอบของตัวเอง** โดย
เอา brief ของเอเจนไปนั่งช่อง direction — ไม่ได้ก๊อปโค้ดไปไว้อีกที่ แต่ยืมตัวประกอบไปใช้
มีที่ประกอบพรอมป์ที่เดียวในระบบ และมีคนเรียกมันคนเดียว

**ตำแหน่งก็สำคัญไม่แพ้กัน** direction ย้ายจากลำดับที่ 13 มาอยู่ที่สอง ต่อจาก identity เสมอ —
เดิม brief ของเอเจนไปนั่งที่ 68% ของพรอมป์ แล้วมันตอบจากบรรทัดแรกที่มันอ่านเจอ ซึ่งเป็น
บรรทัดของผู้ช่วยหลัก **เอเจนคือ Aetox ที่เชี่ยวชาญเฉพาะทาง ไม่ใช่คนอื่น** — สิ่งที่ brief
ต้องการคือถูก*อ่าน* ไม่ใช่แทนที่ตัวตนข้างบน

ของแถม: เพดานความยาว brief เคยวัดกับ brief เปล่า ซึ่งเป็นตัวเลขผิดมาตลอด ตอนนี้วัดกับ
พรอมป์ที่ประกอบเสร็จ

## 4. ⚡ MCP ต่อตอนใช้ ไม่ใช่ตอนเปิดแอป

`for:` เคยตัดสินแค่ว่า**ใครเห็น** tools ไม่เคยตัดสินว่าจะต่อหรือไม่ต่อ — เซิร์ฟเวอร์ที่วางไว้
ให้เอเจนตัวเดียวจึงถูก spawn ทุกครั้งที่เปิดแอป ของทุกคนที่ตั้งค่าไว้ ทั้งที่ทั้งวันไม่มีใคร
แตะเอเจนตัวนั้น สำหรับเซิร์ฟเวอร์ 90 tools นั่นคือ handshake กับการดึงรายการ tools ทั้งชุด
ที่ซื้อไว้เผื่อว่าอาจมีคนใช้

ตอนนี้เซิร์ฟเวอร์ที่ `for:` มีแต่ `agent:*` จะ **ขึ้นตอนมีคนเรียกเอเจนตัวนั้นจริง** —
เรียกจากสองประตูที่เดียวกันเสมอ

**ประตูอนุญาตไม่รอ**: กฎ `ask` สร้างจากชื่อเซิร์ฟเวอร์ล้วนโดยไม่ต้องต่อ เซิร์ฟเวอร์ที่ยัง
หลับอยู่จึงถูกกั้นไว้ก่อนตื่น ไม่มีช่องที่ tool โผล่มาก่อนกฎ

ผลพลอยได้ที่สำคัญกว่าที่คิด: **การขออนุญาตจะเกิดตอนใช้จริงครั้งแรก ไม่ใช่ตอนเปิดแอป** ซึ่ง
เป็นจังหวะเดียวที่คำถาม "จะให้สิทธิ์ไหม" มีบริบทให้ตอบ

## 5. 🗣️ คำศัพท์ — เอเจน / ซับเอเจน

หน้าจอเดียวเคยมีสามคำปนกัน รุ่นนี้เหลือสองคำสำหรับสองชนิด ทั้งใน UI เอกสาร และพรอมป์ที่
ส่งให้โมเดล — สิ่งที่เจ้าของเคาะไว้ตั้งแต่ 6 ส.ค. คือ*สองชนิด* ไม่ใช่ตัวสะกด การเปลี่ยนคำ
จึงไม่ได้ล้มการตัดสินใจเดิม

และไฟล์เอเจนเหลือแค่ **ตัวตน + tools + skills**:

- หัวข้อที่สอนเอเจนให้ทนกับข้อจำกัดของช่องทาง (คุยตรง vs ข้ามเคาน์เตอร์) ถูกลบออกทั้งสี่ไฟล์
  — มันแก้ผิดชั้น ช่องทางต่างกันไม่ควรกลายเป็นสองบุคลิกในพรอมป์
- **`desk:` หายไปจากทุกไฟล์** เพราะบ้านของไฟล์บอกชนิดอยู่แล้ว การเขียนฟิลด์นี้ทำได้อย่าง
  เดียวคือทำให้ผิด และผิดแบบเงียบ: ไฟล์ยัง parse ผ่าน ยังอยู่ในรายการ แต่หายจากหน้าทีม จาก
  ช่องเลือกในหน้าแชท และจากทุกประตูที่ผู้ใช้เดินเข้าได้ มีเทสต์กันไว้แล้ว

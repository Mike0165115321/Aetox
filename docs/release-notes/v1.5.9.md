# 🧩 Aetox v1.5.9

รุ่นนี้ว่าด้วยเรื่องที่ Aetox จำ กับเรื่องที่มันเรียนรู้จากงานตัวเอง บวกกับการเก็บงานที่เห็นระหว่างใช้จริง

---

## ความจำรู้แล้วว่าบรรทัดนี้ควรไปอยู่ที่ไหน

ก่อนหน้านี้ตอนจะจำอะไร โมเดลเป็นคนเลือกเองว่าจะเก็บไว้ที่ไฟล์กลาง ที่โต๊ะ หรือที่โปรเจกต์
ดูจากของจริงแล้วมันไม่ได้เลือก: `memory` ถูกเรียกมาทั้งหมด 11 ครั้ง 7 ครั้งไม่ระบุปลายทางเลย
เลือก "โต๊ะนี้" ศูนย์ครั้ง และโฟลเดอร์ความจำของโต๊ะไม่เคยถูกสร้างขึ้นมาสักไฟล์เดียว
"ไม่ได้ตัดสินใจ" กับ "ตัดสินใจว่าทุกที่" จึงแยกกันไม่ออก

ตอนนี้โต๊ะเป็นคนตอบ โต๊ะผู้ช่วยเก็บลงไฟล์กลางที่ทุกเซสชันอ่าน เพราะงานผู้ช่วยคือการรู้จักคุณกับเครื่อง
ส่วนโต๊ะโค้ดที่เปิดโปรเจกต์อยู่ เก็บลงไฟล์ของโปรเจกต์นั้น เพราะ "ที่นี่ตกลงกันว่าใช้ X"
ถ้าถูกแบกไปอีกโปรเจกต์ มันไม่ใช่ความรู้ มันคือข่าวลือ

ยังสั่งข้ามได้ด้วยคำเดียว "ทุกที่" กับ "โปรเจกต์นี้" ยังอยู่ครบ ส่วนโต๊ะโค้ดที่ยังไม่ได้เปิดโปรเจกต์
จะกลับไปใช้ไฟล์กลางเหมือนเดิม ไม่ตกลงลิ้นชักรวมที่ไม่มีใครอ่าน

และคุยกับเอเจนตรงๆ ตอนนี้อ่านความจำของตัวเองอย่างเดียว ของเดิมมันยังได้ความจำของผู้ช่วยหลัก
กับของโปรเจกต์วางทับลงไปด้วย ทั้งที่การเขียนถูกกั้นไว้แล้ว การอ่านก็ควรกั้นเหมือนกัน

## ไฟล์ความจำของโปรเจกต์ที่โฟลเดอร์หายไป

ความจำของโปรเจกต์ผูกไว้กับที่อยู่ของโฟลเดอร์ ย้ายโฟลเดอร์หรือลบทิ้ง ไฟล์เดิมก็ยังอยู่
อ่านแล้วดูถูกต้องทุกบรรทัด แต่ไม่มีเซสชันไหนไปถึงมันได้อีก และไม่มีที่ไหนในแอปบอกเรื่องนี้เลย

หน้าตั้งค่าติดป้ายให้แล้ว พร้อมสองทางออก: ย้ายบรรทัดไปรวมกับโปรเจกต์ที่โฟลเดอร์นั้นกลายเป็น
หรือลบไฟล์นั้นทิ้ง ลบได้เฉพาะไฟล์ของโปรเจกต์ ไฟล์อื่นแก้ทีละบรรทัดบนหน้าเดียวกันอยู่แล้ว

## ห้องใหม่: ปรับสกิลอัตโนมัติ

เดิม Aetox อ่านได้แค่ความล้มเหลวที่มีร่องรอย คือเครื่องมือที่พัง ถูกปฏิเสธ หรือคืน error มา
ความล้มเหลวที่สำคัญที่สุดของสกิลมันมองไม่เห็น คือสกิลที่รันผ่านฉลุยแล้วตอบผิด
เซ็นเซอร์ตัวเดียวที่จับได้คือปุ่ม 👍 / 👎 ใต้คำตอบ กับการกด "ตอบใหม่" ซึ่งเก็บมาตลอดโดยไม่มีใครใช้

ตอนนี้เมื่อสกิลไหนโดนคะแนนแย่ครบ 3 ครั้ง Aetox จะร่างการแก้ SKILL.md ให้ พร้อมเหตุผลและหลักฐาน
แล้วรอคุณอนุมัติ ไม่มีอะไรแก้สกิลเองได้โดยไม่ผ่านคุณ เหมือนความจำ

ตัวจับเป็นการนับล้วนๆ ไม่เรียกโมเดล จะเรียกก็ต่อเมื่อมีสกิลถูกชูขึ้นมาจริง และร่างในพื้นหลังทีละหนึ่ง
เทิร์นแชทไม่ช้าลง สวิตช์ร่างอัตโนมัติปิดมาจากโรงงาน เพราะการร่างเสียค่าโมเดล
กดตรวจเองได้ตลอดไม่ว่าสวิตช์จะเปิดหรือปิด

การแก้สกิลที่มากับแอปครั้งแรก จะคัดลอกทั้งโฟลเดอร์ออกมาก่อน ทั้ง SKILL.md และเอกสารอ้างอิงข้างใน
ไม่ใช่คัดแค่ไฟล์เดียวแล้วปล่อยให้ตัวที่ทับชี้ไปหาของที่ไม่ได้ตามมาด้วย

## เวอร์ชันย้ายมาอยู่ในเมนูโปรไฟล์

เครื่องอัปเดตครบมานานแล้ว แต่มีประตูอยู่บานเดียวคือ ตั้งค่า → เกี่ยวกับ ซึ่งเป็นหน้าที่คนส่วนใหญ่ไม่เคยเปิด
"มี Aetox ตัวใหม่ออกแล้ว" จึงเป็นข่าวที่ไปถึงเฉพาะคนที่เดินไปหามันเอง

เมนูโปรไฟล์มีแถวเวอร์ชันแล้ว ตรวจ เสนอ ดาวน์โหลด และรีสตาร์ท จบในแถวนั้น
บรรทัดที่สองขึ้นเฉพาะตอนมีอะไรจะบอกจริงๆ แถวที่รายงาน "ไม่มีข่าว" ทุกวันสอนให้คนเลิกอ่านมัน

พร้อมกันนั้นสามอย่าง: ตรวจไม่สำเร็จไม่ลบผลที่หาเจอไว้แล้วทิ้งอีกต่อไป เน็ตหลุดไม่ใช่หลักฐานว่ารุ่นที่
ประกาศไปเมื่อชั่วโมงก่อนเลิกมีตัวตน · เวอร์ชันที่รันอยู่มีคนตอบคนเดียว หน้าเกี่ยวกับกับเมนูจะเห็นตรงกันเสมอ ·
และการ์ดคลุมจอเด้งเฉพาะข่าวที่ไม่มีใครขอ ถ้าคุณกดถามเอง คำตอบไปโผล่ตรงที่คุณกด ไม่ใช่ข่าวเดียวกันสองที่

## สลับโมเดลกลางเทิร์น

มีคนรายงานว่าสลับโมเดลแล้วมีปัญหา แต่ทำซ้ำไม่ได้ เพราะปกติเจ้าของสลับตอนว่าง ซึ่งถูกต้องดีอยู่แล้ว
ที่ไม่มียามเฝ้าเลยคือสลับกลางเทิร์น ซึ่งจะสลับเอเจน สลับชุดเครื่องมือ ล้างทะเบียนงานที่มอบหมายไปแล้ว
และบันทึกบริบทที่เขียนค้างอยู่ครึ่งเดียว แปลว่าทิ้งงานที่คุณกำลังรออยู่

ตอนนี้หน้าปัดสี่ตัวในเมนูโมเดล (โมเดล ผู้ให้บริการ ระดับคิด รูปแบบสาย) บอกออกมาตรงๆ ว่าให้รอเทิร์นจบก่อน
ส่วนของที่ไม่ได้เกิดจากการกดของคุณโดยตรง เช่น สลับการเชื่อมต่อ เปิด MCP เซิร์ฟเวอร์ หรือล็อกอินเสร็จ
จะจอดไว้แล้วมีผลตอนเทิร์นจบ ไม่ต้องกดใหม่

## โต๊ะเป็นของแชทเดียว

แชทที่ทำงานอยู่เบื้องหลังเคยเอาไฟล์ไปวางบนโต๊ะที่บังเอิญเปิดอยู่บนจอ แล้วโต๊ะบนจอก็เซฟมันเป็นของตัวเอง
รอยรั่วเลยรอดข้ามการรีสตาร์ทไปด้วย ตอนนี้ไฟล์ไปอยู่บนโต๊ะของแชทที่สั่ง คุณจะเจอมันตอนเปิดแชทนั้น
และแท็บที่เอเจนเปิดยังเป็นของเอเจนหลังสลับแชทไปมา เมื่อก่อนมันกลายเป็นของผู้ใช้ แล้วเอเจนก็เก็บแท็บตัวเองไม่ได้

## กดหยุด ไม่ใช่ปัญหาที่ต้องรายงาน

กดหยุดครั้งเดียวฆ่า `web_fetch` ที่รันขนานกันสามตัวในวินาทีเดียว ทั้งสามรายงานเหมือนกันหมด
ห้องปัญหาเลยชูขึ้นมาว่า "เครื่องมือล้มซ้ำด้วยเหตุเดียวกัน" แล้วขอให้ไปรายงานให้นักพัฒนา
ทุกใบในคิวนั้นกินความสนใจของคุณ ใบนี้กินไปกับการกดหยุดของคุณเอง ตอนนี้มันไม่ขึ้นแล้ว
ส่วนเครื่องมือที่หมดเวลาซ้ำๆ ยังขึ้นเหมือนเดิม เพราะอันนั้นเป็นรูปแบบจริงที่ควรได้ยิน

## เขียนไฟล์ยาว

เพดาน 300 บรรทัดต่อการเขียนหนึ่งครั้ง ย้ายไปอยู่ในคำอธิบายเครื่องมือ ซึ่งเดินทางไปกับทุกคำขอ
ของเดิมมันอยู่ในคำแนะนำที่ส่งหลังการเขียนครั้งแรก แปลว่าการเขียนไฟล์ยาวครั้งแรกของทุกเซสชัน
สตรีมออกไปจนจบแล้วค่อยรู้ตัวเลข วัดได้ 5 ครั้งจาก 166 การเขียน แต่ละครั้งคือรอบสตรีมราว 100 วินาทีที่ถูกทิ้ง

## แว็บขาวตอนแถวเครื่องมือใหม่โผล่

บล็อคที่บอกว่าเครื่องมือตัวไหนกำลังทำงาน มีสองแบบ คือบาร์ที่เลื่อนตามงานลงไป กับบล็อคประจำแถว
สวิตช์ที่สลับสองตัวนี้เคยปิดตอนไม่มีเครื่องมือไหนรันด้วย ซึ่งคือช่วงที่โมเดลกำลังพิมพ์คั่นระหว่างเครื่องมือสองตัว
แถวใหม่จึงเกิดมาพร้อมบล็อคเต็มความเข้ม แล้วโดนถอดออกในเฟรมถัดมา แล้วค่อยจางกลับเข้ามาใหม่

ตอนนี้แถวใหม่ไม่ใส่บล็อคแล้ว และบาร์แยก "ส่งต่อ" กับ "มาถึง" ออกจากกัน
ส่งต่อระหว่างสองแถวที่รันต่อกันถึงจะไถล ส่วนตอนโผล่มาใหม่มันวางลงตรงนั้นเลยแล้วค่อยจาง
ไม่ลากผ่านย่อหน้าคำบรรยายที่คั่นอยู่ และไม่ยืดขึ้นมาจากศูนย์

## สไลด์

ห้องสไลด์บอกเด็คแล้วว่าใบไหนกำลังอยู่บนเวที ใบที่เห็นอยู่จะได้อนิเมชั่นของตัวเองตอนถูกเรียกขึ้นมา
ไม่ว่าจะมาถึงด้วยการเลื่อน กดลูกศร หรือกระโดดข้ามไป ของเดิมทุกใบวิ่งพร้อมกันตั้งแต่ตอนโหลด
คนเลยเห็นแค่ใบแรก ที่เหลือวิ่งจบไปแล้วก่อนจะมีใครเลื่อนลงไปดู เด็คบนดิสก์ยังเป็น HTML สะอาดเหมือนเดิม
เปิดที่ไหนก็ได้

คู่มือทำสไลด์เติมของที่พลาดซ้ำ: การเปิดทีละบรรทัดที่ต้องรอดไปถึง `.pdf` ต้องเขียนเป็นสไลด์เพิ่ม ไม่ใช่สถานะเพิ่ม ·
เด็คห้ามวาดลูกศรกับเลขหน้าเอง ห้องมีให้ครบแล้ว · กล่องสไลด์ตัดที่ 720px บรรทัดที่ล้นหายเงียบทั้งบนจอและบนกระดาษ ·
และคู่ฟอนต์ไทยที่ฝังไปกับไฟล์ได้จริงตามใบอนุญาต พร้อมคำเตือนเรื่อง TH Sarabun ของราชการที่เอามาใช้บนเว็บไม่ได้

## สกิลใหม่ 10 ตัว

ฝั่งงานหน้าจอ: `aetox-frontend-design` ตัดสินใจว่าหน้าตาจะเป็นแบบไหน · `aetox-ui-design` ชั้นลงมือทำ
ตั้งแต่โทเคนถึง iOS/Android · `aetox-shadcn` สำหรับโปรเจกต์ที่ใช้ shadcn/ui · `aetox-radix-to-base`
สำหรับการย้ายจาก Radix ไป Base UI · `aetox-ux-review` ตรวจ UI ที่ทำเสร็จแล้วด้วยเลนส์มาตรฐาน ·
`aetox-anti-slop` กันงานตกไปที่หน้าตาแบบที่ดูออกว่า AI ทำ

ฝั่งงานวิศวกรรม: `aetox-code-review` ตรวจก่อน merge · `aetox-testing` จะเทสอะไรแค่ไหน ·
`aetox-deploy` เช็คลิสต์ก่อนส่งของ รับมือเหตุ และ postmortem · `aetox-documentation` เขียนเอกสารจากฝั่งคนอ่าน

`aetox-debug` ได้เครื่องมือเพิ่มสำหรับบั๊กที่รอยเย็นแล้ว: ไล่ต้นตอย้อนสายเรียก ปิดทั้งประเภทไม่ใช่ปิดเคสเดียว
รอเงื่อนไขไม่ใช่รอเวลา และสคริปต์ไล่หาเทสที่ทำสถานะร่วมเปื้อน

ทุกตัวรับมาจากโอเพ่นซอส ใบอนุญาตของต้นทางเดินทางมากับโฟลเดอร์เสมอ

## เรื่องตัวตรวจไวรัส

คำสั่ง PowerShell ที่แอปรันเองไม่ใช้ `-EncodedCommand` แล้ว สคริปต์ไปเป็นข้อความที่อ่านออก
เหตุผลเดิมที่เข้ารหัสไว้คือกลัวเครื่องหมายคำพูดเพี้ยน ซึ่งเป็นการแก้ปัญหาที่ไม่มีอยู่จริง
สิ่งที่มันซื้อมาแทนคือบรรทัดคำสั่งที่แยกจากมัลแวร์ไม่ออก และเป็นกฎตรวจจับของ Windows ตรงตัว
แอปเราเองก็ห้ามเอเจนใช้ `-EncodedCommand` ด้วยเหตุผลเดียวกันมานานแล้ว ข้อนั้นใช้กับตัวเราเองด้วย

README ทั้งสองภาษาเขียนคำอธิบายเรื่อง `Wacapew.C!ml` ใหม่ให้ตรงความจริง: ตัวติดตั้งไม่โหลดของ
บุคคลที่สามแล้วตั้งแต่รุ่น 1.5.7 ตัวแอปเป็นคนโหลด เฉพาะความสามารถที่คุณติ๊กเลือก และชื่อที่ลงท้าย `!ml`
คือคำตัดสินจากรูปร่างของไฟล์ ไม่ใช่จากสิ่งที่ไฟล์ทำ ขนาดแอป Wails เปล่าๆ ที่ยังไม่มีโค้ดสักบรรทัดก็โดนชื่อเดียวกัน

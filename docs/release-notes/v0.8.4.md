# 🚀 Aetox v0.8.4 Release Notes — แชทเรียนรู้สองท่าทาง: รันอันนี้ และไว้ทำทีหลัง

สองฟีเจอร์ที่เจ้าของโปรเจกต์ขอ ทั้งคู่ว่าด้วยเรื่องเดียวกัน — **ข้อเสนอในแชทกลายเป็นการกระทำได้โดยผู้ใช้ไม่ต้องพิมพ์ซ้ำ**

### 1. ▶️ ปุ่ม Run บนโค้ดบล็อกที่เป็นคำสั่ง

* โค้ดบล็อกที่แท็ก `bash` / `sh` / `shell` / `zsh` / `powershell` / `ps1` / `cmd` / `bat` ได้ปุ่ม **Run** ข้างปุ่ม Copy ผลลัพธ์ไปโผล่ใน `<pre>` ที่ต่อท้ายในบล็อกเดิม
* **แปดแท็กนี้เท่านั้น** — `console` และ `text` มีไว้ *แสดง* ผลลัพธ์ ส่วน `python` และเพื่อนๆ เป็นไฟล์ซอร์ส การรันทั้งสองกลุ่มคือการเดาผิดที่มีผลข้างเคียงจริง
* **การคลิกคือการยินยอม** — คำสั่งมองเห็นเต็มๆ อยู่ในบล็อก เหมือนผู้ใช้พิมพ์เข้าเทอร์มินัลเอง จึงไม่มีกล่องขออนุญาตซ้อนขึ้นมาอีกชั้น
* **แต่ไม่ได้ข้ามกลไก**: `RunChatCommand` หา `shell` skill จาก registry จริงแล้วเรียก `ExecuteTool` ไม่ใช่ `exec.Cmd` เปล่าๆ — sandbox, RTK rewrite, ทะเบียน background shell และ audit log ทำงานครบเหมือนตอน agent เรียกเอง **มีทางเดียวที่คำสั่งจะรันใน Aetox** ไม่ว่าจะโมเดลสั่งหรือผู้ใช้กด
* ผลลัพธ์ถูกใส่ผ่าน `textContent` เพราะ output ของคำสั่งเป็นข้อความที่เชื่อไม่ได้

### 2. 📌 ชิปงานที่ agent แนะนำ — `suggest_task`

* Workbench tool ตัวใหม่: ระหว่างทำงาน agent ปักธงงานข้างเคียงที่มันเห็นแต่ไม่ได้ถูกสั่งให้ทำ — ชื่อเรื่อง, tldr, และ prompt ที่ต้องอ่านรู้เรื่องด้วยตัวเอง
* ชิปโผล่ที่ช่องพิมพ์ กดแล้ว**เปิด session ใหม่**และส่ง prompt นั้นไปตรงๆ กด ✕ เพื่อปฏิเสธ
* **เทิร์นที่ปักธงไม่หยุด** — ใบเสร็จของ tool สั่งให้โมเดลกลับไปทำงานเดิมชัดเจน และมีเทสตรึงประโยคนั้นไว้ เพราะโมเดลที่เริ่มลงมือทำงานที่เพิ่งปักธงเอง = ทำลายฟีเจอร์นี้ทั้งอัน
* **สองด่านที่ input**: ต้องมีทั้งชื่อและ prompt · prompt สั้นกว่า 40 ตัวอักษรถูกปฏิเสธพร้อมบอกว่า "ระบุไฟล์ สิ่งที่พบ และสิ่งที่ต้องทำ" — prompt บางๆ จะเปิด session อนาคตที่ไม่รู้เรื่องอะไรเลย ให้เสียหนึ่งรอบตอนนี้ดีกว่าเสียทั้ง session ทีหลัง
* **ชิปอยู่ในหน่วยความจำ ไม่ลง `aetox.db`** — ข้อเสนอไม่ใช่บันทึก และการเก็บข้อเสนอที่ถูกปฏิเสธไว้ตลอดกาลจะทำให้ store กลายเป็นรายการจู้จี้

### 🔭 ทิศทางต่อ

ผู้ผลิตชิปวันนี้คือโมเดลที่สังเกตเห็นระหว่างเทิร์น — ผู้ผลิตที่ตั้งใจไว้สำหรับ v2 คือ **ตัว store เอง**: `tool_runs` บวก FTS index สามารถสังเกตได้ว่า "ผู้ใช้คนนี้ทำงานเดิมมาสามครั้งแล้ว" แล้วเสนอ automation เอง — UI ชิป, flow เปิด session ใหม่ และสัญญาว่า prompt ต้องอ่านรู้เรื่องเดี่ยวๆ ที่สร้างในรุ่นนี้คือกลไกส่งมอบของฟีเจอร์นั้น สร้างก่อนเพราะมันมีประโยชน์ด้วยตัวเองอยู่แล้ว

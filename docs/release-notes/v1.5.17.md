# 🧩 Aetox v1.5.17

รุ่นนี้เป็นรุ่นของ **งานวิดีโอทั้งเส้นบนเครื่องคุณ** และ **เสียงทั้งสองทาง** —
เอเจนตัดต่อที่ตัดจริงเรนเดอร์จริงพร้อมห้องตัดข้างแชต ไมค์กับปุ่มฟังที่สลับเจ้าเสียงได้
15 เจ้าจากหน้าตั้งค่า และบั๊คร้ายแรงที่โต๊ะขวามือของแชตหนึ่งโผล่ทับจอของอีกแชต ถูกปิดในเช้าที่มันกัด

---

## ตัดต่อวิดีโอจบในเครื่อง

**เรื่องเดิม** เอเจนวิดีโอเรนเดอร์ได้ตั้งแต่ปลายเดือน แต่เส้นทางยังไม่เป็นชิ้นเดียว:
ห้องตัดไม่มี ตัวเรนเดอร์ต้องหาเอง และผลตัดรายงานด้วยคำพูดของเอเจน —
"ตัดให้ 18 วิแล้วครับ" กับคลิป 40 วินาที หน้าตาเหมือนกันจนกว่าจะได้นั่งดูทั้งไฟล์

**รุ่นนี้** เส้นครบตั้งแต่คำสั่งจนไฟล์ออก ทำในเครื่องทั้งหมด:

- **เอเจนตัดต่อ (editor) กับเอเจนสร้างวิดีโอ (video)** เป็นแพ็กเกจของตัวเอง —
  kinocut (เครื่องมือตัด 50+ แอ็กชัน ผ่าน MCP) + Hyperframes จาก fork ของเรา
  สำหรับเรนเดอร์ฉาก (Tailwind ฝังแล้ว GSAP ปักรุ่น)
- **ทุกไบนารีปักรุ่นและตรวจ SHA** ผ่านตัวติดตั้งของแอปเอง — puppeteer ไม่มีสิทธิ์
  แอบโหลดเบราว์เซอร์เองหลังบ้าน การ์ดติดตั้งบอกขนาดก่อนกด
- **ห้องตัด** ข้างแชต: งานตัดของเซสชั่นนี้เป็นบัญชีพร้อมเครื่องเล่น ตัวเลขทุกตัว
  (ความยาว ขนาด ความละเอียด ช่วงที่รอด) อ่านจาก result JSON ของเครื่องมือ
  ไม่ใช่จากประโยคของเอเจน ผู้ใช้ปิดห้องได้และมันจำ — งานถัดไปส่งเป็นแท็บเงียบ ๆ แทน
- **หน้างานวิดีโอ** ถามคำถามเดียว (ตัดของเดิม หรือสร้างใหม่) แล้วเปิดแชตของ
  เอเจนที่ถูกตัว ม่านล็อกกับปุ่มบนม่านตัดสินจากคำถามเดียวกันเสมอ (AgentGate)
- **สูตรรูป/เสียงได้ขั้นดาวน์โหลดที่หายไป** — `media_fetch` โหลด ตรวจว่าไบต์เป็น
  สื่อจริง (หน้า error ที่ปลอมชื่อ .jpg คือทางพังอันดับหนึ่ง) และออกใบเสร็จ
  format/ขนาด/พิกเซล/วินาที ในคอลเดียว

## จอดำเด้งเอง — และมันจะไปโผล่เครื่องผู้ใช้ด้วย

**เรื่องเดิม** หน้าต่าง Windows Terminal ดำ ๆ หัวเรื่องเป็น path ใน AppData
เด้งขึ้นเองพร้อม log GPU ของ Chromium หนึ่งบรรทัด — chrome-headless-shell
ที่ Google ส่งมาเป็น .exe แบบคอนโซล และมันเป็น "หลาน" ที่ node ในบันเดิล
เรนเดอร์เปิดต่อ ไกลเกินมือกลไกซ่อนคอนโซลของ Aetox ส่วนคำขอซ่อนของ Node
เป็นคำขอที่ Windows Terminal มีประวัติไม่ฟัง

**รุ่นนี้** แก้ที่ชั้นเดียวที่ไม่มีใครย้อนได้: พลิก 2 ไบต์ใน PE header ของไบนารี
จาก CONSOLE เป็น GUI — โปรเซส GUI ไม่มีวันได้คอนโซล ใครเปิดยังไงก็ตาม
ยืนยันบนเครื่องจริงก่อนเขียนโค้ดว่าเรนเดอร์ได้เหมือนเดิม ทำทั้งตอนติดตั้ง
และตรวจซ้ำที่จุดประกอบ path ทุกครั้งที่เรียกใช้ เครื่องที่ติดตั้งไปก่อนรุ่นนี้
จึงหายเองโดยไม่ต้องโหลดใหม่

## พูดกับมันได้ ให้มันอ่านให้ฟังได้

**เรื่องเดิม** แอปมีหูมาตั้งแต่ ก.ค. แต่ฟังได้เฉพาะไฟล์บนดิสก์ ไม่มีอะไรฟังผู้ใช้
และไม่มีอะไรพูดกลับ

**รุ่นนี้** ไมค์ในช่องพิมพ์ถอดเสียงลงดราฟต์ (ไม่ส่งเอง — คำพูดคือข้อความ ไม่ใช่คำสั่งส่ง)
ปุ่มฟังใต้ทุกคำตอบอ่านออกเสียง และหน้าตั้งค่า > เสียง สลับเจ้าได้ทั้งสองทาง:

- **STT 7 เจ้า / TTS 8 เจ้า** — โลคัลเป็นค่าเริ่มต้นทั้งคู่ (whisper.cpp, เสียง Windows)
  เสียงที่อัดไม่ออกจากเครื่องจนกว่าจะเลือกแถวคลาวด์เอง และทุกแถวคลาวด์เขียนไว้
  ว่าอะไรออกไปไหน
- **ข้อเท็จจริงที่ต้องวัดเองถึงเจอ:** Windows เก็บเสียงไว้สองรีจิสทรีที่มองไม่เห็นกัน —
  ทางปกติเห็น 2 เสียงไม่มีไทย ทาง Speech_OneCore เห็นครบ 6 รวมเสียงไทย
  เอนจินของเราไล่เองทั้งสองทาง
- **คีย์ใช้ร่วมกับหน้าโมเดล** — คีย์ OpenAI ที่กรอกไว้แชตได้ก็พูดได้ และ error
  จากคลาวด์ถูกแปลงเป็นประโยคไทยเดียวที่บอกว่าทำอะไรต่อ (ก่อนหน้านี้ 401 ของ
  OpenAI พ่นคีย์ redacted หลายร้อยตัวอักษรใส่หน้าตั้งค่า)

## โต๊ะขวามือเป็นของแชตของมัน

**เรื่องเดิม** ยืนอยู่ในแชตหนึ่ง แล้วหน้าเว็บที่เอเจนของอีกแชตกำลังอ่านโผล่เต็มโต๊ะขวา
แย่งโฟกัส แถมถูกเซฟเป็นของเซสชั่นผิดถาวร — §187 ปิดรูนี้ให้ไฟล์ไปแล้วเมื่อ 25 ส.ค.
แต่จดไว้เองว่าเบราว์เซอร์ยังเปิดอยู่ และเช้า 1 ก.ย. มันกัดจริง

**รุ่นนี้** ทุกการเปิดหน้าเว็บบอกว่าเป็นของแชตไหน หน้าของแชตเบื้องหลังไปรอบนโต๊ะ
ของแชตตัวเอง โดยหน้าต่างจริงยังมีชีวิตอยู่หลังฉากให้เอเจนทำงานต่อ สลับไปเมื่อไหร่
ได้หน้าเดิมคืนทั้งใบไม่รีโหลด และการสลับแชตเลิกฆ่าหน้าที่เอเจนกำลังใช้ —
ภาพแคปของแชตที่ไม่ได้อยู่บนจอจะบอกโมเดลตรง ๆ ว่าอาจเป็นเฟรมเก่า
แทนที่จะแอบดันหน้าต่างขึ้นทับจอคนอื่นเพื่อให้ได้เฟรมสด

## เบราว์เซอร์ในแอปโตขึ้นสองเรื่อง

- **แถบที่อยู่เดาสคีมแบบเบราว์เซอร์จริง** พิมพ์ `localhost:8443` แล้วเซิร์ฟเวอร์
  พูด https หน้าไม่ค้าง error อีกแล้ว — สคีมที่เราเดาให้มีนัดสองเสมอ ส่วนสคีม
  ที่ผู้ใช้พิมพ์เองไม่มีวันถูกแก้
- **พรีเซ็ตมือถือเป็นอุปกรณ์จริงทั้งตัว** ไม่ใช่แค่หน้าต่างแคบ: user agent,
  จอสัมผัส, pixel ratio ตั้งผ่านเอนจินแบบเดียวกับ DevTools เว็บที่แยก mobile
  ฝั่งเซิร์ฟเวอร์จึงส่งหน้ามือถือจริงมา และรายชื่ออุปกรณ์อยู่ฝั่ง Go ที่เดียว
  ให้เมนูกับเอเจนเห็นเครื่องชุดเดียวกัน

## อื่น ๆ ในรุ่นนี้

- เอเจนแต่ละตัวมีหน้าของตัวเอง วาดนิ่งจากชื่อ ใช้ทั้งการ์ดออฟฟิศและหัวแชต
- แผนผังโค้ดปรับจำนวนไฟล์ที่วาดได้จากหน้าจอ (60 เป็นแค่ประโยคแรก ไม่ใช่เพดาน)
- เมนูแนบไฟล์เลือกชนิดก่อนเปิดไดอะล็อก และ .docx/.pptx/.xlsx กลับมาโผล่ใน
  ตัวกรองหลังหายไปเพราะ pattern เขียนมือ
- สกิลระบบ aetox หดจาก 44.7k เหลือ 19.6k ไบต์ ส่วนลึกย้ายไป GUIDE.md
  ที่อ่านเป็นรายหัวข้อเมื่อถึงเรื่อง
- คำปฏิเสธ "tool not exposed" บอกทางต่อ หลังพบเอเจนใช้ ~40 คอลไปสืบหา
  วิธีรันเครื่องมือด้วยมือแทนที่จะถามผู้ใช้หนึ่งคำถาม
- เขียนไฟล์ซ้ำ path ที่ระบบวางให้ ไม่ได้โฟลเดอร์ `output/<session>` ซ้อนสองชั้นแล้ว
- ชั้นผลงานกรองเป็น ไฟล์/วิดีโอ ได้ — คลิปที่เรนเดอร์เสร็จไม่จมอยู่ระหว่าง
  สกรีนช็อตกับไฟล์ทำงานของเซสชั่นที่สร้างมัน

เบราว์เซอร์ข้ามเซสชั่นทั้งชุดใน deskCrossSession, PE subsystem patcher,
เมนูอุปกรณ์, address fallback, และเสียงฝั่งคลาวด์ผ่าน httptest

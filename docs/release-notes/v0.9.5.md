# 🚀 Aetox v0.9.5 — The automation room opens, and the browser becomes one tool

> ⚠️ **Read this first: the automation work in this release is new and not settled.**
> The room, the two engines and the agent behind them all landed inside one day.
> They work — every claim below was verified against a real n8n instance, not a
> mock — but this is the first release where any of it exists, and the rough
> edges have not all been found yet. Treat v0.9.5 as the version where automation
> becomes usable, not the version where it becomes dependable. **v0.9.6 is the
> one that settles it.** If you depend on something running unattended, keep
> watching it until then.

---

## 1. 🔀 ระบบออโตเมชั่น — a room that builds your workflows

The automation room is a conversation with a specialist, not a form. It connects
to the engine **you** already run — n8n or Windmill — and builds on it.

- **Two engines from the first line of code.** Nothing here is shaped around one
  product: an engine is a catalog entry plus a client, the room's picker reads
  the catalog rather than a hardcoded list, and the agent reads which engine it
  is on off its own tools instead of assuming.
- **The agent is a colleague, not a JSON generator.** It reads an existing
  workflow before writing one — the user's own instance is the only accurate
  reference for how a node is shaped, because n8n publishes no node schema at
  all and accepts invented parameters that only fail at run time.
- **It carries what the API cannot tell it**: that `connections` is keyed by node
  *name* with a doubled array, that an update replaces the whole workflow, that a
  Windmill flow path is both its name and its permissions.

## 2. 🔌 A connection pointed at an agent now actually reaches it

The bug that made the room look broken on day one: n8n could be connected,
placed, and shown as connected on every screen, while the agent held none of its
tools.

Four readers agreed the agent was equipped — the engine chip, the settings page,
the readiness check, and the tests — because all four read `agent:` placement.
The one function that hands out tools asked the *desk* instead, and the desk had
never heard of `agent:automation`. Tools were cut before they ever reached the
agent, which then honestly reported having none.

Fixed where it broke: the registry cut now reads agent placement alongside the
MCP servers it already read, and the regression test walks the whole pipe —
writing placement the way the UI writes it and asking the function the dispatch
asks — instead of testing the pieces separately and passing while the wiring was
severed.

## 3. 🔒 An engine belongs to its agent's workstation

Placement for n8n and Windmill is locked to the automation agent. A connection
with eight possible audiences and one real reader is not flexibility; it is
eight ways to reach "connected everywhere, usable nowhere". Placement now has
two states — at its agent, or off — and old placements written before the lock
are repaired at startup.

## 4. 🛠️ The automation agent is a full-rank worker

It has the workstation the job needs: a shell, a terminal you can watch, files,
notes, its own memory — and it **starts its own engine**. `n8n_server_start` and
`windmill_server_start` check whether the server answers and bring it up with
the command saved in Settings, waiting until it really responds. "The server is
down" stopped being a dead end the agent hands back to you.

The start command stays yours: the agent may fill an empty field, and can never
overwrite one you wrote.

## 5. 🌐 `browser` is one tool now — and one tab

Four tools described one object. `browser_open`, `browser_read`, `browser_click`
and `browser_type` are now four **actions** of a single `browser` tool: fewer
entries in every request, and adding a browser capability no longer means adding
a tool.

The permission split survives the packing. Those four names are still the keys —
`categories:` and a profile's `tools:` speak them exactly as before, so a profile
that names only some gets only those actions, and the tool's own description
advertises only what that caller may use.

**And it is one tab.** `open` used to mint a new tab on every call, so a session
that opened five pages left five tabs and the actions that followed targeted
whichever was last. It now steers the tab it already has, minting a new one only
when there is none. Two bugs had to be fixed together for that to be true: the
page-load latch was a one-shot, so a reused tab would have reported the
*previous* page's outcome for the new navigation.

## 6. 🧰 Housekeeping

- `internal/n8n` and `internal/windmill` moved under `internal/automation/`,
  where the code already said they belonged: the catalog calls them one family
  and the picker treats them as interchangeable.
- The Manual Trigger trap is now taught where the model meets it. A workflow
  built for manual testing cannot be activated and does not need to be — it is
  finished when it saves. The agent used to read n8n's refusal as "the job is
  impossible" and hand back a failure over a step that was never required.

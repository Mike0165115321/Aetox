> ตัวจริง ไม่ใช่ของจำลอง แต่นี่เป็นรุ่นแรกที่ของพวกนี้มีอยู่ และยังหาจุดที่ไม่เรียบไม่ครบ ให้ถือว่า

## 1. ห้องระบบออโตเมชั่น

ห้องนี้เป็นการคุยกับผู้เชี่ยวชาญ ไม่ใช่การกรอกฟอร์ม มันต่อกับเครื่องยนต์ที่ **คุณ** รันอยู่แล้ว คือ
n8n หรือ Windmill แล้วสร้างงานบนนั้น

- **รองรับสองเครื่องยนต์ตั้งแต่บรรทัดแรกของโค้ด** ไม่มีอะไรถูกออกแบบรอบผลิตภัณฑ์ตัวเดียว
  ตัวเลือกในห้องอ่านจากรายการจริง ไม่ใช่รายชื่อที่เขียนตายไว้ และเอเจนอ่านจากเครื่องมือของตัวเอง
  ว่ากำลังทำงานอยู่บนเครื่องยนต์ไหน แทนที่จะเดา
- **เอเจนเป็นเพื่อนร่วมงาน ไม่ใช่เครื่องปั๊ม JSON** มันอ่าน workflow ที่มีอยู่ก่อนจะเขียนตัวใหม่
  เพราะระบบของคุณเองเป็นแหล่งอ้างอิงเดียวที่ถูกต้องว่าโหนดหน้าตาเป็นยังไง เนื่องจาก n8n ไม่ได้
  เผยแพร่โครงสร้างโหนดไว้เลย และรับพารามิเตอร์ที่แต่งขึ้นมาเองโดยไปพังเอาตอนรัน
- **มันถือความรู้ที่ API บอกไม่ได้** เช่นวิธีที่ n8n เก็บการเชื่อมโยงระหว่างโหนด และการที่การอัปเดต
  หนึ่งครั้งคือการเขียนทับ workflow ทั้งตัว และการที่พาธของ flow ใน Windmill เป็นทั้งชื่อของมัน
  และสิทธิ์ของมันในตัวเดียวกัน

## 2. การเชื่อมต่อที่วางไว้ให้เอเจน ไปถึงเอเจนจริง ๆ แล้ว

บั๊กที่ทำให้ห้องนี้ดูพังตั้งแต่วันแรก: n8n ต่อได้ วางให้เอเจนได้ และทุกหน้าจอแสดงว่าเชื่อมต่อแล้ว
ขณะที่เอเจนไม่ได้ถือเครื่องมือของมันสักตัว

ตัวอ่านสี่ตัวเห็นตรงกันว่าเอเจนมีเครื่องมือครบ ทั้งชิปแสดงเครื่องยนต์ หน้าตั้งค่า ตัวตรวจความพร้อม
และเทสต์ เพราะทั้งสี่อ่านจากที่เดียวกันคือการวางให้เอเจน แต่ฟังก์ชันเดียวที่แจกเครื่องมือจริง ๆ ไป
ถาม *โต๊ะ* แทน และโต๊ะไม่เคยรู้จักการวางแบบนั้นเลย เครื่องมือจึงถูกตัดก่อนไปถึงเอเจน แล้วเอเจน
ก็รายงานตามตรงว่าไม่มีเครื่องมือ

แก้ที่จุดที่พัง และเทสต์กันถอยเดินทั้งเส้น คือเขียนการวางแบบเดียวกับที่หน้าจอเขียน แล้วถามฟังก์ชัน
เดียวกับที่ระบบมอบงานถาม แทนที่จะทดสอบทีละชิ้นแล้วผ่านทั้งที่สายไฟขาด

## 3. เครื่องยนต์เป็นของโต๊ะทำงานของเอเจนตัวนั้น

การวาง n8n และ Windmill ถูกล็อกไว้กับเอเจนอัตโนมัติ การเชื่อมต่อที่มีผู้รับได้แปดทางแต่มีคนอ่าน
จริงคนเดียวไม่ใช่ความยืดหยุ่น มันคือแปดวิธีที่จะไปถึงสถานะ "เชื่อมต่อทุกที่ ใช้ไม่ได้สักที่" ตอนนี้
การวางมีสองสถานะคืออยู่กับเอเจนของมัน หรือปิด และการวางแบบเก่าจะถูกซ่อมให้ตอนเปิดโปรแกรม

## 4. เอเจนอัตโนมัติเป็นคนทำงานเต็มตัว

มันมีโต๊ะทำงานครบตามที่งานต้องการ ทั้งเชลล์ เทอร์มินัลที่คุณดูได้ ไฟล์ โน้ต และความจำของตัวเอง
และมัน **เริ่มเครื่องยนต์ของตัวเองได้** คือตรวจว่าเซิร์ฟเวอร์ตอบไหม แล้วสั่งเปิดด้วยคำสั่งที่บันทึกไว้
ในหน้าตั้งค่า พร้อมรอจนกว่ามันจะตอบจริง คำว่า "เซิร์ฟเวอร์ไม่ได้เปิด" เลิกเป็นทางตันที่เอเจนโยน
กลับมาให้คุณ

คำสั่งเปิดยังเป็นของคุณ เอเจนเติมช่องที่ว่างได้ แต่เขียนทับสิ่งที่คุณเขียนไว้ไม่ได้เลย

## 5. เครื่องมือเบราว์เซอร์รวมเหลือตัวเดียว และแท็บเดียว

เดิมมีสี่เครื่องมืออธิบายของชิ้นเดียว ตอนนี้การเปิด อ่าน คลิก และพิมพ์ กลายเป็นสี่ **การกระทำ**
ของเครื่องมือ `browser` ตัวเดียว ทำให้รายการที่ส่งไปกับทุกคำขอสั้นลง และการเพิ่มความสามารถ
ใหม่ไม่ได้แปลว่าต้องเพิ่มเครื่องมือใหม่อีกต่อไป

การแบ่งสิทธิ์ยังอยู่ครบ ชื่อทั้งสี่ยังเป็นกุญแจเหมือนเดิม โปรไฟล์ที่ระบุแค่บางอย่างจึงได้แค่นั้น และ
คำอธิบายของเครื่องมือก็โฆษณาเฉพาะสิ่งที่ผู้เรียกคนนั้นใช้ได้

**และมันเป็นแท็บเดียว** เดิมทุกครั้งที่สั่งเปิดจะได้แท็บใหม่ เซสชันที่เปิดห้าหน้าจึงเหลือห้าแท็บ แล้ว
คำสั่งถัดไปก็ไปลงที่แท็บสุดท้าย ตอนนี้มันขับแท็บที่มีอยู่แล้ว จะสร้างใหม่ก็ต่อเมื่อยังไม่มีเลย เรื่องนี้
ต้องแก้บั๊กสองตัวพร้อมกัน เพราะตัวจับสถานะโหลดหน้าเป็นแบบใช้ครั้งเดียว แท็บที่ถูกใช้ซ้ำจึงจะ
รายงานผลของ *หน้าก่อนหน้า* ให้กับการเปิดหน้าใหม่

## 6. งานเก็บกวาด

- โค้ดของ n8n และ Windmill ย้ายไปอยู่ใต้โฟลเดอร์เดียวกัน ตามที่โค้ดบอกอยู่แล้วว่ามันเป็นตระกูล
  เดียวกัน
- กับดักของ Manual Trigger ถูกสอนไว้ตรงจุดที่โมเดลเจอมันแล้ว workflow ที่สร้างไว้ทดสอบด้วยมือ
  เปิดใช้งานไม่ได้และไม่จำเป็นต้องเปิด มันเสร็จตั้งแต่ตอนบันทึกแล้ว เดิมเอเจนอ่านคำปฏิเสธของ
  n8n เป็น "งานนี้ทำไม่ได้" แล้วส่งความล้มเหลวกลับมา ทั้งที่ขั้นตอนนั้นไม่เคยจำเป็น

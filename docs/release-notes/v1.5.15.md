รุ่นใหญ่ 31 คอมมิต และเป็นรุ่นที่เกือบทุกอย่างเกิดจากการ **วัดก่อนแก้** —

## เครื่องมือน้อยลง 10 ตัว โดยไม่มีอะไรหายไปสักอย่าง

**เรื่องเดิม** บล็อกเครื่องมือมี 37 ตัว กินราว 7,800 โทเคนในทุกคำขอของทุกโต๊ะ
ก่อนคุณจะพิมพ์อะไรด้วยซ้ำ และทุกความสามารถใหม่ก็แพงขึ้นอีกหนึ่งช่อง

**รุ่นนี้** ห่อสี่ก้อนเข้าเป็นชื่อเดียว เหลือ 27 ตัว (~7,009 โทเคน) แล้วรับ
`pr` กับ `rename` เข้ามาใหม่เป็น 28 ตัว / ~7,527 โทเคน

```
search     = list, glob, grep
change     = write, edit, append, batch, delete
codebase   = errors, symbol, map
media_read = image, video, audio
```

หลักที่ใช้เลือกว่าอะไรห่อกับอะไรมีข้อเดียว: **pack ห้ามคร่อมเส้นที่ด่านขีดไว้แล้ว**
เส้นอ่าน/เขียนถูกขีดโดยอิสระสามที่และตรงกันหมด `search` จึงอ่านล้วน `change` เขียนล้วน
`rename` ไม่อยู่ใน `codebase` เพราะมันเขียน และ `pdf_read` ไม่อยู่ใน `media_read` เพราะ
มันยิงขนานได้ ส่วน `read` ไม่ถูกห่อเลย เพราะมันบอกว่าไฟล์ *พูดว่าอะไร* ไม่ใช่ว่าอยู่ที่ไหน
และเป็นเครื่องมือที่ถูกเรียกมากที่สุดในประวัติ

พร้อมกันนั้น **โต๊ะกับสแตนซ์หั่นได้ราย action แล้ว** ไม่ใช่แค่ทั้งตัว ซึ่งเป็นสิ่งที่
ทำให้การห่อปลอดภัย เพราะไม่งั้นโหมดวางแผนจะเสียของที่อ่านไปพร้อมกับของที่เขียน
ผลพลอยได้: `deny: browser_click` ในไฟล์โต๊ะที่เคยถูกเมินเงียบ ๆ ตอนนี้ทำงานจริงแล้ว

`grep` ได้พารามิเตอร์ใหม่สองตัวด้วย — `type` (25 ภาษา ชื่อผิดปฏิเสธพร้อมลิสต์ เพราะ
filter ที่แมตช์ไม่เจอเงียบ ๆ จะตอบ "ไม่พบ" ซึ่งอ่านเป็น "ไม่มีคำนี้ในโปรเจกต์") และ
`multiline` แบบ `rg -U`

## แผนที่โค้ดทั้งโปรเจกต์ และแท็บกราฟที่ลากได้

**เรื่องเดิม** เอเจนที่เพิ่งเปิดโปรเจกต์ไม่รู้จักรูปทรงของมันเลย ต้องไล่ `list` กับ `grep`
ทีละชั้นกว่าจะรู้ว่าอะไรอยู่ตรงไหน

**รุ่นนี้** `internal/repomap` เดินทั้งโปรเจกต์ แกะ symbols (Go ด้วย AST จริง อีกสิบกว่าภาษา
ด้วย declaration scan — pure Go ทั้งหมด ไม่แบก tree-sitter ตามจุดขายเรื่องแรม) สร้างกราฟ
import จัดอันดับไฟล์ตามการถูกพึ่งพา แล้วบีบลงราว 1,000 โทเคน วัดจริงบนรีโปนี้: 1,150 ไฟล์
เหลือ ~950 โทเคน ใน 0.6–0.9 วินาที ไม่มีอะไรค้างแรมหลังจบ

และมันขึ้นจอด้วย — **แท็บกราฟบน workbench** (หน้าโค้ดเท่านั้น) จุดคือไฟล์ ขนาดตามการถูกพึ่งพา
สีตามโฟลเดอร์ เส้นคือ import เรียก `repomap.Graph` ตัวเดียวกับที่เอเจนใช้ ไม่มีสำเนาให้เพี้ยน
ฟิสิกส์สดตามเส้น import ลากไฟล์หนึ่งแล้วตระกูลไหลตาม ปล่อยแล้วสั่นเข้าที่ และ **หลับเมื่อไม่มีแรง**
ไม่กิน CPU เปล่า คลิกจุดเปิดไฟล์เป็นแท็บข้าง ๆ

## เปลี่ยนชื่อ symbol ทั้งโปรเจกต์ และแก้แล้วเช็คงานตัวเอง

**เรื่องเดิม** วัดจากล็อกจริง: `symbol` ถูกเรียก 0 ครั้งตลอดอายุ `diagnostics` 9 ครั้ง
เครื่องมือที่ไม่มีใครเรียกไม่ใช่เครื่องมือที่ไม่จำเป็น มันคือเครื่องมือที่ตอบผิดคำถาม

**รุ่นนี้**

- `symbol` ตอบ **call sites ทุกจุด** ผ่าน `textDocument/references` คือ blast radius
  ก่อนแก้ ซึ่งเป็นสิ่งเดียวที่เครื่องมืออื่นตอบไม่ได้
- `rename` เปลี่ยนชื่อ symbol ทั้ง workspace ตรวจ sandbox ทุกไฟล์ก่อนเขียนไฟล์แรก
  (rename ครึ่งทางแย่กว่าไม่ทำเลย) และแปลงตำแหน่ง UTF-16 ถูกต้อง — คอมเมนต์ไทยบนบรรทัด
  เดียวกันไม่ทำไฟล์พัง มีเทสต์คุมไว้
- **แก้แล้วเช็คงานตัวเอง** — `edit`/`edits`/`write`/`rename` แนบ error สดของไฟล์ที่แตะ
  กลับมาในผลของตัวเอง โมเดลเห็นว่าพังในจังหวะเดียวกับที่ทำพัง เฉพาะ error เฉพาะ workspace จริง
  และ server ต้องลงอยู่แล้ว (ไม่ auto-install)

## กวาดคอนเท็กซ์ก่อนถึงจุดสรุป

**เรื่องเดิม** พอคอนเท็กซ์เต็มถึง 80% ระบบจะเรียกโมเดลมาสรุป ซึ่งเสียทั้งเวลาและเงิน
และก่อนหน้านั้นการตัดเทิร์นเก่าทิ้งทำ cache prefix แตก — วัดได้ 96 ครั้งใน 7 วัน
ทิ้งไป 2.49 ล้านโทเคน

**รุ่นนี้** ที่ 60% ของงบ **micro-compact** กวาดผลของเครื่องมืออ่านเก่า ๆ ทิ้งเป็นช็อตเดียว
เหลือ marker บอกว่าเก็บอะไรไป ฟรี ไม่เสีย model call และมักกันไม่ให้ถึงจุดสรุปเลย
จงใจไม่กวาดผลของ `shell` (ชวนให้รันซ้ำคำสั่งที่เปลี่ยนสถานะ) กับ `browser` (หน้าอาจไม่อยู่แล้ว)
กวาดเป็น batch เพราะทุกการกวาดคือ cache แตกหนึ่งครั้ง จ่ายครั้งเดียวต่อการข้ามเส้น ไม่ใช่ทุกเทิร์น

แก้ตามมาอีกอย่างก่อนปล่อยรุ่นหนึ่งวัน: เขตกวาดเคยยืมกฎของตัวสรุป (จบที่ข้อความ user เท่านั้น)
เทิร์นยักษ์เทิร์นเดียวที่อ่านไฟล์ 40 รอบจึงไม่ถูกกวาดเลย ทั้งที่เป็นเคสที่ต้องการมันที่สุด

และ **แผงหน้าต่างคอนเท็กซ์บอกว่ากวาดไปเท่าไหร่** เพราะตัวเลขที่ลดกลางเทิร์นโดยไม่มีคำอธิบาย
อ่านเป็นบั๊กของมิเตอร์เอง

## ห้อง Pull request

**เรื่องเดิม** `github` อ่านรีโปได้ แต่รีวิว PR ไม่ได้เลย

**รุ่นนี้** เครื่องมือ `pr` ห้า action — `list` `read` `checks` `create` `comment` —
`read` คืนทั้งใบในคอลเดียว: สถานะ สาขา merge สะอาดไหม ไฟล์พร้อม +/- และผล CI
ไม่ต้องบอกว่ารีโปไหน มันอ่าน origin จาก `.git/config` เอง

`merge` กับ `close` **จงใจไม่มี** สองอันนั้นปิดเรื่องแทนที่จะเปิด เป็นคลิกเดียวบนหน้าที่คุณเปิดอยู่แล้ว
และไม่ใช่สิ่งที่เอเจนควรทำได้ตอนคุณมองทางอื่น ส่วน `create`/`comment` ผิดแล้วลบทิ้งได้ในวินาทีเดียว
และทั้งคู่เป็น RiskHigh ที่ต้องขออนุมัติ เพราะสิ่งที่ด่านปกป้องตรงนี้คือ **ชื่อของคุณ** ไม่ใช่ดิสก์

พร้อมกับ **ห้อง PR บน workbench** (แท็บ `pr` โต๊ะโค้ดเท่านั้น) ลิสต์พร้อมแบดจ์ CI บนแถว
กางแถวแล้วเห็นรายชื่อไฟล์ โดย **พับ diff ไว้** กดไฟล์ไหนถึงกางอันนั้น — เปิด PR ที่แตะสี่สิบไฟล์
แล้วไม่ต้องเจอ diff พันบรรทัดทับรายการที่กดเข้ามาดู และมีฟอร์มเปิด PR ในตัวห้อง
diff ใช้ `CodeDiff` ตัวเดิม เพราะ GitHub ส่ง patch มาเป็น unified diff อยู่แล้ว ไม่มี renderer ที่สอง

## ย้อนกลับได้หลายจุด ไม่ใช่แค่เทิร์นล่าสุด

**เรื่องเดิม** ปุ่มย้อนกลับย้อนได้แค่เทิร์นล่าสุด ซึ่งซื่อสัตย์กับงานสองเทิร์น และไม่จริงเลย
กับเซสชันยี่สิบเทิร์นที่เทิร์นซึ่งทำพังอยู่ห่างไปสี่เทิร์น

**รุ่นนี้** ชิป "ย้อนไปจุดก่อนหน้า" ข้างชิป undo เปิดเมนูขึ้นบน แถวละเวลา + ข้อความที่คุณพิมพ์
กดแล้วยังไม่ทำอะไร มัน **ถามก่อนพร้อมรายชื่อไฟล์จริง** ที่จะถูกเอากลับมา เก็บ 20 จุด

ปุ่ม undo เดิมยังเป็นปุ่มเดียวจบเหมือนเดิม ไม่กลายเป็นเมนู — แยกสองประตูโดยตั้งใจ
สามข้อที่ต้องถูกไม่งั้นกินงานของคุณ: ไฟล์ที่คุณเซฟเองต้องรอด (และ "เอง" ต้องเทียบกับ *จุดที่กำลังจะย้อนไป*
ไม่ใช่จุดล่าสุดเสมอ) · ย้อนแล้วต้องมีทางกลับ (จับ snapshot ก่อน restore ไม่ใช่หลัง) ·
ย้อนสองครั้งต้องไม่ถอยต่อ

ยังไม่ทำ: ย้อนบทสนทนา (ตอนนี้ย้อนไฟล์อย่างเดียว) และรอดข้ามการปิดแอป

## ไทม์ไลน์เทิร์นอ่านตามที่มันเกิดขึ้นจริง

**เรื่องเดิม** เทิร์นที่คิดสี่นาทีในสี่จังหวะแยกกันมาถึงเป็น "คิดเป็นเวลา 275 วินาที" คร่อม
"ใช้ 36 เครื่องมือ · 272 วินาที" ซึ่งบอกว่าโมเดลทำอย่างมโหฬารหนึ่งอย่าง แทนที่จะเป็น
เก้า สิบสี่ แปด และห้าอย่าง โดยมีประโยคของตัวเองนำหน้าทุกก้อน ส่วน text part ทุกอันยกเว้น
อันสุดท้ายกลายเป็นแถว note ที่พับอยู่ ไม่มี markdown เลย — ตาราง หัวข้อ หรือกราฟที่โมเดลเขียน
ก่อนเรียกเครื่องมือมาถึงเป็นซอร์สโค้ดของตัวเอง

**รุ่นนี้** เทิร์นแสดงเป็นช่วงงานตามลำดับที่มันเกิดจริง ไม่มีข้อมูลใหม่เลย 41+96+84+54
ก็คือ 275 เดิม และ part ที่ถือตัวเลขทั้งสี่อยู่ในฐานข้อมูลมาตั้งแต่ migration v4 —
นี่คือ **การหยุดบวก**

## แถวเครื่องมือบอกความจริงครบขึ้น

**เรื่องเดิม** แถวที่เขียนไฟล์มี `+9 -0` มานาน แถวที่อ่านไม่มีคู่ของมัน

**รุ่นนี้** สามป้ายใหม่:

- `read` โชว์ช่วงบรรทัดตั้งแต่ตอนเรียก แล้วผลจริงทับ เช่น `40-60 (21 บรรทัด)` ·
  `grep` บอก `(พบ N)` · `glob`/`list` บอกจำนวนไฟล์ · `symbol` บอกจำนวนผู้เรียก
- **ป้าย git ตัวอักษรเดียวแบบ editor** — M ส้ม / U,A เขียว / D แดง ไฟล์สะอาดไม่ติดอะไร
- **ป้ายแดง `!N`** เมื่อ self-check เจอ error หลังแก้ — ข้อเท็จจริงเดียวบนแถวที่เปลี่ยนสิ่งที่ผู้อ่านทำต่อ

## ทีม: reviewer กับ tester

**รุ่นนี้** ซับเอเจนสองตัวใหม่ ทั้งคู่ **เขียนอะไรไม่ได้เลย** และ reviewer ไม่มีเชลล์ด้วย —
ผู้อ่านคนที่สองที่แก้โค้ดได้คือผู้เขียนคนที่สอง แล้วไม่เหลือใครอ่าน

ที่น่าสนใจกว่าตัวเอเจนคือเหตุผลที่สองของการจ้าง ซึ่งวัดได้ไม่ใช่เถียงเอา: สามเซสชันยาว
(47, 95 และ 19 tool call) เรียก `task` ศูนย์ครั้งโดยมีทั้งคู่อยู่บน roster ตลอดทาง ไม่มีอะไรพัง
กฎเดิมบอกว่าการจ้างมีไว้สำหรับงานที่จะ "เทลงมาในบทสนทนานี้" ซึ่งเป็นเรื่องปริมาณล้วน ๆ
กฎจึงได้เหตุผลที่ปริมาณอธิบายไม่ได้: **งานที่คุณค่าของมันคือ *คุณ* ไม่ได้ทำเอง** —
คอนเท็กซ์ที่ทำการเปลี่ยนแปลงคือคอนเท็กซ์ที่มองไม่เห็นที่สุดว่าอะไรผิดกับมัน

หมายเหตุตามความจริง: หลังทั้งหมดนี้โมเดลก็ยังไม่เรียกเอง (วัดแล้วรอบที่ห้า) เจ้าของเคาะให้ปล่อยไว้แบบนี้
ทั้งสองเป็นของที่คุณเรียกด้วย `@reviewer` เมื่อรู้สึกว่างานนั้นควรมีคนดูซ้ำ

  Aetox ไม่ได้อยู่ในฐานะจะทำ เพราะตัวเลขเป็นของบุคคลที่สาม ตอนนี้บอกว่ามาจากแหล่งไหน ดึงมาเมื่อไหร่
  (ยังเปิดอยู่: แคตตาล็อกผิดสำหรับ DeepSeek 2–4 เท่า หน้าใช้จ่ายจึงรายงานต่ำกว่าจริง)
- **แคตตาล็อกโมเดลอ่านฟิลด์ได้ครบขึ้น** และการ์ดผู้ให้บริการที่ live discovery ล้มจะเติมจาก
  แคตตาล็อกบนดิสก์แทนชื่อเดียวที่เขียนไว้ตายตัว
- **เบราว์เซอร์ไม่เปิดแท็บซ้ำ** — เปิด url ที่เปิดอยู่แล้วตอบด้วยแท็บเดิม และผลของ browser
  ประทับแท็บที่มันทำงานอยู่มาด้วย
- **จัดการภาพในคอนเท็กซ์** — ภาพจากเครื่องมือถูกนับตามจริงและมีอายุ (22 ภาพเคยกลายเป็น
  620 ช่อง ~800,000 โทเคน เพราะงบมองไม่เห็นรูปเลย: `totalChars` วัดภาพ 130 KB เป็นคำบรรยาย 45 ตัวอักษร)
- **ไฟล์ .svg วาดลงเอกสารของแอป** แทนที่จะแขวนกับ `img` ซึ่งทำให้ `width="100%"` ยุบเป็น 0×0
  และ `var()` ทุกตัวตกเป็นสีดำ ตอนนี้ผ่านประตูเดียวกับรูปในคำตอบ (DOMPurify + confineDrawing)
- **เปลี่ยนโปรเจกต์แล้วแผงขวาไปกับแชทใหม่** ไม่ค้างแท็บของแชทที่เพิ่งจากมา และการกู้ workbench
  รู้จักห้อง deck กับ working tree ที่เคยถูกทิ้งเงียบ ๆ
- **คำแรกเปล่า ๆ ไม่รันสกิลอีกแล้ว ต้องมี slash** — ประโยคที่บังเอิญขึ้นต้นด้วยชื่อสกิล
  เคยกลายเป็นคำสั่งโดยไม่มีตัวอักษรไหนถึงโมเดลเลย
- **ค้นประวัติบอกวันได้แล้ว** — ผลค้นหาฝั่งแชททุกแถวเคยพิมพ์นาฬิกาตรงที่ควรเป็นวันที่
- **`suggest_task` ถูกปิดสวิตช์** — 270 โทเคนทุกคำขอทุกโต๊ะ ต่อศูนย์คอลใน 6,253 runs
  โค้ดกับ UI ยังอยู่ครบ เปิดกลับคือลบคอมเมนต์บรรทัดเดียว
- **regex ที่ขึ้นต้นด้วยแบ็กสแลช** ไม่ถูกอ่านเป็น path ของ Windows อีกแล้ว
- **สกิลเทมเพลตสไลด์กับเว็บแยกเป็นของตัวเอง** — คำอธิบายไม่ใช่เทมเพลต
- **โลโก้ MSIX ครบทุกสเกลที่ Store ขอ** พร้อม `priconfig.xml` — ไอคอนบน taskbar ของช่องทาง Store
  ไม่ถูก Windows ย่อด้วยตัวคูณเศษส่วนอีกแล้ว
- **หน้าเว็บ aetox สลับ EN/TH ได้ในหน้า** ทั้งหน้าแรกและหน้านโยบายความเป็นส่วนตัว
- **tokenaudit จับ cache แตก** พร้อมจำแนกสาเหตุ (เปลี่ยนโมเดล / ทิ้งช่วง / prefix เปลี่ยน)

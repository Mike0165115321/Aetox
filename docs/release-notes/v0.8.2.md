# 🚀 Aetox v0.8.2 Release Notes — ฐานข้อมูลเริ่มจดจำ "งานที่ทำ" และหน้าตั้งค่าได้ระบบดีไซน์

### 1. 🗄️ บันทึกทุกครั้งที่ tool ทำงาน และให้ schema รู้เวอร์ชันตัวเอง

* **ปัญหาเดิม**: Aetox จำ *บทสนทนา* ได้ (สองแถวต่อเทิร์น: ข้อความผู้ใช้ กับคำตอบสุดท้าย) แต่ **ไม่จำงานที่เกิดขึ้นระหว่างนั้นเลย** — argument ที่โมเดลส่งเข้า tool และผลลัพธ์ที่ได้กลับ ถูกทิ้งตรงจุดที่ tool คืนค่า ส่วน `toolHistory` เก็บแค่ป้ายชื่อ 50 รายการล่าสุดใน RAM หายตอนปิดแอป
* **`tool_runs`**: ตารางใหม่บันทึก argument JSON ดิบตามที่โมเดลส่งมาจริง (คำสั่งที่ผิดรูปก็คุ้มค่าที่จะเก็บ), ผลลัพธ์ก่อนถูกแปลงเป็นใบเสร็จให้โมเดล, outcome และเวลาที่ใช้
* **สอง hook ไม่ใช่ hook เดียวที่ขยาย** — `ToolEvent` วิ่งข้าม Wails bridge ทุกครั้งเพื่อวาดบนจอ ถ้าขยายมันจะกลายเป็นการยัดผลลัพธ์เป็นกิโลไบต์ผ่าน UI เพื่อรับใช้ผู้บริโภคที่ UI ไม่มี — จึงแยกเป็น `turn.ToolRun` ออกมาต่างหาก
* **Schema versioning**: `PRAGMA user_version` + migration ที่ตรวจย้อนได้ ฐานข้อมูลที่ใหม่กว่าโค้ดจะถูกปฏิเสธแทนที่จะถูกเขียนทับ
* นี่คือฐานของ workflow layer หลัง 1.0.0 (จับงานซ้ำ → สรุปเป็นกฎ → ให้ sub-agent ปรับ prompt ตัวเอง) — รุ่นนี้วางฐานอย่างเดียว ยังไม่มีชั้นบน

### 2. 🎨 ระบบดีไซน์ใต้หน้า Settings และไม่มีอะไรลบด้วยคลิกเดียว

* **Design system**: token สี ระยะ ตัวอักษร และคอมโพเนนต์กลางของทั้งหน้าตั้งค่า แทนสไตล์ที่ต่างคนต่างเขียนรายหน้า
* **ไม่มีอะไรถูกลบทันที** — การลบ MCP server, การลบ skill, และการเปลี่ยนโปรไวเดอร์ที่กำลังรันอยู่ ทั้งหมดถามก่อน โฟกัสเริ่มที่ปุ่ม Cancel และ Escape ยกเลิกได้ เพื่อไม่ให้ Enter หลงมือลบของ
* แก้บั๊กสามหน้าที่ระบบดีไซน์ไปเจอระหว่างทาง

### 3. 🧩 ติดตั้ง skill จาก repo ธรรมดาและไฟล์ zip ได้

* เดิมรองรับเฉพาะรูปแบบที่กำหนดไว้แคบ — ตอนนี้ดึงจาก GitHub repo ทั่วไปได้ และติดตั้งจาก `.zip` ในเครื่องได้
* ปุ่มเปิดโฟลเดอร์ skill ถูกเอากลับมาให้เห็น (เดิมซ่อนอยู่)

### 4. 🔌 หน้า MCP เลิกเก็บสี่อย่างไว้กับตัวเอง

* `cwd`, `timeout`, และอีกสองฟิลด์อยู่ในไฟล์ config มาตั้งแต่ต้นแต่ไม่มีทางเข้าถึงจาก UI — ผลคือ **การแก้ไข server หนึ่งครั้งลบค่าที่ตั้งไว้ทิ้งเงียบๆ** ตอนนี้แก้ได้ครบและ round-trip กลับไฟล์ถูกต้อง

# 🚀 Aetox v0.8.1 Release Notes — เก็บกวาดการล็อกอินที่เสี่ยงกับ "บัญชีของคุณ"

รุ่นนี้มีเรื่องเดียว และเป็นเรื่องที่ปล่อยไว้ไม่ได้: **การล็อกอินที่เอา OAuth client ของผลิตภัณฑ์อื่นไปยิงกับแพ็กเกจผู้บริโภค** ความเสี่ยงของมันไม่ได้ตกที่ Aetox แต่ตกที่ **บัญชีของผู้ใช้** — ซึ่งเป็นความเสี่ยงประเภทเดียวในโปรเจกต์นี้ที่เป็นแบบนั้น จึงถูกจัดการก่อนและออกมาเป็นรุ่นของตัวเอง

### 1. 🔒 ถอดการล็อกอินแบบ Restricted ออกทั้งหมด

* **ถอดออก 5 ทาง**: Claude Pro/Max, ChatGPT (codex), GitHub Copilot, Qwen และ Gemini Code Assist
* v0.8.0 เคยเลือกวิธี "เตือนแล้วให้ผู้ใช้ตัดสินใจเอง" — รุ่นนี้กลับคำ เพราะคำเตือนไม่ได้ทำให้ความเสี่ยงที่ค้างอยู่กับบัญชีหายไป และการล็อกอินที่ผลลัพธ์ดีที่สุดคือ "ผู้ให้บริการยังไม่ทันสังเกต" ไม่ใช่ฟีเจอร์ที่ควรเปิดค้างไว้
* **เหลือ OpenRouter ทางเดียว** — เป็นทางเดียวที่ผู้ให้บริการประกาศเงื่อนไขให้แอปอื่นใช้ได้เอง (PKCE ที่ออกคีย์ซึ่งผู้ใช้เป็นเจ้าของ)

### 2. 🧾 เหตุผลรายตัว ไม่ใช่เหมารวม

* **Qwen** — ยิง client id ของ qwen-code CLI กับบัญชีผู้บริโภค และในทางปฏิบัติ **ล็อกอินไม่สำเร็จอยู่แล้ว** เหลือแค่ปุ่มที่แบกความเสี่ยงโดยไม่มีทางไปจริง ตัวโปรไวเดอร์ `qwen` ยังอยู่ ใช้ผ่าน `DASHSCOPE_API_KEY` / `QWEN_API_KEY` ได้ตามปกติ
* **Gemini Code Assist** — สองข้อเท็จจริงจาก Google เอง: ประกาศตรวจจับ "การใช้ Gemini CLI OAuth กับซอฟต์แวร์ภายนอก" มีผล 2026-03-25 และปิดบริการ tier ฟรี/ผู้บริโภคไปแล้วเมื่อ 2026-06-18 — ปุ่มนี้จึงชี้ไปที่นโยบายที่เขาบังคับใช้ ให้บริการชั้นที่ตายไปแล้ว 6 สัปดาห์
* **ปฏิเสธ Antigravity ด้วย** — ทั้งที่มันยังใช้ได้จริงและมีปลั๊กอินของคนอื่นทำสำเร็จแล้ว เพราะเงื่อนไขของ Google ระบุเคสนี้ตรงตัวว่าผิด และมีบันทึกการแบนจริง พร้อม **แบนถาวรถ้าผิดครั้งที่สอง** — การที่มันยังใช้ได้ทำให้แย่กว่า Code Assist ไม่ใช่ดีกว่า เพราะสิ่งที่เสียคือทั้งบัญชี Google ไม่ใช่แค่โควตา

### 3. 🗑️ Credential ถูกลบจริง ไม่ใช่แค่เลิกใช้

* `oauth.json` ที่ v0.8.0 เขียนไว้อาจยังมี refresh token ของทางที่ถอดออก — ตัว store กรองทิ้งตั้งแต่ตอนโหลด (`removedProviders`) จึงไม่ถูกอ่าน ไม่ถูก refresh ไม่ถูกส่งออก และ **ถูกล้างออกจากดิสก์ในการเขียนครั้งถัดไป**
* สำคัญที่สุดกับ Code Assist เพราะ token ตัวนั้นคือ credential ของบัญชี Google จริง

### 4. 🧩 ของที่เก็บไว้ทั้งที่ไม่มีคนใช้ — ตั้งใจ

* กลไก device-code (RFC 8628) และ UI สาขา `RiskRestricted` ไม่มีผู้ใช้งานเหลือแล้ว แต่ยังอยู่พร้อมเทสบน method จำลอง — การล็อกอินตัวถัดไปที่ต้องมีคำเตือนจะได้ไม่ต้องประดิษฐ์ใหม่
* สิ่งที่ v0.8.0 ทำถูกยังอยู่ครบ: seam `TokenSource` ต่อ request, ฟิลด์ risk ในทุก method, store ที่เขียนแบบ write-then-rename สิทธิ์ 0600

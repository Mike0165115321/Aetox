# 🚀 Aetox v0.9.4 — เชลล์ที่สอง ปุ่มหยุดที่หยุดจริง และแอปที่อัปเดตตัวเองเป็น

สามเรื่องของรุ่นนี้ไม่ได้ตั้งใจมาเจอกัน แต่มันเป็นคำถามเดียวกันสามมุม:
**เครื่องของผู้ใช้เป็นของผู้ใช้** — โปรเจกต์ที่อยู่ใน WSL ต้องรันด้วยเชลล์ของมันเอง,
ปุ่มหยุดต้องหยุดทุกอย่างที่เอเจนแตะอยู่จริงๆ ไม่ใช่แค่หยุดวาดหน้าจอ,
และการอัปเดตต้องเป็นคลิกเดียวที่พิสูจน์ได้ว่าไฟล์มาจากเราจริง

---

## 1. 🐚 เชลล์เลือกได้ — รวมถึง WSL

Aetox ยังเป็นโปรแกรม Windows ตัวเดียวเหมือนเดิม แต่คำสั่งของเอเจนไม่จำเป็นต้องรันใน
cmd.exe อีกต่อไป: เลือกได้ว่าจะใช้**เชลล์ของเครื่อง หรือ bash ใน WSL distro ตัวไหน**

- โปรเจกต์ที่อยู่ใต้ `\\wsl.localhost\<distro>\…` **เลือก distro นั้นให้เองตั้งแต่เปิด** —
  toolchain, node_modules, virtualenv ของมันอยู่ฝั่ง Linux และเชลล์ Windows รันของพวกนั้นไม่ได้
- ชิปบนแถวพิมพ์ข้อความบอกตลอดว่าคำสั่งกำลังจะลงเชลล์ไหน — เห็นก่อนอนุมัติ ไม่ใช่หลังรัน
  (ตัวเลือกเป็นรายโปรเจกต์ สลับโปรเจกต์แล้วเชลล์ตามของใครของมัน) — CLI ได้ `/shell` เหมือนกัน
- **กำแพง sandbox ไม่เลื่อนตาม**: path ฝั่ง Linux ถูกแปลกลับเป็น path ฝั่ง Windows ก่อนตรวจทุกครั้ง
  (`/mnt/d/…` ↔ `D:\…`, `~` ถามตัว distro เอง, ในไฟล์ระบบของ distro = `\\wsl.localhost\…`)
  คำสั่งที่ชี้ออกนอกพื้นที่ทำงานถูกปฏิเสธเหมือนเดิมไม่ว่าจะสะกดแบบโลกไหน
- ตัวแปรสภาพแวดล้อมที่ hook ต้องอ่านข้ามไปถึง Linux ผ่าน `WSLENV` — ตั้งเฉยๆ แล้วเงียบหาย
  คือกับดักที่ระบบนี้ปิดให้แล้ว

## 2. 🛑 ปุ่มหยุด หยุดจริง — และเทิร์นรู้จักบ้านตัวเอง

รุ่นก่อนมีบั๊คตระกูลเดียวกันซ่อนอยู่หลายตัว: **เทิร์นที่กำลังวิ่งไม่รู้ว่าตัวเองเป็นของแชทไหน**

- **รีเฟรชกลางเทิร์นแล้วงานหาย** — จริงๆ เอนจินทำต่อจนจบและบันทึกครบ แต่หน้าจอใหม่ไม่รู้ว่ามีเทิร์นวิ่งอยู่
  ตอนนี้หน้าต่างที่เพิ่งเปิดถามเอนจินก่อน (`TurnInFlight`) ต่อบล็อกสดกลับ พิมพ์แทรกได้ กดหยุดได้
  และคำตอบลงจอเองเมื่อเสร็จ (`agent:done`)
- **ย้ายแชทกลางเทิร์นแล้วคำตอบตามไปผิดห้อง — ถาวรลง DB** — เทิร์นถูกตอกหมุด session ที่มันเกิด
  ตั้งแต่วินาทีแรก คำตอบ, tool runs, job rows เขียนลงหมุดนั้นเสมอ และทุกประตูที่จะพาออกจากแชท
  ระหว่างเทิร์นวิ่ง (เปิดแชทอื่น, แชทใหม่, สลับโต๊ะ, สลับโปรเจกต์, ลบแชทที่เปิดอยู่) ปฏิเสธด้วย
  ประโยคเดียวกัน: *เอเจนกำลังทำงานอยู่ — รอให้เสร็จ หรือกดหยุดก่อน*
- **ปุ่มหยุด**: ฆ่าทั้งตระกูลโปรเซสของคำสั่ง (`taskkill /T` — ไม่ใช่แค่ cmd.exe ตัวหน้า แล้วปล่อย
  npm กับ node วิ่งต่อ), กดในจังหวะไหนก็ติด (ช่องว่างมิลลิวินาทีก่อนตัวรับเกิด ถูกจำแล้วยิงตาม),
  ผลของ tool ที่ถูกยกเลิกไม่หลอกเทิร์นถัดไป และการหยุดขึ้นจอว่า **"หยุดการทำงานแล้ว"** —
  ไม่ใช่ "เกิดข้อผิดพลาด" — ข้อความที่สตรีมมาแล้วอยู่ครบ พร้อมปุ่มลองใหม่

## 3. ⬆️ อัปเดตตัวเองได้ในคลิกเดียว — และพิสูจน์ที่มาของไฟล์ก่อนเสมอ

ปุ่มใน **การตั้งค่า → เกี่ยวกับ** เปลี่ยนจาก "เปิดหน้าดาวน์โหลด" เป็น **"อัปเดตแล้วรีสตาร์ท"**:
โหลด → ตรวจ → สลับไฟล์ → ปิดตัวเอง → เปิดกลับมาเป็นตัวใหม่ (ท่าเดียวกับ VS Code)

- **portable** ใช้ rename trick — exe ที่รันอยู่เขียนทับไม่ได้แต่เปลี่ยนชื่อได้ สลับสองจังหวะ
  บน volume เดียวกัน ไม่มีสภาพครึ่งเก่าครึ่งใหม่ พังตรงไหนถอยกลับได้
- **installer** รันตัวติดตั้งใหม่แบบเงียบให้ แล้วเปิดแอปกลับ
- **Scoop ไม่ถูกแตะ** — โฟลเดอร์ของ Scoop เป็นของ Scoop ปุ่มยังเป็น `scoop update aetox` ให้ก๊อป
- ตัวใหม่เปิด**หลัง**ตัวเก่าปิดเสมอ — ฐานข้อมูลไม่มีวันถูกเปิดชนกัน

และรุ่นนี้คือรุ่นแรกที่ release ถูก**เซ็นด้วยกุญแจลับ** (ed25519): CI เซ็น `checksums.txt`
ด้วยกุญแจที่อยู่ใน secret เท่านั้น แอปฝังกุญแจสาธารณะไว้ในเนื้อ binary และตรวจตามลำดับ
**ลายเซ็น → checksums → ไฟล์** ก่อนติดตั้งทุกครั้ง — checksums เฉยๆ พิสูจน์แค่ "ไฟล์มาครบ"
แต่มันวางอยู่ที่เดียวกับไฟล์ ใครสลับไฟล์ได้ก็สลับมันได้ ลายเซ็นพิสูจน์ "ไฟล์มาจากเราจริง"
เพราะกุญแจลับไม่ได้อยู่บน GitHub — release ที่ไม่มีลายเซ็นหรือลายเซ็นไม่ผ่าน ปุ่มไม่ทำงานต่อ จุดจบ

> ปุ่มนี้เริ่มออกฤทธิ์กับเครื่องที่ลง v0.9.4 แล้ว — การขึ้น v0.9.5 จะเป็นคลิกเดียวครั้งแรก

## 4. 🍃 เล็กแต่มีเจ้าของ

- **ความจำที่เรียนรู้มา แก้ได้เป็นรายบรรทัด** ใน การตั้งค่า → แต่ละบรรทัดเป็นแถว แก้หรือลบได้ตรงนั้น
- **คุยตรงกับเอเจนในออฟฟิศ ถามกลับได้แล้ว** — `ask_user` เคยถูกปิดสำหรับเอเจนทุกตัวเพราะ
  งานที่ถูก `task` สั่งไม่มีใครนั่งเฝ้า แต่แชทตรง (§85) มีคนนั่งอยู่ตรงนั้นจริงๆ ตอนนี้เอเจนถาม
  เป็นการ์ดตัวเลือกได้แทนที่จะถามเป็นร้อยแก้วแล้วเดาเอา
- สกิลที่มากับตัวแอปขึ้นป้าย "มากับ Aetox" แทนช่องโฟลเดอร์ว่างๆ และลบไม่ได้ (ของที่ไม่มีโฟลเดอร์
  ไม่ควรมีปุ่มลบที่ลบอะไรไม่ได้จริง)

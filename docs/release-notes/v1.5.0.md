# 🚀 Aetox v1.5.0

รุ่นนี้มียี่สิบห้าคอมมิตนับจาก v1.4.0 และเป็นเลขไมเนอร์เพราะสองเรื่อง: **ของที่เคยติดตั้งตอน
ลงโปรแกรม ย้ายมาให้คุณเลือกเองในแอป** และ **คุณเห็นว่ากำลังจ่ายอะไรอยู่ แล้วกดหยุดได้จริง**

**สรุปสั้น ๆ ก่อน**

- ความสามารถสี่อย่าง (อ่านตัวหนังสือในรูป · อ่าน PDF · ดูวิดีโอฟังเสียง · ถอดเสียง) ติ๊กเลือก
  ติดตั้งได้จากในแอป ไม่ต้องขอสิทธิ์แอดมิน ไม่มีจอ UAC
- **แก้ของที่เสียอยู่เงียบ ๆ สองอย่าง** — ffmpeg ที่ตัวติดตั้ง v1.4.0 ไปโหลด หายจากต้นทางไปแล้ว
  จริง ๆ และตัวถอดเสียง `whisper-cli` ไม่เคยถูกติดตั้งโดยอะไรเลยสักครั้ง
- **มีปุ่มหยุดเอเจนและซับเอเจนเป็นรายตัวแล้ว** พร้อมเห็นโทเคนเข้า-ออกและค่าใช้จ่ายระหว่างที่มัน
  ยังทำงานอยู่ ไม่ใช่รู้ทีหลัง
- กดหยุดกลางทางแล้ว **สิ่งที่ผู้ช่วยทำมาทั้งเทิร์นไม่หายไปอีกแล้ว**
- **เลิกยิงคำถามซ้ำเงียบ ๆ** เวลาผู้ให้บริการตอบ error รอบแรก ซึ่งเดิมคิดเงินคุณสองถึงหกรอบ
  ต่อหนึ่งคำถามที่ล้ม
- เบราว์เซอร์ในตัวยกเครื่อง: เห็นของที่ซ่อนอยู่ในหน้า บอกเมื่ออ่านไม่ครบ ดู console กับ network ได้
  ถ่ายภาพทั้งหน้าได้ และเลิกรายงานว่ากดแล้วทั้งที่ไม่ได้กด
- เพิ่มผู้ให้บริการโมเดลสามราย (ModelScope · NVIDIA · Ollama Cloud) รวมเป็น 20 ราย และหน้า
  ตั้งค่ามีปุ่มทดสอบโมเดลทีละตัว กดพร้อมกันหลายตัวได้
- แถมสกิลเพิ่มสามตัว และมีปุ่มให้ผู้ช่วยไปหาสกิล/MCP/ชุดคำสั่งมาให้คุณเอง
- โต๊ะโค้ดมีแผง Git บอกว่าทั้งโปรเจกต์แก้อะไรไปแล้วบ้าง
- ล็อกอินบัญชี Aetox ผ่าน GitHub หรือ Google เขียนเสร็จแล้ว แต่ **ส่งมาแบบปิดไว้**
- ประตูที่สาม **Aetox ทีม** สร้างครบแล้วในโค้ด แต่ยังไม่เปิดให้กด (อ่านข้อ 9)

## 1. ความสามารถย้ายมาอยู่ในแอป ติ๊กเอาเท่าที่อยากได้

**เรื่องเดิม** ตัวติดตั้ง Windows ของ Aetox แอบทำงานหนักกว่าที่ตาเห็น: ระหว่างติดตั้งมันโหลด
Tesseract, poppler, ffmpeg และโมเดลเสียง ลงเครื่องคุณด้วย รวมแล้วร้อยกว่าเมกะไบต์ที่คุณไม่ได้
เลือก และเพราะมันต้องเขียนลง Program Files มันจึงต้องขอสิทธิ์แอดมิน

พฤติกรรมนั้นยังทำให้ Defender ฝั่งคลาวด์ตัดสินตัวติดตั้งของเราเป็น `Program:Win32/Wacapew.C!ml`
แล้วเบราว์เซอร์ลบไฟล์ทิ้งก่อนผู้ใช้จะได้เห็นอะไร ซึ่งพออ่านจากมุมของโมเดลตรวจไวรัสก็เข้าใจได้:
ไฟล์ที่ไม่ได้เซ็น ไม่มีชื่อเสียง แล้วตอนติดตั้งไปโหลดไฟล์จากอินเทอร์เน็ตมารันสี่รอบ คือแม่แบบของ
โปรแกรมประเภทที่มันถูกฝึกมาให้จับ

**รุ่นนี้** จอเปิดครั้งแรกมีหน้าใหม่ชื่อ **"เพิ่มความสามารถให้ Aetox"** เป็นแถวติ๊กได้สี่แถว
แต่ละแถวบอกว่าได้อะไรกลับมา และบอกขนาดของแถวนั้นเอง

| แถว | ได้อะไร | ขนาด |
|---|---|---|
| อ่านตัวหนังสือในรูป | อ่านคำที่อยู่ในภาพที่คุณแนบมา | ~62MB |
| อ่าน PDF | ดึงข้อความออกจาก PDF ที่ไม่งั้นเป็นแค่ไฟล์ทึบ | ~20MB |
| ดูวิดีโอและฟังเสียง | สุ่มเฟรมจากวิดีโอ แปลงไฟล์เสียงให้อ่านต่อได้ | ~63MB |
| ถอดเสียงเป็นข้อความ | ถอดสิ่งที่พูดในไฟล์เสียงออกมาเป็นตัวหนังสือ | ~39MB |

**ขนาดอยู่บนแต่ละแถว ไม่ใช่แค่ยอดรวมใต้ปุ่ม** เพราะยอดรวมบอกว่าทั้งชุดราคาเท่าไร แต่ไม่บอกว่า
ควรตัดตัวไหนออก ซึ่งเป็นคำถามเดียวที่การติ๊กออกตอบ

รายละเอียดที่ตั้งใจให้เป็นแบบนี้:

- **ติ๊กไว้ครบทุกอันตั้งแต่แรก** คนที่อยากได้ทั้งหมดไม่ต้องกดสี่ที
- **ติ๊กออกหมด ปุ่มเปลี่ยนเป็น "ข้ามไว้ก่อน"** ไม่ใช่ปุ่มที่กดไม่ได้
- **กดแล้วเข้าแอปเลย** ไม่ต้องนั่งดูแถบวิ่ง งานโหลดไปอยู่ในแถบงานเบื้องหลังที่มีอยู่แล้ว
- **แถวคือความสามารถ ไม่ใช่ไฟล์** ติ๊ก "ถอดเสียง" ครั้งเดียวได้ทั้งตัวถอดและโมเดล ชื่อ Tesseract,
  poppler, ffmpeg ไม่ขึ้นบนจอเลย เพราะมันไม่ใช่คำถามของคุณ
- **ล้มแล้วลองใหม่ได้ และทำต่อจากเดิม** ตัวไหนลงเสร็จแล้วข้าม ตัวไหนล้มค่อยโหลดใหม่
- **ไม่มีจอ UAC สักจอ** เพราะทุกอย่างลงที่โฟลเดอร์ข้อมูลของ Aetox ซึ่งเขียนได้โดยไม่ต้องแอดมิน
- **คนที่อัปเกรดมาจากรุ่นเก่าไม่ต้องโหลดซ้ำ** ตัวหาไฟล์มองทั้งที่เก่า (Program Files) และที่ใหม่

**ตัวติดตั้ง .exe ของรุ่นนี้ยังทำแบบเดิมอยู่** การถอดสี่ขั้นตอนนั้นออกจาก NSIS เป็นชิ้นสุดท้ายของ
แผนนี้ และกติกาคือไม่ทุบทางเก่าจนกว่าทางใหม่จะพิสูจน์แล้วบนเครื่องสะอาด ดังนั้นรุ่นนี้คือรุ่นที่
**ทางใหม่เปิดใช้ได้จริงคู่กันไป** ส่วนการเซ็นโค้ดยังเป็นงานที่ค้างอยู่ แผนนี้ลดพื้นที่ที่โดนยิง
ไม่ได้ทดแทนใบเซ็น

## 2. สองอย่างที่พังอยู่เงียบ ๆ และเพิ่งเจอตอนไล่ให้ครบ

**ffmpeg หายไปจากต้นทางจริง ๆ** ตัวติดตั้งปักหมุดไฟล์ ffmpeg ไว้ที่แท็กหนึ่งของโปรเจกต์ BtbN
ด้วยเหตุผลที่ฟังดูถูก คือไบต์ของแท็กจะไม่เปลี่ยน สิ่งที่คิดไม่ถึงคือ BtbN **ลบแท็กพวกนั้นทิ้ง**
หลังผ่านไปประมาณห้าวัน หมุดที่ปักไว้ 27 ก.ค. จึงตอบ 404 ตอนเทสต์ไปเรียกจริงวันที่ 21 ส.ค.
แปลว่าเครื่องที่ลง v1.4.0 ใหม่ในช่วงนั้น **ไม่ได้ ffmpeg เลย โดยไม่มีอะไรบอก** รุ่นนี้ Aetox
มิเรอร์ไฟล์ไว้เองแล้ว หมุดจะแน่แค่ไหน ก็แน่ได้เท่าของที่มันชี้ไปเท่านั้น

**ตัวถอดเสียงไม่เคยถูกติดตั้งโดยอะไรเลย** ตัวติดตั้งลงแต่ *โมเดล* 31MB ส่วน `whisper-cli`
ซึ่งเป็นตัวโปรแกรมจริง ๆ ถูกหาจาก PATH อย่างเดียว และไม่มีใครเอาไปวางไว้บน PATH แปลว่า
`audio_transcribe` **ตายมาตลอดบนเครื่องที่ลงใหม่** และเราส่งโมเดล 31MB ไปให้เครื่องยนต์ที่
ไม่มีอยู่ รุ่นนี้แถว "ถอดเสียง" ลงทั้งสองชิ้น

## 3. ปุ่มหยุด และการเห็นว่ากำลังจ่ายอะไรอยู่

เจ้าของนั่งดู `@research` ทำงานถึงเครื่องมือชิ้นที่เจ็ดสิบสอง แล้วเขียนมาว่า *"เราไม่มีปุ่มหยุด
เอเจนหรือซับเอเจนตอนทำงานเลย"* ซึ่งถูก และมันไม่ใช่แค่ปุ่มที่ลืมวาด

**ทำไมถึงไม่มี** งานที่ผู้ช่วยยกให้เอเจนไปทำ ถูกออกแบบให้อยู่ยาวกว่าเทิร์นที่สั่งมัน (ซึ่งถูกแล้ว
ไม่งั้นการมอบงานก็ไม่มีความหมาย) แต่ปุ่ม Stop ที่ช่องพิมพ์จะโผล่เฉพาะตอนที่เทิร์นยังเดินอยู่
เส้นทางปกติจึงเป็นแบบนี้: ผู้ช่วยสั่งงาน บอกว่า "สั่งไปแล้วครับ" เทิร์นจบ ปุ่มกลับเป็นปุ่มส่ง แล้ว
เหลือคนทำงานสี่คนวนอยู่ข้างหลังโดย **ไม่มีอะไรบนจอที่หยุดมันได้เลย**

**รุ่นนี้** การ์ดงานเบื้องหลังมีปุ่มหยุด หนึ่งปุ่มต่อหนึ่งคนทำงาน และอีกหนึ่งปุ่มสำหรับหยุดทั้งงาน
การ์ดนั้นอยู่บนจอตราบเท่าที่งานยังไม่ถูกเก็บ ซึ่งเป็นช่วงเวลาเดียวกับที่คุณอาจอยากหยุดมันพอดี
ส่วนปุ่ม Stop ที่ช่องพิมพ์ยังทำหน้าที่เดิมไม่เปลี่ยน

**"หยุดแล้ว" ไม่ใช่ "พัง"** สองอย่างนี้เคยหน้าตาเหมือนกันเป๊ะในระบบ ซึ่งมีผลจริง: พอมีงาน
จบลง แอปจะส่งเทิร์นใหม่ให้ผู้ช่วยไปอ่านผลงานนั้น ถ้าเอาไปใช้กับงานที่คุณเพิ่งจ่ายคลิกไปหยุด
มันก็คือจ่ายเพิ่มอีกเทิร์น แถมชวนให้โมเดลเริ่มงานเดิมใหม่ ตอนนี้งานที่ถูกสั่งหยุดจะไม่ถูกตามไป
อ่าน และสิ่งที่เหลือไว้บนจอคือใบเสร็จ: มันไปถึงไหน และใช้ไปเท่าไรก่อนที่เบรกจะถึง

**เห็นโทเคนระหว่างทำงาน ไม่ใช่รู้ทีหลัง** ทั้งสองฝั่งอยู่ห่างจากการมองเห็นแค่บรรทัดเดียว
ซับเอเจนถือตัวเลขแยกเข้า-ออกอยู่แล้วแต่โยนทิ้งเหลือแต่ยอดรวม ส่วนผู้ช่วยหลักบันทึกลงตาราง
ที่ไม่มีใครเปิดจนวันรุ่งขึ้น ตอนนี้ทั้งคู่พูดออกมาระหว่างที่ยังใช้อยู่

**เป็นสองตัวเลข ไม่ใช่ตัวเดียว** เพราะมันพังคนละแบบและเบรกคนละจังหวะ: ขาเข้าไต่ขึ้นคือ
บทสนทนาถูกส่งซ้ำใหม่ทุกรอบ ขาออกไต่ขึ้นคือโมเดลที่เขียนไม่ยอมหยุด

## 4. แผงบอกค่าใช้จ่าย: คำพยากรณ์กับใบเสร็จอยู่ที่เดียวกัน

ทีแรกตัวเลขไปอยู่บนแถบช่องพิมพ์ เจ้าของเห็นแล้วสั่งย้ายเข้าไปในแผงบริบท และภาพหน้าจอที่เขา
ส่งมาก็จับบั๊กได้พร้อมกัน: แถบเขียนว่า `เข้า 45.3k · ออก 1.4k` ส่วนแผงข้างหลังเขียนว่า
*"ยังไม่ได้คุยอะไรเลย ยังไม่เสียโทเคนสักตัว"* — สองตัวเลขบนจอเดียวกัน เถียงกันเอง

แผงเป็นฝ่ายพูดถูก ตัวเลขบนแถบไม่ถูกล้างตอนเปลี่ยนห้องแชท แชทใหม่เอี่ยมจึงเปิดมาพร้อมบิล
ของห้องก่อนหน้า แก้แล้ว และย้ายไปอยู่ที่เดียวกับสถานะสด ๆ อย่างอื่นของห้อง

ในแผงเดียวกันตอนนี้มี:

- **ข้างบนคือคำพยากรณ์** — คำขอ*ถัดไป*จะหนักเท่าไร (ของเดิม)
- **ข้างล่างคือใบเสร็จ** — เทิร์นนี้*ใช้ไปแล้ว*เท่าไร input / output / cache hit / cache miss
- **และค่าใช้จ่ายเป็นเงิน** คิดที่ฝั่งโปรแกรมไม่ใช่ให้หน้าต่างคูณเอง เพราะกติกาว่า
  **แพ็กเกจรายเดือนไม่ใช่มิเตอร์** อยู่ฝั่งนั้น (Codex ตอบด้วยโมเดลที่ OpenAI ก็ขายเป็นรายโทเคน
  ด้วย ถ้าคิดราคาตามเรตนั้นก็เท่ากับเก็บเงินคนที่จ่ายเหมาไปแล้วซ้ำอีกรอบ)
- ส่วนที่มาจากแคชคิดที่เรตแคช ซึ่งบางเจ้าต่างกันห้าสิบเท่า การไม่แยกไม่ใช่คลาดเคลื่อน แต่คือ
  ตอบผิดไปคนละหลัก
- **ถ้ามีรอบไหนที่ยังไม่รู้ราคา จะไม่แสดงเงินเลย** ยอดที่แอบขาดไปสามรอบคือตัวเลขที่ผู้ใช้จะเชื่อ
  ทั้งที่ไม่ควรเชื่อ และ "โมเดลนี้ไม่มีในตารางราคา" ไม่ได้แปลว่า "โมเดลนี้ฟรี"
- **cache hit/miss ขึ้นเฉพาะเจ้าที่รายงานแคชจริง ๆ** เจ้าที่ไม่รายงานจะไม่มีบรรทัดนี้ ไม่ใช่ขึ้น 0%
  ที่ไม่มีใครเคยพูด

ป้ายชื่อสี่ตัวใช้คำเดียวกับหน้าสถิติการใช้งานเป๊ะ ๆ (`Input` `Output` `Hit` `Miss` เป็นภาษาอังกฤษ
ทุกภาษา) เพราะมันเป็นศัพท์บิลของผู้ให้บริการ คุณจะได้ยกตัวเลขจากจอหนึ่งไปตรวจกับอีกจอ
และกับแดชบอร์ดของผู้ให้บริการได้

เจ้าของกดหยุดเทิร์นที่ทำงานมาหลายนาที แล้วทุกอย่างที่อ่านค้างไว้หายเกลี้ยง เหลือบรรทัดเดียวว่า
"หยุดการทำงานแล้ว"

**งานไม่ได้หาย มันอยู่ในฐานข้อมูลมาตลอด** แถวของเทิร์นที่เขากดหยุดมีชิ้นส่วนครบสิบหกชิ้น
ทั้งคำบรรยายทุกบรรทัดและเครื่องมือทุกตัว ปัญหาคือมันไปไม่ถึงกล่องข้อความบนจอ ตัวหน้าต่างจึง
ย้อนกลับไปหยิบสำเนาที่มีอยู่ในมือ ซึ่งเก็บได้แค่*รอบล่าสุด* และถูกล้างทิ้งทุกครั้งที่รอบนั้นจบด้วย
การเรียกเครื่องมือ ซึ่งเป็นจังหวะที่คนกดหยุดพอดีเป๊ะ

ตอนนี้กล่องข้อความอ่านจากที่เก็บก่อน ผ่านทางเดียวกับการเปิดแชทเก่า (ซึ่งวาดถูกมาตลอด)
สองทางที่ทำเรื่องเดียวกันคือสองทางที่จะเถียงกันวันหลัง และมันตรวจด้วยว่าแถวที่หยิบมาเป็นคำตอบ
ของคำถามที่เพิ่งถามไปจริง ๆ ไม่ใช่ของเทิร์นเก่า

**อีกอาการที่หายไปพร้อมกัน** คำตอบเดียวถูกวาดสองครั้ง อันบนมีปุ่มคัดลอก/ลองใหม่ อันล่างไม่มี
และปุ่ม Stop ค้างกดไม่ลง ทั้งหมดเป็นบั๊กเดียว: เทิร์นถูก "ปล่อยมือ" ก่อนหนึ่งบรรทัดที่จะเขียน
ผลลัพธ์ลงห้อง ผลคือคำตอบเขียนลงที่ว่าง ส่วนสถานะ "กำลังรอ" รอดชีวิตข้ามเทิร์นที่จบไปแล้ว
เกิดเฉพาะกับข้อความแรกของแชทใหม่ ซึ่งเป็นเหตุผลที่มันอ่านเหมือน "เฉพาะแชทใหม่ที่พัง"

## 6. เลิกยิงซ้ำเงียบ ๆ เวลาผู้ให้บริการตอบ error

เจ้าของส่งภาพกล่องแดงที่มีวงกลมหมุนอยู่ข้างใต้มาถามว่า *"ทำไมมันแอบทำงานเบื้องหลังแบบนั้น
ครับ ทั้งที่มีปัญหาไปแล้ว ... มันจะกินโทเค็น เครดิตเขา ผมหายังไงก็หาไม่เจอ"*

หาไม่เจอเพราะมันไม่เคยเป็นงานเบื้องหลัง มันอยู่ในเทิร์นนั้นเอง ในช่องว่างระหว่าง log สองบรรทัด:

```
[06:38:56.443]     Complete() error: codex: the free plan's limit is used up. It resets in 19 days.
[06:39:01.530]   --- Agent.RespondWithTools (tools=28) (11124.7ms) ---
```

ห้าวินาทีหลังผู้ให้บริการตอบคำตอบสุดท้ายแล้ว โดยไม่มีอะไรเขียนไว้ตรงกลาง สาเหตุคือโค้ดที่
มีมาตั้งแต่คอมมิตแรก: ถ้ารอบแรกล้ม *ด้วยเหตุใดก็ตาม* ให้ถามโมเดลใหม่โดยไม่ส่งเครื่องมือไปด้วย
วัดได้ว่าหนึ่งคำถามกลายเป็นสองครั้ง และตัวลองใหม่ข้างล่างอีกสามครั้งต่อครั้ง — **หนึ่งคำถาม
ต่อโควตาที่บอกว่าเหลืออีกสิบเก้าวัน = หกคำขอ** ใต้ข้อความ "กำลังคิดคำตอบ..." ที่ไม่เปลี่ยนเลย

**รุ่นนี้ประตูนั้นแคบลงเหลือเท่าที่มันมีไว้จริง ๆ** คือกรณีที่ผู้ให้บริการรับโมเดลแต่ปฏิเสธ
*ตัวรายการเครื่องมือ* เท่านั้น อ่านจากคำปฏิเสธของผู้ให้บริการเอง และมันเขียน log บอกเมื่อทำงาน
ความเงียบคือครึ่งหนึ่งที่ทำให้เรื่องนี้หาไม่เจอ

ทิศทางของความผิดพลาดกลับข้างแล้ว: เดิมยิงซ้ำไว้ก่อน ราคาที่จ่ายคือบิลใบที่สองทุกครั้งที่ล้ม
ตอนนี้ไม่ยิงไว้ก่อน ราคาที่จ่ายคือ error ตรง ๆ พร้อมปุ่มลองใหม่ ซึ่งเป็นสิ่งที่ควรได้เห็นตั้งแต่แรก

**และตัวที่แพงจริงไม่ใช่กำแพงโควตา แต่คือเน็ตกระตุก** เดิมถ้ารอบแรก timeout มันจะไปตกในทาง
เดียวกัน ถามใหม่แบบไม่มีเครื่องมือ ได้คำตอบว่าง แล้วมี**ครั้งที่สาม**ที่ไม่มีใครบันทึกโทเคน
สุดท้ายคืนค่าเป็นเทิร์นที่ *สำเร็จ* โดยมีข้อความว่า "เกินขีดจำกัดของโมเดลปัจจุบัน ลองแบ่งงาน
ให้เล็กลงหรือเปลี่ยนโมเดล" — สามคำขอ ไม่มีกล่องแดง ไม่มีปุ่มลองใหม่ และแอปแนะนำให้ผู้ใช้ไป
จ่ายค่าโมเดลใหญ่ขึ้นเพื่อแก้ปัญหาเน็ตของตัวเอง มีเทสต์ชื่อ *"เน็ตกระตุกไม่ใช่ความผิดของโมเดล"*
คุมไว้แล้ว กติกาสั้น ๆ คือ **เทิร์นที่เริ่มด้วย error ของผู้ให้บริการ ต้องไม่จบลงเป็นคำตอบ**

## 7. เบราว์เซอร์: เห็นมากขึ้น และเลิกเดา

เบราว์เซอร์ในตัวได้รับการยกเครื่องรอบใหญ่ สองเรื่องเป็นความสามารถใหม่ อีกสองเรื่องเป็นการซ่อม
สิ่งที่มันเคยตอบไม่ตรงความจริง

### เห็นของที่ซ่อนอยู่หลังเปลือกของหน้าเว็บ

เว็บสมัยนี้ชอบเก็บของไว้ในช่องแยก — ฟอร์มจ่ายเงินที่ฝังมาจากที่อื่น เอดิเตอร์ฝัง ตัวเล่นวิดีโอ
หรือปุ่มที่สร้างด้วย web component เดิมผู้ช่วยมองไม่เห็นของพวกนี้เลย มันอ่านหน้าแล้วได้หน้าว่าง

ที่แย่กว่าคือหน้าว่างหน้าตาเหมือนหน้าที่ยังโหลดไม่เสร็จ ผู้ช่วยจึงบอกว่า "รอแป๊บ" แล้วรอของ
ที่ไม่มีวันมา ตอนนี้มันเห็นและกดได้จริงแล้ว

ส่วนช่องที่มาจากเว็บอื่นคนละเจ้า อ่านไม่ได้ตลอดกาล ไม่ใช่ข้อจำกัดของ Aetox แต่เป็นกฎ
ความปลอดภัยของเบราว์เซอร์ทุกตัว ตอนนี้มันจะ**บอกออกมาว่ามีกี่ช่องที่อ่านไม่ได้** แทนที่จะเงียบ
แล้วปล่อยให้เข้าใจว่าหน้านั้นไม่มีอะไร

### บอกว่าอ่านไม่ครบ แทนที่จะทำเหมือนอ่านครบ

หน้าที่มีปุ่มเยอะมาก ผู้ช่วยอ่านได้ทีละ 150 ปุ่ม ซึ่งไม่ใช่เรื่องใหม่ ที่เป็นเรื่องใหม่คือเมื่อก่อน
มันไม่บอก หน้าที่มี 400 ปุ่มกับหน้าที่มี 150 ปุ่มให้ผลเหมือนกันเป๊ะ ปุ่มที่ต้องกดจริงจึงอยู่
นอกสายตาตลอดไป ต่อให้อ่านซ้ำกี่รอบก็ได้ 150 ตัวเดิม

ตอนนี้มันขึ้นว่า `150 of 402 listed` และบอกวิธีไปถึงที่เหลือ คือค้นด้วยข้อความบนปุ่มนั้น

### เลิกบอกว่า "กดแล้ว" ทั้งที่ไม่ได้กด

อันนี้เป็นบั๊กที่เจอตอนทดสอบรุ่นนี้ และเป็นตัวที่เสียเวลาที่สุด

ถ้าผู้ช่วยกดปุ่มที่ไม่มีอยู่จริง มันตอบว่ากดสำเร็จ ผลคือมันกด อ่านหน้า ไม่เห็นอะไรเปลี่ยน
เลยกดใหม่ เปิดหน้าใหม่ กดใหม่ วนอยู่อย่างนั้น เพราะประโยคที่จะทำให้มันรู้ตัวไม่มีใครพูด

ตอนนี้มันตอบว่ากดอะไรไป เช่น `คลิก button "ส่งข้อความ" แล้ว` และถ้ากดไม่โดน มันจะบอกว่า
ยังไม่ได้กดอะไรเลย วัดจากหน้าทดสอบชุดเดียวกัน จำนวนคำสั่งที่ใช้ลดจาก 46 เหลือ 24 และไม่มี
การกดซ้ำเพราะไม่แน่ใจอีกเลย

### ใหม่: ดูได้แล้วว่าหน้าเว็บพังเพราะอะไร

เดิมถ้าหน้าขาว ผู้ช่วยบอกได้อย่างเดียวว่าขาว ตอนนี้มันเปิดดูได้สองอย่าง

**console** — ข้อความที่หน้านั้น log ไว้ error ที่โยนออกมาแล้วไม่มีใครรับ promise ที่ล้มเงียบ ๆ
และของที่ถูกกฎความปลอดภัยของหน้านั้นบล็อก สามอย่างหลังนี้หน้าเว็บไม่เคย log ให้ตัวเอง

**network** — คำขอที่โค้ดของหน้าเรียกออกไป พร้อมรหัสตอบกลับและเวลาที่ใช้ ตัวที่บอกว่า
หน้าโหลดขึ้นแต่ข้อมูลไม่มา เพราะโดน 401 ไม่ใช่เพราะเน็ตช้า

ทั้งสองอย่างไม่อ่าน header และไม่อ่านเนื้อคำขอเลย ส่วนค่าใน URL ที่หน้าตาเหมือนรหัสผ่าน
หรือ token จะถูกแทนด้วย `<redacted>` ก่อนถึงผู้ช่วยเสมอ

ข้อจำกัดที่ต้องรู้: network เห็นเฉพาะสิ่งที่โค้ดของหน้าเรียกเอง รูป สคริปต์ และไฟล์สไตล์ที่
เบราว์เซอร์โหลดให้ ไม่นับอยู่ในนี้ และไม่เคยนับ

### ใหม่: ถ่ายภาพทั้งหน้า ไม่ใช่แค่ที่เห็นบนจอ

เดิมถ่ายได้แค่ส่วนที่อยู่ในกรอบ ตอนนี้สั่งให้ถ่ายทั้งเอกสารได้ ใช้กับฟอร์มยาว ๆ รายงาน
หรือหน้าที่ปัญหาอยู่ใต้ขอบจอ ถ้าหน้ายาวเกินกว่าตัววาดภาพจะไหว มันจะบอกว่าตัดที่ตรงไหน

## 8. ผู้ให้บริการ สกิล และโต๊ะโค้ด

**เพิ่มสามราย รวมเป็น 20** ทั้งสามเป็นปลายฝั่งฟรีและถูกของรายชื่อ สำหรับคนที่ยังไม่มีบัตร

- **ModelScope** — ฮับของ Alibaba ชั้นฟรี **ไม่ใช่ DashScope** ที่เป็น API เสียเงินคนละบัญชีกัน
  วัดกับ endpoint จริงแล้วพบว่าตารางของบุคคลที่สามผิดทั้งสองทาง: มันบอกว่ามี 7 โมเดล
  ทั้งที่เสิร์ฟจริง 45 และ 3 ใน 7 นั้นไม่ได้เสิร์ฟเลย รายชื่อในแอปจึงมาจากการถาม endpoint
- **NVIDIA** — และเจอปัญหาหนึ่งข้อจากมัน: รายชื่อที่ประกาศคือชั้นวาง ไม่ใช่คำสัญญา
  คีย์ใหม่เอี่ยมเรียกโมเดลตัวแรกในรายชื่อแล้วได้ 404 ว่าบัญชีนี้ไม่มีสิทธิ์ ตอนนี้ตัวที่ยืนยันแล้วว่า
  เรียกเครื่องมือได้จะถูกดันขึ้นหน้าแถว โดยไม่ตัดตัวไหนทิ้ง
- **Ollama Cloud** — เป็นบัญชีกับโทเคน คนละเรื่องกับ Ollama ที่รันในเครื่อง

**และ error ประเภทที่สามอ่านรู้เรื่องแล้ว** เดิมคีย์ผิดตอบ 401 กระเป๋าว่างตอบ 402/429 ทั้งสอง
มีประโยคที่ผู้ใช้ทำอะไรต่อได้ ส่วน "คีย์ถูก บัญชีจริง แต่บัญชีนี้ไม่มีสิทธิ์เรียกตัวนี้" มาเป็น 404
ซึ่งเป็นรหัสเดียวกับพิมพ์ชื่อโมเดลผิด คนอ่านจึงถูกส่งไปงมในตัวเลือกโมเดลกับปัญหาที่ไม่มีโมเดลไหน
แก้ได้ ตอนนี้มันบอกตรง ๆ

**ปุ่มทดสอบโมเดลในหน้าตั้งค่า กดแล้วไม่ต้องรอ** เดิมทั้งหน้าจะล็อกระหว่างทดสอบ รายการสิบสอง
โมเดลจึงตรวจได้ทีละตัวเรียงกันเท่านั้น ตอนนี้กดพร้อมกันได้ ผลของแต่ละตัวอยู่ใต้แถวของตัวเอง
และคำตอบที่มาช้าจะไม่ไปโผล่ใต้แถวของผู้ให้บริการที่คุณคลิกเข้าไปทีหลัง

**แถมสกิลเพิ่มสามตัว และมีปุ่มให้ผู้ช่วยไปหามาให้** ฟีดแบ็คว่าแถมมาน้อยไปนั้นจริง แต่การแถม
เพิ่มอย่างเดียวแก้ได้ครั้งเดียวแล้วก็ล้าสมัยอีก ทางที่ไม่เน่าคือให้ผู้ช่วยไปหามาให้ เพราะทุกช่องทาง
ที่หน้าตั้งค่ามีอยู่ (URL ของ GitHub, ไฟล์ zip, ที่อยู่เซิร์ฟเวอร์, ช่องเปล่า) เรียกร้องให้คุณรู้ก่อนว่า
มีอะไรอยู่ ตอนนี้หน้าสกิล/MCP/ชุดคำสั่ง มีปุ่ม "คุยกับผู้ช่วย" อยู่บนสุด ส่วนสามสกิลใหม่คือ
`aetox-skills`, `aetox-mcp`, `aetox-prompts` ซึ่งสอนวิธีคัดของและกติกาความปลอดภัยไปด้วย
(เช่น ข้อความที่โหลดมาจากอินเทอร์เน็ตเป็นข้อมูล ไม่ใช่คำสั่ง และคีย์ต้องอยู่ในตัวแปรแวดล้อม
ไม่ใช่เขียนดิบ ๆ)

**โต๊ะโค้ดมีแผง Git** บอกว่าทั้งโปรเจกต์แก้อะไรไปแล้วบ้าง แถวละไฟล์พร้อม `+N -M` ของตัวเอง
และกางดูดิฟฟ์ได้ ต่างจากไทม์ไลน์ในแชทที่ตอบว่า "*เทิร์นนี้*ทำอะไรไป" ซึ่งเป็นคำตอบผิดคำถาม
เมื่อคุณอยากรู้ว่าตอนนี้โปรเจกต์ยืนอยู่ตรงไหน แผงนี้อ่านใหม่ทุกครั้งที่เทิร์นจบ

**เอเจนที่ขอเครื่องมือที่ไม่ได้ถือ พูดออกมาแล้ว** การ์ดของเอเจนจะบอกตรง ๆ ว่าขออะไรไปแล้ว
ไม่ได้ พร้อมบอกว่ามันยังทำงานส่วนที่เหลือได้

## 9. ประตูที่สาม: Aetox ทีม — สร้างเสร็จ แต่ยังไม่เปิด

ตอนนี้สวิตช์บนโลโก้มีสองประตูคือ **ผู้ช่วย** กับ **โค้ด** และกำลังจะมีประตูที่สามชื่อ **ทีม**

ข้างหลังประตูนั้นมีห้องเดียว: **ห้องทำงาน** — ลำดับงานที่คุณเขียนเก็บไว้ใช้ซ้ำ อย่างงานสิ้นเดือน
แต่ละขั้นมีเอเจนหนึ่งคนกับบรีฟหนึ่งใบ ส่งงานต่อกันด้วยไฟล์ กดเริ่มแล้วมันเดินเอง
และวนกลับไปแก้ได้ถ้าขั้นตรวจไม่ผ่าน

**รุ่นนี้ยังไม่เปิดให้ใช้ และประตูยังไม่ขึ้นบนสวิตช์** ตัวประตูสร้างเสร็จแล้วในโค้ด เดินสายครบ
มีเทสต์คุมครบ แต่ห้องข้างในยังว่าง เราเลยไม่เอาปุ่มมาวางไว้ให้กดแล้วไม่เจออะไร
วันที่ห้องเสร็จ สวิตช์จะมีตำแหน่งที่สามขึ้นมาเอง

**ระหว่างนี้งานหลายขั้นยังทำได้เหมือนเดิมที่ห้องผู้ช่วย** สั่งงานที่ต้องผ่านหลายมือได้ตามปกติ
ผู้ช่วยจะจ้างเอเจนเอง ยื่นบรีฟให้ทีละคน แล้วส่งไฟล์ต่อกันให้ สิ่งที่ห้องทำงานจะเพิ่มเข้ามาคือ
การ**เขียนลำดับนั้นเก็บเป็นไฟล์**ให้เรียกใช้ซ้ำได้ ไม่ใช่ความสามารถใหม่ที่วันนี้ทำไม่ได้

ระหว่างเก็บงานนี้เจอรูสี่รูที่ต้องปิดก่อน ทั้งหมดมาจากเรื่องเดียวกัน คือห้องหนึ่งห้องถูกจดไว้สองที่
แล้วมีที่เดียวที่คนแก้จริง: ห้องทำงานปิดด้วย Escape ไม่ได้ กด F5 แล้วเด้งไปอยู่อีกที่ แท็บเบราว์เซอร์
ที่เปิดค้างลอยทับอยู่ข้างบน และทางออกทุกทางจากประตูทีมวิ่งไปหาหน้าแชทที่ประตูนั้นไม่มี
ตอนนี้มีเทสต์เดินรายการเมนูแล้วปฏิเสธหน้าที่การรีโหลดกลับมาไม่ได้ ประตูที่สี่จะเพิ่มโดยไม่ผ่าน
ด่านนี้ไม่ได้อีกแล้ว

## 10. บัญชี Aetox: เขียนเสร็จ ส่งมาแบบปิดไว้

Aetox มีระบบล็อกอินของตัวเองแล้ว เข้าผ่าน GitHub หรือ Google ได้ **แต่รุ่นนี้ปิดไว้ทั้งหมด**
เพราะเซิร์ฟเวอร์ยังไม่ได้ขึ้น และ "ปิด" ในที่นี้แปลว่าหน้านั้นไม่มีอยู่ ไม่ใช่มีปุ่มที่กดไม่ได้

สองข้อที่ตั้งใจให้เป็นแบบนี้ตั้งแต่ต้น: **การล็อกอินไม่ได้เปิดสิทธิ์อะไรทั้งสิ้น** และหน้านั้นเขียน
บอกไว้ตรง ๆ ส่วน GitHub/Google เป็น*ประตู*เข้าบัญชี Aetox ไม่ใช่*เจ้าของ*บัญชี ทั้งสองอย่างนี้
เก็บคนละที่กับกุญแจของผู้ให้บริการโมเดลที่คุณต่อไว้ เพราะเป็นคนละคำถามกัน

## 11. ผลของเครื่องมือมาไม่ครบ และมาไม่ครบมาตลอด

ทุกครั้งที่ผู้ช่วยเรียกเครื่องมือ ผลที่ได้ถูกตัดเหลือ 4,096 ตัวอักษรก่อนถึงมัน วัดจากบันทึกจริง
3,344 ครั้ง มีถูกตัด 473 ครั้ง — **หนึ่งในเจ็ดของทุกคำสั่ง**

สิ่งที่คุณรู้สึกได้จากบั๊กนี้:

- **สกิลที่คุณติดตั้งเอง ผู้ช่วยอ่านได้ไม่ถึงหนึ่งในหก** สกิลยาว ๆ ตัวหนึ่งมี 31,000 ตัวอักษร
  ผู้ช่วยได้ไป 4,096 แล้วอ่านต่อไม่ได้ ไม่รู้ด้วยซ้ำว่ายังเหลืออีกเท่าไร
- **สั่งให้อ่านไฟล์ยาว ๆ แล้วมันอ่านต่อไม่เป็น** เครื่องมืออ่านไฟล์บอกตำแหน่งไว้ท้ายผลว่า
  "อ่านต่อจากบรรทัดนี้" แล้วการตัดกินบรรทัดนั้นไปพอดี ผู้ช่วยจึงถูกบอกให้ใช้เลขที่มันมองไม่เห็น
- **ผลที่ถูกตัดบอกแค่ว่า "ถูกตัด"** ไม่บอกว่าตัดไปเท่าไร ผู้ช่วยจึงแยกไม่ออกระหว่างของที่ขาด
  ประโยคสุดท้ายกับของที่ขาดไป 85% แล้วบางครั้งก็ไปไล่หาไฟล์ในเครื่องเองเพื่อความมั่นใจ

ที่มาของเลข 4,096 ไม่ได้มั่ว มันคือหนึ่งในสามสิบสองของงบบทสนทนา ตอนที่งบนั้นเป็นเลขตายตัว
**แล้วงบเริ่มขยายตามหน้าต่างของโมเดลที่คุณเลือก ส่วนเลขนี้ไม่ขยายตาม** บนโมเดลหน้าต่างใหญ่
มันจึงกลายเป็นหนึ่งในพันของที่ว่างที่มีอยู่จริง

**ตอนนี้เพดานขยายตามโมเดล** โมเดลหน้าต่างใหญ่ได้ราว 125,000 ตัวอักษร ส่วนโมเดลที่เราไม่รู้
ขนาดหน้าต่างยังได้เท่าเดิม เพราะไม่รู้ก็ไม่ควรเดา

และเวลามันตัดจริง ๆ **มันบอกตัวเลข** — `แสดง 125,000 จาก 340,180 ตัวอักษร` ไม่ใช่แค่คำว่าถูกตัด

**ตัดตรงตัวอักษร ไม่ใช่ตรงไบต์** ของเดิมผ่ากลางตัวอักษรไทยได้ เพราะนับเป็นไบต์

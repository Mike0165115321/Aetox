# 🚀 Aetox v0.9.2 — Where a conversation lives, and what an answer can be

v0.9.1 answered *whose is what*. This one answers two questions that came straight after it:
**where does a conversation belong**, and **what is an answer allowed to be**.

A chat had exactly one home — the flat history list — so a person working on three
different things had three different things in one column. And an answer had exactly one
shape, prose, even though the surface it is drawn on could already draw a picture, lay out
a panel, and work out a number.

Three of the four capabilities in this release were **already working and had never once
fired**, because nothing told the model they existed. That is the thread running through
this version: a capability nobody is told about is a capability that does not exist.

## 1. 📁 Projects — a folder of conversations, not a fence

The room named in §84 and disabled ever since is open. A project groups chats and carries a
few files into every session held inside it, so the assistant starts each one already
knowing the context.

```
<DataRoot>/project/<name>/          the project
<DataRoot>/project/<name>/context/  files every chat in it knows about
```

**It moves no wall.** The assistant still reaches the whole machine exactly as before —
that is what separates this from the workshop door's project, which roots the sandbox in a
folder and where rooting it is the entire point. Two meanings needed two words in code:
`space` for this one, `project_key` for the workshop's. Both are in the glossary now.

**The disk is the only record.** There is no projects table and deliberately never will be:
the folder is the half a user moves, renames and deletes without telling the app, so an
index would show projects that are gone and hide ones that are there. A folder made by hand
in Explorer is a project, and there is a test that says so. The database holds one new
column, `sessions.space` — which project a conversation was *held in*, a fact about the
conversation, on the conversation's own row.

**Context files are named to the assistant, never pasted.** It is told which project it is
in, where the material lives, and what is in that folder — then told to read only what a
question actually needs. Naming costs one line and buys the only thing it was missing:
knowing they are there. Pasting the contents would spend the whole context window on files
most turns never open, on every turn, forever.

Deleting a project folder deletes the project and leaves the chats. Reopening one lands
outside every project rather than refusing — the folder held context to read, never rights
to use.

## 2. 🔢 calc — a number is worked out, not recalled

A wrong sum is the only failure in the whole tool list that never announces itself. It
arrives in the same confident sentence as a right one, and neither side finds out.

`calc` runs a short JavaScript program in an interpreter compiled into the app
([goja](https://github.com/dop251/goja)) — nothing to install, no dependency on what happens
to be on the machine, and **the user sees the script beside the result**, so a mistake
becomes a line of arithmetic somebody can point at instead of a number they had to trust.

**It asks for no permission, and the reason matters:** `require`, `process`, `fetch` and
`fs` are not blocked in it — they were never there. A tool that cannot see a file, open a
socket or start a process is not asking for a right, and putting it behind the same gate as
`shell` would say the gate is decoration.

Short arithmetic stays the model's own — a round trip to prove 20% of 500 is ceremony. The
threshold for reaching for the tool is written as something *countable* (digits carried,
steps that feed the next one, a repetition down a list, a figure someone will act on) and
never as "when it feels hard": difficulty is the one thing a model cannot judge about its
own arithmetic.

Numbers that live in a file, more of them than anyone would type, or work needing a real
library — that is still `write` plus `shell`, which is the machine's gate and should be the
one asked.

## 3. 🎨 A drawing stays inside its own box

A chart came back correct on top and blank underneath. The blank space was not a bug in the
drawing — it was a hole the renderer cut in it. The legend was laid out in `<foreignObject>`,
which the sanitizer removes along with everything inside it, while the `viewBox` still
reserved the space. A correct picture with its bottom half deleted, and no error anywhere.

Probing the rest of the surface found the same silence in four more places:

- **Markdown read the picture as prose.** A blank line ends an HTML block, so the
  four-space indent anyone pretty-prints XML with turned the rest of the shapes into a code
  block beside the drawing; and `*` around a label became `<em>`, lifted out of the picture.
  A complete drawing in the left margin is now lifted out before the parser sees it and put
  back after — the same treatment a fenced block already gets. One written inside backticks
  is being *discussed* rather than drawn, and still shows as source.
- **`<style>` inside an `<svg>` is not scoped.** It is a document stylesheet, so
  `.row{display:none}` aimed at a legend hid the sidebar. Selectors are now prefixed with a
  fingerprint of the drawing itself.
- **Ids are document-wide.** `url(#g)` resolves to the first match on the page, and `g` is
  what a model names a gradient — so the second drawing in a conversation wore the first
  one's colours. Every id is namespaced by the same fingerprint.
- **`@import` fetches from the network** on the strength of model output. Dropped.

A drawing with neither a stylesheet nor an id — which is most of them — comes out of the
renderer byte for byte as it went in.

The half the model *can* be told, it is now told: the surface is a sanitizer, not a browser;
these three tags vanish without a word; write one block at the left margin with no blank
line in it.

## 4. 🧩 Panels — an answer can lay things out

The third capability found already working and never used. The chat renders answers inside
the app's own document, so a `<div>` with a style attribute lays out normally and
`var(--surface-panel)` inside it resolves against the theme the user is actually running.

A panel written that way is not styled to *look like* Aetox — it **is** Aetox's surface, on
all fourteen themes, including ones written after it.

Kept separate from drawings on purpose: a drawing is for how several things relate, a panel
is for several things of the same kind each carrying the same few facts. Merged, the
instruction would become "make something visual", which is the instruction that produces
decoration.

## 5. 👥 The agent roster is a face, not an inventory

Every agent card carried six tool chips, and five of the six were identical on every card —
the team ceiling hands everyone the same set. Half the card was spent saying nothing about
who anyone is.

What is left is what a card is for: **who this is, what they make, and whether they have
done any of it.** The tools are one click away in the editor, which is also the only place
they can be changed.

- **Every agent has a face.** A profile can name an `icon:`; one that does not gets a mark
  derived from what the agent actually produces. Resolved once in Go, so one agent cannot
  wear two faces on two pages.
- **A picker, not a text field** — the value comes from a fixed set, and a field where a
  typo silently means "no icon" is a field that fails without saying so.
- **The job feed is readable.** It used to print the tool call's raw arguments — the
  machine's copy, shown to the person it was never written for. It now shows the brief the
  caller wrote, with the raw record still on hover.
- **Search on the settings roster**, drawn once there are more than six.

## 6. 💬 Chat that does not lose what you typed

Four symptoms, one root: text a person had typed but not yet had answered was treated as
something that did not exist yet.

- **The question is stored before the answer.** It used to be written together with the
  reply in one transaction at the end of the turn — so a window reloaded while the
  assistant was still working lost the message that started it, and the session row with
  it. The conversation you were looking at a second ago simply did not exist. The pair is
  no longer atomic, and that is the point: a question with no answer under it is an honest
  record; a conversation that vanishes is not.
- **A draft survives a reload.** Half-typed text is the one thing in the app that exists
  nowhere else. It is now kept per session, so it comes back to the chat it was written in
  and never turns up in someone else's.
- **Send works while the agent is running.** Typing into a running turn was already
  supported by the engine; the composer's only button was Stop, so the one gesture a person
  makes after typing threw the work away. With a draft on screen the primary button sends
  again, and the brake stays beside it.
- **An interjected message is drawn where it happened** — below what has already streamed,
  not above it.

## 7. 📖 Aetox knows what Aetox is made of

The system prompt did not contain the word `DataRoot` even once. The assistant did not know
what it is built from or where anything it owns is kept — so it guessed about its own
system, searched the web for things that were on the machine, and reported skills as
installed when they were not.

A bundled `aetox` skill now answers that, practically: where the data root is and what
overrides it · where skills live and the four ways to install one · where agents, helpers
and desks are kept · where chat history and produced files go · how MCP is configured **and
the fact that no tool exists for the assistant to add a server itself** · and which folders
its own file tools always refuse — including the one that trips it up most, that the skills
folder is inside a refused credential store and has to be read through `skills_list`.

Shipped as a skill rather than as prompt text on purpose: **a skill costs nothing until
something opens it**, while a paragraph in the system prompt is paid by every session on
every request. The tool block did not grow by a single token, and a test says so.

Its paths are checked against the real constants in code, so the day one of them moves, the
document goes red instead of going quietly stale.

## 8. 🧹 Smaller things

- `plugin_install`'s description claimed a repository must define `aetox-plugin.json`.
  It never had to — a repository with no manifest is the ordinary case and installs fine —
  so the assistant refused repositories this tool handles happily and reported the skill
  could not be had.
- The grid background behind an empty chat is gone. It read as a table drawn over the
  screen rather than as a backdrop.
- The prompt now says that the output folder is something only the *file tools* know about:
  a script writes wherever its own text says, so a hardcoded path split the script and its
  results across two folders.
- The desktop's provider allowlist records what is deliberately *not* on it, with reasons —
  a missing name was previously indistinguishable from a decision.

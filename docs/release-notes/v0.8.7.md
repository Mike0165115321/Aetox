# 🚀 Aetox v0.8.7

รุ่นแก้บั๊กล้วน ไม่มีฟีเจอร์ใหม่

> **ถ้าคุณกดปุ่ม "ตอบใหม่" บน v0.8.6 ไปแล้ว รุ่นนี้ซ่อมฐานข้อมูลให้อัตโนมัติตอนอัปเกรด**

## 1. ⚠️ กด "ตอบใหม่" ครั้งเดียวทำฐานข้อมูลเสียหาย (ของใหม่ใน v0.8.6)

v0.8.6 เป็นรุ่นแรกที่แก้ไขข้อความเดิมในฐานข้อมูล คือตอนที่ผู้ใช้ขอคำตอบใหม่ แต่ตารางค้นหาข้อความ
ของ SQLite ไม่ได้อัปเดตตัวเองตามการแก้ไข มันมีตัวคอยตามให้เฉพาะตอนเพิ่มและตอนลบเท่านั้น

ผลไม่ใช่แค่ค้นหาแล้วเจอผลเก่า แต่ **การลบที่พยายามปรับให้ตรงกันทีหลัง ทำให้ SQLite รายงานทั้งไฟล์
ว่าเสียหาย** การเปลี่ยนแปลงจึงถูกย้อนกลับ และเซสชันนั้นลบไม่ได้ถาวร พร้อมกับบันทึกที่มีเนื้อไฟล์
และข้อความจากหน้าเว็บที่ดึงมาค้างอยู่ ตรงจุดที่โค้ดสัญญาว่าจะลบพอดี

การอัปเกรดครั้งนี้เพิ่มตัวคอยตามสำหรับการแก้ไข และใส่ให้ตารางค้นหาอีกตัวไปด้วยแบบดักไว้ก่อน
เพราะวันนี้ยังไม่มีใครแก้ไขตารางนั้น และต้นทุนของตัวคอยตามที่ไม่เคยทำงานเท่ากับศูนย์ เทียบกับ
การเจอเรื่องเดียวกันอีกรอบในวันที่มีคนเพิ่มโค้ด การอัปเกรดเดียวกันนี้ยัง **สร้างดัชนีค้นหาใหม่ทั้งสอง
ตัว** เพราะคนที่กดปุ่มไปแล้วมีดัชนีเสียซึ่งไม่หายเอง

ครึ่งหลังของความผิดพลาดเดียวกัน คือการสลับดูคำตอบเวอร์ชันอื่นย้ายแต่ตัวข้อความ แต่ทิ้งประวัติ
การทำงานไว้ที่เดิม สลับคำตอบแล้วจึงเห็นคำตอบหนึ่งอยู่เหนือขั้นตอนของอีกคำตอบ ตอนนี้แต่ละ
เวอร์ชันถือประวัติของตัวเอง

เทสต์เดิมตรวจตัวข้อความกับรายการเวอร์ชัน แต่ไม่เคยแตะตารางค้นหาเลย นั่นคือเหตุผลที่บั๊กนี้หลุด
ออกไป เทสต์ตัวใหม่จะล้มพร้อมข้อความว่าฐานข้อมูลเสียหาย ถ้าไม่มีตัวแก้

## 2. CI ที่แดงมา 21 รอบ ไม่เคยเป็นปัญหาการแย่งข้อมูลเลย

ทุกคนอ่านมันเป็นปัญหาการแย่งข้อมูลระหว่างเธรด รวมถึงเอกสารสถาปัตยกรรมด้วย **ซึ่งไม่ใช่**

ต้นเหตุจริงคือเทสต์ตัวหนึ่งสร้างไฟล์ทดสอบด้วยการคอมไพล์ *หลังจาก* ที่มันย้ายโฟลเดอร์บ้านไปยัง
โฟลเดอร์ชั่วคราวของเทสต์แล้ว ตัวคอมไพเลอร์จึงไปสร้างแคชไว้ในนั้นด้วยสิทธิ์อ่านอย่างเดียว ซึ่งเป็น
สิ่งที่ Go ตั้งใจ และเป็นสิ่งที่ระบบเทสต์ลบไม่ได้ ส่วน Windows ไม่เคยเห็นปัญหานี้ เพราะมันลบ
โฟลเดอร์อ่านอย่างเดียวได้สบาย

**สามอย่างตามมาจากการที่มันไม่ใช่ปัญหาการแย่งข้อมูล:** ตัวตรวจจับรันสะอาดมา 21 รอบและไม่มีใคร
มองเห็น · Ubuntu เป็นงานเดียวที่รันมัน ดังนั้นปัญหาจริงที่ลงพรุ่งนี้จะแยกไม่ออกจากอันนี้ · และ
สคริปต์ตรวจบนเครื่องเจ้าของ **ข้าม** ขั้นตอนนั้นไปทั้งหมด ขณะที่เอกสารยืนยันว่าช่องว่างนั้นปิดไปแล้ว

ตอนนี้ระบุตำแหน่งแคชไว้ชัดเจน และเร็วขึ้นด้วย จาก **14.0 วินาที เหลือ 2.1 วินาที** เพราะไม่ต้อง
โหลดรายการไลบรารีใหม่ทุกรอบ ส่วนขั้นตอนที่ถูกข้ามในสคริปต์ตรวจ **ส่งเสียงแล้ว** และเอกสารก็
พูดสิ่งที่เป็นจริง

macOS พังด้วยเหตุผลของตัวเองคนละเรื่อง คือขั้นตอนบิลด์ฝั่งหน้าจอตายเพราะหน่วยความจำไม่พอ
งานฝั่ง Unix ไม่เคยต้องการไฟล์บิลด์จริงอยู่แล้ว จึงเขียนไฟล์เปล่าแทน ซึ่งตัดการบิลด์ซ้ำซ้อนออกไป
สองครั้งต่อการ push

## 3. ให้กระบวนการปล่อยรุ่นล้มได้จริง

- **กระบวนการปล่อยรุ่นเคยรันเทสต์แค่แพ็กเกจเดียว** และไม่ผูกกับ CI เลย นั่นคือเหตุผลที่ v0.8.6
  ถูกปล่อยจากคอมมิตที่ CI แดง ตอนนี้รันเทสต์ทั้งหมดก่อนแพ็ก โดยวางไว้ *หลัง* ขั้นตอนบิลด์ เพราะ
  นั่นคือขั้นตอนที่สร้างไฟล์ที่โค้ดต้องการ
- อัปเดตเครื่องมือของ CI ทุกตัวที่ยังเล็งไปที่ Node เวอร์ชันที่เลิกสนับสนุนแล้ว
- CI ได้ระบบยกเลิกงานซ้ำและเวลาจำกัดต่องาน แต่ **จงใจไม่ใส่ให้กระบวนการปล่อยรุ่น** เพราะการ
  ยกเลิกการปล่อยของกลางคันแย่กว่าจ่ายค่ารันที่ถูกแทนที่

## 4. PDF ที่แนบไปไม่เคยถึงโมเดล

ฟังก์ชันหนึ่งสร้างข้อความใหม่ทีละฟิลด์ และคอมเมนต์ของมันเองเขียนเตือนไว้แล้วว่าวิธีนี้แลกกับอะไร
คือมันจะทิ้งทุกฟิลด์ที่ไม่ได้ระบุชื่อ และรูปที่แนบมาแล้วหายไปเงียบ ๆ ระหว่างช่องพิมพ์กับผู้ให้บริการ
คือบั๊กที่ไม่มีอาการให้เห็น

ฟิลด์เอกสารแนบถูกเพิ่มเข้ามาหลังคอมเมนต์นั้น **และตกลงไปในกับดักที่คอมเมนต์บรรยายไว้พอดี**
คือมีคนวางเอกสารไว้บนข้อความ แล้วฟังก์ชันนี้โยนทิ้งในการเรียกถัดมา ไม่มีผู้ให้บริการรายไหนได้รับ
เลยสักราย โมเดลจึงตอบจากชื่อไฟล์กับบริบทรอบข้าง ซึ่งเนียนพอที่จะไม่มีใครรายงาน

แก้แล้ว พร้อมเทสต์สองตัว ตัวหนึ่งสำหรับไฟล์แนบเอง อีกตัวเดินตรวจทุกฟิลด์ของข้อความโดยอัตโนมัติ
และจะล้มในวันที่มีฟิลด์ใหม่ถูกทิ้ง เพราะเทสต์แบบระบุฟิลด์เองจะผ่านในวันที่เขียนแล้วเงียบตลอดกาล
ซึ่งคือวิธีที่บั๊กนี้หลุดมา

## 5. การตรวจเส้นทางไฟล์เร็วขึ้น

ตัวตรวจเส้นทางเดินตามลิงก์ของระบบไฟล์สองรอบต่อการเรียกหนึ่งครั้ง และโน้ตเหนือมันเขียนไว้ตั้งแต่
ตอนแก้เรื่องนี้แล้วว่าให้แคชฝั่งโฟลเดอร์ตั้งต้นได้ พอวัดจริงก็พบว่าทั้งสองฝั่งจ่ายเต็มราคาทุกครั้ง

โฟลเดอร์ตั้งต้นแคชได้เพราะ **ค่าเก่าทำให้ผลลัพธ์เป็นการปฏิเสธ ไม่ใช่การอนุญาต** ถ้าโครงสร้าง
เปลี่ยนหลังแคชอุ่นแล้ว เป้าหมายจะถูกปฏิเสธ ส่วนฝั่งเป้าหมายยังตรวจสดทุกครั้ง

แต่สิ่งที่ได้มากกว่าคือการค้นพบว่า **แปดจุดที่เรียกมันส่งค่าว่า "โฟลเดอร์ปัจจุบัน"** แล้วจ่ายค่าเดิน
ตามลิงก์สองรอบเพื่อตอบว่าโฟลเดอร์ตั้งต้นอยู่ในโฟลเดอร์ตั้งต้น ซึ่งเป็นข้อความเดียวกันเป๊ะ ไม่มี
คำถามอะไรให้ถามระบบไฟล์เลย

```
ตรวจไฟล์ในโฟลเดอร์ย่อย   2.51ms → 1.32ms
ตรวจโฟลเดอร์ปัจจุบัน       2.51ms → 1.6µs
```

ตัวเลขนี้วัดบน Windows ที่ Defender สแกนทุกส่วนของเส้นทางที่เปิด ซึ่งเป็นเหตุผลที่มันคุ้มค่าวัด
ตั้งแต่แรก และเทสต์ความปลอดภัยผ่านครบ

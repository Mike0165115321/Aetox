## 1. ⚠️ โฟลเดอร์ที่เจาะจงไว้ เคยเปิดทางให้อ่านกุญแจข้างใน

นี่คือบั๊กที่ร้ายแรงที่สุดในรุ่นนี้ และเป็นบั๊กที่ไม่ต้องใช้ความพยายามอะไรเลยในการชน

ตัวตรวจเส้นทางจะปล่อยผ่านทันทีที่เห็นว่าไฟล์อยู่ในโฟลเดอร์โปรเจกต์ ส่วนตัวกันไฟล์รหัสผ่านถูกวาง
ไว้เฝ้าเฉพาะเส้นทางที่ *ออกนอก* โฟลเดอร์นั้น การอ่านแบบนี้ถูกต้องกับไฟล์ซอร์สโค้ด แต่ไม่ถูกกับ
`~/.ssh` และสองอย่างนี้มาด้วยกัน เพราะการเจาะจงโฟลเดอร์บ้านของตัวเองไม่ใช่การตั้งค่าแปลก ๆ
มันคือสิ่งที่โต๊ะผู้ช่วยมีไว้เพื่อทำ

พูดตรง ๆ คือ เจาะจง `C:\Users\<ชื่อ>` เป็นโปรเจกต์ แล้วขอไฟล์ `.ssh/id_rsa` ตรง ๆ คุณจะได้ไฟล์นั้น
โดยไม่ต้องใช้ลูกเล่นอะไรเลย

เทสต์เดิมสามตัวมองไม่เห็น เพราะทั้งสามตัวขยายขอบเขตจากข้างนอกเข้ามา ทุกตัวจึงไปตกอยู่บนเส้นทาง
ที่มีด่านเฝ้าอยู่แล้ว เทสต์ตัวใหม่ยืนอยู่ตรงช่องว่างระหว่างสามตัวนั้น

## 2. โหมดทำงาน: โต๊ะบอกว่ามีเครื่องมืออะไร โหมดบอกว่ารอบนี้ทำงานยังไง

เดิมสองเรื่องนี้ถูกเรียกด้วยคำเดียวกัน **โต๊ะตอบว่ามีอะไรวางอยู่บนโต๊ะ** และคงที่ทั้งเซสชัน ส่วน
**โหมดตอบว่ารอบนี้ทำงานยังไง** และสลับได้ทุกเมื่อ

มีสามโหมด:

- **ลงมือ** ค่าเริ่มต้น ไม่เปลี่ยนอะไร
- **วางแผน** ดูได้ทุกอย่าง แก้ไม่ได้เลย ใช้รายการอนุญาตแทนรายการห้าม เครื่องมือที่เพิ่มเข้ามา
  เดือนหน้าจึงถูกกันไว้ก่อนโดยอัตโนมัติ แทนที่จะหลุดเข้ามาโดยไม่มีใครสังเกต
- **คู่คิด** ไม่ส่งคำอธิบายเครื่องมือไปเลยสักตัว

กฎที่ทำให้สองแกนนี้อยู่ด้วยกันได้ และเป็นเหตุผลเดียวที่สลับกลางคันแล้วปลอดภัย คือ **โหมดหักออก
จากโต๊ะได้ แต่เพิ่มเข้าไปไม่ได้**

วัดบนโต๊ะผู้ช่วย: จาก 34 เครื่องมือ ~8,023 โทเคน บวกพรอมป์ ~2,860 เหลือ 0 กับ ~1,562
**ประหยัดได้ ~9,321 โทเคนต่อคำขอ (86%)** และหนึ่งในสามของที่ประหยัดไม่ได้มาจากรายการเครื่องมือ
เลย แต่มาจากการตัดคำสอนเรื่องวิธีใช้เครื่องมือออกไปเจ็ดชั้น

มีโหมดที่สี่ที่ออกแบบจนเสร็จแล้วถูกตัดทิ้ง เพราะเจ้าของทักก่อนว่า *"ปกติมันก็ทำแบบนั้นอยู่แล้ว"*

## 3. งานที่มอบให้คนอื่น ไม่จบพร้อมประโยคที่สั่งมัน

ผู้ช่วยที่รับงานไปมีความจำของตัวเองแล้ว แทนที่จะยืมของรอบนั้น พอรอบจบ งานยังเดินต่อ คุณมาเก็บ
ผลด้วยรหัสเดิมในรอบถัดไป และคำถามที่มันหยุดถามก็ยังอยู่ข้ามข้อความด้วย

กฎเดิมที่ว่า "งานมีอายุเท่ารอบสนทนา" ไม่เคยเป็นกฎเรื่องอายุ มันคือเส้นตายที่ไม่มีใครตกลงด้วย
คืออ่านไปสิบนาทีแล้วถูกทิ้งเพราะคำตอบที่สั่งมันเขียนจบไปแล้ว เหตุผลค้านเรื่องนี้ถูกเขียนไว้ในโปรเจกต์
นี้อยู่แล้วที่คำสั่งรันเบื้องหลัง: ของที่ตายพร้อมคำตอบที่สร้างมันไม่เคยเป็นงานเบื้องหลังตั้งแต่ต้น
เหตุการณ์เดียวที่จบงานได้ก่อนเวลาคือผู้ใช้กดหยุด

**การ์ดในแชทมาแทนแถบสถานะ** แถบที่ถูกต้องแต่ไม่ขยับอ่านเหมือนงานตายแล้ว ส่วนตัวเลขที่วิ่งทุก
ไม่กี่วินาทีก็ตอบไม่ได้ว่า *ยังมีชีวิตอยู่ไหม* ขณะที่รายชื่อไฟล์ที่ไหลผ่านตอบได้ งานที่เสร็จแล้วจะเก็บ
ผลของตัวเอง คุณไม่ต้องกดอะไร

และ **แถวปุ่มใต้คำตอบ (คัดลอก / ชอบไม่ชอบ / ขอใหม่) เลิกซ่อนจนกว่าจะเอาเมาส์ไปชี้** ปุ่มที่ไม่มีใคร
เห็นคือปุ่มที่ไม่มีใครกด และสองในสามปุ่มนั้นคืออาหารเพียงอย่างเดียวของระบบเรียนรู้

## 4. แอปบอกได้แล้วว่ามีรุ่นใหม่ออก

ตัวอัปเดตทำงานได้ครบมาตั้งแต่ v0.9.4 ทั้งดาวน์โหลด ตรวจลายเซ็น ตรวจแฮช เปลี่ยนชื่อไฟล์เก่า
แล้วรีสตาร์ตเข้ารุ่นใหม่ แต่มันอยู่หลังปุ่มในหน้า ตั้งค่า → เกี่ยวกับ ที่ไม่มีอะไรพาคุณไปถึงเลย
ความสามารถมีครบแต่ไปไม่ถึง และการที่เจ้าของโปรเจกต์เองยังต้องลงใหม่ด้วยมือ *คือ* ข้อค้นพบ

- **การตรวจทำเอง และเงียบ** ตรวจครั้งแรก 20 วินาทีหลังเปิดโปรแกรม แล้วตรวจวันละครั้ง การ
  ตรวจอัตโนมัติที่ล้มเหลวจะไม่ขึ้นอะไรบนหน้าจอเลย ทั้งเน็ตไม่มี โดนจำกัดจำนวนครั้ง หรือติดพร็อกซี
  แถบแดงที่บอกว่าต่อ GitHub ไม่ได้ บนแอปที่คุณกำลังใช้อยู่ดี ๆ คือการตอบคำถามที่ไม่มีใครถาม
  และทำให้แอปที่ทำงานปกติดูเหมือนพัง ส่วนปุ่มที่คุณกดเองยังรายงานความล้มเหลวของมันตามเดิม
- **มันไม่ดาวน์โหลดอะไรเอง** ข้อความแจ้งแค่เสนอ คุณเป็นคนตัดสิน
- **ปิดได้ด้วยตัวแปร `AETOX_DISABLE_UPDATE_CHECK`** และปิดตั้งแต่ก่อนรอบแรก
- **ข้อความแจ้งกับปุ่มในหน้าเกี่ยวกับ ใช้สถานะเดียวกัน** จึงพูดไม่ตรงกันไม่ได้
- **กล่องข้อความบอกสองอย่างที่เปอร์เซ็นต์บอกไม่ได้** คือแอปจะปิดแล้วเปิดกลับมาเอง โดยบอก
  *ก่อน* ที่จะเกิด และถ้าล้มเหลว จะบอกว่ารุ่นที่คุณมีอยู่ยังอยู่ครบ ซึ่งเป็นสิ่งที่ระบบลายเซ็นมีไว้เพื่อ
  การณ์นี้ ดาวน์โหลดที่ถูกปฏิเสธคือระบบทำงาน

คนที่ติดตั้งผ่าน Scoop จะถูกบอกให้รัน `scoop update aetox` แทนการกดปุ่ม เพราะโฟลเดอร์นั้นไม่ใช่
ของเราที่จะไปเขียน ส่วน macOS กับ Linux ยังไม่มีเส้นทางอัปเดตอัตโนมัติเลย

## 5. สรุปห้อง: ห้องนี้ถืออะไรอยู่ โดยไม่ต้องเลื่อนกลับไปหา

ห้องแชทที่นี่เป็นห้องทำงาน ไม่ใช่บทสนทนา พอมีประวัติเครื่องมือสิบหน้า ของที่ยังใช้อยู่ก็จมไปด้วย
ปุ่มมุมขวาบนเปิดแผงที่ตอบสามคำถามโดยไม่ต้องเลื่อน: **วางแผนอะไรไว้** · **ห้องนี้อ่านอะไรไปแล้ว**
· **ตอนนี้โปรเจกต์อยู่ในสถานะไหน**

ทั้งสามอย่างเป็นการอ่านซ้ำจากของที่มีอยู่แล้ว ไม่มีอะไรเป็นสำเนาที่สอง เพราะที่ที่สองที่ตอบคำถาม
เดียวกันจะเก่าทันทีที่คุณย้ายไฟล์ แล้วมันจะโกหกคุณเรื่องเครื่องของคุณเอง

**อายุของแผนเปลี่ยนไป และนั่นคือหัวใจของเรื่องนี้** เดิมรายการงานถูกล้างทั้งตอนเริ่มและตอนจบทุก
รอบ ซึ่งถูกต้องตอนที่มันถูกวาดอยู่ในบล็อกของรอบนั้น แต่ภายใต้แผงถาวร แถวเดิมพูดคนละเรื่อง คือ
*นี่คือแผนล่าสุดของห้องนี้ และยังไม่มีอะไรมาแทน* แผนที่หายไปพร้อมรอบที่เขียนมันคือแผนที่ไม่มีใคร
ทำงานตามได้ ซึ่งเป็นเหตุผลทั้งหมดที่การวางแผนมีอยู่

แต่การเอาการล้างออกเฉย ๆ ทำให้แผนไม่มีวันหายไป (เจ้าของชนเรื่องนี้ด้วยตัวเอง) จึงแยกเป็นสองทาง
**แผนที่ทำครบทุกข้อคือใบเสร็จ ไม่ใช่งาน** มันไปในรอบถัดไป ส่วน **แผนที่ถูกทิ้งกลางทางจะมีปุ่มให้กด**
เพราะคนเดียวที่รู้ว่ามันถูกทิ้งคือคนที่ทิ้งมัน งานที่ยังเดินอยู่ไม่หายไปไหน

ตัวเลขบนปุ่มนับ **จำนวนที่เหลือ ไม่ใช่จำนวนที่ทำแล้ว** ปุ่มขนาด 30px มีที่ให้เลขเดียว และระหว่าง
สองอย่าง ตัวที่เปลี่ยนสิ่งที่คุณจะทำต่อคือจำนวนที่เหลือ (เดิมเขียนว่า "1/3" ซึ่งกว้าง 20px บนปุ่ม
30px คือทับไอคอนแล้วล้นไปหาปุ่มข้าง ๆ)

## 6. กุญแจที่แอปถืออยู่แล้ว ไม่ควรต้องพิมพ์ลงไฟล์ตั้งค่าอีกรอบ

มีรายงานว่าเซิร์ฟเวอร์ MCP ของ GitHub ต่อไม่ติด ขึ้นว่า `Bad Request` ในไฟล์ตั้งค่ามีบรรทัด
`"Authorization": "Bearer"` คือมีชื่อรูปแบบแต่ไม่มีโทเคนตามหลัง ยิงไปที่ปลายทางจริงได้สองสถานะ
ต่างกัน ไม่ใส่เฮดเดอร์เลยได้ 401 พร้อมข้อความบอกว่าขาดอะไร ส่วนใส่ `Bearer ` เปล่า ๆ ได้ 400
สองรหัสนี้คือหลักฐานว่าเฮดเดอร์ไม่ครบ ไม่ใช่ไม่มี

แบบฟอร์มเติมคำว่า `Bearer ` ไว้ให้ล่วงหน้าเพื่อรอให้วางโทเคนต่อท้าย แล้วก็ปล่อยให้กดบันทึกแบบ
นั้นได้เลย ตอนนี้การบันทึกจะไม่ผ่านถ้าค่าว่างหรือมีแต่ชื่อรูปแบบ

แต่คำถามที่ดีกว่าคือ ทำไมต้องพิมพ์ตั้งแต่แรก Aetox ถือโทเคน GitHub ของคุณอยู่แล้วจากหน้า
การเชื่อมต่อ การให้คุณวางอีกรอบเท่ากับก๊อปความลับที่เก็บไว้ดีแล้วออกมาเป็นข้อความเปล่าในไฟล์
ตั้งค่า และเหลือสองที่ให้ต้องไปเปลี่ยนตอนหมุนกุญแจ

**ตอนนี้ใช้ `${connect:id}` ได้แล้ว** ค่าตั้งต้นของ GitHub คือ `Bearer ${connect:github}` กดปุ่ม
เดียว ไม่ต้องกรอกฟอร์ม และมัน **จงใจไม่ตกไปหาตัวแปรสภาพแวดล้อม** เพราะสองอย่างนั้นเป็นคนละ
คำขอ ถ้าอันแรกแอบไปตอบด้วยตัวแปรที่ตั้งไว้เมื่อหลายเดือนก่อน นั่นคือแอปเดาเอาว่าคุณหมายถึง
ความลับตัวไหน

เพิ่มค่าตั้งต้นอีกห้าตัวที่ทดสอบแล้วว่าต่อได้โดยไม่ต้องล็อกอิน คือ `context7`, `deepwiki`, `exa`,
`huggingface` และ `cloudflare-docs` ส่วน Notion / Linear / Sentry / Atlassian เป็นเซิร์ฟเวอร์จริง
แต่ต้องล็อกอินแบบ OAuth ซึ่งยังไม่ทำ *(สี่ตัวนั้นตอบ 403 ตอนทดสอบครั้งแรกและเกือบถูกบันทึกว่า
"ต้องล็อกอิน" ทั้งที่ความจริงคือ Cloudflare บล็อกตัวทดสอบเอง การตรวจที่ล้มเหลวด้วยเหตุผลของ
ตัวเองได้ ต้องอ่านผลสองรอบ)*

## 7. หน้าไฟล์ผลงานเคยแสดงไฟล์ที่ *เก่าที่สุด* ใต้หัวข้อที่บอกว่าใหม่สุดก่อน

เพดานจำนวนไฟล์ถูกใช้สามที่ และ **ทั้งสามที่อยู่ก่อนการเรียงลำดับ** ส่วนชื่อโฟลเดอร์เซสชันคือเวลา
การไล่อ่านจึงเดินจากเก่าไปใหม่ พอเกิน 500 ไฟล์ หน้านี้จะเดินจากไฟล์เก่าสุด หยุดที่ 500 แล้วค่อย
เรียงใหม่สุดก่อน ผลคืองานของวันนี้จะไม่โผล่มาเลย เครื่องของเจ้าของมี 74 ไฟล์ มันจึงยังไม่เกิด
มันแค่รออยู่

ตอนนี้ไม่มีอะไรหยุดกลางทาง อ่านครบทุกที่ → เรียง → **ตัดด้วยช่วงเวลา** → เพดานเป็นตาข่ายท้ายสุด
ค่าเริ่มต้นคือสัปดาห์นี้ ใช้เส้นแบ่งชุดเดียวกับหัวข้อกลุ่มวัน คือไม่เกิน 7 วันและไม่เกิน 30 วัน
หัวข้อกับตัวกรองจึงพูดไม่ตรงกันไม่ได้ และ **ถ้าสัปดาห์นี้ว่าง มันจะขยายเอง** เป็นเดือน แล้วเป็น
ทั้งหมด พร้อมบอกว่าช่วงไหนเป็นคนตอบ เพราะปุ่มที่เขียนว่า "สัปดาห์นี้" เหนือไฟล์ของทั้งเดือนคือ
ปุ่มที่โกหก

ความหมายของเพดานเปลี่ยนจาก *ถูกทิ้ง* เป็น *ยังไม่ถูกวาด* ข้อมูลมาครบ วาดทีละ 60 การ์ด และปุ่ม
บอกจำนวนที่เหลือ ไฟล์ที่หน้าไม่เคยส่งมาคือไฟล์ที่คุณหาไม่เจอ ส่วนไฟล์ที่ส่งมาแล้วแต่ยังไม่วาดคือ
ข้อมูลแค่แถวเดียว สองอย่างนี้ราคาไม่เท่ากัน แต่เดิมมีตัวเลขเดียวตัดสินทั้งคู่

ตัวอย่างที่แสดงไปแล้วจะถูกคืนหน่วยความจำเมื่อเลื่อนพ้นจอด้วย และเก็บค้างไว้พร้อมกันมากสุด 90 ชิ้น
เพราะเดิมไฟล์ `.html` ที่เปิดเป็นหน้าเว็บจริง กับรูปที่ฝังมาเป็นข้อมูลในหน้า สะสมไปเรื่อย ๆ โดยไม่มี
อะไรปล่อยเลย

เพดานขนาดของหน้าเว็บก็ถูกแยกออกจากเพดานของข้อความ เพราะตัวเลขเดียวคุมของสองอย่างที่ขนาด
ปกติไม่เท่ากัน หน้าแลนดิ้ง 22 KB แสดงเป็นหน้าเว็บได้ ส่วนอีกหน้าที่ 49 KB กลายเป็นกำแพงโค้ด
โดยไม่มีอะไรบนจอบอกว่าเป็นเรื่องขนาด

## 8. กรอบกับการ์ด: โซนที่แยกกันจริง ๆ

เจ้าของวางภาพอ้างอิงลงแล้วบอกว่าของเราอ่านเหมือนแผ่นเดียว มันเป็นแบบนั้นจริง เพราะแถบบน
แถบข้าง และแผงขวา ใช้สีเดียวกัน ส่วนเนื้อหาใช้อีกสีที่ต่างกันแค่ 4 หน่วยจาก 255 และแถบบนไม่มี
เส้นขอบล่างเลย

ตอนนี้เป็นกรอบกับการ์ด คือส่วนควบคุมทั้งหมดอยู่บนสีหนึ่ง เนื้อหาเป็นการ์ดบนอีกสีหนึ่ง มีมุมโค้ง
ครบสี่มุม มีเส้นขอบของตัวเอง และมีระยะห่างเท่ากัน 6px ทุกด้าน ใช้ตัวแปรสีของธีม ไม่ใช่สีที่หยิบมา
เอง เพราะการใส่สีตรง ๆ จะแก้ได้ธีมเดียวและทิ้งอีกสิบเอ็ดธีมไว้ที่เดิม

เมนูตัวหนึ่งเคยมีเงาไม่เหมือนเมนูอื่นทั้งแอป เพราะค่าเงาถูกเขียนตรง ๆ ซ้ำหกที่ แล้วที่เจ็ดไปเรียก
ตัวแปรเงาที่ไม่มีธีมไหนประกาศไว้ จึงตกไปใช้ค่าสำรองที่พิมพ์จากความจำ คือ 34px/.38 แทนที่จะเป็น
32px/.4 ตอนนี้มีตัวแปร `--shadow-menu` ตัวเดียวให้ทุกที่ใช้ร่วมกัน เทสต์ที่ห้ามเรียกตัวแปรที่ไม่มี
ธีมไหนประกาศมีอยู่ก่อนแล้ว แต่ข้ามเคสนี้ไป เพราะการเรียกแบบมีค่าสำรองได้รับการยกเว้น ซึ่งจริง
เรื่องการวาด แต่ไม่จริงเรื่องเจตนา

ปรับอีกสี่จุด: เมนูมีอนิเมชันตอนเปิด 120ms และไม่มีตอนปิด (ตอนปิดคุณตัดสินใจไปแล้ว) · แถบเลื่อน
โปร่งใสจนกว่าจะเอาเมาส์ไปชี้ · แถวปุ่มเป็นแถวจริงที่มีพื้นที่ให้กด แทนไอคอนเปล่าขนาด 13px ·
รายการ "ตัดสินใจไปแล้ว" ยุบเหลือสี่แถว

พร้อมกันนั้นแก้บั๊กหน้าจอสองข้อ:

- **เบราว์เซอร์ของโต๊ะทำงานลอยทับห้องที่เปิดเต็มจอ** มันเป็นหน้าต่างของวินโดวส์จริง ๆ ที่ถูกสั่งให้
  อยู่บนสุด จึงไม่มีค่า CSS ไหนไปถึง ต้องสั่งให้ซ่อนอย่างเดียว และตัวสั่งนั้นมีอยู่แล้ว แต่ **รู้จักห้อง
  เดียว** เพราะเขียนตอนที่หน้าตั้งค่าเป็นหน้าเต็มจอหน้าเดียว อีกสามห้องที่เพิ่มมาทีหลังไม่เคยถูก
  เพิ่มเข้าไป และคนที่เพิ่มก็มองไม่เห็นปัญหา เพราะห้องของเขาทำงานปกติ ที่พังคือหน้าต่างของคนอื่น
- **เมนูคลิกขวาเปิดออกนอกจอ** หลังจากปุ่มของมันถูกย้ายไปทางขวาโดยที่จุดยึดไม่ได้ย้ายตาม การ
  ย้ายปุ่มคือการย้ายพื้นที่ที่เมนูของมันมี และไม่มีอะไรใน CSS เตือนคุณเรื่องนี้

## 9. คำว่า "โหมด" เคยหมายถึงสามอย่าง ตอนนี้เหลืออย่างเดียว

คำนี้ทำงานสามหน้าที่พร้อมกันโดยไม่มีใครสังเกต คือหมายถึง **โต๊ะทำงาน** ในเอกสาร หมายถึง
**ระดับการอนุมัติ** บนหน้าจอ และหมายถึงโมดูลหนึ่งในโค้ด

บนหน้าจอและในเอกสาร ตอนนี้มันแปลว่า **โหมดทำงาน** อย่างเดียว โต๊ะเรียกว่าโต๊ะ ส่วนระดับ
การอนุมัติเรียกว่า **ระดับการอนุมัติ** ซึ่งตรงกว่าอยู่แล้วเพราะมันเป็นระดับ ส่วน **ในโค้ด `mode`
ยังแปลว่าโต๊ะอยู่เหมือนเดิม** เพราะเป็นคนละชั้นกับคำบนหน้าจอ แบบเดียวกับที่ `Chairs()` ยังอยู่
หลังเลิกใช้คำว่า "เก้าอี้" ไปแล้ว

การประเมินขอบเขตงานนี้เป็นบทเรียนของตัวเอง: ประเมินไว้ 16 จุดใน 3 ไฟล์ จากการค้นในเอกสารที่
นิยามคำนี้ ของจริงคือ **~40 จุดใน 18 ไฟล์** **การประเมินขนาดงานเปลี่ยนชื่อ ด้วยการค้นในเอกสารที่
นิยามคำนั้น คือการนับที่ผิดไม่ได้**

ไม่แตะโดยตั้งใจ: บันทึกรุ่นเก่า เอกสารเปรียบเทียบ และคำพูดของเจ้าของเองสองที่ คำพูดคือหลักฐาน
ไม่ถูกแก้ให้เข้ากับคำศัพท์ของวันนี้

# 🚀 Aetox v0.9.9 — The staging release: a second axis for the turn, work that outlives it, and an app that tells you it is out of date

> The number skips 0.9.7 and 0.9.8 on purpose. Nine commits landed between this and
> v0.9.6, and three of them are structural rather than incremental — a second axis
> beside the desk, delegated work that no longer dies with the sentence that started
> it, and an update path that was complete and unreachable for five releases. This is
> the last stop before 1.0.0, and it is where the 0.9.x line is meant to settle.

---

## 1. 🔴 A folder you focused was a licence to read the keys inside it

The most serious bug in this release, and the one that needed no cleverness to hit.

`resolveSandboxPath` returned as soon as a path was inside the project root, and left
`refuseCredentialStore` guarding only the routes that *leave* that root. That reading is
true of source files and untrue of `~/.ssh` — and the two arrive together, because
focusing your home folder is not an exotic configuration in this system. It is the
thing the assistant desk exists to do.

Focus `C:\Users\<name>` as a project, ask for `.ssh/id_rsa` by its plain path, and you
got the file. No traversal, no symlink, and a denylist that exists for precisely this.

Three existing tests missed it because every one of them widened the workspace from the
outside — an added folder, an open machine — so all three landed on branches that were
already gated. The new test stands in the gap between them.

## 2. 🎚️ โหมดทำงาน: the desk says what tools exist, the stance says how this turn runs

Two axes that were being asked to share one word. **The desk answers *what is on the
table*** and is fixed for the session. **The stance answers *how this turn runs*** and
switches at any moment. ([§106](../DECISIONS.md))

Three positions:

- **ลงมือ** — the default; changes nothing.
- **วางแผน** — can look at anything, can change nothing. It uses an allow-list rather
  than a denylist, so a tool added next month is held back by default instead of
  slipping in unnoticed.
- **คู่คิด** — no tool definitions are sent at all.

The rule that lets two axes coexist, and the only reason mid-turn switching is safe:
**a stance can subtract from the desk, never add to it.** `withStance` wraps `Carries`
in an AND; it never replaces it.

Measured on the assistant desk: 34 tools / ~8,023 tok + ~2,860 prompt → 0 + ~1,562.
**~9,321 tokens saved per request (86%)** — and a third of that saving is not from the
tool block at all, but from `prompt.Desk.ToolLess` dropping seven layers that are pure
instruction on how to use tools. Half of those layers never name a tool, so `Carries`
could not have been asked about them.

A fourth stance (**มุ่งเป้า**) was designed to completion and then declined — the owner
found the objection first: *"normally it does that anyway."* ([§106.10](../DECISIONS.md))

## 3. 🧵 Work handed to somebody else no longer ends when the sentence does

A delegate now holds its own context rather than the turn's. The turn ends, the work
keeps going, you collect it by the same id next turn, and a question it stopped to ask
survives into the next message too. ([§105](../DECISIONS.md))

The old rule — "turn-bounded lifetime" — was never a lifetime rule. It was a deadline
nobody agreed to: ten minutes of reading discarded because the answer that started it
finished. The counter-argument was already written down in this repo, at
`shell_background`: a thing that dies with the reply that spawned it was never
background work. The only event that ends a job early is the user pressing Stop, which
is a fact only the host knows — so the registry moved to the host (`subagent.Delegations`).

**A card in the chat replaced the status bar.** A bar that is correct but motionless
reads as dead work; a number ticking every few seconds cannot answer *is this alive*,
while a list of files flowing past can. Status comes from the registry (only it knows —
`task`'s tool call returns the moment the job starts), steps come from the event stream,
and `ToolEvent.Task` joins the two. Finished jobs collect their own results; you press
nothing.

Also: **the action row under an answer (copy / thumbs / regenerate) stopped hiding until
hover.** A button nobody can see is a button nobody presses, and two of those three are
the learning loop's only food.

## 4. ⬇️ The app now tells you a release exists

`internal/update` has downloaded a release, checked its ed25519 signature, verified the
hash against the signed `checksums.txt`, renamed the running exe aside and restarted
into the new one **since v0.9.4** — behind a button in Settings → About that nothing
ever pointed you at. The feature was complete and unreachable. The owner of the project
asking to stop reinstalling by hand *is* the finding. ([§107](../DECISIONS.md))

- **The check runs itself and stays quiet.** Once, 20 seconds after startup, then daily.
  A failed automatic check emits nothing to the window — offline, rate-limited, proxy in
  the way, all of it to `debuglog`. A red banner about GitHub being unreachable, over an
  app you are using, answers a question you never asked and makes a working app look
  broken. The explicit button still reports its own failures; that one *was* asked for.
- **It downloads nothing on its own.** The notice offers, you decide, bytes move on the
  click.
- **`AETOX_DISABLE_UPDATE_CHECK` switches it off before the first sleep** — an opted-out
  user should not have a goroutine ticking on their behalf either.
- **The notice and the About button drive the same state** (`selfUpdate.svelte.ts`), so
  "downloading / 42% / restarting / here is why it failed" cannot live in one page and
  disagree with the other.
- **The dialog says the two things a percentage cannot:** that the app will close and
  come back by itself, said *before* it happens; and on failure, that the version you
  have is intact — which is what the signature chain is for. A refused download is the
  chain working.

Scoop installs are told to run `scoop update aetox` rather than offered a click; that
directory is not ours to write into. macOS and Linux have no auto path at all yet —
part of the 1.0.0 gate, not this release.

## 5. 🗂️ สรุปห้อง — what this room is holding, without scrolling back for it

A chat room here is a workroom, not a conversation. Ten pages of tool timeline, and the
things still in use sink with it. A button in the top-right corner opens a panel that
answers three questions without scrolling: **what was planned**, **what this room has
read**, and **what state the repo is in**.

All three are re-readings of something that already exists — plan from `todo_write`,
sources off `tool_runs` (`desktop/sources.go`), repo from `GitChangedFiles` and the
branch. Nothing here is a second copy: a second place answering the same question goes
stale the moment you move a file, and then it lies to you about your own machine.

**The lifetime of a plan changed, and that is the heart of it.** Todos used to be
cleared at both ends of every turn — correct while they were drawn inside a live block,
where last turn's finished checklist would land on top of this turn's question. Under a
permanent panel the same rows say something different: *this is the room's most recent
plan, and nothing has replaced it.* A plan that vanishes with the turn that wrote it is a
plan nobody can work from, which is the entire reason planning exists.

Removing the clear without putting anything back means a plan that never leaves (the
owner hit this himself), so it splits two ways: **a plan with every item done is a
receipt, not work** — it goes on the next turn. **A plan abandoned halfway gets a button**,
because the only one who knows it was abandoned is the person who abandoned it. Work
still running never disappears.

The badge counts **what is left, not what is done**. A 30px button has room for one
number, and between the two, the one that changes what you do next is the remainder —
1/3 and 2/4 are different situations with the same amount of work left. (It previously
read "1/3", which is 20px wide on a 30px button, over the icon and into its neighbour.)

## 6. 🔑 A secret the app already holds should not be typed into a config file again

A report that the `github` MCP server would not connect, with `Bad Request`. The config
carried `"Authorization": "Bearer"` — a scheme name with no token behind it. Probing the
real endpoint returned two different states: no header at all gives 401 with a message
naming what is missing; an empty `Bearer` gives 400. **Two codes, two states — proof of an
incomplete header rather than a missing one.**

The preset pre-filled `Bearer ` for a token to be pasted after it, and the form let you
press Save exactly like that. The comment above the preset had already written this
lesson down once — and it was fixed on the preset side while **the form side stayed
open**. Saving now fails on an empty header or a bare scheme name.

The better question is why it must be typed at all. Aetox already holds your GitHub token
from the การเชื่อมต่อ page; asking you to paste it again copies a well-kept secret out as
plaintext in `mcp-servers.json` and leaves two places to rotate.

**`${connect:id}` now sits beside the existing `${env:NAME}`.** The github preset is
`Bearer ${connect:github}` — one button, no form, nothing pasted. It **deliberately does
not fall back to env** even though `github.Token()` does: `${connect:x}` and `${env:X}`
are different requests, and if the first quietly answered from an env var exported months
ago, that is the app guessing which secret you meant.

Five presets were added after probing that each answers an MCP handshake with no login:
`context7`, `deepwiki`, `exa`, `huggingface`, `cloudflare-docs`. Notion / Linear / Sentry
/ Atlassian are all real servers but need OAuth, which is still deferred. *(Four of them
returned 403 on the first probe and were nearly recorded as "needs login" — it was
Cloudflare blocking the probe's own user-agent. A check that can fail for its own reasons
has to be read twice.)*

## 7. 🖼️ The artifacts page was showing you the *oldest* files under a heading that said newest first

`maxArtifacts` was applied in three places, **all of them before the sort**, and session
folder names are timestamps — so `os.ReadDir` walks oldest to newest. Past 500 files the
page would walk from the oldest, stop at 500, then sort newest-first: today's work would
not appear at all. The owner's machine has 74 files, so it had not landed yet. It was
waiting.

Now nothing stops mid-walk: every root → sort → **a time range does the cutting** → the
cap is a net at the very end. The default is this week, sharing its numbers with
`dayBucket.ts` (≤7, ≤30) so group headings and the filter cannot disagree. **An empty week
widens itself** to a month and then to everything, and reports back which range answered,
because a button that says "this week" over a month of files is a button that lies.

The ceiling changed meaning from *dropped* to *not drawn yet*: all the data arrives, 60
cards render at a time, the button names the remainder. A file the page never sent is a
file you cannot find; a file sent but not yet drawn is one row of metadata. Those are not
the same price, and one number was deciding both.

Previews are also released when scrolled out of view (LRU 90) — `.html` rendered as a real
iframe and images as data URLs used to accumulate with nothing ever freeing them. And
`previewHTMLBytes` split from `previewTextBytes`, because one token was capping two things
with different natural sizes: a 22 KB landing page rendered as a web page while a 49 KB one
became a wall of markup, with nothing on screen saying it was about size.

## 8. 🎨 Frame and card — zones that are actually separate

The owner put a reference image down and said ours reads as one sheet. It did: top bar,
sidebar and right panel all used `--surface-sunken`, content used `--surface-app`, and the
two differ **by 4 units out of 255**. The top bar had no bottom border at all.

Now it is a frame and a card: all chrome on `--surface-panel`, content a card on
`--surface-app` with four rounded corners, its own border, and an even 6px gutter in every
state. Tokens, not hand-picked colours — every theme already defines app/panel, and a
literal would fix one theme and leave the other eleven where they were.

`--shadow-menu` exists now because the popover shadow was a raw value in six places and a
seventh reached for `--shadow-lg`, which was never declared — so it silently used a
fallback typed from memory (34px/.38 instead of 32px/.4), the one menu in the app with the
wrong shadow. **The test that forbids asking for a token no theme declares already existed
and skipped it**, because `var()` with a fallback is exempt. True about rendering, false
about intent.

Also: a 120ms open animation and nothing on close (the menu closes after you have already
decided) · scrollbars transparent until pointed at · the action row is a flex row with a
real hit area instead of bare 13px icons · "already decided" folds to four rows.

Two UI bugs fixed along the way:

- **The desk browser floated over full-screen rooms.** It is a native Windows window
  forced to the top of the Z order, so no `z-index` reaches it — it has to be told to
  hide, and the guard for that existed but **knew about one room only**, written when
  Settings was the single full-screen page. The three rooms added later were never added
  to it, and whoever added them could not see the problem: their room worked, somebody
  else's window broke. Now derived from the same list (`isOverlayView`).
- **A context menu opened off-screen** after its button moved right without its anchor
  moving. Moving a button moves the space its popover has, and nothing in CSS warns you.

## 9. 🔤 "โหมด" used to mean three things; now it means one

The word was working three jobs at once with nobody noticing: **the desk** in the docs,
**the approval tier** on screen ("โหมดอนุมัติ"), and `internal/mode` in the code — despite
COMPANY.md §8 existing specifically to prevent this.

On screen and in the docs it now means **โหมดทำงาน** and nothing else (§106). The desk is
called the desk; the approval tier is **ระดับการอนุมัติ**, which is more accurate anyway
because it is a level. In the code `mode` still means desk — a different layer from the
word on screen, the same way `Chairs()` outlived the retirement of "เก้าอี้".

Scoping this was its own lesson: estimated at 16 sites in 3 files from
`grep โหมด COMPANY.md`; the real count was **~40 sites in 18 files** — the CLI, onboarding
copy, the `description:` line of all three desk files (which is card text, not a comment),
four error messages, and frontend tests asserting the old strings. **Sizing a rename by
grepping the document that defines the word is the one count that must not be wrong.**

Untouched on purpose: release notes, BENCHMARK.md, `docs/opencode-study`, and two of the
owner's own quotes. Quotes are evidence; they do not get edited to match today's
vocabulary.

## 10. 📄 The README describes this version now

The old one was not badly written — it was the README of an earlier Aetox, still hanging
on this one. Every number was re-measured rather than copied:

- **41.5 MB** from the actual v0.9.6 zip (was 40.8; the site said 35 and 33)
- **installer 15.8 MB** (badge said 13, body said 12.6, site said 13)
- **40 tools / ~9,844 tok, 8 slots free** (was "48, and full" — 48 is the ceiling in a
  test, not a count)
- **1,470 Go / 37 pkg + 463 UI / 42 files** (was 1,438+365/34; the site said 533)
- **turn assembly 0.32 ms / 174.9 KB** — a regression from 0.12/96.2 as tools grew, and
  written down as a regression

Two numbers were deleted rather than updated: "97% from cache" and LM Studio/Ollama first
token. Neither has any origin in the repo — no test, no log, no BENCHMARK entry — and the
machine they described did not have LM Studio installed. The README's own rule at line 256
has no exception for numbers we would like to keep.

The tool table is now generated from the registry the model actually receives
(`TestPrintReadmeToolTable`). The hand-written one still listed `shell_output`,
`shell_kill` and four `github_*` tools months after they were folded into `shell` and
`github`, and never had a row for n8n or windmill.

A Thai edition ships alongside it, and the limits that used to be avoided are stated:
automation cannot run a workflow and show you the result · Windmill has no enable command ·
there is no scheduler and there will not be one · Linux/macOS CI is red on six tests and
one of them is a real hole.

**Windows is the reference platform.** macOS and Linux remain the gate for 1.0.0 — the
in-app browser, packaging, at-rest credential encryption and the auto-update path are all
still Windows-only, and none of them close on this release.

# 🚀 Aetox v0.9.6

> v0.9.5 บอกไว้ว่างานอัตโนมัติลงในวันเดียว และ **v0.9.6 คือรุ่นที่มาเก็บให้เรียบร้อย** นี่คือรุ่นนั้น
> ส่วนใหญ่เป็นการซ่อม และตัวที่ใหญ่ที่สุดคือบั๊กที่ปิดการทำงานของเอเจนที่ใช้ MCP ทุกตัวมาอย่างเงียบ ๆ
> ตั้งแต่ก่อนงานอัตโนมัติจะมีด้วยซ้ำ

## 1. ⚠️ ไม่มีเครื่องมือ MCP ตัวไหนเดินทางไปถึงเซสชันเลย

บั๊กที่ร้ายแรงที่สุดในโปรเจกต์นี้เท่าที่ผ่านมา และมันไม่รายงานอะไรเลยสักอย่าง

สิ่งที่ผู้ใช้เห็นคือ เอเจนเฉพาะทางทุกตัวปฏิเสธที่จะเริ่มงาน แต่ละตัวบอกว่าเซิร์ฟเวอร์ MCP ที่มันใช้
*"ยังต่อไม่เสร็จ ลองสั่งใหม่อีกสักครู่"* พอสั่งใหม่ก็ได้ประโยคเดิม วนแบบนั้นตลอดกาล สั่งไปสิบครั้ง
ถูกปฏิเสธสิบครั้ง ไม่มีครั้งไหนนานเกินหกมิลลิวินาที

ความจริงคือเซิร์ฟเวอร์ต่อติดแล้ว ลงทะเบียนเสร็จใน 12.5 วินาที และไม่มีข้อผิดพลาดในบันทึกเลย
รายการเครื่องมือถูกอ่านมาครบ แล้วถูกทิ้งลงพื้น

ตัวจัดการ MCP ถูกสร้างครั้งเดียวและอยู่ข้ามการเริ่มระบบใหม่ ซึ่งถูกต้อง เพราะการเชื่อมต่อที่ยังมี
ชีวิตอยู่ถูกเก็บไว้ตรงนั้น แต่มันถือธง "ลงทะเบียนเสร็จแล้ว" ที่มีอายุเท่ากัน ขณะที่ตัวรับรายการ
เครื่องมือ **ไม่ได้มีอายุเท่านั้น** เพราะทุกครั้งที่ระบบเริ่มใหม่จะสร้างตัวใหม่ และแอปเดสก์ท็อปเริ่ม
ระบบสองครั้งตอนเปิด ห่างกัน 19 มิลลิวินาที ตัวไหนลงทะเบียนเสร็จก่อนก็ปักธงแล้วส่งเครื่องมือให้
ตัวรับที่ถูกแทนที่ไปแล้ว ส่วนตัวที่ใช้งานจริงพอไปถามก็ถูกตอบว่า "เสร็จแล้ว" และไม่ได้อะไรเลย
การเปลี่ยนโมเดลกลางเซสชันก็เสียเครื่องมือไปด้วยวิธีเดียวกัน

ธงนั้นถูกเอาออกแล้ว ตอนนี้ระบบถามตัวรับตรง ๆ ว่ามีเครื่องมือตัวนั้นอยู่ไหม ซึ่งเป็นคำถามเดียวกับที่
ตัวตรวจความพร้อมของเอเจนถาม ถามด้วยวิธีเดียวกัน สองอย่างจึงพูดไม่ตรงกันไม่ได้อีก และมีเทสต์
สามตัวที่ตั้งชื่อตามความล้มเหลวที่มันจำลองขึ้นมา

## 2. เรียกคนทำงานเองได้ด้วย `@ชื่อ`

ก่อนหน้านี้มีทางเดียวที่จะไปถึงเอเจนเฉพาะทาง คือผู้ช่วยหลักตัดสินใจเรียกมันเองแล้วเขียนคำสั่งให้เอง
คนทำงานไม่เคยเห็นประโยคของคุณ มันเห็นคำที่ถูกเรียบเรียงใหม่

ความผิดพลาดที่ทำให้เรื่องนี้ชัด: ประโยค *"ถาม doc หน่อยว่าเอกสารที่ดีประกอบด้วยอะไรบ้าง"*
ไปถึง `doc` เป็น *"เขียนคู่มือว่าเอกสารที่ดีประกอบด้วยอะไรบ้าง"* แล้ว `doc` ก็เขียนคู่มือมาให้จริง ๆ
ซึ่งถูกต้องตามสิ่งที่มันได้รับ

**พิมพ์ `@doc <คำขอ>` ในช่องพิมพ์** แล้วข้อความนั้นจะไปถึง `doc` แบบคำต่อคำ ตั้งแต่ก่อนโมเดล
จะทำงานด้วยซ้ำ พิมพ์ `@` แล้วรายชื่อทีมจะเปิดขึ้นเหนือช่องพิมพ์ กรองตามที่พิมพ์ และแชทยังอยู่ที่
เดิม เพราะนี่คือการส่งข้อความหนึ่งข้อความ ไม่ใช่การย้ายคุณเข้าไปในห้องของเขา

- ใช้กลไกมอบงานเดิมทั้งหมด ไม่ได้สร้างเส้นทางที่สอง
- **ถ้าคนทำงานหยุดถามอะไรกลับมา ข้อความถัดไปของคุณคือคำตอบ** งานยังเปิดอยู่และยังถือทุกอย่าง
  ที่อ่านไปแล้ว แทนที่จะเริ่มใหม่
- รายชื่อมาจากทะเบียนจริง เอเจนที่คุณเพิ่มเองจึงเรียกได้ทันทีที่โฟลเดอร์ของมันมีอยู่
- คำอธิบายเครื่องมือมอบงานเลิกสัญญาว่าคนทำงานจะคืนอะไรกลับมา ประโยคที่ว่า *"และคืนไฟล์ที่
  เสร็จแล้ว"* คือสิ่งที่เปลี่ยนคำถามให้กลายเป็นคำสั่งให้ผลิตไฟล์ มันถูกลบทิ้งแทนที่จะแก้คำ เพราะ
  ผู้เชี่ยวชาญรู้อยู่แล้วว่างานของตัวเองหน้าตาเป็นยังไง

**ข้อจำกัดที่รู้อยู่:** ถ้าเปิดแชทนั้นขึ้นมาดูใหม่ทีหลัง คุณจะเห็นคำตอบโดยไม่มีขั้นตอนข้างใต้ ตอนที่
มันทำงานสด ๆ ประวัติจะครบ

## 3. เทอร์มินัลที่ดูเหมือนพังสามแบบพร้อมกัน

เช้าวันหนึ่ง อาการเดียว คือเทอร์มินัลบนโต๊ะทำงานพ่นบรรทัดซ้ำที่เหลื่อมกันเป็นร้อยบรรทัด และมีสาม
สาเหตุที่ไม่เกี่ยวกันเลย:

- **การเริ่มเครื่องยนต์รอบที่สองเดินผ่านด่านไปได้** ด่านเดียวที่มีคือ "เซิร์ฟเวอร์ตอบไหม" ซึ่ง
  เซิร์ฟเวอร์ที่กำลังบูตอยู่ตอบไม่ได้ การเรียกครั้งที่สองจึงไปเปิดเครื่องยนต์ตัวที่สองมาแย่งพอร์ตและ
  แย่งไฟล์บันทึกเดียวกัน ตอนนี้การเริ่มถูกประทับเวลาไว้ และการเรียกซ้ำภายใน 90 วินาทีจะถูกปฏิเสธ
- **ไฟล์บันทึกถูกล้างขณะมีคนอ่านอยู่** แผงจะตามอ่านไฟล์นั้นด้วยตำแหน่งไบต์ พอไฟล์ถูกล้าง
  ตำแหน่งก็เลยท้ายไฟล์ไปแล้วและตามกลับไม่ได้อีก ตอนนี้การบูตจะเขียนต่อท้ายใต้เครื่องหมายเวลา
  และเมื่อไฟล์ถึง 4 MB จะถูก *เปลี่ยนชื่อ* เก็บไว้ ไม่ใช่ล้างทิ้ง
- **ระบบเทอร์มินัลของวินโดวส์วาดหน้าจอใหม่ทั้งหน้าทุกครั้งที่ถูกสั่งปรับขนาด** แม้แต่ครั้งที่ขนาด
  ไม่ได้เปลี่ยน (วัดแล้ว: สั่งขนาดเดิมสิบครั้ง ได้แบนเนอร์เพิ่มสิบอัน) และแถบเลื่อนของแผงเองก็เป็น
  ตัวขับให้เกิดการปรับขนาดวนไปเรื่อย ๆ คือ ข้อความล้น → แถบเลื่อนโผล่ → แผงแคบลง → ปรับขนาด
  → วาดใหม่ → ความสูงเปลี่ยน → แถบเลื่อนหาย → วนใหม่

ข้อสุดท้ายน่าสนใจ เพราะการแก้ครั้งแรกคือตัดคำสั่งปรับขนาดที่ให้ขนาดเดิมทิ้ง ซึ่งถูกต้อง และ
**ไม่ช่วยอะไรเลย** เพราะทุกขนาดในวงวนนั้นเป็นขนาดใหม่จริง ๆ ทางแก้จริงคือหยุดไม่ให้ช่องของ
เทอร์มินัลเลื่อนได้ เพราะตัวเทอร์มินัลมีระบบเลื่อนของตัวเองอยู่แล้ว

## 4. ระบบเรียนรู้เลิกเรียนเรื่องไร้สาระ

เครื่องมือที่ล้มเหลวด้วยการคืนคำปฏิเสธ แทนที่จะคืนข้อผิดพลาดของภาษา เคยถูกบันทึกด้วยคำเดียว
ว่า `ไม่สำเร็จ` คำนั้นไปทั้งบนหน้าจอ ในฐานข้อมูล และไปถึงตัวสรุปที่เอาคอลัมน์นั้นมาจัดกลุ่มเป็น
ข้อเสนอให้จำ ผลคือคำปฏิเสธสิบครั้งที่แต่ละครั้งมีเหตุผลชัดเจน กลายเป็นการ์ดใบเดียวที่เขียนว่า
*ล้มเหลวซ้ำ ๆ ด้วย "ไม่สำเร็จ" ควรเลี่ยงรูปแบบนี้* ซึ่งคือบทเรียนที่สาเหตุถูกลบทิ้ง จากหลักฐานที่
อยู่ห่างไปแค่ฟิลด์เดียว

ตอนนี้ความล้มเหลวบันทึกสิ่งที่เครื่องมือพูดจริง ๆ และเครื่องมือเขียนเอกสาร ตาราง และสไลด์ ก็พูด
อะไรที่ควรค่าแก่การบันทึก คือบอกว่าต้องมีฟิลด์อะไรบ้างและยกตัวอย่างการเรียกที่ใช้ได้จริง แทนที่จะ
บอกแค่ว่า "ต้องระบุพาธ" ซึ่งไม่เคยอธิบายความล้มเหลวจริงอยู่แล้ว เพราะกรณีที่เกิดจริงคือโมเดล
เรียกมันโดยไม่ใส่อะไรเลยสักตัว

## 5. หน้าตั้งค่า: ทีมกลับมาอยู่ในหน้าจอเดียวได้

- **รายชื่อเอเจนเป็นแถว ไม่ใช่การ์ด** ซึ่งกลับคำตัดสินใจเมื่อสองวันก่อน คำตัดสินนั้นถูกที่ว่าชื่อที่จม
  อยู่ใต้ป้ายสีเทาห้าอันไม่ใช่หน้าตาที่มองปราดเดียวแล้วเจอ แต่กริดการ์ดขนาด 240px ทำให้เพื่อน
  ร่วมทีมแปดคนอยู่ในหน้าจอเดียวไม่ได้ ตอนนี้ชื่อมาก่อน คำอธิบายมีบรรทัดของตัวเอง
- **คำสั่งงานที่ยาวจะถูกพับ** เหลือตัวอย่างพร้อมปุ่มกางเต็ม ช่องโมเดลและเครื่องมือที่อยู่ข้างใต้จึง
  กดถึงโดยไม่ต้องเลื่อนผ่านข้อความร้อยบรรทัด และการคลิกเข้าไปในช่องนั้นจะกางเต็มให้เสมอ
- **ชั้นวาง MCP แสดงแค่ `github` ตัวเดียว** ซึ่งเป็นเซิร์ฟเวอร์ที่เอเจนที่มากับแอปประกาศใช้จริง
  แทนที่จะเป็นรายชื่อของยอดนิยม และมันเลิกยื่นเฮดเดอร์ที่พังมาให้แล้ว ค่าตั้งต้นเติม
  `Authorization: Bearer ` มาให้แทน `Authorization: ` เฉย ๆ ซึ่งพอวางโทเคนลงไปแล้วถูกปฏิเสธ
- ปุ่มเปิดแชทใหม่อยู่บนแถบหัวเรื่องตลอดเวลา ไม่ใช่เฉพาะตอนที่แถบข้างถูกยุบ

# 🚀 Aetox v0.8.8 Release Notes — โต๊ะทำงานรับของวางได้ และ AI ได้สิทธิ์คิดเอง

รุ่นนี้มีสองเส้นเรื่อง: **โต๊ะทำงาน (Workbench) กลายเป็นโต๊ะจริง ๆ** — ลากไฟล์มาวางได้ คลิกแล้วเปิดบนโต๊ะเป็นค่าเริ่มต้น — และ **การคืนอำนาจตัดสินใจให้โมเดล** — เลิกดักคำใน tool, สอนหลักคิดแทนกฎตายตัว, และเปิดทั้งเครื่องให้โหมดไม่โฟกัสโปรเจกต์

### 1. 🖥️ โต๊ะทำงานรับของวางได้แล้ว (§80)

* **ลากไฟล์จาก Explorer มาวางบนแผงขวา → เปิดเป็นแท็บตรงนั้นทันที** ตำแหน่งที่วางตัดสินความหมาย: วางบนโต๊ะ = เปิดบนโต๊ะ, วางบนช่องพิมพ์ = แนบไฟล์ (เหมือนเดิม)
* ไฟล์จากนอกโปรเจกต์ถูก**ก๊อปเข้ามาให้เอง** — เอเจนต์เลยอ่านของที่วางบนโต๊ะได้ด้วย ไม่ใช่แค่ตอบว่า "path is outside project root"
* แท็บเบราว์เซอร์ (ที่เป็นหน้าต่าง OS จริงซ้อนอยู่) **หลบให้ตอนลาก** — ไม่งั้นมันกลืน drag ทิ้ง
* **รูปภาพได้แผงของตัวเอง** (ImagePane) — webview วาดรูปเป็นอยู่แล้ว ไม่ต้องเขียนอะไรเพิ่ม สกรีนช็อตของตัวเองต้องดูได้ ไม่ใช่เจอ "binary file cannot be previewed"
* การ์ดไฟล์ในแชท**ลากไปวางบนโต๊ะได้** — ไฟล์ที่ AI เพิ่งสร้างอยู่บนจอแล้ว ลากไปดูเลย
* วางแล้วพัง (ใหญ่เกิน/อ่านไม่ได้) ก็ยังเปิดแท็บบอกเหตุผล — ความเงียบคือคำตอบที่แย่ที่สุดของโต๊ะ

### 2. 📂 คลิกไฟล์ = เปิดบนโต๊ะ ไม่ใช่โยนให้โปรแกรมอื่น (§81)

* เดิมคลิกการ์ดไฟล์ → หน้าต่าง Excel/PowerPoint เด้งทับ Aetox ทันที ตอนนี้**เปิดบนโต๊ะเป็นค่าเริ่มต้น** ปุ่ม "เปิดด้วยโปรแกรมในเครื่อง" ยังอยู่ — ย้ายเข้าไปเป็นปุ่มในแผงแทน (กฎใหม่: ทุกแผงต้องมีปุ่มนี้)
* **แท็บเบราว์เซอร์ใหม่ไม่ใช่หน้าว่างแล้ว** — โชว์หน้าที่ Aetox เคยเปิด รวมกับหน้าที่คุณเปิดเอง (เก็บใน localStorage ฝั่ง UI เท่านั้น — ไม่เข้า database ที่เอเจนต์ค้นได้ เส้นแบ่งนี้ตั้งใจ) คลิกเดียวกลับไปหน้านั้น ลิงก์ตายถูกกรองทิ้ง ไม่มี dead end
* แก้เลขผิดของเพดานขนาดแผง: ปิด sidebar แล้วโต๊ะเคยได้พื้นที่แค่ 765px จาก 1051px ที่ควรได้ — สูตรย้ายไป `panelSize.ts` พร้อมเทสต์ตรึงตัวเลข

### 3. 🌍 โหมดไม่โฟกัสโปรเจกต์ = ทั้งเครื่องคือโต๊ะทำงาน (§19.1 แก้ไข)

* "หาไฟล์ PDF ในเครื่องนี้หน่อย" เคยถูกตอบว่า *ทำไม่ได้* — กำแพง sandbox ของ 26 ก.ค. ทำให้โหมดนี้ปลอดภัยด้วยการทำให้มันไร้ประโยชน์ ตอนนี้**ไม่โฟกัสโปรเจกต์ = ไปได้ทั้งเครื่อง** (absolute path และ `../` ใช้ได้หมด)
* สิ่งที่**ไม่**เปิดคืนคือตู้กุญแจ: `.ssh`, `.aws`, credential ของ gh/git, token store ของเบราว์เซอร์ และ `~/.aetox` (กุญแจของ Aetox เอง) — ถูกปฏิเสธใน `resolveSandboxPath` ชั้นเดียวกับที่ tool ทุกตัววิ่งผ่าน
* ไฟล์ใหม่ยังลง `output/<เซสชัน>` เสมอ — ทุกอย่างที่แชตหนึ่งสร้างอยู่ที่เดียว ตรวจง่าย
* **โปรเจกต์ที่โฟกัสกับ CLI กำแพงเดิมอยู่ครบทุกก้อน** — ความปลอดภัยของโปรเจกต์ไม่เปลี่ยนแม้แต่บรรทัดเดียว

### 4. 🧠 คืนอำนาจตัดสินใจให้โมเดล

* **Tool เลิกดักคำ** — `slides_write` เคยประกาศว่า "ใช้ตัวนี้*เมื่อไหร่ก็ตาม*ที่ผู้ใช้อยากได้สไลด์" ผลคือพิมพ์ "สร้างสไลด์" แล้วขอ HTML ตามหลังยังได้ .pptx กลับมา ตอนนี้ tool ทั้งสามตัว (slides/sheet/doc) บอกแค่ความสามารถ: "สร้างไฟล์ PowerPoint (.pptx)" — เป็นตัวเลือกบนชั้นวาง ไม่ใช่ด่านดักคำ มีเทสต์ยามกันภาษาชี้นำงอกกลับทุก tool ในระบบ
* **System prompt สอนหลักคิด ไม่ใช่กฎรายเคส** — โจทย์ว่างเปล่า ("สร้างไฟล์ให้หน่อย") → ถามหนึ่งคำถามผ่านการ์ดตัวเลือกก่อนลงมือ / ค่า default ของ tool แพ้คำพูดจริงของผู้ใช้เสมอ รวมถึงคำแก้ที่มาทีหลังกลางบทสนทนา / รายละเอียดที่ผู้ใช้ไม่แคร์ ตัดสินใจเองไม่ต้องถาม

### 5. 🔧 ไฟล์ .pptx ที่มีโน้ตผู้บรรยาย ไม่พังอีกแล้ว

* ทุก deck ที่มี speaker notes เคยเจอ "PowerPoint พบปัญหากับเนื้อหา… ให้คลิกซ่อมแซม" — ไล่หาด้วยการ bisect ผ่าน PowerPoint จริง (COM) จนเจอราก: **notesMaster แชร์ไฟล์ theme กับ slideMaster** ซึ่งสเปก OPC ยอมแต่ PowerPoint ไม่ยอม — master แต่ละตัวต้องเป็นเจ้าของ theme ตัวเอง
* แก้ให้ notesMaster ได้ `theme2.xml` สำเนาของตัวเอง + เทสต์กันถอยหลัง — deck มีโน้ต เปิดสะอาดทุกตัวแล้ว
* การ์ดพรีวิว .pptx/.docx เลิกโกหกว่า "file too large" — บอกเหตุผลจริง: "ไฟล์ปกติดี — แอปแค่ตั้งใจไม่วาดสไลด์/เอกสารเอง เพราะ PowerPoint กับ Word ทำได้ดีกว่า"

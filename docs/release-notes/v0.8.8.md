# 🚀 Aetox v0.8.8

รุ่นนี้มีสองเส้นเรื่อง คือ **โต๊ะทำงานกลายเป็นโต๊ะจริง ๆ** ลากไฟล์มาวางได้ คลิกแล้วเปิดบนโต๊ะเป็น
ค่าเริ่มต้น และ **การคืนอำนาจตัดสินใจให้โมเดล** คือเลิกดักคำในเครื่องมือ สอนหลักคิดแทนกฎตายตัว
และเปิดทั้งเครื่องให้โหมดที่ไม่ได้เจาะจงโปรเจกต์

---

## 1. โต๊ะทำงานรับของวางได้แล้ว

- **ลากไฟล์จาก File Explorer มาวางบนแผงขวา แล้วมันเปิดเป็นแท็บตรงนั้นทันที** ตำแหน่งที่วางเป็น
  ตัวตัดสินความหมาย คือวางบนโต๊ะเท่ากับเปิดบนโต๊ะ ส่วนวางบนช่องพิมพ์เท่ากับแนบไฟล์เหมือนเดิม
- ไฟล์จากนอกโปรเจกต์ถูก **คัดลอกเข้ามาให้เอง** เอเจนต์จึงอ่านของที่วางบนโต๊ะได้ด้วย แทนที่จะ
  ตอบว่าไฟล์อยู่นอกขอบเขต
- แท็บเบราว์เซอร์ซึ่งเป็นหน้าต่างของระบบปฏิบัติการจริงซ้อนอยู่ **จะหลบให้ตอนคุณลาก** ไม่งั้นมัน
  จะกลืนการลากทิ้ง
- **รูปภาพได้แผงของตัวเอง** เพราะระบบวาดรูปเป็นอยู่แล้ว ไม่ต้องเขียนอะไรเพิ่ม ภาพหน้าจอของ
  ตัวเองต้องดูได้ ไม่ใช่เจอข้อความว่าเปิดดูไฟล์ไบนารีไม่ได้
- การ์ดไฟล์ในแชท **ลากไปวางบนโต๊ะได้** ไฟล์ที่ AI เพิ่งสร้างอยู่บนจอแล้ว ลากไปดูได้เลย
- วางแล้วเปิดไม่ได้ เช่นใหญ่เกินหรืออ่านไม่ออก มันก็ยังเปิดแท็บมาบอกเหตุผล เพราะความเงียบคือ
  คำตอบที่แย่ที่สุดของโต๊ะ

## 2. คลิกไฟล์แล้วเปิดบนโต๊ะ ไม่ใช่โยนให้โปรแกรมอื่น

- เดิมคลิกการ์ดไฟล์แล้วหน้าต่าง Excel หรือ PowerPoint เด้งทับ Aetox ทันที ตอนนี้ **เปิดบนโต๊ะ
  เป็นค่าเริ่มต้น** ส่วนปุ่ม "เปิดด้วยโปรแกรมในเครื่อง" ยังอยู่ แค่ย้ายเข้าไปอยู่ในแผงแทน และตั้ง
  เป็นกฎว่าทุกแผงต้องมีปุ่มนี้
- **แท็บเบราว์เซอร์ใหม่ไม่ใช่หน้าว่างแล้ว** มันแสดงหน้าที่ Aetox เคยเปิด รวมกับหน้าที่คุณเปิดเอง
  โดยเก็บไว้ฝั่งหน้าจอเท่านั้น ไม่เข้าฐานข้อมูลที่เอเจนต์ค้นได้ เส้นแบ่งนี้ตั้งใจ คลิกเดียวกลับไป
  หน้านั้น และลิงก์ที่ตายแล้วถูกกรองทิ้ง
- แก้ตัวเลขผิดของเพดานขนาดแผง เดิมพอปิดแถบข้าง โต๊ะได้พื้นที่แค่ 765px จาก 1,051px ที่ควรได้

## 3. โหมดไม่เจาะจงโปรเจกต์ = ทั้งเครื่องคือโต๊ะทำงาน

- คำสั่งอย่าง "หาไฟล์ PDF ในเครื่องนี้หน่อย" เคยถูกตอบว่าทำไม่ได้ เพราะกำแพงความปลอดภัยที่ตั้งไว้
  เมื่อ 26 ก.ค. ทำให้โหมดนี้ปลอดภัยด้วยการทำให้มันไร้ประโยชน์ ตอนนี้ **ไม่เจาะจงโปรเจกต์ = ไปได้
  ทั้งเครื่อง**
- สิ่งที่ **ไม่** เปิดคืนคือตู้กุญแจ ทั้ง `.ssh`, `.aws`, ข้อมูลล็อกอินของ git, ที่เก็บโทเคนของเบราว์เซอร์
  และโฟลเดอร์กุญแจของ Aetox เอง ถูกปฏิเสธในชั้นเดียวกับที่เครื่องมือทุกตัววิ่งผ่าน
- ไฟล์ใหม่ยังลงโฟลเดอร์ผลลัพธ์ของเซสชันนั้นเสมอ ทุกอย่างที่แชทหนึ่งสร้างจึงอยู่ที่เดียว ตรวจง่าย
- **โปรเจกต์ที่เจาะจงไว้ และโหมด CLI กำแพงเดิมอยู่ครบทุกก้อน** ความปลอดภัยของโปรเจกต์ไม่
  เปลี่ยนแม้แต่บรรทัดเดียว

## 4. คืนอำนาจตัดสินใจให้โมเดล

- **เครื่องมือเลิกดักคำ** เดิมเครื่องมือสร้างสไลด์ประกาศว่า "ใช้ตัวนี้ *เมื่อไหร่ก็ตาม* ที่ผู้ใช้อยากได้
  สไลด์" ผลคือพิมพ์ว่า "สร้างสไลด์" แล้วขอเป็น HTML ตามหลัง ก็ยังได้ `.pptx` กลับมา ตอนนี้
  เครื่องมือทั้งสามตัวบอกแค่ความสามารถของตัวเอง เป็นตัวเลือกบนชั้นวาง ไม่ใช่ด่านดักคำ และมี
  เทสต์คอยกันไม่ให้ภาษาชี้นำงอกกลับมาในเครื่องมือตัวไหนก็ตาม
- **คำสั่งตั้งต้นสอนหลักคิด ไม่ใช่กฎรายกรณี** เช่น โจทย์ที่ว่างเปล่าอย่าง "สร้างไฟล์ให้หน่อย" ให้ถาม
  หนึ่งคำถามผ่านการ์ดตัวเลือกก่อนลงมือ · ค่าเริ่มต้นของเครื่องมือแพ้คำพูดจริงของผู้ใช้เสมอ รวมถึง
  คำแก้ที่มาทีหลังกลางบทสนทนา · ส่วนรายละเอียดที่ผู้ใช้ไม่สนใจ ให้ตัดสินใจเองไม่ต้องถาม

## 5. ไฟล์ .pptx ที่มีโน้ตผู้บรรยาย ไม่พังอีกแล้ว

- ทุกไฟล์สไลด์ที่มีโน้ตผู้บรรยายเคยเจอข้อความว่า "PowerPoint พบปัญหากับเนื้อหา ให้คลิกซ่อมแซม"
  ไล่หาด้วยการตัดครึ่งทดสอบผ่าน PowerPoint ตัวจริงจนเจอต้นเหตุ คือแม่แบบของโน้ตใช้ไฟล์ธีม
  ร่วมกับแม่แบบของสไลด์ ซึ่งมาตรฐานของไฟล์ยอมแต่ PowerPoint ไม่ยอม แต่ละแม่แบบต้องเป็น
  เจ้าของธีมของตัวเอง
- แก้ให้แม่แบบของโน้ตได้ไฟล์ธีมสำเนาของตัวเอง พร้อมเทสต์กันถอยหลัง ไฟล์สไลด์ที่มีโน้ตจึงเปิด
  สะอาดทุกไฟล์แล้ว
- การ์ดตัวอย่างของไฟล์เอกสารและสไลด์เลิกโกหกว่า "ไฟล์ใหญ่เกินไป" แล้วบอกเหตุผลจริงแทนว่า
  "ไฟล์ปกติดี แอปแค่ตั้งใจไม่วาดสไลด์หรือเอกสารเอง เพราะ PowerPoint กับ Word ทำได้ดีกว่า"

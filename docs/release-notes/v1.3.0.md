# 🚀 Aetox v1.3.0

รุ่นนี้ยาวกว่าปกติ สิบหกคอมมิตนับจาก v1.2.4 และเป็นเลขไมเนอร์เพราะมีสองเรื่องที่เปลี่ยนวิธีทำงาน
ของแอปจริง ๆ คือ **ห้องสไลด์** กับ **การแยกงานของแต่ละแชทออกจากกัน** ที่เหลือคือของที่เจ้าของ
เจอตอนใช้งานจริงแล้วชี้ให้แก้ทีละอย่าง

**สรุปสั้น ๆ ก่อน**

- ทำสไลด์เป็นไฟล์ HTML แล้วกดส่งออกเป็น `.pptx` / PDF / รูป ทีหลัง
- แต่ละแชทมีเอเจนต์และความจำของตัวเอง สลับแชทระหว่างงานเดินอยู่แล้วกลับมาได้
- เอเจนเฉพาะทางเขียนไฟล์และรันคำสั่งได้แล้ว จากเดิมที่ถูกกันไว้จนทำงานที่ตัวเองถูกสั่งให้ทำไม่ได้
- แก้ OCR ที่ติดตั้งแล้วแต่แอปหาไม่เจอ
- **สัญญาอนุญาตเปลี่ยน** Aetox ยังใช้ฟรีและอ่านโค้ดได้ แต่ไม่ใช่โอเพนซอร์สอีกต่อไป

## 1. สไลด์: เขียนเป็น HTML แล้วค่อยส่งออก

เครื่องมือทำสไลด์ตัวเดิมเขียน `.pptx` ได้แค่สี่อย่าง คือหัวเรื่อง บุลเล็ต รูปหนึ่งรูป และโน้ต ไม่มีสี
สักจุดเดียวบนสไลด์ เจ้าของเปิดไฟล์ที่ได้แล้วสรุปสั้น ๆ ว่า *"ตอนนี้มีแค่ตัวหนังสือ"*

ทางที่ไม่เลือกคือเขียนโปรแกรมสร้าง PowerPoint ขึ้นมาเองให้รู้จักตาราง สี และเลย์เอาต์ ซึ่งเป็นงาน
ใหญ่มาก ทางที่เลือกคือแยกสองงานออกจากกัน: **ให้โมเดลเขียน HTML** ซึ่งเป็นสิ่งที่มันถนัดที่สุด
แล้ว **ส่งออกทีหลัง** เป็น PNG หรือ PDF หรือ `.pptx` ตามที่ต้องการ

สิ่งเดียวที่ทำให้ไฟล์ `.html` กลายเป็นสไลด์คือแท็ก `<section class="slide">` ไม่มีอย่างอื่น ไฟล์
`.html` ที่ไม่มีแท็กนี้ยังเปิดเป็นซอร์สโค้ดตามปกติ

**สามอาการที่เจอตอนใช้จริง และแก้ในรุ่นเดียวกัน**

เด็ค 8 สไลด์ส่งออกเป็น PDF แล้วได้ 12 หน้า สาเหตุคือตอนแอปวัดขนาดกระดาษ เอกสารมีแถบเลื่อน
อยู่ด้วย ความกว้างจึงขาดไป 14.7px พอดีกับความกว้างแถบเลื่อน ทุกบรรทัดเลยตัดคำใหม่แล้วล้นหน้า
ตอนนี้แอปซ่อนแถบเลื่อนก่อนวัด และตรึงทุกสไลด์ให้เป็นกล่องขนาดเดียวกัน **หนึ่งสไลด์คือหนึ่งหน้า**

หน้าต่างที่ใช้เรนเดอร์เคยเด้งขึ้นมาทับทั้งแอป และสั่งให้ไปอยู่ข้างหลังไม่ได้ ตอนนี้มันเป็นหน้าต่าง
ของตัวเองที่จอดไว้นอกจอ คุณจึงไม่เห็นมันอีก

และระหว่างส่งออก มีแผ่นคลุมบอกว่ากำลังสร้างไฟล์อยู่ เพราะเดิมกดปุ่มแล้วเงียบไปสองสามวินาที
ซึ่งอ่านเหมือนแอปค้าง

## 2. แต่ละแชทมีงานของตัวเอง

เดิมแอปเก็บเอเจนต์ ความจำ และประวัติไว้ชุดเดียว แล้วจำว่า "ตอนนี้ผู้ใช้เปิดแชทไหนอยู่" เพื่อเดา
ว่างานที่กำลังทำเป็นของแชทนั้น วิธีนี้ใช้ได้ตราบใดที่มีงานเดียว ข้อความ *"เอเจนกำลังทำงานอยู่
รอให้เสร็จ"* ที่เจอบ่อย ๆ คือผลของข้อจำกัดนี้

ตอนนี้ **หนึ่งแชท หนึ่งเอเจนต์ หนึ่งความจำ** ส่วนของหนัก ๆ อย่างการเชื่อมต่อผู้ให้บริการและ
ฐานข้อมูลยังใช้ร่วมกันเหมือนเดิม

และมี **ทางกลับ** ให้หาเจอด้วย เจ้าของสรุปอาการเดิมไว้ว่า *"ตอนสั่งงานเอเจนกำลังทำงาน พอสลับ
เซสชั่นปุ๊บ งานเอเจนหายไปเลย"* งานไม่เคยหาย มันแค่กลับไปดูไม่ได้ ซึ่งจากมุมคนใช้ก็คือเรื่อง
เดียวกัน ตอนนี้มีแถบบอกว่าแชทไหนกำลังทำอะไรอยู่ และกดกลับไปได้จากรายชื่อแชทตามปกติ

## 4. เอเจนเฉพาะทางเขียนไฟล์ได้แล้ว

เจ้าของเปิดแชทกับเอเจน `github` สั่งงาน แล้วถูกบอกว่าเขียนไฟล์ไม่ได้ ต้นเหตุมีสองชั้น และจาก
หน้าแชทมองเห็นแค่ชั้นเดียว

ชั้นแรกคือรายการเครื่องมือในโปรไฟล์ของเอเจนแคบเกินไป สี่ในหกตัวที่มากับแอปไม่มีเครื่องมือเขียน
ไฟล์ธรรมดาเลย หลักฐานที่ชัดที่สุดว่านี่เป็นข้อจำกัดที่หลุดมา ไม่ใช่การออกแบบ คือคำสั่งงานของ
`github` เองบอกให้มันไปดู repo จาก checkout ทั้งที่มันไม่มีเครื่องมือ `git` และไม่มีเชลล์ให้ใช้เลย

ชั้นที่สองคือเพดานของโต๊ะทำงานที่เอเจนนั่งอยู่ ซึ่งไม่ได้อนุญาตเครื่องมือกลุ่มนั้นไว้ตั้งแต่แรก ต่อให้
แก้โปรไฟล์อย่างเดียวก็ไม่มีอะไรเปลี่ยน ต้องขยับพร้อมกันทั้งสองชั้น

ตอนนี้เอเจนใช้เครื่องมือไฟล์และเชลล์ได้เต็มที่ และความระวังทั้งหมดอยู่ตรงที่ **เครื่องมือเหล่านี้ถูก
เปิดให้เฉพาะเอเจน ไม่ได้เปิดให้ผู้ช่วยหลักที่นั่งโต๊ะเดียวกัน** ผู้ช่วยหลักจึงไม่ได้อะไรเพิ่ม และรายการ
เครื่องมือที่ส่งไปกับทุกข้อความไม่ได้ใหญ่ขึ้นเลย

เครื่องมือลบไฟล์ก็รวมอยู่ด้วย ตามที่เจ้าของสั่งว่า *"ให้พวกมันเข้าถึงได้เต็มที่"* โดยยังมีด่านขออนุมัติ
ทุกครั้งเหมือนเดิม หลักการคือสิทธิ์ต้องมาจากรายการที่ผู้ใช้เห็นและกดเอง ไม่ใช่จากการแอบไม่ให้
เครื่องมือ

เรื่องเล็ก ๆ ที่เจอระหว่างทาง: ห้าในหกเอเจนไม่เคยมีความจำเป็นของตัวเองเลย ตอนนี้มีครบทุกตัว

## 5. เครื่องมือที่ไม่มีใครใช้ แต่ถูกคิดเงินทุกข้อความ

เจ้าของกางรายการเครื่องมือทั้งหมดแล้วถามถึงบรรทัดหนึ่ง: *"notebook_edit … ลบออกดีไหมอ่ะ
เพราะเรายังไม่เคยใช้จริงเลย จะประหยัดโทเค็นไหมครับ"*

คำตอบมาจากบันทึกการใช้งานจริง ไม่ใช่จากความเห็น: ถูกเรียก **0 ครั้งจาก 2,687 ครั้ง** ที่บันทึกไว้
ตั้งแต่ 4 ส.ค. เทียบกับ **317 โทเคน** ที่ต้องจ่ายไปกับคำอธิบายของมันในทุกข้อความ ก่อนผู้ใช้จะ
พิมพ์อะไรด้วยซ้ำ

แต่การลบไฟล์ทิ้งไม่ใช่ทางเลือก เพราะโค้ดที่ทำให้ **อ่าน** ไฟล์โน้ตบุ๊กได้อยู่ในไฟล์เดียวกัน ทางที่
เลือกคือทางกลาง: โค้ดยังอยู่ แต่ไม่ถูกลงทะเบียนเป็นเครื่องมือ ผลคือโน้ตบุ๊กยังอ่านได้ และกลาย
เป็น **อ่านอย่างเดียว** การเปิดกลับใช้แก้บรรทัดเดียว

## 6. OCR: "ติดตั้งแล้ว" กับ "หาเจอ" เป็นคนละเรื่อง

เจ้าของอ่านล็อกตัวติดตั้งของ v1.2.4 ที่ลงสะอาด ๆ แล้วถามว่าทำไมตัวอ่านภาพยังใช้ไม่ได้

ล็อกพูดความจริง Tesseract ถูกติดตั้งแล้วจริง ๆ ที่ `C:\Program Files\Tesseract-OCR` แต่แอป
**หามันไม่เจอ** เพราะตัวติดตั้งของ Tesseract เพิ่มพาธให้ผ่านช่องติ๊กบนหน้าจอ ซึ่งการติดตั้งแบบ
เงียบไม่เคยแสดงหน้านั้น แอปเลยบอกให้ไปติดตั้งของที่ติดตั้งอยู่แล้ว สองเรื่องนี้ถูกนับเป็นเรื่องเดียว
มาตลอด คือ "ตัวติดตั้งวางไฟล์ลงเครื่อง" ซึ่งถูกตรวจแล้ว กับ "โปรแกรมหาไฟล์นั้นเจอ" ซึ่งไม่เคย
ถูกตรวจเลย

คำถามถัดมาว่ามันอ่านภาษาอะไรได้บ้าง พาไปเจอปัญหาที่ใหญ่กว่า: Tesseract ที่ถูกตั้งให้อ่านไทย
กับอังกฤษ **ไม่ปฏิเสธ** หน้าที่เป็นภาษาจีน มันคืนตัวอักษรไทยที่ดูเหมือนอ่านได้ออกมาพร้อมสถานะ
ว่าสำเร็จ ของที่อ่านได้ครึ่งเดียวควรบอกว่าอ่านได้ครึ่งเดียว ตอนนี้มันบอกแล้ว

## 7. ความจำ ชื่อไฟล์ และการแจ้งปัญหา

**ข้อเสนอที่รอการอนุมัติกดแล้วบันทึกลงความจำได้จริงแล้ว** จากเดิมที่กดแล้วไม่มีอะไรเกิดขึ้น

**ชื่อไฟล์จะถูกส่งไปกับข้อความ ก็ต่อเมื่อผู้ใช้เป็นคนตั้งชื่อเอง** เดิมหัวข้อของทุกไฟล์ที่พับเข้าไปใน
ข้อความขึ้นต้นด้วยพาธเต็ม ซึ่งแปลว่า **ชื่อบัญชีผู้ใช้ของเครื่องถูกส่งไปด้วยทุกครั้ง** เส้นแบ่งใหม่คือ
ใครเป็นคนตั้งชื่อ ถ้าเป็นไฟล์ที่ผู้ใช้ตั้งชื่อเอง ชื่อนั้นมีความหมายและถูกส่งไป ถ้าเป็นไฟล์ที่ Aetox
ตั้งชื่อให้ ก็ไม่ต้องส่ง

**การ์ดแจ้งปัญหาถูกจัดกลุ่มถูกต้องแล้ว** ตัวกรองทำงานถูกอยู่แล้ว แต่ไม่มีใครติดป้ายบอกว่าข้อความ
ผิดพลาดแต่ละอันคืออะไร การ์ดสี่ใบบนจอเจ้าของจึงผ่านตัวกรองไปหมด ตอนนี้ความผิดพลาดจากระบบ
ปฏิบัติการถูกรู้จักที่จุดเดียว ครอบคลุมเครื่องมือไฟล์ทุกตัวพร้อมกัน

**และปุ่ม "แจ้งปัญหานี้" เปิดหน้าเว็บได้จริงแล้ว** เดิมมันไม่เปิดอะไรเลยและไม่บอกด้วยว่าทำไม
สาเหตุมีสองอย่าง: ล็อกภาษาไทย 4,000 ตัวอักษรพองเป็นราว 36,000 ตัวอักษรเมื่อเข้ารหัสลง URL
ซึ่งเกินความยาวบรรทัดคำสั่งที่วินโดวส์รับได้ และก่อนจะถึงตรงนั้น URL ที่มีวงเล็บก็ถูกปฏิเสธตั้งแต่ต้น
ทางอยู่แล้ว ซึ่งการ์ดปัญหาทุกใบมีวงเล็บ

หน้า **การเชื่อมต่อ** กลับมาเป็นหน้าเดียวหลังแยกเป็นสองหน้าอยู่เก้าวัน เจ้าของสรุปว่า *"มันคือ
อันเดียวกันแท้ๆ เชื่อมต่อแอปภายนอก เอาคีย์ไปใส่"*

## 8. แผงเครื่องมือออกจากโต๊ะทำงาน

เมนู `+` ของโต๊ะทำงานเคยมีสี่รายการ และรายการสุดท้ายผิดประเภท เทอร์มินัล เบราว์เซอร์ ไฟล์
สไลด์ คือ *ที่ที่งานเกิดขึ้น* คุณเปิดมันเพื่อทำอะไรสักอย่างในนั้น ส่วนแผง "เครื่องมือ" เป็นรายการ
ของสิ่งที่ต่อเข้ามา ซึ่งไม่ใช่ที่ทำงาน

และมันตอบคำถามเดียวกับที่หน้าตั้งค่าตอบอยู่แล้ว โดยที่หน้าตั้งค่าทำได้มากกว่า คือติดตั้ง ลบ และ
รีเฟรชได้ ส่วนแผงบนโต๊ะทำไม่ได้สักอย่าง จึงถูกเอาออก ความเสี่ยงจริงคือวันที่สองที่พูดไม่ตรงกัน

แท็บนี้ที่เคยเปิดค้างไว้จะถูกข้ามตอนเรียกคืนเลย์เอาต์ แท็บอื่นของเซสชันนั้นยังกลับมาครบ

## 1. 🖼️ เด็คคือ HTML ส่วนการส่งออกเป็นขั้นตอนต่างหาก

`slides_write` เขียน `.pptx` ได้สี่อย่าง — หัวเรื่อง บุลเล็ต รูปหนึ่งรูป โน้ต — และไม่มีสีบนสไลด์
เลยแม้แต่จุดเดียว เจ้าของเปิดของที่ได้แล้วสรุปสั้น ๆ ว่า *"ตอนนี้มีแค่ตัวหนังสือ"*

ทางที่ **ไม่** เลือกคือขยาย `internal/ooxml` ให้รู้จักตาราง สี เลย์เอาต์ ซึ่งแปลว่าเขียน PowerPoint
ขึ้นมาเอง และถูกตัดออกไปแล้วตั้งแต่ `OFFICE-EXPORT-PLAN §8` ทางที่เลือกคือแยกสองงานที่ถูกมัด
ไว้ด้วยกันออกจากกัน: **โมเดลเขียน HTML** ซึ่งเป็นภาษาที่มันคล่องที่สุด แล้ว **ส่งออกทีหลัง**
เป็น PNG หรือ PDF หรือ `.pptx` ตามที่เล็ง

เครื่องหมายเดียวที่รับน้ำหนักคือ `<section class="slide">` ไม่มีอย่างอื่น — `<meta name="aetox-deck">`
ถูกร่างแล้วตัดทิ้ง เพราะเป็นที่ที่สองที่ตอบคำถามเดียวกัน และวันที่สองที่ตอบไม่ตรงกันคือวันที่ไม่มีใคร
รู้ว่าอันไหนถูก ผลข้างเคียงที่ตั้งใจคือ `.html` ที่ไม่มีเครื่องหมายนี้ยังเปิดเป็นซอร์สเหมือนเดิม

การส่งออกใช้ Chromium ที่อยู่ในไบนารีอยู่แล้วจากงานคนละเรื่อง ผ่าน `CallDevToolsProtocolMethod`
หนึ่งเมธอดกับหนึ่งแฮนด์เลอร์ แทนสี่อินเทอร์เฟซ COM และใช้ซ้ำได้กับคำถาม CDP ทุกข้อที่จะตามมา

**สามอย่างที่ตามมาจากการใช้จริง และถูกแก้ในรุ่นเดียวกัน**

เด็ค ๘ สไลด์ออกมา ๑๒ หน้า และตัวเลขในไฟล์บอกเอง: `MediaBox [0 0 948.96 540]` สูงถูก
กว้างขาดไป 14.7px ซึ่งเท่ากับความกว้างสกรอลบาร์พอดี เอกสารที่สูงแปดสไลด์มีสกรอลบาร์ วิวพอร์ต
แคบลง แล้วเลขที่แคบลงนั้นกลายเป็นขนาดกระดาษ ทุกบรรทัดตัดใหม่ สไลด์ล้นหน้า วันนี้สกรอลบาร์
ถูกซ่อนก่อนวัด และทุกสไลด์ถูกตรึงเป็นกล่องเดียวกับใบแรก **หนึ่งสไลด์คือหนึ่งหน้า**

หน้าต่างเรนเดอร์เคยโผล่ทับทั้งแอป และการสั่งให้มันไปอยู่ข้างหลังไม่มีวันได้ผล เพราะหน้าต่างลูก
วาดทับพื้นที่ของแม่เสมอ ส่วน Z-order จัดลำดับระหว่างพี่น้องเท่านั้น — เว็บวิวของแอปไม่ใช่พี่น้อง
มันคือเนื้อของแม่ คำตอบคือหน้าต่างระดับบนสุดของตัวเอง จอดไว้นอกจอ

และระหว่างส่งออก มีแผ่นคลุมบอกว่ากำลังสร้างไฟล์อยู่เบื้องหลัง เพราะการกดปุ่มแล้วเงียบสองสาม
วินาทีอ่านเหมือนแอปค้าง

## 2. 💬 เทิร์นเป็นของบทสนทนา ไม่ใช่ของแอป

`App` เคยถือเอเจนต์ตัวเดียว รีจิสทรีชุดเดียว ทรานสคริปต์เดียว และเคอร์เซอร์ `sessionID` อันเดียว
สิบจุดในเส้นทางเทิร์นถามเคอร์เซอร์นั้นเพื่อ *เดา* ว่ากำลังทำงานของใครอยู่ ซึ่งซื่อสัตย์และถูกต้อง
ตราบเท่าที่มีเทิร์นได้ทีละอัน คำปฏิเสธที่เจ้าของชนซ้ำ ๆ (*"เอเจนกำลังทำงานอยู่ รอให้เสร็จ"*) คือ
เคอร์เซอร์อันนั้นป้องกันตัวเอง

วันนี้ **หนึ่งแชท หนึ่งเอเจนต์ หนึ่งคอนเท็กซ์** อยู่ในแมปที่เรียกด้วย id ของแต่ละบทสนทนา ส่วนของ
แพงยังใช้ร่วมกันตามเดิม — MCP manager ไคลเอนต์ผู้ให้บริการ ฐานข้อมูล ผลที่ตามมาคือทั้งแพ็กเกจ
เลิกถาม "เซสชันปัจจุบัน" แล้วรับ id มาจากผู้เรียกแทน

และ **ทางกลับ** §134.2 เปิดประตูให้อ่านแชทอื่นระหว่างงานเดินไปแล้ว เพราะการอ่านไม่เขียนทับอะไร
แต่ไม่ได้ทิ้งทางกลับที่ผู้ใช้จะหาเจอ เจ้าของชนซ้ำจนพูดออกมาตรง ๆ ว่า *"ตอนสั่งงานเอเจนกำลังทำงาน
พอสลับเซสชั่นปุ๊บ งานเอเจนหายไปเลย"* — งานไม่เคยหาย มันแค่ **ไปถึงไม่ได้** ซึ่งจากเก้าอี้ของคนใช้
คือเรื่องเดียวกัน วันนี้แถบบอกว่าแชทที่กำลังทำงานอยู่กำลังทำอะไร และกดกลับไปได้ตลอด จากรายชื่อ
ที่คนใช้อยู่แล้ว ไม่ใช่จากปุ่มเดียวที่ไม่มีใครเจอ

## 4. 🔓 เอเจนเฉพาะทางเลิกถูกกันออกจากงานที่บรีฟของมันเองสั่ง

เจ้าของเปิดแชทกับเอเจน `github` สั่งงาน แล้วถูกบอกว่าเขียนไฟล์ไม่ได้ กำแพงลึกสองชั้นและมองเห็น
ได้แค่ชั้นแรกจากหน้าแชท

ชั้นแรกคือรายชื่อเครื่องมือในโปรไฟล์: สี่ในหกเอเจนที่มากับตัวแอปแคบ — `github` ถือแค่ตัวมันเอง
กับการอ่าน ส่วน `doc`/`sheet`/`deck` ถือแค่ตัวเขียนของตัวเองกับการอ่าน **ไม่มีตัวไหนเขียนไฟล์
ธรรมดาได้** หลักฐานที่ชัดที่สุดว่านี่เป็นกำแพงไม่ใช่ดีไซน์ อยู่ในบรีฟของ `github` เอง ซึ่งสั่งให้มัน
ไล่ repo จาก `origin` ของ checkout โดยไม่มี `git` และไม่มี `shell` ให้อ่านด้วยสักตัว

ชั้นที่สองคือเพดานของโต๊ะ ทุกเอเจนนั่งที่โต๊ะเฉพาะทาง ซึ่งไม่ได้ตั้งชื่อ `edit`, `grep`, `apply_patch`,
`delete`, `git` ไว้เลย — ขยายโปรไฟล์อย่างเดียวจึงไม่เปลี่ยนอะไร ทั้งสองครึ่งต้องขยับพร้อมกัน

วันนี้ทั้งหมวดไฟล์และหมวดเชลล์อยู่ในห้องให้เอเจนใช้ได้เต็มที่ และ **ความระวังทั้งหมดของงานนี้อยู่
ที่คำว่า `chairs:` แทน `tools:`** — เครื่องมือพวกนี้อยู่ในห้องสำหรับเอเจนของโต๊ะ และยังไม่ได้อยู่บน
โต๊ะของผู้ช่วย ผู้ช่วยที่นั่งโต๊ะเดียวกันจึงไม่ได้อะไรเพิ่ม และบล็อกเครื่องมือของมันไม่โตขึ้นแม้แต่ไบต์เดียว

`delete` รวมอยู่ด้วย ตามคำสั่ง *"ให้พวกมันเข้าถึงได้เต็มที่"* และบนกำลังของด่านที่อยู่หน้ามัน:
`internal/safety` ให้มันเป็นความเสี่ยงสูง มันจึงถามทุกครั้ง สิทธิ์มาจากรายชื่อที่ผู้ใช้เห็น ไม่ใช่จาก
การแอบไม่ให้เครื่องมือ ส่วนที่ยังปฏิเสธอยู่คือหมวด **code** (`diagnostics`, `symbol`) ซึ่งตอนนี้เป็น
กำแพงเดียวที่เหลือของโต๊ะนี้

เรื่องเงียบ ๆ ที่เจอระหว่างทาง: ห้าในหกเอเจนไม่เคยตั้งชื่อ `memory` เลย แปลว่ามันวิ่งมาโดยไม่มี
ความจำของตัวเองสักไฟล์ ทุกตัวมีแล้ววันนี้

## 5. 🧾 เครื่องมือที่ไม่มีใครเรียก แต่ถูกคิดเงินทุกรีเควสต์

พอกางรายการเครื่องมือทั้งหมดให้ดู เจ้าของถามถึงบรรทัดหนึ่ง: *"notebook_edit … ลบออกดีไหมอ่ะ
เพราะเรายังไม่เคยใช้จริงเลย จะประหยัดโทเค็นไหมครับ"*

คำตอบมาจาก `tool_runs` ไม่ใช่จากความเห็น: **ศูนย์ครั้งจาก 2,687 รอบ** ที่บันทึกไว้ตั้งแต่ 4 ส.ค.
เทียบกับ **317 โทเค็น** ในบล็อกของทุกโต๊ะที่ถือหมวดไฟล์ จ่ายทุกรีเควสต์ก่อนผู้ใช้จะพิมพ์อะไรด้วยซ้ำ

แต่ **การลบไฟล์ทิ้งไม่เคยเป็นหนึ่งในตัวเลือก** เพราะ `read` เรนเดอร์ `.ipynb` เป็นเซลล์ที่มีเลขกำกับ
ด้วยโค้ดในไฟล์เดียวกัน ลบไฟล์ก็คือลบการอ่านโน้ตบุ๊กทิ้งไปด้วย ตัวเลือกจึงมีสามทาง ไม่ใช่สอง และ
ทางกลางคือทางที่เลือก: ชนิดยังคอมไพล์อยู่ แต่ **ไม่ถูกลงทะเบียน** โน้ตบุ๊กยัง **อ่านได้** และกลายเป็น
**อ่านอย่างเดียว** ซึ่งเป็นคำอธิบายที่ซื่อสัตย์ เพราะไม่มีเครื่องมืออื่นแก้มันได้จริง

การเปิดกลับคือบรรทัดเดียวใน `defaults.go` และคอมเมนต์ตรงนั้นตั้งชื่อไฟล์ที่เหลือให้ครบ ส่วนหมุด
ขนาด 317 โทเค็นถูกเก็บไว้ตั้งใจ: มันคือขนาดที่เครื่องมือนี้จะกลับมา และการกลับมาเกินมาตรฐาน
ควรต้องถูกสังเกต ไม่ใช่ได้มาฟรี

## 6. 🔍 OCR: "ติดตั้งแล้ว" กับ "หาเจอ" เป็นคนละคำถาม

เจ้าของอ่านล็อกของตัวติดตั้งหลังลง v1.2.4 สะอาด ๆ แล้วถามว่าทำไมตัวอ่านภาพใช้ไม่ได้ ล็อกพูด
ความจริง: Tesseract ถูกติดตั้งแล้วจริง ๆ อยู่ที่ `C:\Program Files\Tesseract-OCR` ตามที่ออกแบบ
และ **หาไม่เจอ** เพราะตัวติดตั้งของมันเพิ่ม PATH จากช่องติ๊กบนหน้าที่โหมดเงียบไม่เคยวาด แอปจึง
บอกให้ไปติดตั้งของที่มีอยู่แล้ว สองคำกล่าวถูกนับเป็นคำเดียวมาตลอด — **ตัวติดตั้งวางมันลงดิสก์**
ซึ่งจริงและถูกตรวจแล้ว กับ **โปรแกรมหามันเจอ** ซึ่งไม่เคยถูกตรวจเลย

และคำถามถัดมาว่ามันอ่านภาษาอะไรได้ พาไปเจอข้อบกพร่องที่ใหญ่กว่าเรื่องภาษา: Tesseract ที่ถูก
สั่ง `tha+eng` **ไม่ปฏิเสธ** หน้าที่เป็นภาษาจีน มันคืนตัวอักษรไทยที่ดูสมเหตุสมผลพร้อม exit code 0
ของที่อ่านได้ครึ่งเดียวต้องบอกว่าครึ่งเดียว วันนี้มันบอก

## 7. 🧠 ความจำ ชื่อไฟล์ และห้องปัญหา

**ข้อเสนอไม่ใช่ความจำ และคำที่ผู้ใช้พูดถึงตัวเองไม่ใช่การเดา** การ์ดที่กดอนุมัติแล้วลงจริงได้แล้ว

**ชื่อไฟล์จะถูกพิมพ์ลงพร้อมต์ ก็ต่อเมื่อผู้ใช้เป็นคนตั้งชื่อมันเอง** หัวของทุกชั้นเคยขึ้นด้วยพาธเต็ม
ซึ่งแปลว่า **ชื่อบัญชีของเครื่องถูกส่งไปกับทุกรีเควสต์** ที่มีความจำหรือไฟล์ตัวตนให้พับ เป็นค่าเดียวกับ
ที่เคยถูกเขียนใหม่เพื่อเลิกจ่ายไปแล้วครั้งหนึ่ง แค่เข้ามาทางประตูอื่น เส้นแบ่งคือใครเป็นคนตั้งชื่อ:
ไฟล์ตัวตนกับกฎของโปรเจกต์ผู้ใช้ตั้งเอง ส่วนไฟล์ความจำของเอเจนต์ Aetox ตั้งให้

**ตัวกรองห้องปัญหาถูกอยู่แล้ว แต่ไม่มีใครเซ็นแบบฟอร์มให้มัน** กฎคือผู้เขียน error เป็นคนบอกว่า
มันคืออะไร และการ์ดสี่ใบบนจอเจ้าของผ่านตัวกรองไปได้ทั้งสี่ใบเพราะไม่มีใครติดป้ายให้เลย ความ
ล้มเหลวของระบบปฏิบัติการถูกรู้จักด้วยชนิดที่จุดเดียว ครอบคลุมเครื่องมือไฟล์ทุกตัวพร้อมกัน

**และปุ่ม "แจ้งปัญหานี้" เปิดของมันได้จริงแล้ว** มันไม่เคยเปิดอะไรเลยและเงียบด้วย จากสองสาเหตุ
ไม่ใช่หนึ่ง — ล็อกไทย 4,000 ตัวอักษรบวมเป็นราว 36,000 เมื่อเข้ารหัส ขณะที่วินโดวส์จำกัดบรรทัด
คำสั่งไว้ 32,767 และก่อนจะถึงตรงนั้น URL ที่มีวงเล็บถูกปฏิเสธตั้งแต่ต้นทาง — ซึ่งเหตุผลของการ์ด
ปัญหาทุกใบมีวงเล็บ

หน้า **การเชื่อมต่อ** ก็กลับมาเป็นหน้าเดียว หลังแยกเป็นสองหน้าอยู่เก้าวัน เหตุผลตอนแยกไม่ผิด
แต่มันเล็กกว่าสิ่งที่ทั้งสองอย่างมีร่วมกัน ซึ่งเจ้าของสรุปว่า *"มันคืออันเดียวกันแท้ๆ เชื่อมต่อแอป
ภายนอก เอาคีย์ไปใส่"*

## 8. 🧰 กล่องเครื่องมือออกจากโต๊ะทำงาน

เมนู `+` ของโต๊ะทำงานเคยมีสี่รายการ และรายการสุดท้ายผิดชนิด เทอร์มินัล เบราว์เซอร์ ไฟล์ สไลด์
คือ **ที่ที่งานเกิดขึ้น** เปิดมันเพื่อทำอะไรสักอย่างในนั้น ส่วนแผง "เครื่องมือ" คือรายการของ MCP
กับสกิลภายนอกที่ผู้ใช้เสียบเข้ามา ซึ่งไม่ใช่ที่ทำงาน มันคือข้อเท็จจริงว่าเครื่องนี้ถูกตั้งค่าไว้ยังไง

และมันเป็นที่ที่สองที่ตอบคำถามที่ Settings ตอบอยู่แล้ว — **เครื่องมือ**, **สกิลภายนอก**, **MCP
servers** อยู่ครบในนั้น พร้อมติดตั้ง ลบ และรีเฟรช ซึ่งแผงบนโต๊ะทำไม่ได้สักอย่าง ไม่มีอะไรหายไป
กับการลบมัน สิ่งที่เสี่ยงจริงคือวันที่สองรายการนี้พูดไม่ตรงกัน

แท็บที่เคยเปิดค้างไว้ในเลย์เอาต์เก่าจะถูกข้ามตอนเรียกคืน เหมือนที่แผง Review ที่ถูกถอดไปก่อนหน้า
ถูกข้าม แท็บที่เหลือของเซสชันนั้นยังกลับมาครบ

## 9. 🌐 หน้าเว็บเหลือหน้าเดียว

แลนดิ้งเพจถูกรื้อใหม่ทั้งหน้า เอาหลักฐานงานจริงขึ้นหน้าแรก และยืมภาษาภาพมาจากแอปเอง ส่วน
เอกสารที่เคยกระจายเป็นหลายหน้าเว็บลงมาอยู่บน GitHub ที่เดียว ซึ่งเป็นที่ที่มันถูกอ่านจริงอยู่แล้ว

## ⚠️ สิ่งที่รุ่นนี้ยังไม่ได้ติ๊ก

**สองข้อของการส่งออกเด็คยังไม่ได้พิสูจน์บนเครื่องหลากหลาย** PDF ผ่าน CDP ไมโครซอฟท์ไม่ได้
รับรองว่าใช้ได้ และการ compose ของหน้าต่างที่จอดนอกจอเป็นข้อสันนิษฐาน ถ้าผิด ตัวตรวจภาพว่าง
จะจับได้แล้วขึ้น error แทนที่จะเขียนโฟลเดอร์ของสี่เหลี่ยมเปล่า เจ้าของยืนยันผลบนเครื่องของเขาแล้ว
ทั้ง PNG และการแบ่งหน้า PDF

**เปิดแชทที่สองเพื่อทำงานจริงกลางเทิร์นยังถูกปฏิเสธ** สิ่งที่ลงในรุ่นนี้คือคอนเท็กซ์ต่อบทสนทนาและ
ทางกลับที่หาเจอ ช่องพิมพ์ในแชทที่เปิดอ่านยังปิดอยู่ ขั้นที่เหลือของ §134.4 เป็นงาน ไม่ใช่แพตช์

**เอเจนที่ถูกขอสิ่งที่เครื่องมือในมือทำไม่ได้ ยังไม่พูดออกมาตรง ๆ** การขยายชุดเครื่องมือลดโอกาส
ที่จะเจอ แต่ไม่ได้แก้กลไก กำแพงที่เก็บไว้ตั้งใจยังผลิตประโยคผิดแบบเดิมได้อยู่

**โน้ตบุ๊กเป็นอ่านอย่างเดียว** ตั้งใจ ตามข้อ 5 ห้องโน้ตบุ๊กบนหน้าโค้ดยังไม่มี และวันที่มันมา
เครื่องมือนี้อยู่ห่างไปหนึ่งบรรทัด

**Linux / macOS ยังเป็นพอร์ตที่ทำอยู่** และการเซ็นโค้ดยังไม่มี (ตัวติดตั้งยังขึ้น SmartScreen) —
แต่ตัวรุ่นที่ปล่อยเซ็นด้วย ed25519 ตั้งแต่ v0.9.4 และตัวอัปเดตปฏิเสธลายเซ็นที่ไม่ผ่าน

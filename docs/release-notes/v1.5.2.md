# 🧩 Aetox v1.5.2

รุ่นนี้มีของใหม่หนึ่งอย่างที่ใหญ่ กับบั๊กสี่ตัวที่มาจากผู้ใช้จริงและจากการนั่งเทสเอง
ของใหม่คือ **สกิลงานสี่ตัวติดมากับตัวติดตั้งแล้ว** ไม่ต้องไปหามาลงเอง

**สรุปสั้น ๆ ก่อน**

- **สกิลงานสี่ตัวติดมากับแอปเลย** — อ่านโครงสร้างระบบแล้วเขียนเป็นเอกสาร, งานภาพ,
  ระบบดีไซน์โทเคน, และงานแบรนด์ ลงแอปเสร็จมีให้ใช้ทันที
- **คำตอบที่ยาวเกินกำหนดทำให้งานทั้งเทิร์นหายไปเฉย ๆ** ผู้ใช้บน Gemini เจอทุกครั้งที่
  สั่งให้เขียนไฟล์ใหญ่ ๆ และมันหายหลังจากโมเดลทำงานเสร็จและจ่ายเงินไปแล้ว
- **โมเดล OpenAI รุ่นปัจจุบันตอบ 400 กับ 404 ทุกตัว** เพราะแอปยิงผิดปลายทาง
- **ผู้ใช้ปิดแท็บเบราว์เซอร์ระหว่างเอเจนทำงาน แล้วค้างไปทั้งเทิร์น** ไม่ error ไม่หมดเวลา
  ไม่มีอะไรในบันทึก
- **เปิดเด็คค้างไว้แล้ว Space กับลูกศรถูกกินไปเดินสไลด์** ทั้งที่กำลังพิมพ์อยู่ในช่องพร้อมต์

## 1. สกิลงานสี่ตัว ติดมากับตัวติดตั้ง

**ของใหม่** ลง Aetox แล้วมีสกิลพวกนี้อยู่แล้ว ไม่ต้องดาวน์โหลด ไม่ต้องตั้งค่า

- **`aetox-architect`** — อ่านระบบที่มีอยู่จริงแล้วกางออกมาเป็นเอกสาร เดินเก้าขั้นตั้งแต่รับโจทย์
  สำรวจของจริง ถามสิ่งที่ยังไม่รู้ วาดแผนที่โมดูลกับการไหลของข้อมูล ประเมินหนี้ทางเทคนิคกับ
  ความเสี่ยง แล้วเขียนออกมาจากแม่แบบ 11 ใบ ใช้ตอนต้องเข้าใจโค้ดเบสก่อนลงมือ ตรวจระบบ
  ปัจจุบัน หรือส่งงานต่อให้คนอื่น
- **`aetox-design`** — โลโก้ ไอคอน แบนเนอร์ ภาพโซเชียล และชุดอัตลักษณ์องค์กร พร้อม
  แคตตาล็อกสไตล์ สีตามอุตสาหกรรม และขนาดมาตรฐานของทุกแพลตฟอร์ม
- **`aetox-design-system`** — โทเคนสามชั้น สเปกคอมโพเนนต์ และตารางที่บอกว่าเด็คแบบไหน
  ควรใช้เลย์เอาต์ไหน กราฟไหน คำโปรยแบบไหน
- **`aetox-brand`** — เสียงและน้ำเสียง โครงข้อความ กฎการใช้โลโก้ และเช็กลิสต์ก่อนปล่อยงาน

**เรื่องเดิมที่ต้องแก้ก่อนถึงจะทำได้** สกิลที่คนเขาเผยแพร่กันจริง ๆ ไม่ใช่ไฟล์เดียว มันคือ
"สารบัญ" ที่ชี้ไปโฟลเดอร์ข้าง ๆ ตัว แต่ Aetox ฝังได้แค่ตัวสารบัญ สกิลที่ชิปมากับแอปจึงเป็น
เอกสารที่เต็มไปด้วยประตูที่เปิดออกไปแล้วไม่มีอะไรอยู่หลังมัน

ที่น่าสนใจคือ **ฝั่งของผู้ใช้ไม่เคยมีปัญหานี้** สกิลที่ลงเองใน `~/.aetox/skills` อ่านไฟล์ลูกได้
มาตลอด ที่ขาดคือฝั่งของที่แอปแถมมา ซึ่งแปลว่าของที่ผู้ใช้เอามาลงเองมีสิทธิ์มากกว่าของที่แอป
ให้มาเอง — ความเหลื่อมที่ไม่มีใครตั้งใจให้มี

**รุ่นนี้** โฟลเดอร์ทั้งก้อนเดินทางไปกับแอป และเรื่องนี้พลอยแก้ให้อีกที่หนึ่งด้วย: **สกิลที่ติดมา
กับตัวเอเจน** ก็พกโฟลเดอร์ของตัวเองได้แล้วเหมือนกัน ซึ่งเป็นครึ่งที่ขาดไปของหลัก "หนึ่งเอเจน
หนึ่งโฟลเดอร์"

**เรื่องที่พูดตรง ๆ ไว้ในสกิลงานภาพ** แอปนี้ไม่มีโมเดลสร้างภาพ และสกิลบอกเรื่องนี้เป็น
ประโยคแรก แทนที่จะแกล้งทำเป็นมี สิ่งที่มันทำได้จริงมีสองมือ คือ **วาดเอง** ด้วย SVG กับ HTML
(ซึ่งเป็นคำตอบที่แข็งที่สุดสำหรับโลโก้ที่ทำจากตัวอักษรกับรูปทรง) และ **หารูปจริงจากเน็ต** มาใช้
พร้อมกฎเรื่องลิขสิทธิ์ภาพว่าอย่าเอารูปจากหน้าไหนก็ไม่รู้มาบอกว่าใช้ได้

ส่วนการส่งออกเป็นไฟล์ภาพ วัดจริงแล้วว่าเบราว์เซอร์ Edge ที่ติดมากับ Windows ทุกเครื่องทำได้
ทุกขนาด รวมกับดักที่เจอตอนวัด: พาธของไฟล์ปลายทางต้องเป็นพาธเต็ม ไม่งั้นมันล้มเงียบ ๆ โดยที่
คำสั่งดูเหมือนสำเร็จ

**ที่คัดออกไม่เอา** สกิลสาย React (shadcn, ui-styling, การย้าย Radix ไป Base UI) เพราะผูก
กับเวอร์ชันไลบรารีที่จะเน่าอยู่ในตัวติดตั้ง และแก้ไม่ได้จนกว่าจะออกแอปรุ่นใหม่ — ของแบบนั้นอยู่
ที่ `~/.aetox/skills` แล้วอัปเดตเมื่อไหร่ก็ได้ ดีกว่า

## 2. คำตอบยาว ๆ ทำให้งานทั้งเทิร์นหายไป

**เรื่องเดิม** ผู้ใช้รายงานมาว่าเทิร์นไหนที่สั่งให้เขียนไฟล์ใหญ่ ๆ จะจบด้วยข้อความนี้ทุกครั้ง

> เกิดข้อผิดพลาด: bufio.Scanner: token too long

เปิดแชทใหม่ก็ยังติด ซึ่งเป็นเบาะแสที่ดี เพราะมันแปลว่าไม่เกี่ยวกับความยาวของประวัติแชท แต่
เกี่ยวกับ**ขนาดของคำตอบ**

ตัวอ่านคำตอบแบบไหลของ Aetox มีเพดานบรรทัดละ 64 KB ซึ่งเป็นค่าเริ่มต้นของไลบรารี และมี
ทางเดียวจากสี่ทางที่เคยยกเพดานนั้นไว้ ส่วน Gemini วิ่งผ่านทางที่ไม่ได้ยก แล้วฝั่งนั้นส่งพารามิเตอร์
ของคำสั่งทั้งก้อนมาในบรรทัดเดียว พอเกิน 64 KB สายก็ขาด

จุดที่แย่ที่สุดคือ**เวลาที่มันขาด**: หลังจากโมเดลคิดเสร็จ เขียนเสร็จ และถูกเรียกเก็บเงินไปแล้ว
งานที่จ่ายไปแล้วถูกทิ้งทั้งก้อน

**รุ่นนี้** ทั้งสี่ทางใช้ตัวอ่านตัวเดียวกันหมด เพดาน 8 MiB และมีเทสกันไว้ว่าไม่มีทางไหนกลับไป
รับค่าเริ่มต้นได้อีก

## 3. โมเดล OpenAI รุ่นปัจจุบันตอบ 400 กับ 404 ทุกตัว

**เรื่องเดิม** ใส่คีย์ OpenAI แล้วเลือกโมเดลไหนก็ตอบไม่ได้ เรื่องนี้แก้ผิดมาสองรอบก่อนหน้า
เพราะเดาเอาจากเอกสาร ไม่มี error จริงในมือ รอบนี้มีแล้ว สองบรรทัดจากแอปของเจ้าของเอง

> 400 — Function tools with reasoning_effort are not supported for gpt-5.6-luna in
> /v1/chat/completions. To use function tools, use /v1/responses or set reasoning_effort to 'none'.

> 404 — This is not a chat model and thus not supported in the v1/chat/completions endpoint.

บรรทัดแรกคือตัวตัดสิน โมเดลรองรับปลายทางเดิมจริงตามเอกสาร แต่ไม่รองรับ **"มีเครื่องมือ +
เปิดปุ่มคิด" พร้อมกัน** ซึ่งคือทุกเทิร์นของแอปนี้ ปลายทางเองบอกทางออกไว้สองทาง คือย้าย
ปลายทาง หรือปิดปุ่มคิดทิ้ง — และทางที่สองคือการลบความสามารถออก

บรรทัดที่สองคือตระกูลที่เสิร์ฟที่ปลายทางใหม่ที่เดียว (Pro, codex, cyber) ซึ่งคีย์ OpenAI
เรียกไม่ได้เลยมาก่อนหน้านี้

**รุ่นนี้** ค่าเริ่มต้นเป็น `/responses` ส่วน `/chat/completions` ยังเลือกกลับได้ในตั้งค่า สำหรับคน
ที่เอาแถวนี้ไปชี้ปลายทางที่รองรับรูปแบบ OpenAI ของเจ้าอื่น

## 4. ปิดแท็บเบราว์เซอร์ระหว่างเอเจนทำงาน แล้วค้างทั้งเทิร์น

**เรื่องเดิม** ผู้ใช้ปิดแท็บที่เอเจนกำลังใช้อยู่ แล้วทุกอย่างหยุดนิ่ง ไม่มี error ไม่มีการหมดเวลา
ไม่มีอะไรในบันทึก และคำสั่งเบราว์เซอร์ทุกคำสั่งหลังจากนั้นก็ไปเข้าคิวต่อกัน

ข้างในมีตัวล็อกที่ยกธง "เริ่มแล้ว" ขึ้นก่อนจะไปหาหน้าต่างจริง คนที่สองที่เข้ามาระหว่างนั้นเห็นธง
ขึ้นแล้วไปจอดรอ ส่วนคนแรกพอหาไม่เจอก็ปลดธงแล้วเดินจากไป โดยไม่เคยปลุกคนที่จอดอยู่ —
รอไปตลอดอายุโปรเซส (ที่กด "หยุด" แล้วหายไม่ใช่เพราะมันถูกปลุก แต่เพราะ "หยุด" ยกเลิกทั้ง
เทิร์นทิ้ง)

**รุ่นนี้** ตัวล็อกถูกปิดครั้งเดียวเสมอ ทั้งตอนสำเร็จและตอนล้ม พร้อมเหตุผลติดไปด้วย ตัวที่ล้ม
ปลุกทุกคนที่รออยู่แล้วเตรียมให้คนถัดไปลองใหม่ได้ และมีเพดาน 10 วินาทีคุมอีกชั้น เพราะการรอ
ที่ไม่มีเพดานคือสิ่งเดียวที่ระบบนี้ทำไม่ได้

**อีกครึ่งคือให้โมเดลรับรู้** เดิมพอผู้ใช้ปิดแท็บ เอเจนได้ข้อความเดียวกับตอนที่ยังไม่เคยเปิดหน้า
เลย ("ยังไม่ได้เปิดหน้า ใช้ open ก่อน") อ่านกลางงานแล้วเหมือนโดนกล่าวหา โมเดลก็เถียงว่ามัน
เปิดไปแล้ว แทนที่จะเปิดใหม่แล้วทำต่อ ตอนนี้แยกสองเรื่องนี้ออกจากกัน

> **เจ้าของ (22 ส.ค.):** "มันไม่ควรหยุดสิ การเปลี่ยนแปลงอะไรในเบราว์เซอร์หรือการกดอะไร
> คือแอ็คชั่นฝั่งผู้ใช้ โมเดลยังรับรู้และทำงานของตัวเองได้สิ เว้นแต่จะถูกกดหยุด"

## 5. เปิดเด็คค้างไว้แล้วปุ่มถูกกิน

**เรื่องเดิม** เปิดสไลด์ค้างไว้ แล้วกด Space ในช่องพร้อมต์ — ไม่เว้นวรรค แต่ไปเดินสไลด์แทน
ลูกศร Home End ก็ชุดเดียวกัน และอาการยังเห็นตอนสลับไปดูเบราว์เซอร์ด้วย

สองสาเหตุคนละชั้น ชั้นแรก ห้องสไลด์ฟังปุ่มที่ระดับหน้าต่าง (ซึ่งจำเป็น เพราะเด็คควรเดินได้โดย
ไม่ต้องคลิกที่สไลด์ก่อน) แต่หน้าต่างเดียวกันนั้นมีช่องพร้อมต์อยู่ด้วย ชั้นที่สอง โต๊ะเก็บทุกแท็บ
ค้างไว้แล้วซ่อนอันที่ไม่ได้ใช้ (เพราะเทอร์มินัลกับเบราว์เซอร์ถอดแล้วต่อกลับไม่ได้) ห้องสไลด์ที่
มองไม่เห็นจึงยังฟังอยู่

**รุ่นนี้** ปุ่มที่กดลงในช่องพิมพ์เป็นของช่องพิมพ์ และห้องรับปุ่มเฉพาะตอนเป็นแท็บที่อยู่บนจอ

**แอปยังสร้างรูปเองไม่ได้** สกิลงานภาพพูดเรื่องนี้ไว้ตรง ๆ และเสนอทางที่ทำได้จริงแทน แต่ถ้า
สิ่งที่คุณอยากได้คือ "พิมพ์บรรยายแล้วได้รูป" รุ่นนี้ยังไม่ใช่

**คำว่า "ใช้เร็วเกินไป" กับ "โควตาหมดยาว" ยังแยกกันไม่ออกในบางเจ้า** ยกมาจาก v1.5.0
ยังไม่แก้

**ยังไม่ได้เซ็นโค้ด** Windows จะยังขึ้นเตือน SmartScreen ส่วนไฟล์รุ่นที่ปล่อยออกมาถูกเซ็นด้วย
ลายเซ็น ed25519 ตั้งแต่ v0.9.4 เหมือนเดิม

**Linux / macOS ยังทำอยู่** สถานะพอร์ตจริงอยู่ที่ [PLATFORM-SUPPORT.md](../../PLATFORM-SUPPORT.md)

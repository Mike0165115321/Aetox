# 🚀 Aetox v0.8.9 Release Notes — ฐานของการเรียนรู้ และสี่อย่างที่การทดสอบจริงเปิดโปง

รุ่นนี้มีเส้นเรื่องเดียวแต่ยาว: **วางฐานให้ Aetox เรียนรู้จากงานที่ทำเสร็จได้** — และระหว่างทดสอบฐานนั้นด้วยมือจริง ก็เจอบั๊กสี่ตัวที่ไม่มีเทสต์ไหนจับได้ ทั้งสี่เป็นอาการเดียวกัน: **ระบบพูดไม่ตรงกับสิ่งที่ตัวเองเป็น**

> ⚠️ รุ่นนี้ยัง **ไม่มีการเรียนรู้อัตโนมัติ** — สิ่งที่เพิ่มคือ *ฐาน* ที่ชั้นการเรียนรู้จะยืนบนมัน ทุกอย่างที่เอเจนต์เสนอต้องให้คุณอนุมัติก่อนเสมอ และปิดทั้งระบบได้ด้วยสวิตช์เดียว

---

### 1. 🧠 ฐานของการเรียนรู้ (§82)

ปัญหาที่แท้จริงไม่ใช่ "จำไม่ได้" แต่คือ **"วัดไม่ได้"** — Aetox บันทึกทุก tool call มาตั้งแต่ v0.8.2 แต่ `ok` แปลว่า "เครื่องมือไม่ error" ซึ่ง OCR ที่อ่านผิดอย่างมั่นใจก็ผ่าน ระบบที่บอกไม่ได้ว่างานไหนดี ปรับปรุงตัวเองไม่ได้ ทำได้แค่เปลี่ยนตัวเองแล้วเรียกว่าดีขึ้น

* **ตาราง `jobs`** — หนึ่งแถวต่อหนึ่งงาน (หนึ่งเทิร์น หรือหนึ่งงานที่ส่งให้ซับเอเจนต์) เก็บ *รูปทรง* ของงานไว้เป็น `read>image_ocr>sheet_write` ซึ่งหา "งานนี้เคยทำมาแล้วห้าครั้ง" ได้ด้วย SQL ล้วน ไม่ต้องเรียกโมเดล
* **👍/👎 ใต้คำตอบ** — กดซ้ำที่เดิมคือถอนคะแนน · และ **"ตอบใหม่" นับเป็นสัญญาณลบให้เอง** เพราะคุณกดปุ่มนั้นอยู่แล้ว ไม่ต้องทำอะไรเพิ่ม (แต่ไม่ทับคะแนนที่คุณให้เอง)
* **ความจำข้ามเซสชัน** — เป็นไฟล์ `.md` ธรรมดาใน `<DataRoot>/memory` ยกโฟลเดอร์ไปใช้กับ Claude Code / Codex ได้ทันที ไม่มีฟอร์แมตเฉพาะของเรา
* **ประตูอนุมัติ** — ทุกอย่างที่เอเจนต์อยากจำหยุดรอคุณ และ**แถวไม่ถูกลบตอนอนุมัติ** มันคือหลักฐานว่าทำไมความจำบรรทัดนั้นถึงอยู่ตรงนั้น ตอบคำถาม "ทำไมมันคิดแบบนี้" ได้เสมอ
* **ขอบเขตบังคับด้วยโครงสร้าง** — ซับเอเจนต์เขียนความจำได้เฉพาะของตัวเอง ไม่ใช่เพราะเราขอ แต่เพราะมัน**ไม่มี scope อื่นให้เรียก** ความจำของลูกจึงไม่ไหลเข้าพรอมป์ของตัวหลัก คอนเท็กซ์ของตัวหลักเลยแบนเท่าเดิมไม่ว่าลูกจะเรียนรู้ไปเท่าไหร่
* หน้า **ตั้งค่า → การเรียนรู้** — สวิตช์ปิด, คิวรออนุมัติพร้อมเหตุผลและบรรทัดเดิมที่จะถูกทับ, ความจำปัจจุบัน, และประวัติที่ตัดสินไปแล้ว · มีจุดเล็ก ๆ บนเฟืองเมื่อมีของรอ เพราะคิวที่ไม่มีใครรู้ว่ามี คือคิวที่ไม่มีวันถูกเคลียร์

### 2. 💬 คำตอบยาวเคยเหลือคำเดียว

เส้นทางสนทนาส่งสตรีมทีละคำเข้าช่อง "ส่งมอบคำตอบ" ทำให้**ทุกคำอ้างตัวเป็นคำตอบทั้งก้อน** บับเบิลจึงกลายเป็นคำนั้น ๆ ทีละ 40ms แล้วค้างที่คำสุดท้าย — คำตอบ markdown เต็มหน้าเหลือเลข `12` ที่หลุดมาจากกลางตาราง

เห็นได้เฉพาะโมเดลที่เรียก tool ไม่ได้ ซึ่งคือโมเดลทดสอบในตัวของ Aetox เอง — provider จริงทุกเจ้าใช้อีกเส้นทางที่ถูกอยู่แล้ว **เป็นบั๊กที่มองไม่เห็นจากที่อื่นเลย**

### 3. 📄 การ์ดไฟล์ยื่นข้อเสนอที่ทำไม่ได้

ถ้าไฟล์ที่ AI สร้างถูกลบไปแล้ว (เอเจนต์ลบเองได้ และโฟลเดอร์ output ก็หมดอายุ) การ์ดยังบอกว่า "โปรแกรมในเครื่องคุณเปิดได้" — กดแล้วได้ error ดิบของ Windows ใส่หน้า

ตอนนี้หน้าจอถามก่อนว่าไฟล์ยังอยู่ไหม ไม่อยู่ก็บอกตรง ๆ และไม่ยื่นปุ่มให้กด · **การ์ดยังอยู่** เพราะเทิร์นนั้นสร้างไฟล์นั้นจริง — ประวัติบอกว่าเกิดอะไรขึ้น หน้าจอบอกว่าตอนนี้จริงอะไร

### 4. 🔧 สองรอบที่เสียไปเปล่า ๆ ทุกครั้ง

* **`shell` ไม่เคยบอกว่ามันรันบน shell อะไร** โมเดลจึงเขียนให้ POSIX ตามข้อมูลฝึก แล้วตายกับ `ls -la` ก่อนหนึ่งรอบเสมอบน Windows — ตอนนี้บอกชื่อ interpreter จริง และชื่อมาจากที่เดียวกับตัวที่รันจริง จะขัดกันไม่ได้
* **บรีฟชัดเจนได้ ทั้งที่ตั้งอยู่บนสิ่งที่ไม่มีอยู่** — สั่งให้ย้ายโปรเจกต์ทั้งที่ไม่มีโปรเจกต์ มันค้นแปดรอบกว่าจะถามว่าอยู่ไหน ตอนนี้สอนไว้ว่า **การค้นที่ว่างเปล่าสองครั้งคือคำตอบ ไม่ใช่เหตุผลให้ค้นกว้างขึ้น**

### 5. 📚 สกิลที่ไม่มีใครเคาะประตู

`skills_list` เป็นประตูมาตั้งแต่ v0.8.4 — สกิลไม่ถูกส่งเข้าคอนเท็กซ์ เรียกดูเมื่อต้องการ ซึ่งทำให้สกิล 300 ตัวมีราคาเท่าสกิล 3 ตัว **แต่พรอมป์ไม่เคยเอ่ยถึงสกิลเลยสักคำ** โมเดลจะเคาะประตูหรือไม่จึงขึ้นกับโชค

เพิ่มหลักการเดียว: *รายการเครื่องมือที่เห็นไม่ใช่ทั้งหมดที่เครื่องนี้ทำได้ — ก่อนจะบอกว่าทำไม่ได้ ให้ไปดูก่อน* · ทดสอบแล้วได้ผล: ถามเรื่องย้าย UI library โดยไม่เอ่ยคำว่าสกิลเลย โมเดลไปเปิดสกิลที่ติดตั้งไว้เองถูกตัว

พร้อมกัน: **`skill_view` เปิดไฟล์ประกอบในสกิลได้แล้ว** (L2) — สกิลยาว ๆ ที่แตกเป็นหลายไฟล์จึงอ่านครบได้ · และแก้ตัวอย่าง path ในคำอธิบายที่กลายเป็นแม่แบบให้โมเดลลอกจนขอไฟล์ผิดชื่อ

### 6. 🧪 เครื่องมือทดสอบในตัว

* `aetox-image:test` + `aetox-markdown:test` **ยุบเป็น `aetox-render:test`** — มันคือ renderer ตัวเดียว เบนช์เดียวพอ (ชื่อเดิมยังใช้ได้ ไม่มีใครต้องแก้อะไร)
* `aetox-tools:test` รับคีย์เวิร์ด `memory` — ทดสอบชั้นการเรียนรู้ได้โดยไม่ต้องมี API key
* **เทสต์เฝ้างบของ tool block** — วัดได้ว่าตอนนี้ 44 เครื่องมือ ≈ 8,800 โทเคนต่อทุกคำขอ เทสต์นี้ไม่ได้จำกัดว่า Aetox ทำอะไรได้ แต่จำกัดว่าอะไรที่ต้องแบกไปทุกที่ ซึ่งเป็นคนละคำถาม และเป็นคำถามที่ไม่เคยถูกถาม

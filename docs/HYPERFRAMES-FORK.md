ฟอร์กนี้**ไม่ได้ถูกฝังในตัวติดตั้ง** ก้อนที่ได้ยังเป็นซิปราว 150 MB แตกออกมา 374 MB
โหลดเมื่อคนกดปุ่มในห้องงานวิดีโอ เหมือนเดิมทุกอย่าง การเป็นเจ้าของซอร์สไม่ได้
เปลี่ยนข้อนี้แม้แต่ไบต์เดียว

## กฎข้อเดียวที่ต้องจำ: diff ต้องเล็ก

ฟอร์กนี้มีไว้ใส่แพตช์สามข้อ ไม่ใช่จุดเริ่มของการเขียนเอนจินใหม่ ต้นทางมี 4,096
คอมมิตและยังเดินอยู่ ทุกบรรทัดที่เราเพิ่มคือหนี้ที่ต้องเมิร์จทุกครั้งที่ดึงเขาเข้ามา

**ถ้าวันหนึ่งต้นทางรับข้อไหนไป แพตช์ข้อนั้นต้องหายจากฟอร์ก** และของที่เราแก้อ้อมไว้
ฝั่งเราต้องถูกลบตามในคอมมิตเดียวกัน ไม่งั้นจะเหลือโค้ดที่กันปัญหาที่ไม่มีอยู่แล้ว
โดยไม่มีใครกล้าลบเพราะไม่รู้ว่ามันกันอะไร

## สามแพตช์ที่ตั้งใจจะมี และของที่แก้อ้อมไว้ตอนนี้

### 1. ฟอนต์ อ่านจากเครื่องก่อน (ยังไม่ได้ทำ และสำคัญที่สุด)

`fetchGoogleFont` ใน `packages/cli` ยิงหา `fonts.googleapis.com` **ทุกครั้งที่
เรนเดอร์** เพื่อขอ stylesheet ที่ซับเซ็ตตามตัวอักษรบนหน้านั้น แล้วแคชเฉพาะไฟล์
ฟอนต์ที่ stylesheet นั้นชี้ ไม่มีเส้นทางอ่านจากเครื่องก่อนเลย

**อย่าเสียเวลาไปกับสองทางที่พิสูจน์แล้วว่าไม่ได้ผล**

- เอาไฟล์ฟอนต์ไปวางในแคชล่วงหน้า ไม่ช่วย เพราะขั้นที่ยิงเน็ตคือขั้นขอ stylesheet
  ซึ่งเกิดก่อนแคชเสมอ
- `hyperframes-localize-fonts` ที่เขามีให้ ฝังฟอนต์เป็น base64 ในไฟล์ได้จริง
  (ทดสอบแล้ว `statement-title` จาก 6.9 KB เป็น 300 KB) **แต่มันซับเซ็ตตามตัวอักษร
  ที่อยู่บนหน้านั้นตอนนั้น** เห็นได้จาก `unicode-range` ที่ออกมา พอเอเจนเปลี่ยนคำ
  ตัวอักษรใหม่จะไม่มีในฟอนต์ ใช้เป็นทางออกถาวรไม่ได้

รูปร่างของแพตช์ที่ควรเป็น: เพิ่มตัวแปรแวดล้อมแบบ `HYPERFRAMES_FONT_DIR` ที่ถ้ามี
ฟอนต์ตระกูลนั้นอยู่ในโฟลเดอร์ ให้สร้าง `@font-face` จากไฟล์ในเครื่องและ**ไม่ยิงเน็ต
เลย** ถ้าไม่มีค่อยตกไปทางเดิม แล้วฝั่งเราค่อยทำคลังฟอนต์เป็นรีลีสของเราเอง

**ตอนนี้ยังไม่มีของแก้อ้อม** ฉาก 20 จาก 22 ยังต้องต่อเน็ตตอนเรนเดอร์ (ทุกฉาก
ยกเว้น `bold-portrait-title` กับ `structured-grid`) ถ้าไม่ได้ก็ตก
ไปใช้ฟอนต์สำรอง ไม่พังแต่หน้าตาเพี้ยนโดยไม่มีอะไรบอก

### 2. fast capture เป็นสวิตช์ ไม่ใช่การเดาจาก GPU

`--experimental-fast-capture` เปิดตัวเองเมื่อโพรบเจอ GPU ฮาร์ดแวร์ ทางนั้นย้าย
`[data-composition-id]` เข้าไปใน canvas ที่มันสร้าง ฉากที่ไม่มี composition root
จึงตายที่เฟรมแรกด้วย `HF_DE_COMPOSITION_ROOT_MISSING` **ฉากเดียวกันเรนเดอร์ผ่านบน
เครื่องหนึ่งและตายบนอีกเครื่อง**

**แก้อ้อมไว้ที่** `hyperframesEnvironment()` ใน `desktop/videotooling.go` พิน
`PRODUCER_EXPERIMENTAL_FAST_CAPTURE=false` ไว้ตายตัว
มีเทสต์ `TestTheRendererDoesNotTakeTheFastPathThatSkipsHalfTheLibrary` กันหาย

**ถ้าแพตช์นี้ขึ้นต้นทางแล้ว** ให้ลบทั้งบรรทัดนั้นและเทสต์นั้น แล้ววัดใหม่ว่าเรนเดอร์
ยังผ่านครบ 22 ฉาก

### 3. exit code ของ `check` แยก "เจอปัญหา" ออกจาก "รันไม่ได้"

`hyperframes check` คืนค่าไม่เป็นศูนย์ทันทีที่มีอะไรจะบอก และรายงานทั้งหมดอยู่บน
stdout อ่าน exit code เป็นความล้มเหลวเมื่อไหร่ รายงานหายทั้งอันทันที

**แก้อ้อมไว้ที่** `runHyperframesReport()` ใน `desktop/video_tool.go` ซึ่งแยกสอง
กรณีด้วยการดู `exec.ExitError` ประกอบกับว่ามีข้อความออกมาไหม
มีเทสต์ใน `desktop/video_render_integration_test.go` ที่บังคับว่าคำตอบของ
`video check` ต้องมีหัวข้อ `Lint`, `Layout`, `Contrast` อยู่จริง

## ของที่แก้ฝั่งคลังฉาก ไม่ใช่บั๊กของเอนจิน อย่าเอาไปใส่แพตช์

สามอย่างนี้อยู่ในคลังฉากของเราเองที่
`internal/subagent/profiles/agents/video/skills/video-templates/` และไม่เกี่ยวกับ
ฟอร์ก บันทึกไว้เพราะมันหน้าตาคล้ายกันจนสับสนได้

1. **composition root บน `<body>` ของ 13 ฉากไฟล์เดียว** ประกาศเฟรมกับความยาว
   ถ้าไม่มี ตัวเรนเดอร์ออกมา 1080x1920 ทุกใบและตัดงานที่วาดกว้าง 1920 ทิ้งเงียบ ๆ
2. **Tailwind ที่คอมไพล์ฝังไว้แล้วใน 6 ฉาก** แทนการโหลด `cdn.tailwindcss.com`
   ตอนเรนเดอร์ พิสูจน์ด้วย SSIM 1.000000
3. **GSAP** คลังยังเขียน URL ของ CDN ไว้ตามต้นทาง `video new` เป็นคนเปลี่ยนเป็น
   `vendor/gsap.min.js` ในสำเนาที่ก๊อปออกมา

รายละเอียดทั้งสามอยู่ใน `CREDITS.md` ของคลังฉากนั้น

## วิธีลงแพตช์บนฟอร์ก

โคลนแยกจากโปรเจกต์นี้ ไม่ใช่ submodule ไม่ใช่ worktree ในรีโปนี้

```bash
git clone --branch aetox https://github.com/Mikedev115/hyperframes.git
```

แก้ คอมมิต พุชขึ้นสาขา `aetox` แล้วบิ้วด้วย job ข้างล่าง **คอมมิตแรกของทุกแพตช์
ควรอธิบายว่ามันแก้อะไรของเราและของแก้อ้อมตัวไหนจะถูกลบตาม** เพราะคนที่อ่านมันครั้ง
ต่อไปคือคนที่กำลังจะเมิร์จต้นทางเข้ามาแล้วเจอคอนฟลิกต์

## วิธีดึงต้นทางเข้ามา

```bash
git remote add upstream https://github.com/heygen-com/hyperframes.git
git fetch upstream --tags
git rebase v0.9.0        # หรือแท็กที่จะขึ้นไปหา
```

รีเบสไม่ใช่เมิร์จ เพราะสิ่งที่เราอยากเห็นคือ "แพตช์สามข้อของเราอยู่บนอะไร" ไม่ใช่
ประวัติที่พันกัน หลังรีเบสต้องบิ้วและ**เรนเดอร์ครบทั้ง 22 ฉากใหม่** ก่อนจะพิน

## วิธีบิ้วและพิน

```bash
gh workflow run tools.yml -f only=hyperframes -f node_version=24.20.0
```

`node_version` ไม่มีค่าตั้งต้นโดยตั้งใจ อ่าน LTS ปัจจุบันจาก nodejs.org ก่อนกด
ตัวที่อยู่ในก้อนตอนนี้คือ 24.20.0

อินพุตอีกสองตัวที่ปกติไม่ต้องใส่

- `hyperframes_repo` ตั้งต้นเป็น `Mikedev115/hyperframes` **ส่ง
  `heygen-com/hyperframes` เข้าไปคือทางกลับไปบิ้วต้นทางล้วน ในการดิสแพตช์เดียว
  ไม่ต้องแก้โค้ด**
- `hyperframes_ref` ตั้งต้นเป็น `aetox` ส่ง SHA เข้าไปเมื่อจะบิ้วของที่นิ่งแล้ว
  ซึ่งคือสิ่งที่ควรทำก่อนพิน เพราะไบต์ของสาขาขยับได้ ไบต์ของ SHA ขยับไม่ได้

job จะพิมพ์ URL, SHA256, Marker, ApproxBytes และคอมมิตที่บิ้วออกมา เอาสี่ค่าแรกไป
วางใน `Manifest()` **ถ้าเวอร์ชันใน `packages/cli/package.json` ไม่ตรงกับ
`hyperframes_version` job จะพังตั้งแต่ขั้นที่สาม** ตั้งใจให้พังตรงนั้น ดีกว่าปล่อย
แท็กที่ชื่อบอกเวอร์ชันหนึ่งแต่ข้างในเป็นอีกเวอร์ชัน

## เวลาบิ้วพัง ดูตรงไหนก่อน

| อาการ | น่าจะเป็น |
|:--|:--|
| `bun install` ล้ม | lockfile ขยับหลังรีเบส ลอง `bun install` ในเครื่องก่อนแล้วคอมมิต lockfile ที่ได้ |
| `bun run build` ล้มที่ package ที่ไม่ใช่ cli | สคริปต์ build ตัวแม่เรียงลำดับ workspace ไว้ ถ้าต้นทางเพิ่ม package ใหม่ลำดับเปลี่ยน ดู `scripts.build` ใน `package.json` ราก |
| ไม่มี `packages/cli/dist/cli.js` | tsup ไม่ได้รัน หรือ `files` ใน `packages/cli/package.json` เปลี่ยน job เช็กสองไฟล์นี้ให้อยู่แล้ว |
| ขั้นพิสูจน์บอก `--version` ไม่ตรง | เวอร์ชันถูกสแตมป์ตอนบิ้ว ถ้าไม่ตรงแปลว่าบิ้วคนละคอมมิตกับที่คิด |
| ก้อนใหญ่ผิดปกติ | `onnxruntime-node` คือ 218 MB จาก 374 MB มันเป็น dynamic import ล้วน ลบทิ้งได้ถ้าจะยอมทิ้งฟีเจอร์ลบพื้นหลัง เจ้าของเคยตัดสินไว้ว่าเก็บ |

## ถ้าจะเลิกถือฟอร์ก

ทำได้ในคอมมิตเดียว ไม่ใช่โปรเจกต์

1. ดิสแพตช์ job ด้วย `hyperframes_repo=heygen-com/hyperframes` และ
   `hyperframes_ref=v<เวอร์ชัน>`
2. เอา SHA256 ที่ได้ไปพินตามปกติ
3. ลบ §12 ในเอกสารทิศทาง และลบไฟล์นี้

ของที่แก้อ้อมไว้ฝั่งเราสามข้อยังทำงานได้เหมือนเดิม เพราะมันไม่เคยพึ่งฟอร์ก

# โปรแกรมตัดต่อของห้องงานวิดีโอ

> **ทุกตัวเลขในไฟล์นี้วัดจากเครื่องจริงเมื่อ 30 ส.ค. 2569** บน kinocut 1.15.0
> Python 3.13.14 Windows 11

## ติดตั้งยังไง

เข้าห้อง **งานวิดีโอ** ถ้ายังไม่มีโปรแกรมตัดต่อ จะมีแถบขึ้นใต้การ์ดสองใบพร้อมปุ่ม **ติดตั้ง**
กดแล้วมันโหลดมาเองแบบเดียวกับตอนเปิดโปรแกรมครั้งแรก แถบความคืบหน้าตัวเดียวกับที่โหลด
ffmpeg กับ Tesseract ไม่ต้องยกสิทธิ์ ไม่แตะ PATH ไม่ต้องลง Python ก่อน

ไฟล์ที่โหลดคือซิปเดียว **28.8 MB** (วัดจากรีลีสจริง `tools-kinocut-1.15.0`) ข้างในมี kinocut กับตัวแปลภาษา Python แบบฝังตัวของ
python.org มาด้วยกัน ลงที่ `<DataRoot>/tools/kinocut` แล้ว Aetox เรียกมันด้วย
`python.exe -m kinocut --mcp` โดยไม่ยุ่งกับ Python ตัวอื่นในเครื่องเลย

**ทำไมต้องแถม Python มาด้วย** เพราะ kinocut มีแต่บน PyPI ไม่มีบิ้วเดี่ยว รีลีส v1.15.0
บน GitHub ไม่มีไฟล์แนบสักตัว (ตรวจ 30 ส.ค.) ทางเลือกจึงมีสองทาง คือบอกผู้ใช้ทุกคนให้ไป
ลง Python แล้วรัน pip เอง กับเอาตัวแปลภาษาใส่มาในซิปด้วย ทางแรกคือการให้แอปไปสั่ง
ตัวจัดการแพ็กเกจบนเครื่องคนอื่น ซึ่งเป็นรูปร่างเดียวกับที่ทำให้ตัวติดตั้ง NSIS โดน Defender
ตีตรา Wacapew มาแล้ว

**ขั้นเชื่อมต่อไม่มีแล้ว (1 ก.ย. 2569)** พอซิปลงเครื่องเสร็จ Aetox เขียนรายการ MCP ชื่อ
`kinocut` พร้อมชี้ไปที่เอเจน `editor` ให้เองในจังหวะเดียวกัน (`connectVideoEditor` ใน
[`desktop/videotooling.go`](../desktop/videotooling.go)) การกดติดตั้งบนการ์ดของเอเจนที่
ต้องใช้มันคือคำยินยอมอยู่แล้ว สิ่งที่ตัดออกคือการต้องไปหาเจอเองว่าเชื่อมที่ไหน ไม่ใช่การถาม

มันไม่ทับของใคร: ถ้ามีรายการชื่อ `kinocut` อยู่แล้ว คำสั่ง รายชื่อเครื่องมือ และสถานะ
เปิด/ปิด ของเดิมอยู่ครบ อย่างมากแค่เพิ่มการชี้ไปที่ `editor` ถ้ายังไม่มีใครชี้

ชั้นวางใน **ตั้งค่า → MCP servers** ยังมีรายการ `kinocut` อยู่ สำหรับคนที่ลบรายการทิ้งแล้ว
อยากได้คืน หรืออยากดูว่าระบบเขียนอะไรให้ รายชื่อเครื่องมือ 54 ตัวที่รายการนี้ใช้มีสำเนาเดียว
อยู่ฝั่ง Go และชั้นวางก็อ่านจากที่เดียวกันนั้น

## ffmpeg สองตัว และทำไมถึงไม่ปนกัน

**ตัวอ่าน** อยู่ที่ `<DataRoot>/tools/ffmpeg/bin` เป็นบิ้ว LGPL มีไว้ให้ Aetox เอง
ใช้อ่านสื่อเท่านั้น แตกเฟรมให้ `video_ocr` และดึงเสียงให้ `audio_transcribe`

**เอาตัวนั้นไปให้ kinocut ใช้ไม่ได้** โค้ดของ kinocut 1.15.0 เขียน `-c:v libx264` ไว้ตายตัว
38 จุด บิ้ว LGPL ไม่มี libx264 (มีแต่ `libopenh264` กับตัวฮาร์ดแวร์) ถ้าชี้ไปหามัน
จะพังด้วย "Unknown encoder" แทบทุกคำสั่งที่ต้องเข้ารหัสภาพ

**ตัวเข้ารหัส** จึงเป็นอีกรายการหนึ่ง `ffmpeg-gpl` ใน `Manifest()`: FFmpeg 9.0.1 บิ้ว GPL
ของ gyan.dev โหลดจากรีลีสของเขาเองแบบพินแฮช ลงที่ `<DataRoot>/tools/ffmpeg-gpl/bin`
และถูกบอกให้ kinocut รู้ผ่าน `KINOCUT_FFMPEG_EXECUTABLE` เท่านั้น ไม่มีตัวไหนถูกวางบน
PATH ของเครื่อง การแจกแบบ "ผู้ใช้กดโหลดเองเป็นโปรแกรมแยกในโฟลเดอร์ของมัน แล้ว Aetox
เรียกใช้" คือรูปเดียวกับ poppler ไลเซนส์ GPL จึงไม่ปนเข้ามาในตัว Aetox ที่แจก

เครื่องที่มี ffmpeg เต็มของตัวเองอยู่แล้ว (PATH, scoop, chocolatey, winget, Program Files)
ระบบหาเจอและใช้ตัวนั้นแทนการชวนโหลด 111MB ซ้ำ โดยตรวจ `-encoders` จริงก่อนติ๊กเขียว
ไม่ใช่ดูแค่ชื่อไฟล์

## สิ่งที่ kinocut ต้องการ วัดจาก `kino doctor`

| | จำเป็น | มากับซิปไหม |
|:--|:--|:--|
| kinocut + Python | ใช่ | **ใช่** |
| ffmpeg + ffprobe | **ใช่** | ไม่ (ดูหัวข้อบน) |
| Node | ไม่ | ไม่ |
| hyperframes / @hyperframes/core | ไม่ | ไม่ |

สองแถวล่างคือฝั่งสร้างวิดีโอ **Hyperframes เป็นแพ็กเกจ Node แยกอีกตัว** งานตัดต่อใช้ได้
โดยไม่มีมัน งานเรนเดอร์ฉาก HTML ต้องมี

ห้องอ่านตารางนี้จาก `kino --format json doctor` โดยตรง ไม่ได้เก็บรายการไว้เอง เวอร์ชันหน้า
ของ kinocut ต้องการอะไรเพิ่ม หน้าจอก็จะบอกเองโดยไม่ต้องแก้ Aetox

## ราคาที่ต้องรู้ก่อนกดเชื่อมต่อ

kinocut เปิดเครื่องมือมา **196 ตัว** สคีมารวม 150,487 ตัวอักษร ประมาณ **37,600 โทเคน**
และไม่มีการแบ่งหน้า ตัวเลขนี้ติดไปกับ*ทุกคำขอ*ของเอเจนที่ถือมันไว้ ทั้งบล็อกเครื่องมือของ
เครื่องที่ลงสดอยู่ที่ประมาณ 10,100 โทเคน แปลว่ามันใหญ่กว่าบล็อกทั้งอันสามเท่า

รายการที่ตั้งไว้ให้จึงเลือกไว้ **54 ตัว ประมาณ 12,400 โทเคน** เท่าที่งานของเอเจนสองตัวนี้
ใช้จริง และมี `search_tools` ติดไปด้วยตั้งใจ มันคือทางที่เอเจนจะรู้ว่ามีอะไรไม่ได้ถูกเลือกมา
แล้วบอกผู้ใช้ได้ แทนที่การตัดจะเงียบ

อยากได้ครบทั้ง 196 ก็ลบรายการนั้นทิ้งได้ที่ ตั้งค่า → MCP servers → แก้ไข ช่องเครื่องมือ
ว่างเปล่าแปลว่าเอาทั้งหมด

## ถ้ายังไม่ติดตั้ง จะเป็นยังไง

ห้องยังเข้าได้ เอเจนทั้งสองยังคุยได้ ยังอ่านและฟังคลิปที่มีอยู่ได้ด้วย `video_ocr` กับ
`audio_transcribe` ซึ่งเป็นเครื่องมือของ Aetox เอง และตัวสร้างวิดีโอยังออกแบบฉากเป็นไฟล์
HTML จากคลังเทมเพลตได้ครบ สิ่งที่ทำไม่ได้คือขั้นสุดท้ายของทั้งสองงาน ตัดจริงและเรนเดอร์จริง

## สำหรับคนดูแลรีลีส

ซิปนี้ประกอบโดย job `kinocut` ใน [`.github/workflows/tools.yml`](../.github/workflows/tools.yml)
มาตรฐานเดียวกับที่ Tesseract และ ffmpeg ถูกห่อใหม่: เอาไบต์ของคนอื่นที่พินไว้ แกะครั้งเดียว
ในสคริปต์ที่ใครก็อ่านได้ แล้วปล่อยเป็นรีลีสของตัวเองชื่อ `tools-kinocut-<version>`

job นั้นพิสูจน์ตัวเองก่อนปล่อย: มันคุย MCP handshake จริงและเรียก `doctor` จริง
จากโฟลเดอร์ที่ไม่มี Python ตัวอื่นเลย ถ้าขั้นตอนตัดไฟล์ทิ้งไปโดนของที่ใช้จริง job จะพัง
ตรงนั้นแทนที่จะไปพังบนเครื่องผู้ใช้

รันเสร็จมันจะพิมพ์ URL กับ SHA256 ออกมา เอาไปวางใน `Manifest()` ที่
[`internal/capability/capability.go`](../internal/capability/capability.go)
ช่อง SHA256 ที่ว่างทำให้ `pinned()` ข้ามรายการนั้นทั้งอัน ความสามารถจึงไม่ถูกเสนอ
แทนที่จะถูกเสนอแล้วโหลดมาแล้วตรวจไม่ผ่าน

job รันจริงครั้งแรก 1 ก.ย. 2569 รีลีส `tools-kinocut-1.15.0` ขึ้นแล้วและแฮชถูกวางแล้ว
เวอร์ชันถัดไปของ kinocut คือการรัน job ใหม่ด้วยเลขใหม่ แล้ววางแฮชใหม่ตามเดิม

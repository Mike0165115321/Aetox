## 0. ประตูนี้มีไว้เพื่อใคร

### ทิศทาง
> _(เจ้าของเขียน — ตอนนี้มีแค่ประโยคที่คุยกันไว้)_

หน้าร้านของบริษัท สำหรับทุกคน **รวมถึงคนที่เพิ่งจับคอมพิวเตอร์ครั้งแรก** —
*"ผู้ช่วยในคอมพิวเตอร์ควรทำอะไรได้ทุกอย่างในคอมพิวเตอร์ รวมถึงแก้ปัญหาซอฟต์แวร์"*
ความสำเร็จของประตูนี้วัดที่: คนที่ไม่รู้ว่าโฟลเดอร์คืออะไร ก็ใช้ได้และได้งาน

### วันนี้มีอะไร
สวิตช์ **Aetox ▾** บนโลโก้สลับไปโรงช่างได้ แอปจำประตูล่าสุด
ห้องในประตูนี้: ผู้ช่วย · โปรเจกต์ · ทีมเอเจน · ทำงานอัตโนมัติ (ยังปิด) · ผลงาน
คอลัมน์ซ้ายเป็นรายการแชทล้วน — การจัดกลุ่มแชทอยู่ในห้องโปรเจกต์ ไม่ใช่แท็บในคอลัมน์นี้
**โปรเจกต์ของประตูนี้ไม่ใช่โปรเจกต์ของประตูโค้ด** (§90): อันนี้จัดกลุ่มบทสนทนาและพกไฟล์บริบท
ขอบเขตไม่ขยับ ส่วนของโรงช่างหยั่งรากแซนด์บ็อกซ์ลงในโฟลเดอร์ — คนละเรื่อง เจอกันไม่ได้ (§86)

### ช่องว่าง
ยังไม่มีการต้อนรับผู้ใช้ใหม่ที่ออกแบบมาเพื่อกลุ่มนี้โดยเฉพาะ · ข้อความขออนุมัติยังโชว์คำสั่งดิบ
ซึ่งขัดกับกลุ่มเป้าหมายตรง ๆ

## 1. ห้อง "ผู้ช่วย" — แชทหลัก

### ทิศทาง
> _(เจ้าของเขียน)_

### วันนี้มีอะไร
**เครื่องมือที่ถือ** (`internal/mode/modes/assistant.md` → `categories: agent, web, media,
files, shell`) = **ทุกอย่างบนเครื่อง ยกเว้นเครื่องมือนักพัฒนาและเครื่องมือเขียนเอกสาร**
อ่าน/เขียน/แก้/ลบไฟล์ · ค้นไฟล์ · รันคำสั่ง (shell, git) · เว็บ + เบราว์เซอร์ในตัว ·
อ่าน PDF/ภาพ/วิดีโอ/เสียง · ความจำ · สั่งงานทีมเอเจน
**ไม่มี:** `diagnostics`, `symbol`, `github_*` (เครื่องมือนักพัฒนา) และ
`doc_write`, `sheet_write` — .docx/.xlsx ได้มาด้วยการสั่งทีมเอเจน
ไม่ใช่เขียนเอง (COMPANY.md §1.1 กติกาข้อ 1: อยู่ใน Core ไม่ได้แปลว่าอยู่บนโต๊ะ)

**ไม่มีการปฏิเสธงานในโต๊ะนี้ (เจ้าของเคาะ 9 ส.ค. — §92):** *"ให้มันเป็นผู้ช่วยในคอมพิวเตอร์
ที่ทำอะไรก็ได้ในคอม"* — ไม่มีเครื่องมือโค้ดเป็นเรื่องของ*เครื่องมือที่ถือ* ไม่ใช่เรื่องของ
*สิ่งที่ทำได้* เขียนเว็บ เขียนสคริปต์ เขียนโปรแกรมเล็ก ๆ แก้โปรแกรมที่เพี้ยน คืองานของโต๊ะนี้
ทำด้วยไฟล์ + เชลล์ที่มีอยู่แล้ว **ไม่ส่งงานคืน และไม่ชี้ให้ผู้ใช้ไปทำที่อื่น**
การแยกสองประตูเป็นการแยกเชิง*ระบบ* ไม่ใช่การแยกพฤติกรรมของ AI

**ขอบเขต:** ไม่ผูกโปรเจกต์ — ทั้งเครื่อง ยกเว้นที่เก็บ credential (§19)
**ความปลอดภัย:** safety gate เดิมทุกประการ — มี shell ไม่ได้แปลว่าสิทธิ์กว้างขึ้น
**ความจำ:** `memory/MEMORY.md` (ข้ามโต๊ะ) + `memory/modes/assistant.md` — ต้องผ่านคนอนุมัติ
**ส่งงานต่อ:** `dispatch: specialized` → จ้างทีมเอเจนได้

**ใช้งานได้แล้ว:** แนบไฟล์/รูป/วิดีโอ/เสียง · ชุดคำสั่ง `/` · Ctrl+K · ให้คะแนนคำตอบ ·
ตอบใหม่ · แก้ข้อความแล้วส่งใหม่ · ย้อนไฟล์ (undo) · ไทม์ไลน์เครื่องมือ · ขออนุมัติก่อนทำของเสี่ยง

## 2. ห้อง "ทีมเอเจน"

### ทิศทาง
> _(เจ้าของเขียน — ที่คุยกันไว้: บริษัทขยายด้วยการเพิ่มเอเจน ไม่ใช่เพิ่มบุคลิก
> จ้างพนักงานใหม่ = วางไฟล์เพิ่มหนึ่งไฟล์)_

### วันนี้มีอะไร
แกลเลอรีการ์ดเอเจน + feed งานที่รับมา + การ์ด "สร้างเอเจนใหม่" (เปิดโฟลเดอร์)

**พนักงานที่มากับแอป** (`internal/subagent/profiles/agents/<ชื่อ>/AGENT.md`)
| เอเจน | หน้าที่ — อาชีพ ไม่ใช่นามสกุลไฟล์ (§91) | ไฟล์ที่มักได้กลับ |
|---|---|---|
| `doc` | เอกสารที่ต้องเชื่อถือได้ — รายงาน สัญญา ใบเสนอราคา ใบกำกับภาษี จดหมาย คู่มือ | `.docx` |
| `sheet` | ตัวเลข — รวบรวม จัดระเบียบ ตั้งสูตร ตรวจความถูกต้อง | `.xlsx` |
| `github` | GitHub — เปิดและรีวิว PR ไล่ CI ที่แดง จัดการ issue ตั้งรีโปให้ได้มาตรฐาน | — (ผลอยู่บนรีโป) |

`github` ประกาศ `needs: connection:github, mcp:github` — เอเจนขอ*การเชื่อมต่อ*เพิ่มได้
โดยไม่พ้นเพดานเครื่องมือ

**การ์ดแสดง:** ชื่อ · คำอธิบาย · **เครื่องมือจริงหลังเพดานทีมเอเจน** (ไม่ใช่ที่ไฟล์ขอ) ·
งานที่ทำแล้ว + ใช้ล่าสุด · ปุ่ม "แชทกับเอเจนนี้"

**เพดานทีมเอเจน** (`specialized.md`): `categories: media, web, agent` +
`tools: read, write, list, glob` + `chairs: doc_write, sheet_write`
— เอเจนที่ขอเกินนี้ไม่ได้ ไม่ว่าเขียนอะไรในไฟล์ตัวเอง

**สองทางที่งานถึงเอเจน:** (1) บอกผู้ช่วย → ผู้ช่วยส่ง brief → ได้ไฟล์กลับ
(2) กด "แชทกับเอเจนนี้" → คุยตรง (เครื่องมือ/ความจำ/พรอมป์ของเอเจนตัวนั้น) พร้อมแถบบอกตัวตน
บนหัวแชท + ช่องพิมพ์ "พิมพ์ถึง <ชื่อ>…"

**กติกาที่บังคับด้วยโครงสร้าง:** เอเจนไม่จ้างเอเจนต่อ · ไม่เห็นบทสนทนาของคุณ ·
ไฟล์โปรไฟล์หาย = เปิด session เดิมไม่ได้ (ไม่ให้ตัวหลักสวมชื่อตอบแทน)

### ช่องว่าง
ยังไม่มีหน้าสร้าง/แก้เอเจนในแอป (แก้ที่ไฟล์ `.md`) · ยังไม่มีทางดูว่าเอเจนตัวหนึ่งเรียนรู้อะไรไปแล้ว
> _(เจ้าของเขียนเพิ่ม)_

## 3. ห้อง "ทำงานอัตโนมัติ" — ยังปิด

### ทิศทาง
> _(เจ้าของเขียน — คำที่ให้ไว้: "ทำโครงพร้อม แต่มองข้ามไปก่อน อย่าจับปลาหลายมือ")_

**เคาะแล้ว 9 ส.ค. 2026:** ห้องนี้**ไม่ใช่ scheduler ที่เราเขียนเอง** แต่เป็น*หน้าที่ใช้เชื่อม*
เครื่องมืออัตโนมัติที่ผู้ใช้มีอยู่แล้ว — **n8n หรือ Windmill · รองรับหลายเจ้า ไม่ผูกเจ้าเดียว**
เจ้าพวกนั้นมี cron/webhook/trigger ครบกว่าที่เราจะเขียนทัน **ปล่อยให้มันเป็นนาฬิกา
Aetox เป็นมือ** และ *"ทำงานได้ก็ต่อเมื่อเชื่อมภายนอก"* คือนิยามของห้องนี้ ไม่ใช่ข้อจำกัดชั่วคราว

### วันนี้มีอะไร
ปุ่มมีอยู่ กดไม่ได้ ติดป้าย "เร็ว ๆ นี้" โดยเจตนา — ให้เห็นรูปร่างผลิตภัณฑ์ทั้งใบตั้งแต่วันนี้
(ปุ่ม `kind: 'soon'` อยู่ต่อในรุ่น 1.0 — COMPANY.md §2 ชนะ ไม่ใช่หนี้ที่ต้องซ่อน)
**ประตูจ้างงานพร้อมแล้ว** — ทริกเกอร์จากข้างนอกเดินเข้าประตูเดียวกับที่ห้องผู้ช่วยใช้ ไม่ต้องรื้อ

### ช่องว่าง
ระบบ "การเชื่อมต่อ" (`internal/connect`) รับได้เลย ขาดช่อง base URL และการออกแบบให้
เจ้าที่สองไม่ใช่การเขียนใหม่ (`jobs` ในฐานข้อมูลคือชั้นบันทึกการเรียนรู้ §82 ไม่ใช่ cron)
**คำถามที่ยังต้องตอบ และไม่หายไปเพราะนาฬิกาอยู่ข้างนอก:** งานที่รันตอนไม่มีคนเฝ้า
ขออนุมัติกับใคร (ทิศทางที่คุยไว้: ใช้สิทธิ์ที่อนุมัติล่วงหน้าเท่านั้น เจอเกินสิทธิ์ = ข้ามแล้วรายงาน)

## 4. ห้อง "ผลงาน" — คลังไฟล์

### ทิศทาง
> _(เจ้าของเขียน)_

### วันนี้มีอะไร
กวาดโฟลเดอร์ `output/<session>/` สดทุกครั้งที่เปิดหน้า (สูงสุด 500 ไฟล์) แสดงชื่อ · ขนาด ·
เวลา · session ที่สร้าง — เปิดด้วยโปรแกรมในเครื่อง และกระโดดกลับไปบทสนทนาที่สร้างมันได้

**ดิสก์คือความจริง** — ไม่มีตาราง index แยก เพราะ index กับโฟลเดอร์เถียงกันเมื่อไหร่
ผู้ใช้จะเห็นไฟล์ที่ไม่มี และไม่เห็นไฟล์ที่มี
**ลบบทสนทนา ≠ ลบผลงาน** — ลบผลงานทำได้จากหน้านี้เท่านั้น

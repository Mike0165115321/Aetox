# ประตูโค้ด (Aetox โค้ด) — ระบบที่มีอยู่จริงวันนี้

> สถานะ ณ 5 สิงหาคม 2026 · ภาพรวมผลิตภัณฑ์: [COMPANY.md](../COMPANY.md) · เหตุผลเชิงวิศวกรรม: [DECISIONS.md](DECISIONS.md) §83–§86
>
> **เอกสารนี้บันทึกสิ่งที่*ทำงานอยู่แล้ว* ไม่ใช่สิ่งที่อยากให้มี** ส่วนที่ยังไม่มีถูกทำเครื่องหมาย
> "ยังไม่มี" ไว้ชัด ๆ และช่อง "อยากให้ทำอะไรได้บ้าง" เว้นไว้ให้เจ้าของเขียนเอง

---

## 0. ประตูนี้คืออะไร

โรงช่างของบริษัท — นักพัฒนามุ่งเป้ามาที่นี่ เป็นแผนกใหญ่ที่มีทางของตัวเอง
กดสวิตช์ **Aetox ▾** บนโลโก้เพื่อสลับกลับหน้าร้าน (ประตูผู้ช่วย)

**ห้องในประตูนี้:** โค้ด (ห้องเดียว โดยเจตนา — ดู §5)
**คอลัมน์ซ้าย:** รายการโปรเจกต์ โดยมีแชทของโปรเจกต์นั้นซ้อนอยู่ข้างใน (ไม่มีลิสต์แชทลอย ๆ)

**สิ่งที่ประตูนี้ไม่วาดเลย:** ทีมเอเจน · ผลงาน · ออโต้ · ตัวสลับเอเจนที่ช่องพิมพ์
— ไม่ใช่เพราะซ่อน แต่เพราะดาว (COMPANY.md §3) ไม่ได้เชื่อมโต๊ะโค้ดกับของพวกนั้น

---

## 1. ห้อง "โค้ด" — โต๊ะทำงาน

**เครื่องมือที่โต๊ะนี้ถือ** (จาก `internal/mode/modes/coding.md`)
`categories: files, shell, code, web, agent` — อ่าน/เขียน/แก้ไฟล์แบบละเอียด (`edit`,
`apply_patch`, `notebook_edit`), ค้นด้วย `grep`/`glob`, รันคำสั่งและงานเบื้องหลัง
(`shell`, `shell_output`, `shell_kill`), `git`, **`diagnostics`** (ภาษาเซิร์ฟเวอร์บอก error),
**`symbol`** (ตัวระบุนี้คืออะไร ประกาศที่ไหน), `github_*` (อ่าน repo), เว็บ+เบราว์เซอร์,
สั่ง sub-agent (`task`), ความจำ

**ไม่มีบนโต๊ะนี้:** `slides_write` / `doc_write` / `sheet_write` (หมวด deliverables) และ
`image_ocr` / `video_ocr` / `pdf_read` / `audio_transcribe` (หมวด media)
— อยากได้สไลด์*เกี่ยวกับ*โค้ด = งานของประตูผู้ช่วย

**ขอบเขตไฟล์:** ผูกโปรเจกต์ — โฟลเดอร์โปรเจกต์ + โฟลเดอร์ที่ผู้ใช้เพิ่มเข้ามาเอง (สิทธิ์เท่ากัน)
**ความจำ:** `memory/MEMORY.md` + `memory/modes/coding.md`
**ส่งงานต่อ:** ไม่มี `dispatch:` — โต๊ะนี้จ้างข้ามโต๊ะไม่ได้ และไม่มีใครจ้างมันได้

**พื้นที่ทำงานที่มีอยู่แล้ว (workbench):** แท็บไฟล์ + เอดิเตอร์ (Monaco), เทอร์มินัลจริง (ConPTY),
เบราว์เซอร์ในตัวที่ AI ขับเองได้, แผงเครื่องมือ, ตารางสำหรับ .xlsx, ลากไฟล์/หน้าเว็บมาวางบนโต๊ะได้

**ทำอะไรได้แล้ววันนี้:** เปิด/สลับโปรเจกต์, ไล่โครงสร้างไฟล์พร้อมสถานะ git, ให้ AI อ่าน-แก้-รัน-
ตรวจ error, ย้อนไฟล์ที่เทิร์นล่าสุดแก้ (undo ด้วย shadow-git), ไทม์ไลน์เครื่องมือ + ขออนุมัติก่อนทำ,
ลากผลลัพธ์ขึ้นโต๊ะดู

**อยากให้ทำอะไรได้อีก:** _(เว้นไว้ให้เจ้าของเขียน)_

---

## 2. sub-agent ที่โต๊ะนี้ใช้ได้วันนี้

ไม่ใช่ "ทีมเอเจน" แบบออฟฟิศ (ยังไม่มีหน้าจอของตัวเอง) แต่ `task` เรียกได้จริงแล้ว 3 โปรไฟล์:

| โปรไฟล์ | ทำอะไร |
|---|---|
| `explore` | ค้นไฟล์ — grep/glob/list/read คืนรายการ path ที่เกี่ยวข้องจริง |
| `plan` | วางแผนก่อนลงมือ |
| `general` | งานทั่วไปที่ไม่อยากให้กินคอนเท็กซ์หลัก |

ทั้งสามอยู่ใต้เพดานโต๊ะโค้ด และไม่มีตัวไหนประกาศ `desk: coding` — จึงยังไม่ใช่ "เก้าอี้"
ที่จะขึ้นหน้าทีม และคุยตรงไม่ได้

**อยากให้ทีมโค้ดมีใครบ้าง:** _(เว้นไว้ให้เจ้าของเขียน — ที่เคยคุยกันไว้: reviewer / explorer / tester)_

---

## 3. ประตูส่งไม้ จากผู้ช่วย → โค้ด (ออกแบบแล้ว ยังไม่สร้าง)

แผนที่คุยกันไว้: วางแผนกับผู้ช่วย → ผู้ช่วยเรียบเรียงเป็นภาษาช่างแล้ว**เปิด session โต๊ะโค้ด
พร้อมวางแผนไว้ให้** → ปล่อยมือ ผู้ใช้เดินมาดูงานที่โรงช่างเอง อนุมัติที่นี่
**ทางเดียว ไม่มีขากลับ ไม่มีการคุยสดข้ามโต๊ะ** (COMPANY.md §3)

**สถานะ:** ยังไม่ได้สร้าง

---

## 4. ของที่ใช้ร่วมกันทั้งแอป

ตั้งค่า · ตัวตน AI · ผู้ให้บริการโมเดล + คีย์ · สิทธิ์/การอนุมัติ · MCP · สกิล · ชุดคำสั่ง ·
ธีม/ฟอนต์/ภาษา — **หนึ่ง binary หนึ่ง DataRoot หนึ่งชุดตั้งค่า** สลับประตูไม่เปลี่ยนอะไรในนี้

---

## 5. ทำไมมีห้องเดียว และของที่ตัดสินใจไม่เอา

เจ้าของเคาะไว้ว่ายังไม่เพิ่มห้อง — *"ไม่อยากด่วนเพิ่มจนของไม่มีประสิทธิภาพ"* — และสี่อย่างที่
ผลิตภัณฑ์อ้างอิงมี ก็ตกด้วยเหตุผลคนละข้อ (บันทึกเต็มใน DECISIONS.md §86):

| ของ | ทำไมไม่เอา |
|---|---|
| New chat | มีอยู่แล้วเป็นปุ่มแรกของคอลัมน์ + Ctrl+N |
| Scheduled | คือออโต้ ซึ่งจ้างออฟฟิศ จึงอยู่หลังประตูผู้ช่วยตามดาว |
| Plugins | Settings เป็นเจ้าของอยู่แล้ว (MCP + สกิล) — ประตูที่สองคือ drift |
| Pull requests | อันเดียวที่*ขาดจริง* — `github_*` อ่านได้แต่รีวิวไม่ได้ ต้องมี Decision ของตัวเอง |

## 6. รู้ไว้ว่ายังไม่มี

- หน้าทีมเอเจนของโค้ด (กลไกพร้อม — `Chairs(desk)` เป็น per-desk อยู่แล้ว — แต่ยังไม่มีใครนั่ง)
- ประตูส่งไม้จากผู้ช่วย (§3)
- แผงรีวิว diff ในแอป (เคยมี ถูกถอดใน §76 — ทางที่เลือกคือส่งออกไปโปรแกรมจริงของผู้ใช้)
- อะไรที่เกี่ยวกับ PR / CI

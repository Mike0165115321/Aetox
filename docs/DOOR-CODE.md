# ประตูโค้ด (Aetox โค้ด) — เอกสารกำหนดทิศทาง

> **นี่คือเอกสารทิศทาง ไม่ใช่บันทึกสถานะ** — เขียนว่าประตูนี้*ควรเป็นอะไร* หน้าตาแบบไหน
> ทำอะไรได้บ้าง แล้วค่อยไล่ว่าวันนี้ไปถึงไหนแล้ว
> ภาพรวมบริษัท: [COMPANY.md](../COMPANY.md) · ประตูอีกบาน: [DOOR-ASSISTANT.md](DOOR-ASSISTANT.md) ·
> เหตุผลเชิงวิศวกรรม: [DECISIONS.md](DECISIONS.md) §83–§86
>
> **วิธีใช้เอกสารนี้:** ทุกส่วนมีสามช่อง — **ทิศทาง** (อยากให้เป็นยังไง · เจ้าของเขียน) ·
> **วันนี้มีอะไร** (ของจริงที่ทำงานอยู่ · ผู้ช่วยเขียนให้ตรงกับโค้ดเสมอ) · **ช่องว่าง**
> เขียนยาวได้เต็มที่ ทิศทางที่ตกผลึกแล้วค่อยเลื่อนขึ้นไป COMPANY.md หรือกลายเป็น Decision
>
> สถานะโค้ด ณ 5 สิงหาคม 2026

## 0. ประตูนี้มีไว้เพื่อใคร

### ทิศทาง
> _(เจ้าของเขียน — ตอนนี้มีแค่ประโยคที่คุยกันไว้)_

โรงช่างของบริษัท — *"นักพัฒนาเขาจะมุ่งเป้ามาที่ตัวนี้แน่นอน มันเหมือนแผนกใหญ่เลย"*
เป็นแผนกที่มีทางของตัวเอง ไม่ใช่ห้องหนึ่งของผู้ช่วย

**และไม่ใช่กำแพงด้วย (เจ้าของเคาะ 9 ส.ค. — §92):** *"โค้ดก็โฟกัสสร้างระบบเต็มรูปแบบเฉย ๆ"*
ประตูนี้คือที่ทำงานเต็มรูปแบบสำหรับงานที่มีโค้ดเบสบนดิสก์ — workbench, terminal, diagnostics,
repo อยู่ครบข้าง ๆ กัน **ไม่ได้มีไว้กันผู้ช่วยจากงานซอฟต์แวร์** ผู้ช่วยเขียนเว็บหรือสคริปต์
ได้เองและต้องทำเมื่อผู้ใช้สั่ง — ประตูนี้เป็นการแยกเชิง*ระบบ* ไม่ใช่การแบ่งว่าใครได้รับอนุญาตทำอะไร

### วันนี้มีอะไร
สวิตช์ **Aetox ▾** บนโลโก้สลับกลับหน้าร้านได้ · ห้องเดียว: โค้ด
คอลัมน์ซ้ายเป็นรายการโปรเจกต์ โดยมีแชทของโปรเจกต์นั้นซ้อนข้างใน (ไม่มีลิสต์แชทลอย ๆ)

**ประตูนี้ไม่วาดเลย:** ทีมเอเจน · ผลงาน · ทำงานอัตโนมัติ · ตัวสลับเอเจนที่ช่องพิมพ์
— ไม่ใช่ซ่อน แต่เพราะดาว (COMPANY.md §3) ไม่ได้เชื่อมโต๊ะโค้ดกับของพวกนั้น

## 1. ห้อง "โค้ด" — โต๊ะทำงาน

### ทิศทาง
> _(เจ้าของเขียน)_

### วันนี้มีอะไร
**เครื่องมือที่ถือ** (`internal/mode/modes/coding.md` → `categories: files, shell, code, web, agent`)
อ่าน/เขียน/แก้ไฟล์ละเอียด (`edit`, `edits`) · ค้นด้วย `grep`/`glob` ·
รันคำสั่งและงานเบื้องหลัง (`shell` — `run`, `output`, `kill`, `list`) · `git` ·
**`diagnostics`** (language server บอก error) · **`symbol`** (ตัวระบุนี้คืออะไร ประกาศที่ไหน) ·
`github` (อ่าน repo — `search`, `repo_summary`, `list_files`, `read_file`) ·
เว็บ + เบราว์เซอร์ · `task` (sub-agent) · ความจำ

**ไม่มีบนโต๊ะนี้:** `doc_write`/`sheet_write` และ
`image_ocr`/`video_ocr`/`pdf_read`/`audio_transcribe` — อยากได้สไลด์*เกี่ยวกับ*โค้ด = งานของประตูผู้ช่วย

**ขอบเขต:** ผูกโปรเจกต์ — โฟลเดอร์โปรเจกต์ + โฟลเดอร์ที่ผู้ใช้เพิ่มเอง (สิทธิ์เท่ากัน)
**ความจำ:** `memory/MEMORY.md` + `memory/modes/coding.md`
**ส่งงานต่อ:** ไม่มี `dispatch:` — จ้างข้ามโต๊ะไม่ได้ และไม่มีใครจ้างมันได้

**พื้นที่ทำงาน (workbench):** แท็บชนิดที่มีจริงวันนี้คือ
`terminal · browser · files · file · decks · git · repomap · pr`
(`desktop/frontend/src/lib/stores/workbench.svelte.ts`) — แท็บไฟล์ + เอดิเตอร์ Monaco ·
เทอร์มินัลจริง (ConPTY) · เบราว์เซอร์ในตัวที่ AI ขับเองได้ · **แท็บ git: ไฟล์ที่ต่างจาก HEAD
พร้อม +N -M และ diff ต่อไฟล์ (§161.4)** · **แท็บ pr: pull request ของโปรเจกต์
พร้อมแบดจ์ CI และ diff ต่อไฟล์** · **แผนที่โค้ด (repo map)** · ตารางสำหรับ .xlsx ·
ลากไฟล์/หน้าเว็บมาวางบนโต๊ะ

**ใช้งานได้แล้ว:** เปิด/สลับโปรเจกต์ · ไล่โครงสร้างไฟล์พร้อมสถานะ git · ให้ AI อ่าน-แก้-รัน-ตรวจ error ·
ย้อนไฟล์ที่เทิร์นล่าสุดแก้ (shadow-git undo) · ไทม์ไลน์เครื่องมือ + ขออนุมัติก่อนทำ ·
กางแถวเครื่องมือแล้วเห็น diff ของคอลนั้นเป็น hunk แบบ git (§161.2 — โต๊ะโค้ดเท่านั้น)

## 2. ทีมเอเจนของโค้ด

### ทิศทาง
> _(เจ้าของเขียน — ที่คุยกันไว้: reviewer / explorer / tester และ
> *"ยังไงงานโค้ดก็ต้องมีทีมเอเจนแยกอยู่ละ"*)_

### วันนี้มีอะไร
ยังไม่มีหน้าจอทีม แต่ `task` เรียกได้จริงแล้ว 4 โปรไฟล์
(`internal/subagent/profiles/subagents/`):

| โปรไฟล์ | ทำอะไร | ถืออะไร |
|---|---|---|
| `explore` | ค้นไฟล์ คืนรายการ path ที่เกี่ยวข้องจริง | grep, glob, list, read |
| `general` | งานทั่วไปที่ไม่อยากให้กินคอนเท็กซ์หลัก | ทั้งชุด ยกเว้น plugin_install/delete |
| `reviewer` | อ่านสิ่งที่เพิ่งเปลี่ยน ชี้จุดที่จะพังพร้อมไฟล์และบรรทัด | read, grep, glob, list, git, diagnostics, symbol, repo_map |
| `tester` | รันชุดทดสอบของโปรเจกต์ อ่านผล บอกว่าอันไหนพังเพราะอะไร | shell, read, grep, glob, list, git, diagnostics |

**สองตัวหลังเขียนอะไรไม่ได้เลย โดยตั้งใจ** — คนที่แก้คือเอเจนหลักที่เป็นคนเขียนโค้ดนั้น
รีวิวเวอร์ที่แก้เองคือนักเขียนคนที่สอง แล้วจะไม่เหลือใครอ่าน ส่วน tester ที่ซ่อมเทสต์ที่ตัวเองรัน
คือเทสต์ที่ไม่มีใครเห็นว่ามันเคยพัง

ทั้งสี่เป็น**ซับเอเจน** — ไม่มีโต๊ะ จึงไม่ขึ้นหน้าทีมและคุยตรงไม่ได้ (COMPANY.md §4)

### ช่องว่าง
**เคาะแล้วที่ §94 — เอเจนบอกโต๊ะตัวเองด้วย*ที่อยู่* ไม่ใช่ด้วยฟิลด์** บ้านกลายเป็น
`<DataRoot>/agents/<โต๊ะ>/<ชื่อ>/` และไม่มีไฟล์ไหนเขียน `desk:` เลย — กติกาที่ v0.9.3
ตั้งไว้ไม่ถูกล้ม

> ย่อหน้านี้เคยเขียนว่าขาด *"ไฟล์เอเจนที่ประกาศ `desk: coding`"* ซึ่งขัดกับ v0.9.3
> ที่ลบฟิลด์นั้นออกจากทุกไฟล์ พร้อมเทสต์ที่เขียนว่า *"none should"* — เป็นตัวอย่างของ
> เอกสารทิศทางที่ค้างอยู่หลังโค้ด และเป็นเหตุผลที่หัวเอกสารนี้บังคับให้ช่อง "วันนี้มีอะไร"
> ตรงกับโค้ดเสมอ

เหลืองานช่างสามอย่าง: `resolve()` ไล่บ้านเพิ่มมิติโต๊ะ (ชื่อซ้ำข้ามโต๊ะ = `Conflict`
เพราะความจำ/งานคีย์ด้วยชื่อเปล่า) · `config.AgentHome(name)` กลายเป็น lookup แทน join ·
คลาย `setStation` ให้ chair นั่งได้ทุกโต๊ะที่ประกาศตัวเอง ไม่ใช่แค่ `specialized`
แล้วจึงวาดห้องทีมเอเจนฝั่งประตูโค้ด (§86 บอกว่าวันนี้ยังไม่วาด)

**เพดานของเอเจนที่นี่คือ manifest ของโต๊ะโค้ด — มีเชลล์** (§94.2) เป็นครั้งแรกที่เอเจน
ถือเชลล์ได้ และมันผ่าน safety gate ชุดเดียวกับที่โต๊ะโค้ดเองใช้

> _(เจ้าของเขียนว่าอยากได้ใครบ้าง — ที่คุยไว้: reviewer / explorer / tester)_

## 3. ประตูส่งไม้ จากผู้ช่วย → โค้ด

### ทิศทาง
ออกแบบไว้แล้วใน COMPANY.md §3: วางแผนกับผู้ช่วย → ผู้ช่วยเรียบเรียงเป็นภาษาช่างแล้ว
**เปิด session โต๊ะโค้ดพร้อมวางแผนไว้ให้** → ปล่อยมือ ผู้ใช้เดินมาดูงานที่โรงช่างเอง อนุมัติที่นี่
**ทางเดียว ไม่มีขากลับ ไม่มีการคุยสดข้ามโต๊ะ**

### วันนี้มีอะไร
ยังไม่ได้สร้าง

### ช่องว่าง
ทั้งอัน · อนาคตอาจเพิ่มแจ้งเตือน "งานที่ฝากไว้เสร็จแล้ว" โดยไม่ต้องเปิดขากลับ

## 5. ทำไมมีห้องเดียว และของที่ตัดสินใจไม่เอา

เจ้าของเคาะไว้ว่ายังไม่เพิ่มห้อง — *"ไม่อยากด่วนเพิ่มจนของไม่มีประสิทธิภาพ"* — และสี่อย่างที่
ผลิตภัณฑ์อ้างอิงมี ก็ตกด้วยเหตุผลคนละข้อ (เต็มใน DECISIONS.md §86):

| ของ | ทำไมไม่เอา |
|---|---|
| New chat | มีอยู่แล้วเป็นปุ่มแรกของคอลัมน์ + Ctrl+N |
| Scheduled | คือห้องทำงานอัตโนมัติ ซึ่งจ้างทีมเอเจน จึงอยู่หลังประตูผู้ช่วยตามดาว |
| Plugins | Settings เป็นเจ้าของอยู่แล้ว (MCP + สกิล) — ประตูที่สองคือ drift |
| Pull requests | ~~อันเดียวที่*ขาดจริง*~~ **สร้างแล้ว 29 ส.ค.** — เครื่องมือ `pr` ห้า action: `list` `read` `checks` `create` `comment` (`internal/skill/pr_pack.go`) **และห้องบน workbench** (`desktop/pr_room.go` + `PRPane.svelte`) ยิงผ่าน client ตัวเดียวกันที่ `internal/github/pr.go` · merge/close จงใจไม่มี |

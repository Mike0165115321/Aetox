# ย้ายการติดตั้งความสามารถออกจากตัวติดตั้ง

**21 ส.ค. 2026** · สถานะ: ชิ้น 1, 2, 4 เขียนแล้ว · ชิ้น 3 มี workflow แล้วแต่ยังไม่ได้ปล่อย · ชิ้น 5 ยังไม่แตะ

## ปัญหาที่แก้

Defender ฝั่งคลาวด์ตอบ `Program:Win32/Wacapew.C!ml` กับ
`aetox-amd64-installer.exe` แล้วเบราว์เซอร์ลบไฟล์ทิ้งก่อนผู้ใช้จะได้เห็นอะไรเลย

ที่วัดได้ 20 ส.ค.:

- เป็นคำตัดสินจาก **คลาวด์** ไม่ใช่ signature (`Client: Pending`) และลงท้าย `!ml`
  คือโมเดล ไม่ใช่คนวิเคราะห์
- เครื่องเจ้าของปิดคลาวด์อยู่ (`MAPSReporting = 0`) จึงสแกนกี่ครั้งก็สะอาด
  และมองไม่เห็นปัญหาที่ผู้ใช้เจอ
- ไฟล์ไม่ได้เซ็นโค้ด (`Get-AuthenticodeSignature` → `NotSigned`)

สิ่งที่โมเดลเห็นคือ NSIS ที่ไม่เซ็น ไม่มีชื่อเสียง แล้วตอนติดตั้งเรียก `curl.exe`
โหลดไฟล์ → `powershell` ตรวจแฮช → `ExecWait` รัน .exe ที่เพิ่งโหลด → `tar.exe`
แตกลงเครื่อง สี่รอบ นั่นคือแม่แบบของ trojan-downloader

การเซ็นโค้ดแก้จอ SmartScreen แต่ **ไม่ได้ลบพฤติกรรมนี้ออก** แผนนี้ลบมันออก

## ตัดสินแล้ว

1. **ตัวติดตั้งเลิกยัดของลงเครื่อง** ทั้งสี่ตัวย้ายไปติดตั้งตอนแอปรัน
2. **จอ onboarding ให้ติ๊กเลือกทีละความสามารถ** พร้อมบอกว่าแต่ละอันคืออะไร
   *(แก้ 21 ส.ค. เดิมตัดสินว่าปุ่มเดียวติดตั้งทั้งชุด เจ้าของเปลี่ยนหลังเห็นจอจริง
   ผลพลอยได้คือแถวใส่เปลือก `.ob-row` ได้อย่างซื่อสัตย์ เพราะมันเป็นตัวเลือกจริง)*
3. **Tesseract มาเป็น archive ธรรมดา** ไม่ใช้ตัวติดตั้งทางการ เพื่อไม่ต้องขอแอดมิน
4. **คนที่อัปเกรดมา ไม่ต้องโหลดซ้ำ** ตัวหาไฟล์มองทั้งที่เก่าและที่ใหม่

## ข้อค้นพบสองข้อที่กำหนดรูปงาน

### ปลายทางต้องย้าย ไม่ใช่แค่คนกดเปลี่ยน

ตัวติดตั้ง NSIS รันด้วยสิทธิ์แอดมิน `$INSTDIR` จึงอยู่ใน Program Files และ
poppler/ffmpeg ถูกแตกลงตรงนั้น **Aetox ตอนรันปกติเขียนที่นั่นไม่ได้**

`internal/rtk/install.go` แก้ปัญหานี้ไปแล้วครั้งหนึ่ง: ลงที่ `config.DataRoot()/bin/`
ซึ่งเขียนได้โดยไม่ต้องแอดมิน ทั้งสี่ตัวเดินตามรอยเดียวกัน แล้ว `bundledBinary()`
ใน `internal/skill/bundled.go` ที่หาไฟล์ข้าง ๆ ตัว exe ต้องเปลี่ยนตาม

ผลพลอยได้: ถ้าไม่มีอะไรลง Program Files อีกเลย ก็ไม่มีอะไรต้องขอแอดมิน
ไม่มี UAC สักจอ ทั้งสี่ตัวกลายเป็นเรื่องเดียวกันหมด

### ไม่มี Tesseract portable ที่เชื่อถือได้ให้ปักหมุด

[เอกสารทางการของ Tesseract](https://tesseract-ocr.github.io/tessdoc/Downloads.html)
ระบุว่า **ไม่มีตัวติดตั้ง Windows ทางการสำหรับรุ่นใหม่** ช่องทางที่มีคือ
UB-Mannheim (ตัวติดตั้ง NSIS) กับ Cygwin ส่วน zip portable ที่ค้นเจอเป็นของ
รุ่น 3.02 บน SourceForge ซึ่งเก่ากว่าที่ใช้อยู่หลายปี

ที่เหลือเป็นบิลด์ของบุคคลที่สาม ซึ่งย้อนแย้งกับสิ่งที่กำลังแก้: เราจะแก้ปัญหา
ความน่าเชื่อถือของไฟล์ ด้วยการไปพึ่งไฟล์ที่ตรวจสอบที่มาได้น้อยลง

**ทางออก: แพ็กเองใน CI จากไบต์ทางการ** งานหนึ่งใน release workflow โหลดตัวติดตั้ง
UB-Mannheim ที่ปักหมุดไว้ ตรวจ SHA256 เดิม แตกด้วย `7z` (มีบน windows runner)
เอาเฉพาะที่ใช้จริง แล้ว zip ขึ้นเป็น release asset ของ Aetox เอง

ได้สิ่งที่ข้อ 3 ต้องการครบ โดยไม่เสียที่มา: ไบต์ยังมาจาก UB-Mannheim
การแตกเกิดครั้งเดียวในที่ที่ตรวจสอบได้ และไฟล์ผลลัพธ์เข้า `checksums.txt`
ที่เซ็น ed25519 อยู่แล้ว

## รูที่มีมาก่อนงานนี้ และเพิ่งเจอตอนไล่ให้ครบ

**`whisper-cli` ไม่เคยถูกติดตั้งโดยอะไรเลย** ตัวติดตั้ง NSIS ลงแต่ *โมเดล* 31MB
ส่วนตัวโปรแกรมถอดเสียง `findBinary` ใน `internal/stt/whisper_cpp.go` หาจาก PATH
อย่างเดียว และไม่มีใครเอาไปวางไว้บน PATH ข้อความ error บอกผู้ใช้ให้ไปรัน
`scoop install whisper-cpp` เอง

แปลว่า `audio_transcribe` **ตายมาตลอดบนเครื่องที่ลงใหม่** และเราส่งโมเดล 31MB
ไปให้เครื่องยนต์ที่ไม่มีอยู่ ยืนยันบนเครื่องเจ้าของแล้ว: `whisper-cli` ไม่อยู่บน PATH

แก้แล้วในงานนี้ — `whisper-bin-x64.zip` (8MB) จาก release ของ ggml-org/whisper.cpp
เป็น zip ธรรมดา ปักหมุดได้ตรง ๆ และ `findBinary` มองที่ `<DataRoot>/tools/whisper`
ต่อจาก PATH แล้ว

**`tha.traineddata` ปักหมุดไว้กับ branch ที่ขยับได้** `project.nsi` โหลดจาก
`raw.githubusercontent.com/.../tessdata/main/tha.traineddata` พร้อม SHA256 ตายตัว
วันที่ต้นทางสร้างไฟล์นั้นใหม่ แฮชจะไม่ตรง แล้ว error path ของมันเองจะ**ข้ามภาษาไทย
เงียบ ๆ** ไม่ใช่ล้ม `.github/workflows/tools.yml` จึงรับ commit เป็น input ไม่ใช่ `main`

## ขนาดจริง

| ความสามารถ | เครื่องมือ | ขนาด |
|---|---|---|
| อ่านตัวหนังสือในรูป | Tesseract + tha.traineddata | ~48MB |
| อ่าน PDF | poppler | ~20MB (ต้องวัด) |
| ดูวิดีโอ ฟังเสียง | ffmpeg LGPL shared | 59.5MB |
| ถอดเสียงเป็นข้อความ | ggml-tiny-q5_1 | 31MB |

บวก `whisper-cli` อีก 8MB รวมราว **160MB** และเลขนี้ไปอยู่**บนแต่ละแถว** ไม่ใช่ยอดรวม
ใต้ปุ่มอย่างเดียว เพราะยอดรวมบอกว่าทั้งชุดราคาเท่าไร แต่ไม่บอกว่าควรตัดตัวไหนออก
ซึ่งเป็นคำถามเดียวที่การติ๊กออกตอบ

## งานเป็นชิ้น

### 1 · ตัวหาไฟล์มองสองที่ (Go ล้วน ไม่มี UI)

- `bundledBinary()` ลำดับใหม่: `DataRoot()/tools/<name>/bin/` → ข้าง exe (ของเดิม) → PATH
- `resolveTesseract()` ใน `image_ocr.go:146` เพิ่ม DataRoot ไว้ก่อน Program Files

ชิ้นนี้จบ = คนที่อัปเกรดมาไม่ต้องโหลดซ้ำ (ข้อ 4) และยังไม่มีใครโหลดอะไรทั้งนั้น
ปลอดภัยที่จะส่งก่อน

### 2 · ตัวติดตั้งความสามารถฝั่ง Go

แพ็กเกจใหม่ ใช้รูปแบบเดียวกับ `internal/rtk/install.go`

- manifest สี่รายการ: URL ปักหมุด · SHA256 · ปลายทาง · วิธีแตก · ไฟล์ที่ต้องเจอถึงจะนับว่าสำเร็จ
- โหลด → ตรวจแฮช → แตกลง `DataRoot()/tools/<name>/` → เขียน marker ชื่อตามเวอร์ชัน
  (รูปแบบเดียวกับ `.ok` ใน nsi ตอนนี้)
- ทำซ้ำได้โดยไม่พัง ตัวไหนสำเร็จแล้วข้าม ตัวไหนล้มลองใหม่ได้
- รายงานความคืบหน้าออกมาให้ UI

### 3 · CI แพ็ก Tesseract เป็น zip

`.github/workflows/tools.yml` เขียนแล้ว รันด้วยมือจากแท็บ Actions
แยกจาก release ของแอปโดยตั้งใจ: archive นี้เปลี่ยนก็ต่อเมื่อ Tesseract เปลี่ยน
การผูกไว้กับเลขเวอร์ชันที่ขยับทุกสัปดาห์คือการอัปไบต์ชุดเดิมซ้ำแล้วปักหมุดใหม่ฟรี ๆ

**ยังต้องรันหนึ่งครั้ง** มันจะพิมพ์ URL กับ SHA256 ออกมาให้เอาไปวางใน `Manifest()`
จนกว่าจะรัน Tesseract จะยังไม่อยู่ในรายการ และความสามารถอ่านภาพยังมาจาก NSIS เหมือนเดิม

### 4 · จอและประตูทั้งสาม

**ประตูที่ 1 — จอเปิดครั้งแรก** แทรกเป็นจอที่ 4 ใน `Onboarding.svelte`
(`0 ภาษา · 1 เชื่อมต่อ · 2 หน้าตา · 3 การอนุมัติ · 4 ความสามารถ · 5 เสร็จ`)
จุดบอกตำแหน่งข้างล่างจาก 4 เป็น 5

จอนี้เป็น:

- **แถวที่ติ๊กได้ หนึ่งแถวต่อหนึ่งความสามารถ** ใช้เปลือก `.ob-row` เดียวกับจอ
  การอนุมัติ เพราะมันเป็นตัวเลือกจริง ๆ
- แต่ละแถวมีชื่อความสามารถ คำอธิบายว่าได้อะไร และ**ขนาดของแถวนั้นเอง**
- ติ๊กไว้ครบทุกอันตั้งแต่แรก คนที่อยากได้ทั้งหมดไม่ต้องกดสี่ที
- แถวคือความสามารถ ไม่ใช่ไฟล์ ติ๊ก "ถอดเสียง" ครั้งเดียวได้ทั้งตัวถอดและโมเดล
  หน้าต่างส่งชื่อความสามารถไปให้ Go ไม่เคยส่งชื่อชิ้นส่วน
- ติ๊กออกหมด ปุ่มเปลี่ยนเป็น "ข้ามไว้ก่อน" ไม่ใช่ปุ่มที่กดไม่ได้
- ชื่อ Tesseract, poppler, ffmpeg ไม่ขึ้นบนจอเลย

กดแล้ว **เข้าแอปเลย** ไม่ใช่นั่งดูแถบวิ่ง ให้โหลดอยู่เบื้องหลังผ่าน
`BackgroundWork.svelte` ที่มีอยู่แล้ว จอสุดท้ายของ onboarding ต้องไม่ใช่การรอ

**ประตูที่ 2 — Settings** หน้า "ความสามารถ" สำหรับคนที่ข้ามไปแล้วเปลี่ยนใจ

**ประตูที่ 3 — ตอนต้องใช้พอดี · ประตูหลักจริง ๆ** ผู้ใช้ลากรูปเข้ามา เอเจนต์
ต้องใช้ `image_ocr` แล้ว Aetox ถามตรงนั้นว่าติดตั้งเลยไหม

นาทีนั้นเขารู้แน่ชัดว่าจะได้อะไรกลับมา ต่างจากตอนเปิดครั้งแรกที่ยังไม่เคย
ลากอะไรเข้ามาเลย ของนี้มีอยู่ครึ่งทางแล้ว: ทุกเครื่องมือตอนนี้ตอบว่า
*"จะบอกวิธีติดตั้งเองถ้าถูกเรียกใช้"* แค่เปลี่ยนข้อความนั้นให้เป็นปุ่ม

### 5 · เอาสี่ macro ออกจาก NSIS

ทำ**ท้ายสุด** อย่าทุบทางเก่าจนกว่าทางใหม่จะใช้ได้จริงบนเครื่องสะอาด

- ลบ `wails.tesseractocr`, `wails.poppler`, `wails.ffmpeg`, `wails.whispermodel`
- ตัวติดตั้งเหลือแค่วางไฟล์กับลงทะเบียน uninstall
- แก้ย่อหน้า antivirus ใน `README.md` และ `README.th.md` ในคอมมิตเดียวกัน
  เพราะมันเขียนไว้ว่า "ตอนติดตั้งมันโหลด Tesseract, poppler, ffmpeg" ซึ่งจะกลายเป็นเท็จ
- `internal/skill/skills/aetox/SKILL.md` ถ้าพูดถึงเส้นทางนี้ ต้องแก้ด้วย

## เกณฑ์ว่าเสร็จ

- ติดตั้งบนเครื่องสะอาดแล้วใช้ครบทุกความสามารถ โดย**ไม่มีจอ UAC สักจอ**
- คนที่อัปเกรดจากรุ่นเก่าไม่ต้องโหลดอะไรซ้ำ
- ตัวติดตั้งรุ่นใหม่ผ่าน Defender ที่**เปิดคลาวด์** ไม่ใช่แค่ผ่านเครื่องที่ปิดคลาวด์
  (เจ้าของต้องเปิด Cloud-delivered protection บนเครื่องตัวเองก่อน ไม่งั้นวัดไม่ได้เลย)

## ที่ยังไม่ตัดสิน

- โมเดลเสียงอยู่ในชุดเดียวกับอีกสามตัวไหม มันเป็นข้อมูล ไม่ใช่โปรแกรม
  และเป็นตัวเดียวที่ผู้ใช้อาจอยากเปลี่ยนเป็นรุ่นใหญ่กว่า
- ถ้าไม่มีเน็ตตอนกดติดตั้ง จะบอกว่าอย่างไร และเก็บความตั้งใจไว้ลองใหม่ทีหลังไหม
- การเซ็นโค้ดยังคงต้องทำอยู่ดี แผนนี้ลดพื้นที่ที่โดนยิง ไม่ได้ทดแทนใบเซ็น
  ดู `ROADMAP.md` และ `docs/DECISIONS.md` เรื่อง Azure Trusted Signing
  ซึ่ง**ยังไม่ได้ตรวจว่าคนไทยคนเดียวสมัครได้ไหม**

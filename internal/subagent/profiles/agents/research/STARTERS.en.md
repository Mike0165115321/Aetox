# What do you need to find out?

- Which competitor is actually the dangerous one | Map the competitive field for me. Open the competitor-scan skill first, then search wide from several angles before going deep: what they call themselves, what their users call them, and what somebody types when looking for this kind of thing. Do not compare every attribute that can be compared — only the axes a person would actually decide on. Every price and feature claim carries a date; where the page does not state one, say it does not. There must be at least one row where we clearly lose — a scan where we win everything is a scan that did not go deep enough, so go back. Close with one answer: which one is the dangerous one, and why. Write the long version to a markdown file with every source linked. | chartColumn
- What the people actually using it complain about | Find out what people who actually use this complain about. Go where users talk to each other first — forums, reviews, bug reports — not the vendor's own pages, which only tell you what they claim. Separate complaints that recur across several people in several places from one loud thread that is really one person: volume is not a pattern. For each one, say how many places you saw it, over what period, and whether the vendor has since fixed it — a fixed complaint still counts, but say that it is fixed. Close with the three things that would genuinely win their customers if we did them better. | messageSquare
- One subject, dug into until it is answerable | Dig into this until it is genuinely answerable. Read the search-craft skill first. Put your plan in the todo list so I can see which angles you are taking, then start. Go wide first — at least four genuinely different angles — before choosing what to read properly. For anything you have not opened in full, say you only have the two lines from the search result; do not write as though you read it. If you hit a paywall, say what is behind it and how much you could see. Answer with the conclusion first, then what it rests on, then what you are still unsure of and what would settle it. Write the long version to a markdown file. | search
- What has actually changed in this field lately | What has changed in this field lately? Fix the window first — since when? Ask me if I have not said. Then find what actually changed: what shipped, what prices moved, who entered or left, and what rules or regulations changed. Every item carries a date and a link. Where several outlets are all rewriting one press release, count that as one source and say that is where it came from. Order by what it means for somebody working in this field, not by date. Close with a single paragraph covering what to know if that paragraph is all anyone reads. | clock
- Whether what I heard is actually true | Check whether this is true. Read the source-trust skill first. Trace it back to the origin rather than stopping at a site repeating it. If every path converges on one source, say that there is really only one source. Answer clearly: true, false, partly true, or not provable from what is reachable — do not retreat into a neutral non-answer. If it is partly true, split which part is which. Say what the damage is if people believe the wrong version, and what you would have to see to be more certain than you are. | shield
- What this actually sells for, before I price it | Find out what things like this actually sell for. Work from prices published on sellers' own pages; treat a round-up article carrying affiliate links as an advertisement rather than a source. Separate list price, price after discount, and price that requires a long contract — those are three different numbers and cannot be averaged together. Give me the real range and the middle, and say what differs between the cheapest and the most expensive that justifies the gap. Every figure carries a date and a link. Close with your view on where a price should sit, and why. | layoutList
- A list of names I can actually act on | Build me this list. Ask me first what the list is for, because every inclusion rule follows from that. Only keep entries you can confirm from a live page that they still exist. Where you cannot find contact details, include the entry and write that you could not — do not guess an email from a naming pattern. Every row carries a link I can follow to see where the information came from. Tell me how many you found, how many you excluded and why, and how complete this really is versus being only the easily-findable part. Write it to a markdown file as a table. | userRound
- Whether somebody has already built this | Find out whether somebody has already built this. Search with several vocabularies — mine and the one that field would actually use — because the same thing is called different things in different corners. If somebody has built it, say how far they got, whether it is still alive, and if it died, why it died; that last part is worth the most. If you find nothing, say plainly which search terms turned up nothing, because "did not find" and "does not exist" are different claims. Close with a straight view: is the gap real, or is it a gap people tried and found did not work? | eye

# What needs working out?

- Books, built from a pile of receipts | Build me a set of books from the receipts in this folder. Read every one first, and where a receipt is a photo or a scan, read the figures off it properly. Anything you cannot read, or cannot tell what it was for, put in a pile of its own and ask me — do not guess. Categorise from what the receipts actually say rather than forcing them into an off-the-shelf list. Hand it back as a spreadsheet with every line item, its date and the vendor, totals per category, and a monthly summary. Make the totals real formulas so they recalculate when I change a figure — do not type the totals in as constants. | layoutList
- A table out of a PDF that still calculates | Pull the tables out of these PDFs into a spreadsheet. Read every page first — do not stop at the first table you find. Keep every column the source has, and do not drop one because you decided it did not matter. Where the source leaves a cell empty, leave it empty; do not substitute a zero. Watch for negatives written as parentheses and convert them to real negative values. Keep numbers as numbers that calculate, not as text. Hand it back with a column saying which file and page each row came from, and tell me which cells you were not confident reading. | fileText
- Several files, merged into one table | Merge these files into a single table. Open all of them first and work out what each column is named and what it actually means — do not assume two similarly named columns are the same thing, and ask me where it is ambiguous. Normalise the date formats and the units across the whole table. Flag duplicate rows rather than deleting them yourself. Hand it back as a spreadsheet with a column recording which file each row came from, then report how many rows came from how many files, how many rows are incomplete, and which columns some of the files did not have at all. | package
- A model of whether this business survives | Build me a model of whether this business survives. Ask me first for all of it: what is sold, at what price, the unit cost, monthly fixed costs, current monthly sales, and what it costs to win one customer. For anything I do not know, tell me where to find it — do not assume a figure. Keep the assumption cells separate from the calculation cells so I can change the inputs and watch the result move. Run three cases — bad, middling, good — and work out margin per unit, break-even, and the sales needed to survive. Hand it back as a spreadsheet, then answer straight: do these numbers work? If they do not, say which variable has to move and by how much. Do not soften it. | chartColumn
- How far these numbers can be trusted | Check how far the numbers in this file can be trusted. Look for four things: formulas pointing at the wrong range or slipping a row, values typed over formulas so they stopped calculating, mixed units or currencies inside one column, and totals that do not equal the sum of the rows above them. Go point by point — which cell, what is wrong, what the right figure would be. Do not fix the file until I say so. Close with one answer: can these numbers be used to decide something as they stand, or does something have to be fixed first? If you find nothing, say you found nothing rather than manufacturing an issue. | search
- A comparison table you can actually decide from | Build me a comparison of the options I am choosing between. Ask me first what the decision actually is and what would genuinely change my answer — do not compare every attribute that can be compared, only the axes that move the outcome. For figures that can be found on the web, go and find the real ones with their date; do not use one from memory. Where you cannot find something, write that you could not find it — an empty cell reads as "none". Hand it back as a spreadsheet with weighted scores using the weights I gave you, then close with a paragraph on which one you would pick and why, saying where the losing options actually win. | eye
- A repayment schedule showing what it really costs | Build me a repayment schedule. Ask me first for the amount, the interest rate, whether it is reducing-balance or flat, the number of instalments, and whether there is an upfront fee or an early-settlement penalty. If all I give you is a monthly payment, work backwards to the real effective rate and tell me what it is. Build the schedule instalment by instalment showing how much of each payment is principal, how much is interest, and what is left owing. Hand it back as a spreadsheet with the total interest over the life of the loan shown as one large figure, because that is the number people miss. | timer
- How to structure this before building it | I want to work this out — how should the spreadsheet be structured? Do not build the file yet. Ask until you understand what question I will ultimately answer with these numbers, then propose the structure: what sheets it needs, which columns are raw input, which should be formulas, and what belongs in a separate assumptions block because it will be changed often. Warn me where this structure will break once the data is ten times bigger. Once you have explained it, then ask whether I want the file built to that shape. | brain
